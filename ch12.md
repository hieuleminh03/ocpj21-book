## Khái niệm cơ bản {#basic-concepts}
Hãy bắt đầu bằng việc định nghĩa một vài khái niệm.

Như chúng ta đã biết, dữ liệu trong máy tính được tổ chức thành file, directory và file system.

File là một nhóm dữ liệu liên quan được lưu trên disk hoặc thiết bị lưu trữ khác. File có thể chứa chương trình, tài liệu, hình ảnh hoặc bất kỳ loại dữ liệu nào khác. 

Directory, còn được gọi là folder, là tập hợp các file và directory khác được lưu dưới cùng một tên. Directory cho phép bạn tổ chức file theo cấu trúc phân cấp. Ví dụ:
```
documents/
  work/
    report.pdf  
    presentation.ppt
  personal/
    resume.doc
    family.jpg
```

Directory ở trên cùng của cấu trúc được gọi là root directory. Trên hệ thống Unix nó được biểu diễn bằng dấu gạch chéo xuôi (`/`), còn trên Windows nó được nhận diện bằng một drive letter theo sau là dấu hai chấm, như `C:`.

Để định vị một file hoặc directory cụ thể, bạn cần chỉ định path của nó, tuyến đường từ root directory đến mục cụ thể trong cấu trúc phân cấp. Dấu phân cách path khác nhau giữa các hệ điều hành. Unix dùng dấu gạch chéo xuôi (`/`) còn Windows dùng dấu gạch chéo ngược (`\`). 

Một path có thể là absolute, chỉ định tuyến đường đầy đủ từ root:
```
/home/steve/documents/work/report.pdf
C:\Users\Steve\Documents\Work\report.pdf 
```

Hoặc nó có thể là relative, chỉ định tuyến đường từ directory hiện tại, còn được gọi là working directory:
```
documents/work/report.pdf
..\personal\resume.doc
```

Hai ký hiệu đặc biệt thường được dùng trong relative path:
- Một dấu chấm đơn (`.`) biểu diễn directory hiện tại 
- Hai dấu chấm (`..`) biểu diễn directory cha của directory hiện tại (lên một cấp trong cấu trúc phân cấp)

Ví dụ, nếu directory hiện tại là `/home/steve/documents`, thì:
- `./work/report.pdf` tương đương với `work/report.pdf`  
- `../downloads/file.zip` trỏ đến `/home/steve/downloads/file.zip`

Trong Java, bạn có thể làm việc với file system theo hai cách chính:

1. Dùng class `java.io.File` (legacy I/O API)
2. Dùng interface `java.nio.file.Path` (NIO.2 API) 

Để tạo một instance `File`, chỉ cần truyền path của file hoặc directory vào constructor của nó:

```java
File file = new File("/home/steve/documents/work/report.pdf");
File dir = new File("C:\\Users\\Steve\\Documents");
```

Lưu ý rằng thao tác này không thực sự tạo file hay directory trên disk, nó chỉ tạo một object biểu diễn path đó. Sau đó bạn có thể gọi nhiều method khác nhau trên object `File` để lấy thông tin về file hoặc directory hay để thao tác với nó.

Trong NIO.2 (New Input/Output) API mới hơn, path được biểu diễn bằng interface `Path` thay vì class `File`. Bạn có thể lấy một instance `Path` theo một vài cách:

```java
// 1. Using the Paths helper class
Path p1 = Paths.get("/home/steve/documents/work/report.pdf");

// 2. From a File object  
File file = new File("C:\\Users\\Steve\\Documents");
Path p2 = file.toPath();

// 3. By joining path strings
Path p3 = Paths.get("documents", "work", "report.pdf"); 
Path p4 = Paths.get("/home", "steve").resolve("documents");

// 4. From the default FileSystem
Path p5 = FileSystems.getDefault().getPath("documents/work/report.pdf");
```

Bạn có thể dễ dàng chuyển đổi qua lại giữa `File` và `Path` bằng các method `toFile()` và `toPath()`:

```java
File file = path.toFile();
Path path = file.toPath();  
```

Interface `Path` cung cấp các method tương tự `File` nhưng linh hoạt hơn và có thêm nhiều tính năng để làm việc với path.

Ví dụ, bạn có thể trích xuất các phần cụ thể của một path:

```java
Path path = Paths.get("/home/steve/documents/work/report.pdf");
        
Path parent = path.getParent(); // /home/steve/documents/work
Path root = path.getRoot(); // /  
Path name = path.getFileName(); // report.pdf
```

Hoặc tạo path bằng cách nối các thành phần:

```java
Path documents = Paths.get("/home/steve/documents");
Path file = documents.resolve("work/report.pdf"); 
```

Path thu được không nhất thiết phải tồn tại, nó chỉ là một biểu diễn trừu tượng có thể được dùng cho các xử lý tiếp theo.

Trong các phần tiếp theo, chúng ta sẽ tập trung vào interface `Path` và NIO.2 API.

## Sử dụng NIO.2 Paths {#using-nio2-paths}
Hãy cùng khám phá chi tiết hơn một số method và khái niệm chính liên quan đến `Path`.

Interface này cung cấp các method sau để lấy thông tin cơ bản của path:
- `String toString()`: Trả về biểu diễn dạng string của path.
- `int getNameCount()`: Trả về số phần tử name trong path.
- `Path getName(int index)`: Trả về phần tử name tại index được chỉ định.

Đây là một ví dụ:
```java
Path path = Paths.get("/home/user/documents/file.txt");
System.out.println(path.toString()); // Output: /home/user/documents/file.txt
System.out.println(path.getNameCount()); // Output: 4
System.out.println(path.getName(0)); // Output: home
System.out.println(path.getName(2)); // Output: documents
```

Ngoài ra, có các method để truy cập các thành phần của path:
- `Path getFileName()`: Trả về filename (thành phần cuối cùng) của path.
- `Path getRoot()`: Trả về thành phần root của path, hoặc `null` nếu path là relative.
- `Path getParent()`: Trả về path cha, hoặc `null` nếu không có path cha.

Đây là một ví dụ:
```java
Path path = Paths.get("/home/user/documents/file.txt");
System.out.println(path.getFileName()); // Output: file.txt
System.out.println(path.getRoot()); // Output: /
System.out.println(path.getParent()); // Output: /home/user/documents
```

Method `relativize` tạo một relative path giữa path hiện tại và một path cho trước. Ví dụ:
```java
Path base = Paths.get("/home/user");
Path path = Paths.get("/home/user/documents/file.txt");
Path relativePath = base.relativize(path);
System.out.println(relativePath); // Output: documents/file.txt
```

Method `normalize` trả về một path đã được chuẩn hóa so với path gốc, loại bỏ mọi thành phần dư thừa như `.` (directory hiện tại) và `..` (directory cha):
```java
Path path = Paths.get("/home/user/./documents/../file.txt");
Path normalizedPath = path.normalize();
System.out.println(normalizedPath); // Output: /home/user/file.txt
```

Method `toRealPath` trả về real path của một file đang tồn tại trong file system, giải quyết mọi symbolic link:
```java
Path path = Paths.get("/path/to/symlink");
Path realPath = path.toRealPath();
System.out.println(realPath); // Output: /actual/path/to/file
```

Method `resolve` phân giải một path dựa trên path hiện tại, cho phép bạn kết hợp absolute path và relative path:
```java
Path base = Paths.get("/home/user");
Path relativePath = Paths.get("documents/file.txt");
Path resolvedPath = base.resolve(relativePath);
System.out.println(resolvedPath); // Output: /home/user/documents/file.txt
```

Tuy nhiên, nếu path cần phân giải đã là absolute path, nó sẽ được trả về nguyên trạng:
```java
Path base = Paths.get("/home/user");
Path absolutePath = Paths.get("/other/path/file.txt");
Path resolvedPath = base.resolve(absolutePath);
System.out.println(resolvedPath); // Output: /other/path/file.txt
```

## Class `Files` {#the-files-class}

Class `java.nio.file.Files` là một phần của NIO.2 API. Nó cung cấp một tập phong phú các static utility method để làm việc với file và directory một cách ngắn gọn và hiệu quả hơn so với class `File` legacy.

Dưới đây là một số tính năng chính của nó:

- **Xử lý exception tốt hơn:**
  Nhiều method của `Files` throw các exception cụ thể hơn như `NoSuchFileException`, `DirectoryNotEmptyException`, v.v., giúp việc xử lý các tình huống lỗi khác nhau dễ dàng hơn. Ngược lại, các method của class `File` thường trả về giá trị boolean hoặc throw các exception chung chung hơn.

- **Hỗ trợ symbolic link:**
  Class `Files` có hỗ trợ sẵn cho symbolic link. Bạn có thể tạo, phát hiện và phân giải symbolic link bằng các method như `createSymbolicLink()`, `isSymbolicLink()` và `readSymbolicLink()`.

- **Thao tác atomic:**
  Class `Files` cung cấp các method để thực hiện các thao tác file atomic. Ví dụ, `move()` với option `StandardCopyOption.ATOMIC_MOVE` đảm bảo thao tác di chuyển file được thực hiện một cách atomic.

- **File attribute:**
  Class `Files` giúp đọc và sửa file attribute một cách dễ dàng, như permission của file, owner, timestamp, v.v. Bạn có thể dùng các method như `readAttributes()`, `setOwner()`, `setLastModifiedTime()`, v.v.

- **Duyệt directory:** 
  Method `Files.walkFileTree()` cho phép bạn duyệt đệ quy một cây directory và thực hiện hành động trên từng file và directory bắt gặp. Cách này hiệu quả và linh hoạt hơn việc tự duyệt cây bằng class `File`.

- **Stream và buffer:**
  Class `Files` cung cấp các method để mở file dưới dạng stream (`newInputStream()`, `newOutputStream()`) hoặc buffered reader/writer (`newBufferedReader()`, `newBufferedWriter()`), giúp các thao tác I/O thuận tiện hơn.

- **Thao tác path:**
  Vì class `Files` làm việc với các object `Path`, nó có thể thực hiện các thao tác liên quan đến path như phân giải, chuẩn hóa và lấy các thành phần của path, v.v.

- **Thao tác nội dung file:**
  Class `Files` có các method đọc và ghi nội dung file chỉ trong một dòng code, như `readAllBytes()`, `readAllLines()`, `write()`, v.v. Điều này loại bỏ nhu cầu viết code I/O file thủ công.

Dưới đây là một số method chính do class `Files` cung cấp:

- **Thao tác file:**
  - `static Path createFile(Path path)`: Tạo một file mới.
  - `static Path createDirectory(Path path)`: Tạo một directory mới.
  - `static Path createDirectories(Path path)`: Tạo một directory và tất cả directory cha chưa tồn tại.
  - `static void delete(Path path)`: Xóa một file hoặc directory.
  - `static boolean deleteIfExists(Path path)`: Xóa một file hoặc directory nếu nó tồn tại.
  - `static Path copy(Path source, Path target, CopyOption... options)`: Sao chép một file hoặc directory.
  - `static Path move(Path source, Path target, CopyOption... options)`: Di chuyển hoặc đổi tên một file hoặc directory.

- **Đọc và ghi:**
  - `static byte[] readAllBytes(Path path)`: Đọc tất cả byte từ một file.
  - `static String readString(Path path)`: Đọc một file dưới dạng string.
  - `static List<String> readAllLines(Path path)`: Đọc tất cả dòng từ một file.
  - `static Path write(Path path, byte[] bytes, OpenOption... options)`: Ghi byte vào một file.
  - `static Path writeString(Path path, CharSequence csq, OpenOption... options)`: Ghi một string vào một file.
  - `static Path write(Path path, Iterable<? extends CharSequence> lines, OpenOption... options)`: Ghi các dòng text vào một file.

- **File attribute:**
  - `static boolean exists(Path path, LinkOption... options)`: Kiểm tra một file hoặc directory có tồn tại không.
  - `static boolean notExists(Path path, LinkOption... options)`: Kiểm tra một file hoặc directory có không tồn tại không.
  - `static boolean isReadable(Path path)`: Kiểm tra một file có đọc được không.
  - `static boolean isWritable(Path path)`: Kiểm tra một file có ghi được không.
  - `static boolean isExecutable(Path path)`: Kiểm tra một file có thực thi được không.
  - `static boolean isDirectory(Path path, LinkOption... options)`: Kiểm tra một path có phải là directory không.
  - `static boolean isRegularFile(Path path, LinkOption... options)`: Kiểm tra một path có phải là regular file không.
  - `static long size(Path path)`: Trả về kích thước của một file.

- **Hỗ trợ stream:** 
  - `static Stream<Path> list(Path dir)`: Trả về một stream các entry trong một directory.
  - `static Stream<Path> walk(Path start, FileVisitOption... options)`: Trả về một stream được điền dần (lazily) với `Path` bằng cách duyệt cây file bắt nguồn tại một file khởi điểm cho trước.
  - `static Path walkFileTree(Path start, FileVisitor<? super Path> visitor)`: Duyệt một cây file.

- **Symbolic link:**
  - `static Path createSymbolicLink(Path link, Path target, FileAttribute<?>... attrs)`: Tạo một symbolic link.
  - `static Path readSymbolicLink(Path link)`: Đọc target của một symbolic link.

- **Permission của file:**
  - `static Path setPosixFilePermissions(Path path, Set<PosixFilePermission> perms)`: Đặt POSIX permission cho file.
  - `static Set<PosixFilePermission> getPosixFilePermissions(Path path, LinkOption... options)`: Đọc POSIX permission của file.

Một số method của class `Files` nhận các tham số tùy chọn điều khiển cách thao tác được thực hiện. Dưới đây là một số tham số phổ biến:

- `java.nio.file.LinkOption`: Chỉ định cách xử lý symbolic link. Một giá trị phổ biến là `LinkOption.NOFOLLOW_LINKS`, cho biết không nên đi theo symbolic link.
- `java.nio.file.StandardCopyOption`: Điều khiển cách thực hiện thao tác copy file. Các giá trị gồm `REPLACE_EXISTING` (thay thế target nếu nó tồn tại), `COPY_ATTRIBUTES` (sao chép cả file attribute), `ATOMIC_MOVE` (thực hiện thao tác di chuyển atomic).
- `java.nio.file.StandardOpenOption`: Chỉ định các option để mở file. Các giá trị phổ biến là `CREATE` (tạo file mới nếu nó chưa tồn tại), `APPEND` (ghi thêm vào cuối file), `TRUNCATE_EXISTING` (cắt ngắn file nếu nó tồn tại).
- `java.nio.file.FileVisitOption`: Được dùng với method `Files.walkFileTree()` để điều khiển cách duyệt cây file. Giá trị `FOLLOW_LINKS` cho biết nên đi theo symbolic link trong quá trình duyệt.

Trong các phần tiếp theo, chúng ta sẽ xem xét chi tiết hơn một số method và tham số tùy chọn của class này. Nhưng trước tiên, hãy nói về I/O stream.


## I/O Streams {#io-streams}
Trong Java, I/O (Input/Output) stream cung cấp cách đọc dữ liệu từ một source hoặc ghi dữ liệu đến một destination.

Đây là một phép so sánh để giải thích I/O stream. Hãy tưởng tượng bạn có một bể nước và muốn chuyển nước sang một container khác. Bạn có thể nối một đường ống giữa bể và container, nước sẽ chảy từ bể sang container qua đường ống. Tương tự, I/O stream đóng vai trò như đường ống, cho phép dữ liệu chảy từ source (một file, network hay memory) đến destination (một file, network hay memory khác).

I/O stream có thể được phân loại thành một số nhóm.

Trước hết, Java cung cấp hai loại I/O stream: byte stream và character stream.

- **Byte stream**, đúng như tên gọi, đọc và ghi dữ liệu dưới dạng byte (dữ liệu 8-bit). Chúng phù hợp để xử lý dữ liệu binary thô, như hình ảnh, file âm thanh hoặc bất kỳ loại dữ liệu phi text nào khác. Ví dụ gồm `InputStream` và `OutputStream`.

- **Character stream** được thiết kế để đọc và ghi dữ liệu dưới dạng ký tự (dữ liệu Unicode 16-bit). Chúng hữu ích để xử lý dữ liệu dạng text, như đọc từ hoặc ghi vào file text. Ví dụ gồm `Reader` và `Writer`.

I/O stream cũng có thể được phân loại thành input stream và output stream.

- **Input stream** được dùng để đọc dữ liệu từ một source. Chúng cung cấp các method như `read()` để đọc byte hoặc ký tự từ input source. Ví dụ về các input stream class trong Java gồm `FileInputStream`, `BufferedInputStream`, `FileReader` và `BufferedReader`.

- **Output stream** được dùng để ghi dữ liệu đến một destination. Chúng cung cấp các method như `write()` để ghi byte hoặc ký tự đến output destination. Ví dụ về các output stream class trong Java gồm `FileOutputStream`, `BufferedOutputStream`, `FileWriter` và `BufferedWriter`.

Cuối cùng, I/O stream có thể được phân thành low-level stream và high-level stream.

- **Low-level stream**, còn được gọi là node stream, được kết nối trực tiếp với data source hoặc destination. Chúng là những khối xây dựng của các thao tác I/O và cung cấp chức năng cơ bản để đọc từ hoặc ghi đến một source hay destination cụ thể. Ví dụ về low-level stream gồm `FileInputStream`, `FileOutputStream`, `FileReader` và `FileWriter`.

- **High-level stream**, còn được gọi là processing stream hay filter stream, được xây dựng trên low-level stream. Chúng cung cấp thêm chức năng và tính năng, như buffering, filtering hoặc biến đổi dữ liệu khi nó đi qua stream. Ví dụ về high-level stream gồm `BufferedInputStream`, `BufferedOutputStream`, `BufferedReader`, `BufferedWriter`, `ObjectInputStream` và `ObjectOutputStream`.

### Các class Stream {#stream-classes}
Thư viện `java.io` định nghĩa bốn abstract class làm parent của tất cả I/O stream class:

- `InputStream`: Class cơ sở cho tất cả byte input stream.
- `OutputStream`: Class cơ sở cho tất cả byte output stream.
- `Reader`: Class cơ sở cho tất cả character input stream.
- `Writer`: Class cơ sở cho tất cả character output stream.

Các abstract class này cung cấp những method nền tảng để đọc từ hoặc ghi vào một stream, như `read()`, `write()`, `close()` và nhiều method khác. Các concrete stream class extends những base class này để cung cấp chức năng cụ thể.

Java cung cấp rất nhiều concrete I/O stream class trong package `java.io`. Một số class thường dùng gồm:

- `FileInputStream` và `FileOutputStream`: Dùng để đọc từ và ghi vào file dưới dạng byte stream.
- `FileReader` và `FileWriter`: Dùng để đọc từ và ghi vào file dưới dạng character stream.
- `BufferedInputStream` và `BufferedOutputStream`: Cung cấp khả năng buffering để cải thiện hiệu năng của byte stream.
- `BufferedReader` và `BufferedWriter`: Cung cấp khả năng buffering và các method bổ sung để đọc, ghi character stream.
- `ObjectInputStream` và `ObjectOutputStream`: Dùng để đọc và ghi Java object vào stream.
- `PrintStream` và `PrintWriter`: Cung cấp các method để ghi dữ liệu đã format vào một stream.

Các concrete class này extends các base class phù hợp (`InputStream`, `OutputStream`, `Reader` hoặc `Writer`) và implement chức năng cụ thể để xử lý các loại data source và destination khác nhau.

### `FileInputStream` {#fileinputstream}

`FileInputStream` đọc byte từ một file. Nó kế thừa từ `InputStream`.

Nó có thể được tạo bằng một object `File` hoặc một `String path`:

```java
FileInputStream(File file)
FileInputStream(String path)
```

Đây là cách bạn dùng nó:

```java
try (InputStream in = new FileInputStream("/file.txt")) {
    int b;
    // -1 indicates the end of the file
    while((b = in.read()) != -1) {
        // Do something with the byte read
    }
} catch(IOException e) {
    /** ... */
}
```

Ngoài ra còn có một method `read()` đọc byte vào một array byte:

```java
byte[] data = new byte[1024];
int numberOfBytesRead;
while((numberOfBytesRead = in.read(data)) != -1) {
    // Do something with the array data
}
```

Tất cả các class chúng ta sẽ xem xét đều nên được đóng. May mắn thay, chúng implement `java.lang.AutoCloseable` nên có thể được dùng trong `try-with-resources`.

Ngoài ra, gần như tất cả method của các class này đều throw `IOExceptions` hoặc một trong các subclass của nó (như `FileNotFoundException`, tên khá mô tả rõ vấn đề).

### `FileOutputStream` {#fileoutputstream}

`FileOutputStream` ghi byte vào một file. Nó kế thừa từ `OutputStream`.

Nó có thể được tạo bằng một `File` object hoặc một `String` path, kèm theo một `boolean` tùy chọn cho biết bạn muốn overwrite hay append vào file nếu file đã tồn tại (mặc định là overwrite):

```java
FileOutputStream(File file)
FileOutputStream(File file, boolean append)
FileOutputStream(String path)
FileOutputStream(String path, boolean append)
```

Đây là cách bạn sử dụng nó:

```java
try (OutputStream out = new FileOutputStream("/file.txt")) {
    int b;
    // Made up method to get some data
    while((b = getData()) != -1) {
        // Writes b to the file output stream
        out.write(b);
        out.flush();
    }
} catch(IOException e) {
    /** ... */
}
```

Khi bạn ghi vào một `OutputStream`, dữ liệu có thể được cache nội bộ trong memory và được ghi xuống disk vào một thời điểm sau đó. Nếu bạn muốn chắc chắn rằng mọi dữ liệu đã được ghi xuống disk mà không cần đóng `OutputStream`, bạn có thể gọi method `flush()` định kỳ.

`FileOutputStream` cũng chứa các phiên bản overload của `write()` cho phép bạn ghi dữ liệu nằm trong một byte array.

### `FileReader` {#filereader}

`FileReader` đọc các character từ một text file. Nó kế thừa từ `Reader`.

Nó có thể được tạo bằng một `File` object hoặc một `String` path:

```java
FileReader(File file)
FileReader(String path)
```

Đây là cách bạn sử dụng nó:

```java
try (Reader r = new FileReader("/file.txt")) {
    int c;
    // -1 indicates the end of the file
    while((c = r.read()) != -1) {
        char character = (char)c;
        // Do something with the character
    }
} catch(IOException e) {
    /** ... */
}
```

Ngoài ra còn có một method `read()` đọc các character vào một array các `char`:

```java
char[] data = new char[1024];
int numberOfCharsRead = r.read(data);
while((numberOfCharsRead = r.read(data)) != -1) {
    // Do something with the array data
}
```

`FileReader` giả định rằng bạn muốn decode các character trong file bằng character encoding mặc định của máy đang chạy chương trình.

### `FileWriter` {#filewriter}

`FileWriter` ghi các character vào một text file. Nó kế thừa từ `Writer`.

Nó có thể được tạo bằng một `File` object hoặc một `String` path, kèm theo một `boolean` tùy chọn cho biết bạn muốn overwrite hay append vào file nếu file đã tồn tại (mặc định là overwrite):

```java
FileWriter(File file)
FileWriter(File file, boolean append)
FileWriter(String path)
FileWriter(String path, boolean append)
```

Đây là cách bạn sử dụng nó:

```java
try (Writer w = new FileWriter("/file.txt")) {
    w.write('-'); // writing a character
    // writing a string
    w.write("Writing to the file...");
} catch(IOException e) {
    /** ... */
}
```

Cũng giống như một `OutputStream`, dữ liệu có thể được cache nội bộ trong memory và được ghi xuống disk vào một thời điểm sau đó. Nếu bạn muốn chắc chắn rằng mọi dữ liệu đã được ghi xuống disk mà không cần đóng `FileWriter`, bạn có thể gọi method `flush()` định kỳ.

`FileWriter` cũng chứa các phiên bản overload của `write()` cho phép bạn ghi dữ liệu nằm trong một `char` array, hoặc trong một `String`.

`FileWriter` giả định rằng bạn muốn encode các character trong file bằng character encoding mặc định của máy đang chạy chương trình.

### `BufferedReader` {#bufferedreader}

`BufferedReader` đọc text từ một character stream. Thay vì đọc từng character một, `BufferedReader` đọc cả một block lớn vào buffer mỗi lần. Nó kế thừa từ `Reader`.

Đây là một wrapper class được tạo bằng cách truyền một `Reader` vào constructor của nó, và tùy chọn, kích thước của buffer:

```java
BufferedReader(Reader in)
BufferedReader(Reader in, int size)
```

`BufferedReader` có thêm một read method (ngoài những method được kế thừa từ `Reader`), `readLine()`. Đây là cách bạn sử dụng nó:

```java
try (BufferedReader br = new BufferedReader(new FileReader("/file.txt"))) {
    String line;
    // null indicates the end of the file
    while((line = br.readLine()) != null) {
        // Do something with the line
    }
} catch(IOException e) {
    /** ... */
}
```

Khi `BufferedReader` bị đóng, nó cũng sẽ đóng `Reader` instance mà nó đọc từ đó.

### `BufferedWriter` {#bufferedwriter}

`BufferedWriter` ghi text vào một character stream, buffer các character để tăng hiệu quả. Nó kế thừa từ `Writer`.

Đây là một wrapper class được tạo bằng cách truyền một `Writer` vào constructor của nó, và tùy chọn, kích thước của buffer:

```java
BufferedWriter(Writer out)
BufferedWriter(Writer out, int size)
```

`BufferedWriter` có thêm một write method (ngoài những method được kế thừa từ `Writer`), `newLine()`. Đây là cách bạn sử dụng nó:

```java
try (BufferedWriter bw = new BufferedWriter(new FileWriter("/file.txt"))) {
    bw.write("Writing to the file...");
    bw.newLine();
} catch(IOException e) {
    /** ... */
}
```

Vì dữ liệu được ghi vào buffer trước, bạn có thể gọi method `flush()` để đảm bảo rằng text được ghi cho đến thời điểm đó thực sự đã được ghi xuống disk.

Khi `BufferedWriter` bị đóng, nó cũng sẽ đóng `Writer` instance mà nó ghi tới.

### `ObjectInputStream` và `ObjectOutputStream` {#objectinputstream-and-objectoutputstream}

Quá trình chuyển một object thành một data format có thể lưu trữ được (ví dụ trong một file) được gọi là *serialization* và việc chuyển data format đã lưu đó trở lại thành một object được gọi là *deserialization*.

Nếu bạn muốn serialize một object, class của nó phải implement interface `java.io.Serializable`, interface này không có method nào cần implement, nó chỉ đánh dấu các object của class đó là serializable.

Chúng ta sẽ tìm hiểu quá trình này chi tiết hơn ở phần sau, nhưng ngay bây giờ, bạn cần biết rằng `ObjectOutputStream` cho phép bạn serialize object vào một `OutputStream`, còn `ObjectInputStream` cho phép bạn deserialize object từ một `InputStream`. Vì vậy cả hai đều được coi là wrapper class.

Đây là constructor của class `ObjectOutputStream`:

```java
ObjectOutputStream(OutputStream out)
```

Class này có các method để ghi nhiều primitive type, như:

```java
void writeInt(int val)
void writeBoolean(boolean val)
```

Nhưng hữu ích nhất là `writeObject(Object)`. Đây là một ví dụ:

```java
class Box implements java.io.Serializable {
    /** ... */
}
...
try(ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("obj.dat"))) {
    Box box = new Box();
    oos.writeObject(box);
} catch(IOException e) {
    /** ... */
}
```

Để deserialize file `obj.dat`, chúng ta dùng class `ObjectInputStream`. Đây là constructor của nó:

```java
ObjectInputStream(InputStream in)
```

Class này có các method để đọc nhiều data type, trong đó có:

```java
Object readObject() throws IOException, ClassNotFoundException
```

Lưu ý rằng nó trả về kiểu `Object`. Do đó, chúng ta phải cast object một cách tường minh. Điều này có thể dẫn đến một `ClassCastException` được throw tại runtime. Lưu ý rằng method này cũng throw một `ClassNotFoundException` (một checked exception), trong trường hợp không tìm thấy class của object đã được serialize.

Đây là một ví dụ:

```java
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("obj.dat"))) {
    Box box = null;
    Object obj = ois.readObject();
    if(obj instanceof Box) {
        box = (Box)obj;
    }
} catch(IOException ioe) {
    /** ... */
} catch(ClassNotFoundException cnfe) {
    /** ... */
}
```

### `PrintStream` {#printstream}

`PrintStream` là một subclass của `OutputStream`, bổ sung chức năng in nhiều data type khác nhau ở định dạng con người đọc được. Nó tương tự `PrintWriter`, nhưng chỉ làm việc với `OutputStream`. Hãy cùng xem các constructor của nó:

```java
PrintStream(OutputStream out)
PrintStream(OutputStream out, boolean autoFlush)
PrintStream(OutputStream out, boolean autoFlush, String encoding) throws UnsupportedEncodingException
PrintStream(File file) throws FileNotFoundException
PrintStream(File file, String encoding) throws FileNotFoundException, UnsupportedEncodingException
PrintStream(String fileName) throws FileNotFoundException
PrintStream(String fileName, String encoding) throws FileNotFoundException, UnsupportedEncodingException
```

Mặc định, nó dùng charset mặc định của máy đang chạy chương trình, nhưng bạn có thể chỉ định một charset nếu cần.

`PrintStream` có method `write()` như các subclass khác của `OutputStream`, nhưng nó override chúng để tránh throw một `IOException`.

Nó cũng bổ sung các method như `print()`, `println()`, `format()` và `printf()` để output thuận tiện. Đây là cách bạn sử dụng class này:

```java
// Opens or creates the file without automatic line flushing
// and using the default character encoding
try (PrintStream ps = new PrintStream("file.txt")) {
    ps.write("Hi".getBytes()); // Writing a String as bytes
    ps.write(100); // Writing a character as bytes

    // write the string representation of the argument
    // it has versions for all primitives, char[], String, and Object
    ps.print(true);
    ps.print(10);

    // same as print() but it also writes a line break as defined by
    // System.getProperty("line.separator") after the value
    ps.println(); // Just writes a new line
    ps.println("A new line...");

    // format() and printf() are the same methods
    // They write a formatted string using a format string,
    // its arguments and an optional Locale
    ps.format("%s %d", "Formatted string ", 1);
    ps.printf("%s %d", "Formatted string ", 2);
    ps.format(Locale.GERMAN, "%.2f", 3.1416);
    ps.printf(Locale.GERMAN, "%.3f", 3.1416);
} catch (FileNotFoundException e) {
    // if the file cannot be opened or created
}
```

Bạn có thể tìm hiểu thêm về format string cho `format()` và `printf()` trong [tài liệu của class `java.util.Formatter`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Formatter.html).

### `PrintWriter` {#printwriter}

`PrintWriter` là một subclass của `Writer`, ghi dữ liệu đã định dạng vào một stream khác (được wrap), kể cả một `OutputStream`. Hãy xem các constructor của nó:

```java
PrintWriter(File file) throws FileNotFoundException
PrintWriter(File file, String charset) throws FileNotFoundException, UnsupportedEncodingException
PrintWriter(OutputStream out)
PrintWriter(OutputStream out, boolean autoFlush)
PrintWriter(String fileName) throws FileNotFoundException
PrintWriter(String fileName, String charset) throws FileNotFoundException, UnsupportedEncodingException
PrintWriter(Writer out)
PrintWriter(Writer out, boolean autoFlush)
```

Mặc định, nó dùng charset mặc định của máy đang chạy chương trình, nhưng class này chấp nhận các charset sau (còn có những charset tùy chọn khác):

- `US-ASCII`
- `ISO-8859-1`
- `UTF-8`
- `UTF-16BE`
- `UTF-16LE`
- `UTF-16`

Như mọi `Writer`, class này có method `write()` mà chúng ta đã thấy ở các subclass khác của `Writer`, nhưng nó override chúng để tránh throw một `IOException`.

Nó cũng bổ sung các method `format()`, `print()`, `printf()`, `println()`.

Đây là cách bạn sử dụng class này:

```java
// Opens or creates the file without automatic line flushing
// and converting characters by using the default character encoding
try(PrintWriter pw = new PrintWriter("/file.txt")) {
    pw.write("Hi"); // Writing a String
    pw.write(100); // Writing a character

    // write the string representation of the argument
    // it has versions for all primitives, char[], String, and Object
    pw.print(true);
    pw.print(10);

    // same as print() but it also writes a line break as defined by
    // System.getProperty("line.separator") after the value
    pw.println(); // Just writes a new line
    pw.println("A new line...");

    // format() and printf() are the same methods
    // They write a formatted string using a format string,
    // its arguments and an optional Locale
    pw.format("%s %d", "Formatted string ", 1);
    pw.printf("%s %d", "Formatted string ", 2);
    pw.format(Locale.GERMAN, "%.2f", 3.1416);
    pw.printf(Locale.GERMAN, "%.3f", 3.1416);
} catch(FileNotFoundException e) {
    // if the file cannot be opened or created
}
```

Cũng như với `PrintWriter`, bạn có thể tìm hiểu thêm về format string cho `format()` và `printf()` trong [tài liệu của class `java.util.Formatter`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Formatter.html).


### Standard Streams {#standard-streams}

Java khởi tạo và cung cấp ba stream object dưới dạng field `public static` của class `java.lang.System`:

- `InputStream System.in`  
  Standard input stream (thường là input từ bàn phím)
- `PrintStream System.out`  
  Standard output stream (thường là output hiển thị mặc định)
- `PrintStream System.err`  
  Standard error output stream (thường là màn hình hiển thị lỗi mặc định)

Hãy nhớ rằng, `PrintStream` làm đúng những việc và có đúng những tính năng như `PrintWriter`, chỉ khác là nó chỉ làm việc với `OutputStream`.

Ví dụ sau cho thấy cách đọc một character đơn (một byte) từ command line:

```java
System.out.print("Enter a character: ");
try {
    int c = System.in.read();
} catch(IOException e) {
    System.err.println("Error: " + e);
}
```

Hoặc để đọc string:

```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
String line = br.readLine();
// Or using the java.util.Scanner class
Scanner scanner = new Scanner(System.in);
String line = scanner.nextLine();
```

Các stream này (`System.in`, `System.out`, `System.err`) được dùng cho input và output cơ bản trong nhiều chương trình Java.


## Sao chép, di chuyển, xóa và so sánh file {#copying-moving-deleting-and-comparing-files}
Bạn đã biết từ trước rằng class `java.nio.file.Files` cung cấp nhiều method cho các thao tác file như sao chép, di chuyển, xóa và so sánh file. Hãy cùng khám phá chi tiết các thao tác này.

Method `Files.copy()` cho phép bạn sao chép một file từ vị trí này sang vị trí khác. Nó nhận một source path và một target path làm tham số.

Nếu target file đã tồn tại, bạn có thể chỉ định cách xử lý thao tác copy bằng enum `StandardCopyOption`.
```java
Path source = Paths.get("path/to/source/file.txt");
Path target = Paths.get("path/to/target/file.txt");

// Copy the file, replacing the target file if it exists
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
```

Option `StandardCopyOption.REPLACE_EXISTING` cho biết rằng nếu target file đã tồn tại, nó sẽ được thay thế bằng source file.

Bạn cũng có thể sao chép file bằng I/O stream. Điều này hữu ích khi bạn cần kiểm soát nhiều hơn quá trình copy hoặc khi làm việc với file lớn:
```java
try (InputStream inputStream = new FileInputStream("source.txt");
     OutputStream outputStream = new FileOutputStream("target.txt")) {
    
    byte[] buffer = new byte[1024]; // Buffer size can be adjusted for performance
    int bytesRead;
    while ((bytesRead = inputStream.read(buffer)) != -1) {
        outputStream.write(buffer, 0, bytesRead);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

Trong ví dụ này, chúng ta tạo một `InputStream` để đọc từ source file và một `OutputStream` để ghi vào target file. Chúng ta dùng một buffer để đọc và ghi dữ liệu theo từng chunk.

Để sao chép một file vào một directory, bạn có thể chỉ định target directory path và tên file.
```java
Path sourceFile = Paths.get("path/to/source/file.txt");
Path targetDirectory = Paths.get("path/to/target/directory");

// Copy the file into the target directory
Files.copy(sourceFile, targetDirectory.resolve(sourceFile.getFileName()));
```

Biểu thức `targetDirectory.resolve(sourceFile.getFileName())` tạo target path bằng cách kết hợp target directory path với tên file của source file.

Method `Files.move()` cho phép bạn di chuyển hoặc đổi tên một file hay directory.
```java
Path source = Paths.get("path/to/source/file.txt");
Path target = Paths.get("path/to/target/file.txt");

// Move the file
Files.move(source, target);
```

Nếu target file đã tồn tại, một exception sẽ được throw. Bạn có thể dùng option `StandardCopyOption.REPLACE_EXISTING` để thay thế target file nếu nó tồn tại:
```java
Files.move(source, target, StandardCopyOption.REPLACE_EXISTING);
```

Một atomic move đảm bảo rằng thao tác move được thực hiện như một thao tác đơn không thể chia tách. Nó hoặc hoàn thành thành công hoặc thất bại mà không có bất kỳ thay đổi dở dang nào:
```java
Path source = Paths.get("path/to/source/file.txt");
Path target = Paths.get("path/to/target/file.txt");

// Perform an atomic move
Files.move(source, target, StandardCopyOption.ATOMIC_MOVE);
```

Option `StandardCopyOption.ATOMIC_MOVE` đảm bảo rằng thao tác move là atomic, ngăn ngừa hỏng dữ liệu trong quá trình move.

Method `Files.delete()` cho phép bạn xóa một file hoặc một directory rỗng:
```java
Path path = Paths.get("path/to/file.txt");

// Delete the file
Files.delete(path);
```

Nếu file không tồn tại, một `NoSuchFileException` sẽ được throw.

Method `Files.deleteIfExists()` xóa file nếu nó tồn tại và trả về một boolean cho biết file đã được xóa hay chưa:
```java
Path path = Paths.get("path/to/file.txt");

// Delete the file if it exists
boolean deleted = Files.deleteIfExists(path);
```

Method này không throw exception nếu file không tồn tại.

Method `Files.isSameFile()` cho phép bạn xác định xem hai path có trỏ đến cùng một file trong file system hay không:
```java
Path path1 = Paths.get("path/to/file1.txt");
Path path2 = Paths.get("path/to/file2.txt");

// Check if the paths refer to the same file
boolean isSame = Files.isSameFile(path1, path2);
```

Nó trả về `true` nếu các path trỏ đến cùng một file, và `false` nếu ngược lại.

Method `Files.mismatch()` so sánh nội dung của hai file và trả về vị trí của byte đầu tiên khác nhau:
```java
Path file1 = Paths.get("path/to/file1.txt");
Path file2 = Paths.get("path/to/file2.txt");

// Compare the content of the files
long mismatchPosition = Files.mismatch(file1, file2);
```

Nếu các file có nội dung giống hệt nhau, nó trả về -1. Nếu các file có kích thước khác nhau, nó trả về kích thước của file nhỏ hơn.

Đây là một số method chính mà class `Files` cung cấp để sao chép, di chuyển, xóa và so sánh file trong Java. Chúng mang lại những cách thuận tiện để thực hiện các thao tác file phổ biến mà không cần xử lý I/O stream thủ công.



## Đọc và ghi file {#reading-and-writing-files}
Java cung cấp nhiều method trong class `java.nio.file.Files` để đọc từ file và ghi vào file. Hãy cùng khám phá một số method và kỹ thuật thường dùng.

### Đọc file {#reading-files}
Class `Files` cung cấp hai method thuận tiện để đọc nội dung của một file: `readAllLines()` và `lines()`.

Method `Files.readAllLines()` đọc tất cả các dòng của một file vào một `List<String>`:
```java
Path path = Paths.get("path/to/file.txt");

try {
    List<String> lines = Files.readAllLines(path);
    for (String line : lines) {
        System.out.println(line);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

Method này phù hợp khi bạn cần xử lý toàn bộ các dòng của một file cùng lúc. Tuy nhiên, lưu ý rằng nó đọc toàn bộ file vào memory, nên có thể không hiệu quả với file lớn.

Mặt khác, method `Files.lines()` trả về một `Stream<String>` cho phép bạn xử lý các dòng của file một cách lazy:
```java
Path path = Paths.get("path/to/file.txt");

try (Stream<String> lines = Files.lines(path)) {
    lines.forEach(System.out::println);
} catch (IOException e) {
    e.printStackTrace();
}
```
Method này tiết kiệm memory hơn vì nó đọc các dòng theo nhu cầu và không nạp toàn bộ file vào memory cùng lúc. Nó đặc biệt hữu ích khi bạn cần xử lý file lớn hoặc thực hiện các thao tác như filtering hay mapping trên các dòng.

Tuy nhiên, để kiểm soát nhiều hơn quá trình đọc, bạn có thể dùng method `Files.newBufferedReader()` để tạo một `BufferedReader` instance:
```java
Path path = Paths.get("path/to/file.txt");

try (BufferedReader reader = Files.newBufferedReader(path)) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```
`BufferedReader` cung cấp các method như `readLine()` để đọc file từng dòng, cho phép bạn xử lý các dòng tùy theo nhu cầu.

### Ghi file {#writing-files}
Class `Files` cung cấp các method để ghi nội dung vào file, như `write()` và `newBufferedWriter()`.

Method `Files.write()` cho phép bạn ghi nội dung vào một file trong một thao tác duy nhất:
```java
Path path = Paths.get("path/to/file.txt");
String content = "Hello, World!";

try {
    Files.write(path, content.getBytes(StandardCharsets.UTF_8));
} catch (IOException e) {
    e.printStackTrace();
}
```

Method này ghi byte array được chỉ định vào file. Nếu file đã tồn tại, nó sẽ bị overwrite theo mặc định.

Ngoài ra, bạn có thể chỉ định các option bổ sung bằng enum `StandardOpenOption`.
```java
Path path = Paths.get("path/to/file.txt");
String content = "Appended content";

try {
    Files.write(path, content.getBytes(StandardCharsets.UTF_8), StandardOpenOption.APPEND);
} catch (IOException e) {
    e.printStackTrace();
}
```
Option `StandardOpenOption.APPEND` chỉ định rằng nội dung sẽ được append vào cuối file thay vì overwrite nó.

Một số option hữu ích khác gồm:
- `StandardOpenOption.CREATE`: Tạo một file mới nếu nó chưa tồn tại.
- `StandardOpenOption.CREATE_NEW`: Tạo một file mới, thất bại nếu nó đã tồn tại.
- `StandardOpenOption.TRUNCATE_EXISTING`: Cắt file về zero byte nếu nó tồn tại.

Những option này cho bạn kiểm soát nhiều hơn cách file được mở và ghi vào.

Tuy nhiên, bạn cũng có thể dùng method `Files.newBufferedWriter()` để tạo một `BufferedWriter` instance:
```java
Path path = Paths.get("path/to/file.txt");

try (BufferedWriter writer = Files.newBufferedWriter(path)) {
    writer.write("Hello, World!");
    writer.newLine();
    writer.write("This is a new line.");
} catch (IOException e) {
    e.printStackTrace();
}
```

`BufferedWriter` cung cấp các method như `write()` và `newLine()` để ghi nội dung vào file, cho phép bạn ghi từng dòng hoặc theo từng chunk.


## Làm việc với file attribute {#working-with-file-attributes}
Package `java.nio.file` cung cấp các class và method để làm việc với file attribute. File attribute là metadata gắn với một file hoặc directory, như kích thước, thời gian sửa đổi, permissions, v.v. Bạn có thể truy xuất và sửa đổi file attribute bằng NIO.2 API.

Java định nghĩa một số attribute type và view type đại diện cho các tập file attribute khác nhau:

**BasicFileAttributes**
Interface `BasicFileAttributes` cung cấp các file attribute cơ bản thường gặp trên nhiều file system khác nhau. Nó bao gồm các attribute như:
- `FileTime creationTime()`: Trả về thời gian tạo của file.
- `FileTime lastModifiedTime()`: Trả về thời gian sửa đổi lần cuối của file.
- `FileTime lastAccessTime()`: Trả về thời gian truy cập lần cuối của file.
- `long size()`: Trả về kích thước của file tính bằng byte.
- `boolean isRegularFile()`, `isDirectory()`, `isSymbolicLink()`: Kiểm tra kiểu của file.

**DosFileAttributes**
Interface `DosFileAttributes` kế thừa `BasicFileAttributes` và cung cấp thêm các attribute dành riêng cho file system DOS/Windows. Nó bao gồm các attribute như:
- `boolean isReadOnly()`: Kiểm tra xem file có phải read-only không.
- `boolean isHidden()`: Kiểm tra xem file có bị ẩn không.
- `boolean isArchive()`: Kiểm tra xem file có phải archive không.
- `boolean isSystem()`: Kiểm tra xem file có phải system file không.

**PosixFileAttributes**
Interface `PosixFileAttributes` kế thừa `BasicFileAttributes` và cung cấp thêm các attribute dành riêng cho file system tuân theo POSIX. Nó bao gồm các attribute như:
- `UserPrincipal owner()`: Trả về owner của file.
- `GroupPrincipal group()`: Trả về group owner của file.
- `Set<PosixFilePermission> permissions()`: Trả về permissions của file dưới dạng một set các `PosixFilePermission`.

Để truy xuất file attribute, bạn có thể dùng method `Files.readAttributes()`, chỉ định attribute type bạn muốn lấy:
```java
Path path = Paths.get("path/to/file.txt");

try {
    BasicFileAttributes attrs = Files.readAttributes(path, BasicFileAttributes.class);
    System.out.println("Creation Time: " + attrs.creationTime());
    System.out.println("Last Modified Time: " + attrs.lastModifiedTime());
    System.out.println("Size: " + attrs.size());
} catch (IOException e) {
    e.printStackTrace();
}
```
Trong ví dụ này, chúng ta truy xuất `BasicFileAttributes` của file và truy cập thời gian tạo, thời gian sửa đổi lần cuối và kích thước của nó.

Ngoài ra, bạn có thể chỉ định `LinkOption` để kiểm soát cách xử lý symbolic link:
```java
Path path = Paths.get("path/to/symlink.txt");

try {
    BasicFileAttributes attrs = Files.readAttributes(path, BasicFileAttributes.class, LinkOption.NOFOLLOW_LINKS);
    boolean isSymLink = attrs.isSymbolicLink();
} catch (IOException e) {
    e.printStackTrace();
}
```
Khi truyền `LinkOption.NOFOLLOW_LINKS`, method `readAttributes()` sẽ không đi theo symbolic link mà thay vào đó trả về attribute của chính symbolic link đó.

Để nhanh chóng kiểm tra xem một file có thể truy cập để đọc, ghi hay thực thi hay không, bạn có thể dùng các method `Files.isReadable()`, `Files.isWritable()` và `Files.isExecutable()`:
```java
Path path = Paths.get("path/to/file.txt");

boolean isReadable = Files.isReadable(path);
boolean isWritable = Files.isWritable(path);
boolean isExecutable = Files.isExecutable(path);
```
Các method này trả về `true` nếu file có thể truy cập cho thao tác tương ứng, và `false` nếu ngược lại.

Để sửa đổi file attribute, bạn có thể dùng method `Files.setAttribute()`, chỉ định tên attribute và giá trị:
```java
Path path = Paths.get("path/to/file.txt");

try {
    Files.setAttribute(path, "dos:readonly", true);
    Files.setAttribute(path, "dos:hidden", true);
} catch (IOException e) {
    e.printStackTrace();
}
```
Trong ví dụ này, chúng ta đặt các attribute `readonly` và `hidden` cho một file trên file system DOS/Windows.

## Duyệt cây thư mục {#traversing-a-directory-tree}
Duyệt một cây thư mục, còn gọi là walking a directory tree, chỉ quá trình đệ quy thăm tất cả các subdirectory và file bên trong một directory cho trước. NIO.2 API, cụ thể là class `Files`, cung cấp các method giúp đơn giản hóa quá trình này và cho phép bạn thực hiện hành động trên mỗi file và directory được thăm.

Method `Files.walk()` là một cách thuận tiện để duyệt một cây thư mục. Nó trả về một `Stream<Path>` đại diện cho cây file bắt nguồn từ starting directory cho trước:
```java
Path startingDir = Paths.get("/path/to/directory");

try (Stream<Path> stream = Files.walk(startingDir)) {
    stream.forEach(path -> {
        // Process each path
        System.out.println(path);
    });
} catch (IOException e) {
    e.printStackTrace();
}
```

Method `Files.walk()` thăm tất cả các file và directory trong cây, bao gồm cả chính starting directory. Bạn có thể thực hiện nhiều thao tác khác nhau trên mỗi path bằng stream API, như filtering, mapping hoặc collecting các path.

Bạn có thể kiểm soát độ sâu của việc duyệt bằng cách truyền giá trị độ sâu tối đa vào method `Files.walk()`:
```java
Path startingDir = Paths.get("/path/to/directory");
int maxDepth = 3;

try (Stream<Path> stream = Files.walk(startingDir, maxDepth)) {
    // ...
} catch (IOException e) {
    e.printStackTrace();
}
```

Trong ví dụ này, việc duyệt sẽ đi tối đa 3 cấp bên dưới starting directory. Độ sâu 0 nghĩa là chỉ có starting directory được thăm.

Mặc định, `Files.walk()` đi theo symbolic link. Nếu bạn muốn kiểm soát hành vi này, bạn có thể truyền một `FileVisitOption` vào method:
```java
Path startingDir = Paths.get("/path/to/directory");

try (Stream<Path> stream = Files.walk(startingDir, FileVisitOption.FOLLOW_LINKS)) {
    // ...
} catch (IOException e) {
    e.printStackTrace();
}
```

Option `FileVisitOption.FOLLOW_LINKS` chỉ định rằng symbolic link sẽ được đi theo trong quá trình duyệt.

Tuy nhiên, khi duyệt cây thư mục trong Java, điều quan trọng là phải lưu ý đến các circular path do symbolic link gây ra. Một circular path xảy ra khi một symbolic link trỏ đến một directory là ancestor của link, tạo ra một vòng lặp vô hạn.

Để tránh circular path, bạn có thể dùng option `FileVisitOption.FOLLOW_LINKS` và tự implement logic phát hiện chu trình. Đây là một ví dụ hoàn chỉnh:

```java
import java.io.IOException;
import java.nio.file.*;
import java.nio.file.attribute.BasicFileAttributes;
import java.util.EnumSet;
import java.util.HashSet;
import java.util.Set;

public class DirectoryTraversal {
    public static void main(String[] args) {
        Path startingDir = Paths.get("/path/to/directory");
        Set<Path> visitedPaths = new HashSet<>();

        try {
            Files.walkFileTree(
                               startingDir, 
                               EnumSet.of(FileVisitOption.FOLLOW_LINKS), 
                               Integer.MAX_VALUE, new SimpleFileVisitor<Path>() {
                @Override
                public FileVisitResult visitFile(
                        Path file, BasicFileAttributes attrs) throws IOException {
                    if (visitedPaths.contains(file)) {
                        // Circular path detected, skip processing
                        return FileVisitResult.CONTINUE;
                    }
                    visitedPaths.add(file);
                    // Process the file
                    System.out.println(file);
                    return FileVisitResult.CONTINUE;
                }

                @Override
                public FileVisitResult preVisitDirectory(
                        Path dir, BasicFileAttributes attrs) throws IOException {
                    if (visitedPaths.contains(dir)) {
                        // Circular path detected, skip processing
                        return FileVisitResult.SKIP_SUBTREE;
                    }
                    visitedPaths.add(dir);
                    // Process the directory
                    System.out.println(dir);
                    return FileVisitResult.CONTINUE;
                }

                @Override
                public FileVisitResult visitFileFailed(
                        Path file, IOException exc) throws IOException {
                    System.err.println(
                        "Error visiting file: " + file + " - " + exc.getMessage()
                    );
                    return FileVisitResult.CONTINUE;
                }
            });
        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}
```

Chương trình này minh họa cách duyệt một cây thư mục đồng thời tránh các circular path do symbolic link gây ra. Nó bắt đầu bằng việc định nghĩa starting directory được chỉ định bởi biến `startingDir` và dùng method `Files.walkFileTree` để duyệt cây thư mục. Method này được khuyến nghị vì nó thăm tất cả các file và directory và có thể đi theo symbolic link khi được chỉ định bởi option `FileVisitOption.FOLLOW_LINKS`. Để ngăn chặn vòng lặp vô hạn do circular path gây ra, chương trình duy trì một set các path đã thăm (`visitedPaths`). Set này được dùng để theo dõi tất cả các directory và file đã được thăm trong quá trình duyệt.

Phần cốt lõi của chương trình là việc implement một `SimpleFileVisitor`, override một số method để định nghĩa các hành vi tùy chỉnh khi thăm file và directory. Khi chương trình tìm thấy một file hoặc directory, nó kiểm tra set `visitedPaths` để xem path đó đã được thăm chưa. Nếu path có trong set, điều này cho thấy một circular path, và chương trình bỏ qua việc xử lý tiếp path đó. Nếu path không có trong set, nó được thêm vào set `visitedPaths`, và path được xử lý (trong trường hợp này là in ra console). Điều này đảm bảo mỗi path chỉ được xử lý một lần, ngăn chặn hiệu quả các vòng lặp vô hạn.


## Serialization dữ liệu {#serializing-data}
Chúng ta đã nói về serialization trước đó. Đó là quá trình chuyển một object thành một byte stream, có thể được lưu vào file hoặc truyền qua mạng. Deserialization là quá trình ngược lại, khi byte stream được chuyển ngược trở lại thành object. Hãy cùng khám phá những khái niệm và kỹ thuật chính liên quan đến serialization trong Java.

Serialization cho phép bạn lưu giữ state của một object và tạo lại nó sau này. Điều này hữu ích cho:
- Lưu state của object vào file
- Gửi object qua mạng
- Cache object để cải thiện hiệu năng

Java Object Serialization API cung cấp một cơ chế chuẩn để developer xử lý quá trình này.

Để một class trở nên serializable, nó phải implements interface `java.io.Serializable`. Đây là một marker interface (không có method nào) báo cho Java runtime biết rằng class đó có thể được serialized:

```java
public class Employee implements Serializable {
    private String name;
    private int age;

    // Constructor, getters, and setters
}
```

Nếu bạn cố serialize một class không implements interface đó, một `java.io.NotSerializableException` (subclass của `IOException`) sẽ được throw at runtime.

`serialVersionUID` là một định danh duy nhất cho class được serialized. Nó được dùng trong quá trình deserialization để xác minh rằng bên gửi và bên nhận của một serialized object đã nạp những class tương thích với nhau về mặt serialization:

```java
public class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    // ... rest of the class
}
```

Nếu bạn không khai báo `serialVersionUID` một cách tường minh, Java runtime sẽ tự sinh một giá trị dựa trên nhiều khía cạnh khác nhau của class. Tuy nhiên, nên khai báo tường minh để giữ quyền kiểm soát việc đánh phiên bản (versioning) của class.

Nếu class của bạn có những field không muốn bị serialized (ví dụ dữ liệu nhạy cảm hoặc dữ liệu dẫn xuất), bạn có thể đánh dấu chúng bằng keyword `transient`:

```java
public class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private transient String password; // This won't be serialized
    // ... rest of the class
}
```

Tóm lại, để đảm bảo một class có thể được serialized:
1. Class phải được đánh dấu `Serializable`.
2. Mọi instance member của class phải serializable, được đánh dấu transient, hoặc có giá trị `null` tại thời điểm serialization.

Sau đó, bạn có thể dùng `ObjectOutputStream` và `ObjectInputStream` cho quá trình serialization/deserialization như đã trình bày ở phần trước. Đây là một ví dụ hoàn chỉnh minh họa quá trình này:

```java
import java.io.*;

public class SerializationDemo {
    public static void main(String[] args) {
        Person person = new Person("John Doe", 30);

        // Serialization
        try (ObjectOutputStream out = 
                 new ObjectOutputStream(new FileOutputStream("person.ser"))) {
            out.writeObject(person);
            System.out.println("Person object serialized");
        } catch (IOException e) {
            e.printStackTrace();
        }

        // Deserialization
        try (ObjectInputStream in = 
                new ObjectInputStream(new FileInputStream("person.ser"))) {
            Person deserializedPerson = (Person) in.readObject();
            System.out.println("Person object deserialized");
            System.out.println("Name: " + deserializedPerson.getName());
            System.out.println("Age: " + deserializedPerson.getAge());
        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
        }
    }
}

class Person implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getters
    public String getName() { return name; }
    public int getAge() { return age; }
                                      
    // ... rest of the class
}
```

Trong ví dụ này, chúng ta serialize một object `Person` vào file tên `person.ser` rồi deserialize nó trở lại thành một object `Person`.

Điều quan trọng cần lưu ý là khi deserialize một object, constructor và mọi initialization block đều không được thực thi. Tuy nhiên, việc khởi tạo mặc định của các instance variable vẫn diễn ra.

Ngoài ra, khác với class, record tự động serializable. Chúng ngầm implements interface `Serializable`, nên bạn không cần khai báo tường minh:

```java
public record PersonRecord(String name, int age) /** implements Serializable */ {
    // No need to declare serialVersionUID, as it's automatically generated
}
```

Hãy nhớ rằng, record cung cấp một cách ngắn gọn để khai báo những class chủ yếu dùng để lưu dữ liệu, và khả năng serialization sẵn có khiến chúng trở nên thuận tiện trong những tình huống cần serialization object.


## Bảng tham chiếu {#reference-tables}
Dưới đây là một số bảng giúp bạn ôn tập và hiểu rõ hơn về các class I/O stream cùng những khái niệm liên quan:

**Tóm tắt các class I/O Stream**

| Loại stream | Byte Stream                                                                 | Character Stream                          |
|-------------|------------------------------------------------------------------------------|--------------------------------------------|
| **Input**   | **Abstract Class**: `InputStream`<br>**Concrete Class**: `FileInputStream`, `BufferedInputStream`, `ObjectInputStream` | **Abstract Class**: `Reader`<br>**Concrete Class**: `FileReader`, `BufferedReader` |
| **Output**  | **Abstract Class**: `OutputStream`<br>**Concrete Class**: `FileOutputStream`, `BufferedOutputStream`, `ObjectOutputStream`, `PrintStream` | **Abstract Class**: `Writer`<br>**Concrete Class**: `FileWriter`, `BufferedWriter`, `PrintWriter` |


**So sánh các thao tác trên File và Path**

| Thao tác | Class `File` | NIO.2 (`Path` và `Files`) |
|-----------|------------|------------------------|
| Tạo file | `file.createNewFile()` | `Files.createFile(path)` |
| Xóa file | `file.delete()` | `Files.delete(path)` |
| Kiểm tra tồn tại | `file.exists()` | `Files.exists(path)` |
| Lấy absolute path | `file.getAbsolutePath()` | `path.toAbsolutePath()` |

## Các điểm chính {#key-points}
- Trong NIO.2 API, những class chính cho các thao tác file là:
  - `java.nio.file.Path`: Biểu diễn đường dẫn file và directory theo cách linh hoạt hơn (so với class `java.io.File`).
  - `java.nio.file.Files`: Class tiện ích cho các thao tác file.

- Có hai loại I/O stream chính:
  - Byte stream: Làm việc với dữ liệu nhị phân thô (8-bit). Các abstract class chính là `InputStream` và `OutputStream`.
  - Character stream: Làm việc với dữ liệu text (Unicode 16-bit). Các abstract class chính là `Reader` và `Writer`.

- Tuy nhiên, stream có thể được phân loại như sau:
  - Input stream: Dùng để đọc dữ liệu từ một nguồn.
  - Output stream: Dùng để ghi dữ liệu đến một đích.
  - Low-level stream: Kết nối trực tiếp đến nguồn hoặc đích dữ liệu.
  - High-level stream: Được xây dựng trên các stream khác, cung cấp thêm chức năng.

- Dưới đây là những class stream quan trọng nhất:
  - `FileInputStream` và `FileOutputStream`: Đọc và ghi byte từ/vào file.
  - `FileReader` và `FileWriter`: Đọc và ghi character từ/vào file.
  - `BufferedReader` và `BufferedWriter`: Thêm khả năng buffering cho character stream.
  - `ObjectInputStream` và `ObjectOutputStream`: Đọc và ghi các serialized object.
  - `PrintStream` và `PrintWriter`: Ghi dữ liệu đã định dạng vào byte stream và character stream tương ứng.

- Nên dùng câu lệnh `try-with-resources` với các I/O class để đảm bảo quản lý tài nguyên đúng cách.

- Hầu hết các thao tác I/O có thể throw `IOException` hoặc các subclass của nó, và chúng cần được xử lý.

- Standard stream:
  - `System.in`: Standard input stream (thường là nhập từ bàn phím).
  - `System.out`: Standard output stream (thường là output ra console).
  - `System.err`: Standard error stream (thường là output lỗi ra console).

- Khi làm việc với character stream, hãy chú ý đến character encoding. Mặc định thường là encoding mặc định của hệ thống.

- Buffered stream (`BufferedReader`, `BufferedWriter`, v.v.) có thể cải thiện hiệu năng bằng cách giảm số lượng thao tác I/O.

- Class `Files` cung cấp các method cho nhiều thao tác file khác nhau như sao chép, di chuyển, xóa và so sánh file.

- Sao chép file:
  - Dùng `Files.copy(source, target, CopyOption...)` để sao chép file.
  - Có thể dùng `StandardCopyOption.REPLACE_EXISTING` để ghi đè file đã tồn tại.
  - Với file lớn, hãy cân nhắc dùng I/O stream kèm buffer để kiểm soát quá trình sao chép tốt hơn.

- Di chuyển file:
  - Dùng `Files.move(source, target, CopyOption...)` để di chuyển hoặc đổi tên file.
  - `StandardCopyOption.ATOMIC_MOVE` đảm bảo thao tác di chuyển được thực hiện như một thao tác đơn nhất, không thể chia tách.

- Xóa file:
  - `Files.delete(path)` xóa một file hoặc directory rỗng.
  - `Files.deleteIfExists(path)` xóa một file nếu nó tồn tại và trả về một `boolean` cho biết thành công hay không.

- So sánh file:
  - `Files.isSameFile(path1, path2)` kiểm tra hai path có cùng trỏ đến một file hay không.
  - `Files.mismatch(file1, file2)` so sánh nội dung của hai file và trả về vị trí byte đầu tiên không khớp.

- Đọc file:
  - `Files.readAllLines(path)` đọc tất cả dòng của file vào một `List<String>`.
  - `Files.lines(path)` trả về một `Stream<String>` để xử lý lazy các dòng của file.
  - `Files.newBufferedReader(path)` tạo một `BufferedReader` để kiểm soát việc đọc tốt hơn.

- Ghi file:
  - `Files.write(path, bytes, OpenOption...)` ghi nội dung vào file trong một thao tác duy nhất.
  - `Files.newBufferedWriter(path)` tạo một `BufferedWriter` để ghi từng dòng hoặc theo từng chunk.
  - Dùng enum `StandardOpenOption` để chỉ định cách file nên được mở hoặc ghi vào.

- File attribute:
  - Các interface `BasicFileAttributes`, `DosFileAttributes` và `PosixFileAttributes` cung cấp quyền truy cập nhiều file attribute khác nhau.
  - Dùng `Files.readAttributes(path, Class<A>, LinkOption...)` để lấy file attribute.
  - `Files.setAttribute(path, attribute, value)` sửa đổi file attribute.

- Duyệt directory:
  - `Files.walk(path, options)` trả về một `Stream<Path>` để duyệt cây directory.
  - Dùng `FileVisitOption.FOLLOW_LINKS` để đi theo symbolic link trong quá trình duyệt.
  - Cài đặt logic phát hiện chu trình (cycle detection) để tránh vòng lặp vô hạn do symbolic link vòng gây ra.

- Serialization cho phép object được chuyển thành một byte stream, có thể được lưu lại hoặc truyền đi. Class phải implements interface `Serializable` để có thể được serialized.

- Class phải implements interface `Serializable` để có thể được serialized.

- Dùng `serialVersionUID` để kiểm soát phiên bản của các class được serialized.

- Đánh dấu field là `transient` để loại chúng khỏi quá trình serialization.

- Dùng `ObjectOutputStream` để serialization và `ObjectInputStream` để deserialization.

- Record tự động serializable và không yêu cầu implements `Serializable` một cách tường minh.
