## Functional Interface {#functional-interfaces}
Java 8 mang đến cho chúng ta biểu thức lambda, một tính năng mới nhằm đơn giản hóa việc phát triển bằng cách tiếp cận lập trình hàm (functional programming). Nhưng để điều này hoạt động, Java cũng giới thiệu khái niệm functional interface.

Một functional interface là interface chỉ chứa duy nhất một abstract method. Chúng có thể chứa một hoặc nhiều default method hay static method, nhưng chỉ được có duy nhất một abstract method.

Thoạt nhìn, bạn có thể nghĩ rằng dùng functional interface không khác mấy so với dùng class và object thông thường. Suy cho cùng, chúng ta đã có thể định nghĩa interface với một method duy nhất từ lâu rồi. Nhưng khác biệt then chốt nằm ở cách chúng cho phép dùng biểu thức lambda.

Biểu thức lambda cho phép bạn coi functionality như method argument, hay code như data. Thay vì định nghĩa một class implement interface một method, bạn có thể truyền trực tiếp biểu thức lambda như một instance của functional interface, giúp code gọn gàng và súc tích hơn.

```java
public interface MyInterface {
    public void myMethod();
}

MyInterface ref = () -> System.out.println("Hello World!"); 
```

Trong ví dụ này, biểu thức lambda `() -> System.out.println("Hello World!")` được coi là một instance của functional interface `MyInterface`. Chúng ta đang gán một block code cho biến `ref`.

### Annotation `@FunctionalInterface` {#the-functionalinterface-annotation}
Java 8 cũng giới thiệu annotation `@FunctionalInterface`, dùng để chỉ ra rằng một interface được dự định là functional interface. Đây là một dạng *gợi ý* cho compiler rằng bạn muốn interface này tuân theo các quy tắc của functional interface:

```java
@FunctionalInterface
public interface MyInterface {
    void myMethod();
}
```

Tuy nhiên, annotation `@FunctionalInterface` không bắt buộc. Nếu một interface thỏa tiêu chí của functional interface (chỉ có một abstract method), nó là functional interface bất kể có annotation `@FunctionalInterface` hay không.

Vậy tại sao nên dùng nó?

Có một vài lý do:

1. Nó làm rõ ý định của bạn. Bằng cách dùng `@FunctionalInterface`, bạn báo hiệu cho các developer khác (và chính bạn trong tương lai) rằng interface này được thiết kế để dùng với biểu thức lambda.

2. Nó cho phép compiler kiểm tra. Nếu bạn annotate một interface với `@FunctionalInterface` rồi cố thêm abstract method thứ hai vào đó, compiler sẽ throw error. Điều này giúp ngăn chặn những vi phạm vô ý đối với contract của functional interface.

```java
@FunctionalInterface
public interface MyInterface {
    void myMethod();
    void myOtherMethod();  // Đoạn này sẽ gây ra compiler error
}
```

Tuy nhiên, annotation này không trở thành một phần của bytecode được sinh ra. Nó thuần túy dùng cho việc kiểm tra lúc compile-time và giúp developer dễ hiểu.

Ngoài ra, lưu ý rằng nếu một interface được annotate với `@FunctionalInterface` nhưng thực tế không thỏa tiêu chí (ví dụ, nếu nó không có abstract method nào cả), compiler sẽ báo error:

```java
@FunctionalInterface
public interface NonFunctionalInterface {
    // Không có abstract method
}  // Đoạn này sẽ gây ra compiler error
```

### Quy tắc định nghĩa functional interface {#rules-for-defining-a-functional-interface}

Functional interface không giới hạn những gì bạn có thể làm. Bạn vẫn có thể định nghĩa bao nhiêu default method và static method trên interface tùy thích.

Default method cho phép bạn thêm functionality mới vào interface trong thư viện của mình và đảm bảo binary compatibility với code viết cho các phiên bản cũ hơn của những interface đó. Static method trong interface được dùng để cung cấp các utility method, ví dụ như kiểm tra `null`.

```java
interface MyInterface {
    void abstractMethod(int x);  
    default void defaultMethod() { }        
    static void staticMethod() { }  
}
```

Chỉ `abstractMethod` được tính vào phép kiểm tra single abstract method của functional interface.

Cũng cần lưu ý rằng nếu một interface khai báo một abstract method override một trong các public method của `java.lang.Object`, method đó cũng không được tính vào số lượng abstract method của interface, vì mọi implementation của interface sẽ có implementation từ `java.lang.Object` hoặc từ nơi khác. Ví dụ:

```java 
interface MyInterface {
    boolean equals(Object obj); 
    // Các method khác
}
```

Trong trường hợp này, `MyInterface` vẫn là functional interface vì `equals` là một public method trong `Object`.

Dùng biểu thức lambda với functional interface chỉ đơn giản là một lựa chọn mới trong hộp công cụ lập trình của chúng ta. Bạn vẫn có thể dùng anonymous inner class hoặc implement interface theo cách truyền thống:

```java
MyInterface ref = new MyInterface() {
    @Override
    public void myMethod() {
        System.out.println("Hello World!");
    }
};

// Triển khai interface trong một class riêng
class MyClass implements MyInterface {
    @Override
    public void myMethod() {
        System.out.println("Hello World!");
    }
}
MyInterface ref = new MyClass();
```

Ngoài ra, một class hay biểu thức lambda có thể implement nhiều functional interface nếu chúng tương thích. Ví dụ, nếu hai interface có abstract method giống hệt nhau, chúng thực chất là cùng một functional interface:
```java
@FunctionalInterface
interface Interface1 {
    void method();
}

@FunctionalInterface
interface Interface2 {
    void method();
}

// Triển khai nhiều interface tương thích trong một class
class MyClass implements Interface1, Interface2 {
    @Override
    public void method() {
        System.out.println("Hello World!");
    }
}

// Sử dụng biểu thức lambda 
Interface1 ref1 = () -> System.out.println("Hello World!");
Interface2 ref2 = () -> System.out.println("Hello World!");
```

Và nếu các functional interface có sẵn như `Runnable` hay `Comparator` không đáp ứng nhu cầu của bạn, bạn có thể dễ dàng định nghĩa interface của riêng mình. Chỉ cần nhớ quy tắc single abstract method.


## Biểu thức Lambda {#lambda-expressions}

Biểu thức lambda cho phép bạn coi functionality như method argument hay code như data, mở ra một phong cách lập trình hàm hơn. Ví dụ, chúng cho phép bạn viết code như thế này:
```java
List<Car> compactCars = findCars(cars,
     (Car c) ->
        c.getType().equals(CarTypes.COMPACT)
);
```

Thay vì:
```java
List<Car> compactCars = findCars(cars,
     new Searchable() {
        public boolean test(Car car) {
           return car.getType().equals(
                     CarTypes.COMPACT);
        }
});
```

Về bản chất, biểu thức lambda là cách ngắn gọn để biểu diễn một function. Thuật ngữ lambda expression xuất phát từ lambda calculus, viết là λ-calculus, trong đó λ là chữ cái Hy Lạp lambda. Dạng giải tích này liên quan đến việc định nghĩa và áp dụng các function.

Functional interface là nền tảng để xây dựng biểu thức lambda. Ví dụ, xét functional interface sau:
```java
@FunctionalInterface
interface MyFunction {
    int apply(int a);
}
```

Bạn có thể dùng biểu thức lambda ở bất cứ đâu cần một instance của interface này:
```java
MyFunction doubler = (int a) -> a * 2;
```

Biểu thức lambda `a -> a * 2` khớp với signature của method `apply` trong `MyFunction`.

### Cú pháp của biểu thức lambda {#syntax-of-a-lambda-expression}

Một biểu thức lambda có ba phần: danh sách parameter, arrow token (->), và function body.

Đây là cú pháp cơ bản:
```java
(parameters) -> expression
// hoặc 
(parameters) -> { statements; }
```

Ví dụ, xét functional interface này:
```java
@FunctionalInterface
interface MyFunction {
    int apply(int a, int b);
}
```

Và biểu thức lambda này nhận hai số nguyên và trả về tổng của chúng:
```java
MyFunction f = (int a, int b) -> a + b
```

Bạn có thể dùng keyword `var` trong danh sách parameter của biểu thức lambda. Điều này cho phép compiler suy luận kiểu của parameter:
```java
MyFunction f = (var a, var b) -> a + b
```

Bạn có thể bỏ qua kiểu của parameter, compiler cũng có thể suy luận chúng từ ngữ cảnh:
```java
MyFunction f = (a, b) -> a + b
```

Nếu biểu thức lambda chỉ nhận một parameter, bạn thậm chí có thể bỏ qua dấu ngoặc đơn:
```java
@FunctionalInterface
interface MyFunction {
    int apply(int a);
}

//...

MyFunction f = a -> a * 2
```

Bạn cũng có thể dùng keyword `var` để khai báo một biến mà không cần chỉ định kiểu, nhưng chỉ khi compiler có thể suy luận kiểu từ ngữ cảnh.

Ví dụ, xét interface `MyFunction` của ví dụ trước và chỉ với biểu thức sau:
```java
var f = a -> a * 2;
```

Bạn sẽ nhận được compile-time error với thông báo sau: "Cannot infer type: lambda expression requires an explicit target type."

Bạn không thể dùng `var` trực tiếp với biểu thức lambda như `var f = (var a) -> a * 2;` vì lambda cần một target type mà `var` không thể cung cấp.

Tuy nhiên, trong trường hợp này:
```java
MyInterface f = (a) -> a * 2; // Lambda được gán cho functional interface
var fVar = f; // `var` suy luận type MyInterface
System.out.println(fVar.apply(5)); // Kết quả 10
```

Bạn có thể dùng `var` vì bạn đang gán một lambda cho một functional interface đã được định nghĩa trước đó, nơi kiểu có thể được suy luận từ ngữ cảnh.

Những ngữ cảnh mà target type (functional interface) của biểu thức lambda có thể được suy luận bao gồm:
- Một khai báo biến
- Một phép gán
- Một câu lệnh return
- Một array initializer
- Argument của method hoặc constructor
- Một biểu thức điều kiện ba ngôi (ternary)
- Một biểu thức cast

Nếu bạn hiểu khái niệm, bạn không cần học thuộc danh sách này.

### Biểu thức lambda và anonymous class {#lambda-expressions-and-anonymous-classes}

Trước Java 8, anonymous class là cách chính để biểu diễn một functionality dùng một lần. Với sự ra đời của biểu thức lambda trong Java 8, chúng ta giờ có cách ngắn gọn hơn để viết một số loại anonymous class.

Xét anonymous class này:

```java
Runnable r1 = new Runnable() {
    public void run() {
        System.out.println("Hello!");
    }
};
```

Đoạn này có thể được thay bằng biểu thức lambda:

```java
Runnable r2 = () -> System.out.println("Hello!");
```

Tuy nhiên, dù biểu thức lambda và anonymous class có một số điểm giống nhau, chúng cũng có những khác biệt đáng kể:

**Điểm giống nhau:**

- Local variable chỉ có thể được dùng nếu chúng được khai báo final hoặc effectively final.
- Bạn có thể truy cập instance variable hoặc static variable của enclosing class.
- Chúng không được throw nhiều checked exception hơn số được chỉ định trong throws clause của method của functional interface.

**Điểm khác nhau:**

- Trong anonymous class, `this` tham chiếu đến instance của chính anonymous class đó. Trong biểu thức lambda, `this` tham chiếu đến instance của enclosing class.
- Default method của functional interface không thể được truy cập từ bên trong biểu thức lambda, nhưng có thể được truy cập từ anonymous class.
- Biểu thức lambda cho phép bạn bỏ qua kiểu của các parameter trong danh sách parameter, điều không thể làm được với anonymous class.
- Nếu bạn tham chiếu một instance variable bên trong biểu thức lambda, bạn đang tham chiếu biến từ enclosing instance. Trong anonymous class, bạn sẽ tham chiếu một bản copy riêng của biến đó.

Đây là ví dụ về việc dùng local variable bên trong body của một lambda:

```java
public class LambdaExample {
    public void testLambda() {
        int localVariable = 10;
        Runnable r = () -> {
            System.out.println("Lambda: " + localVariable);
        };
        r.run();
    }

    public void testAnonymous() {
        int localVariable = 10;
        Runnable r = new Runnable() {
            public void run() {
                System.out.println("Anonymous: " + localVariable);
            }
        };
        r.run();
    }

    public static void main(String[] args) {
        LambdaExample example = new LambdaExample();
        example.testLambda();
        example.testAnonymous();
    }
}
```

Kết quả là:
```
Lambda: 10
Anonymous: 10
```

Trong ví dụ này, cả biểu thức lambda lẫn anonymous class đều có thể truy cập `localVariable` được định nghĩa trong method tương ứng của chúng. Tuy nhiên, nếu chúng ta cố sửa `localVariable` sau khi nó đã được dùng trong biểu thức lambda hoặc anonymous class, chúng ta sẽ nhận compilation error:

```java
public void testLambda() {
    int localVariable = 10;
    Runnable r = () -> {
        System.out.println("Lambda: " + localVariable); // Compilation error
    };
    localVariable = 20;  // Vì điều này
    r.run();
}
```

Điều này là vì `localVariable` phải là effectively final (giá trị của nó không thay đổi sau khi khởi tạo) để có thể được dùng bên trong biểu thức lambda hoặc anonymous class.

Local variable phải là final vì cách chúng được implement trong Java. Instance variable được lưu trên heap, còn local variable sống trên stack. Biến trên heap được chia sẻ giữa các thread, nhưng biến trên stack bị giới hạn trong thread chứa chúng.

Khi bạn tạo một instance của anonymous inner class hoặc biểu thức lambda, giá trị của các local variable được copy. Điều này ngăn ngừa các vấn đề liên quan đến thread và đảm bảo bạn đang làm việc với một giá trị nhất quán, vì biến không thể bị sửa đổi sau khi khởi tạo.

Bằng cách yêu cầu biến final (hoặc effectively final), Java đảm bảo thread safety và tính nhất quán, vì giá trị không thể thay đổi, loại bỏ các vấn đề về visibility và những vấn đề thread tiềm ẩn.


## Java Built-In Lambda Interfaces {#java-built-in-lambda-interfaces}

Ở phần trước, chúng ta đã dùng những functional interface như sau:
```java
@FunctionalInterface
interface MyFunction {
    int apply(int a, int b);
}
```

Tuy nhiên, bạn không cần phải viết một interface như vậy trong mỗi chương trình sử dụng nó (hay link một thư viện chứa nó). Một interface làm điều tương tự nhưng chấp nhận mọi object type đã tồn tại sẵn trong ngôn ngữ.

Java cung cấp các functional interface cho những use case phổ biến trong package `java.util.function`.

Đây là năm interface chính:
- `Predicate<T>`
- `Consumer<T>`
- `Function<T, R>`
- `Supplier<T>`
- `UnaryOperator<T>`

Trong đó `T` và `R` đại diện cho các generic type (`T` đại diện cho kiểu parameter và `R` là kiểu return).

Chúng cũng có các phiên bản chuyên biệt cho trường hợp input parameter là primitive type (cụ thể là `int`, `long`, `double`, và `boolean` đối với `Supplier`), ví dụ:
- `IntPredicate`
- `LongConsumer`
- `BooleanSupplier`

Trong đó tên được thêm tiền tố là primitive type phù hợp.

Ngoài ra, bốn trong số chúng có phiên bản binary, nghĩa là chúng nhận hai parameter thay vì một:
- `BiPredicate<L, R>`
- `BiConsumer<T, U>`
- `BiFunction<T, U, R>`
- `BinaryOperator<T>`

Trong đó `T`, `U`, và `R` đại diện cho các generic type (`T` và `U` đại diện cho kiểu parameter và `R` là kiểu return).

Các bảng sau hiển thị danh sách đầy đủ các interface. Bạn không cần học thuộc chúng, chỉ cần cố gắng hiểu chúng.

| Functional Interface | Phiên bản primitive |
|----------------------|--------------------|
| `Predicate<T>`       | `IntPredicate`<br/> `LongPredicate`<br/> `DoublePredicate` |
| `Consumer<T>`        | `IntConsumer`<br/> `LongConsumer`<br/> `DoubleConsumer` |
| `Function<T, R>`     | `IntFunction<R>`<br/> `IntToDoubleFunction`<br/> `IntToLongFunction`<br/> `LongFunction<R>`<br/> `LongToDoubleFunction`<br/> `LongToIntFunction`<br/> `DoubleFunction<R>`<br/> `DoubleToIntFunction`<br/> `DoubleToLongFunction`<br/> `ToIntFunction<T>`<br/> `ToDoubleFunction<T>`<br/> `ToLongFunction<T>` |
| `Supplier<T>`        | `BooleanSupplier`<br/> `IntSupplier`<br/> `LongSupplier`<br/> `DoubleSupplier` |
| `UnaryOperator<T>`   | `IntUnaryOperator`<br/> `LongUnaryOperator`<br/> `DoubleUnaryOperator` |


| Functional Interface     | Phiên bản primitive |
|--------------------------|--------------------|
| `BiPredicate<L, R>`      |                    |
| `BiConsumer<T, U>`       | `ObjIntConsumer<T>`<br/> `ObjLongConsumer<T>`<br/> `ObjDoubleConsumer<T>` |
| `BiFunction<T, U, R>`    | `ToIntBiFunction<T, U>`<br/> `ToLongBiFunction<T, U>`<br/> `ToDoubleBiFunction<T, U>` |
| `BinaryOperator<T>`      | `IntBinaryOperator`<br/> `LongBinaryOperator`<br/> `DoubleBinaryOperator` |


### `Predicate` {#predicate}

Predicate là một statement có thể là `true` hoặc `false` tùy thuộc vào giá trị của các biến trong nó.

Functional interface này có thể được dùng ở bất cứ đâu bạn cần đánh giá một điều kiện `boolean`.

Đây là cách interface được định nghĩa:

```java
@FunctionalInterface
public interface Predicate<T> {
    boolean test(T t);
    // Các default method và static method khác
    // ...
}
```

Functional descriptor (method signature) là:

```java
Predicate<T>
```

Đây là ví dụ dùng anonymous class:

```java
Predicate<String> startsWithA = new Predicate<String>() {
    @Override
    public boolean test(String t) {
        return t.startsWith("A");
    }
};
boolean result = startsWithA.test("Arthur");
```

Và với biểu thức lambda:

```java
Predicate<String> startsWithA = t -> t.startsWith("A");
boolean result = startsWithA.test("Arthur");
```

Interface này cũng có các default method sau:

```java
default Predicate<T> and(Predicate<? super T> other)
default Predicate<T> or(Predicate<? super T> other)
default Predicate<T> negate()
```

Những method này trả về một `Predicate` được kết hợp, biểu diễn phép **AND** và **OR** logic short-circuiting giữa predicate này với predicate khác, cùng phép phủ định logic của nó.

Short-circuiting nghĩa là predicate còn lại sẽ không được đánh giá nếu giá trị của predicate thứ nhất có thể dự đoán kết quả của phép toán (nếu predicate thứ nhất trả về false trong trường hợp **AND** hoặc trả về true trong trường hợp **OR**).

Những method này hữu ích để kết hợp các predicate và làm code dễ đọc hơn, ví dụ:

```java
Predicate<String> startsWithA = t -> t.startsWith("A");
Predicate<String> endsWithA = t -> t.endsWith("A");
boolean result = startsWithA.and(endsWithA).test("Hi");
```

Ngoài ra, có một `static` method:

```java
static <T> Predicate<T> isEqual(Object targetRef)
```

Method này trả về một `Predicate` kiểm tra xem hai argument có bằng nhau theo `Objects.equals(Object, Object)` hay không.

Cũng có các phiên bản primitive cho `int`, `long`, và `double`. Chúng không kế thừa từ `Predicate`.

Ví dụ, đây là định nghĩa của `IntPredicate`:

```java
@FunctionalInterface
public interface IntPredicate {
    boolean test(int value);
    // Và các default method: and, or, negate
}
```

Vậy nên thay vì dùng:

```java
Predicate<Integer> even = t -> t % 2 == 0;
boolean result = even.test(5);
```

Bạn có thể dùng:

```java
IntPredicate even = t -> t % 2 == 0;
boolean result = even.test(5);
```

Tại sao?

Chỉ để tránh việc chuyển đổi từ `Integer` sang `int` và làm việc trực tiếp với primitive type.

Lưu ý rằng các phiên bản primitive này không có generic type. Do cách generics được implement, parameter của functional interface chỉ có thể được bound với object type.

Vì việc chuyển đổi từ wrapper type (`Integer`) sang primitive type (`int`) tốn nhiều bộ nhớ hơn và kèm theo chi phí hiệu năng, Java cung cấp những phiên bản này để tránh các thao tác autoboxing khi input hoặc output là primitive.

### `Consumer` {#consumer}

`Consumer` biểu diễn một operation nhận một input argument duy nhất và không trả về kết quả, nó chỉ thực thi một số thao tác trên argument đó.

Đây là cách interface được định nghĩa:

```java
@FunctionalInterface
public interface Consumer<T> {
    void accept(T t);
    // Và một default method
    // ...
}
```

Functional descriptor (method signature) là:

```java
T -> void
```

Đây là ví dụ dùng anonymous class:

```java
Consumer<String> consumeStr = new Consumer<String>() {
    @Override
    public void accept(String t) {
        System.out.println(t);
    }
};
consumeStr.accept("Hi");
```

Và với biểu thức lambda:

```java
Consumer<String> consumeStr = t -> System.out.println(t);
consumeStr.accept("Hi");
```

Interface này cũng có default method sau:

```java
default Consumer<T> andThen(Consumer<? super T> after)
```

Method này trả về một `Consumer` được kết hợp, thực hiện tuần tự operation của consumer rồi đến operation của parameter.

Những method này hữu ích để kết hợp các `Consumer` và làm code dễ đọc hơn, ví dụ:

```java
Consumer<String> first = t ->
    System.out.println("First:" + t);
Consumer<String> second = t ->
    System.out.println("Second:" + t);
first.andThen(second).accept("Hi");
```

Kết quả là:

```java
First: Hi
Second: Hi
```

Hãy để ý cách cả hai `Consumer` nhận cùng một argument và thứ tự thực thi.

Cũng có các phiên bản primitive cho `int`, `long`, và `double`. Chúng không kế thừa từ `Consumer`.

Ví dụ, đây là định nghĩa của `IntConsumer`:

```java
@FunctionalInterface
public interface IntConsumer {
    void accept(int value);
    default IntConsumer andThen(IntConsumer after) {
        // ...
    }
}
```

Vậy nên thay vì dùng:

```java
int[] a = { 1,2,3,4,5,6,7,8 };
printList(a, t -> System.out.println(t));
//...
void printList(int[] a, Consumer<Integer> c) {
    for(int i : a) {
        c.accept(i);
    }
}
```

Bạn có thể dùng:

```java
int[] a = { 1,2,3,4,5,6,7,8 };
printList(a, (IntConsumer) t -> System.out.println(t));
//...
void printList(int[] a, IntConsumer c) {
    for(int i : a) {
        c.accept(i);
    }
}
```

### `Function` {#function}

`Function` biểu diễn một operation nhận một input argument thuộc một kiểu nhất định và tạo ra kết quả thuộc một kiểu khác.

Một use case phổ biến là chuyển đổi hay biến đổi từ object này sang object khác.

Đây là cách interface được định nghĩa:

```java
@FunctionalInterface
public interface Function<T, R> {
    R apply(T t);
    // Các default method và static method khác
    // ...
}
```

Functional descriptor (method signature) là:

```java
T -> R
```

Giả sử có một method:

```java
void round(double d, Function<Double, Long> f) {
    long result = f.apply(d);
    System.out.println(result);
}
```

Đây là ví dụ dùng anonymous class:

```java
round(5.4, new Function<Double, Long>() {
    @Override
    public Long apply(Double d) {
        return Math.round(d);
    }
});
```

Và với biểu thức lambda:

```java
round(5.4, d -> Math.round(d));
```

Interface này cũng có các default method sau:

```java
default <V> Function<V,R> compose(
    Function<? super V,? extends T> before)
default <V> Function<T,V> andThen(
    Function<? super R,? extends V> after)
```

Sự khác biệt giữa hai method này là `compose` áp dụng function được đại diện bởi parameter trước, và kết quả của nó trở thành input cho function còn lại. `andThen` áp dụng function gọi method trước, và kết quả của nó trở thành input của function được đại diện bởi parameter.

Ví dụ:

```java
Function<String, String> f1 = s -> s.toUpperCase();
Function<String, String> f2 = s -> s.toLowerCase();
System.out.println(f1.compose(f2).apply("Compose"));
System.out.println(f1.andThen(f2).apply("AndThen"));
```

Kết quả là:

```java
COMPOSE
andthen
```

Trong trường hợp thứ nhất, `f2` là function đầu tiên được áp dụng. Trong trường hợp thứ hai, `f2` là function cuối cùng được áp dụng.

Ngoài ra, có một `static` method:

```java
static <T> Function<T, T> identity()
```

Method này trả về một function luôn trả về input argument của nó.

Đối với các phiên bản primitive, chúng cũng áp dụng cho `int`, `long`, và `double`, nhưng có nhiều tổ hợp hơn các interface trước:

- Để chỉ ra rằng function trả về một generic type và nhận một primitive argument, interface được đặt tên là **XXXFunction**, ví dụ `IntFunction`:
    ```java
    @FunctionalInterface
    public interface IntFunction<R> {
        R apply(int value);
    }
    ```

- Để chỉ ra rằng function trả về một primitive type và nhận một generic argument, interface được đặt tên là **ToXXXFunction**, ví dụ `ToIntFunction`:
    ```java
    @FunctionalInterface
    public interface ToIntFunction<T> {
        int applyAsInt(T value);
    }
    ```

- Để chỉ ra rằng function nhận một primitive argument và trả về một primitive type khác, interface được đặt tên là **XXXToYYYFunction**, trong đó **XXX** là kiểu argument và **YYY** là kiểu return, ví dụ `IntToDoubleFunction`:
    ```java
    @FunctionalInterface
    public interface IntToDoubleFunction {
        double applyAsDouble(int value);
    }
    ```

Nhớ rằng những interface này chỉ để tiện lợi, giúp làm việc trực tiếp với primitive, ví dụ:

`DoubleFunction<R>` thay vì `Function<Double, R>`  
`ToLongFunction<T>` thay vì `Function<T, Long>`  
`IntToLongFunction` thay vì `Function<Integer, Long>`


### `Supplier` {#supplier}

`Supplier` là ngược lại của `Consumer`. Nó không nhận argument nào và chỉ trả về một giá trị.

Đây là cách interface được định nghĩa:

```java
@FunctionalInterface
public interface Supplier<T> {
    T get();
}
```

Functional descriptor (method signature) là:

```java
() -> T
```

Đây là ví dụ dùng anonymous class:

```java
String t = "One";
Supplier<String> supplierStr = new Supplier<String>() {
    @Override
    public String get() {
        return t.toUpperCase();
    }
};
System.out.println(supplierStr.get());
```

Và với biểu thức lambda:

```java
String t = "One";
Supplier<String> supplierStr = () -> t.toUpperCase();
System.out.println(supplierStr.get());
```

Interface này không định nghĩa default method nào.

Cũng có các phiên bản primitive cho `int`, `long`, `double`, và `boolean`, nhưng chúng không kế thừa từ `Supplier`.

Ví dụ, đây là định nghĩa của `BooleanSupplier`:

```java
@FunctionalInterface
public interface BooleanSupplier {
    boolean getAsBoolean();
}
```

Những phiên bản primitive này được dùng thay cho `Supplier` đối với kiểu tương ứng của chúng.


### `UnaryOperator` {#unaryoperator}

`UnaryOperator` chỉ là một specialization của interface `Function` (thực tế, interface này kế thừa từ nó) cho trường hợp argument và kết quả có cùng kiểu.

Đây là cách interface được định nghĩa:

```java
@FunctionalInterface
public interface UnaryOperator<T> extends Function<T, T> {
    // Chỉ có identity
    // method được định nghĩa
}
```

Functional descriptor (method signature) là:

```java
T -> T
```

Đây là ví dụ dùng anonymous class:

```java
UnaryOperator<String> uOp = new UnaryOperator<String>() {
    @Override
    public String apply(String t) {
        return t.substring(0,2);
    }
};
System.out.println(uOp.apply("Hello"));
```

Và với biểu thức lambda:

```java
UnaryOperator<String> uOp = t -> t.substring(0,2);
System.out.println(uOp.apply("Hello"));
```

Interface này kế thừa các default method của interface `Function`:

```java
default <V> Function<V, T> compose(
    Function<? super V, ? extends T> before)
default <V> Function<T, V> andThen(
    Function<? super T, ? extends V> after)
```

Và chỉ định nghĩa thêm `static` method `identity()` cho interface này (vì `static` method không được kế thừa):

```java
static <T> UnaryOperator<T> identity()
```

Method này trả về một `UnaryOperator` luôn trả về input argument của nó.

Cũng có các phiên bản primitive cho `int`, `long`, và `double`. Chúng không kế thừa từ `UnaryOperator`.

Ví dụ, đây là định nghĩa của `IntUnaryOperator`:

```java
@FunctionalInterface
public interface IntUnaryOperator {
    int applyAsInt(int operand);
    // Định nghĩa cho compose, andThen và identity
}
```

Vậy nên thay vì dùng:

```java
int[] a = {1,2,3,4,5,6,7,8};
int sum = sumNumbers(a, t -> t * 2);
//...
int sumNumbers(int[] a, UnaryOperator<Integer> unary) {
    int sum = 0;
    for(int i : a) {
        sum += unary.apply(i);
    }
    return sum;
}
```

Bạn có thể dùng:

```java
int[] a = {1,2,3,4,5,6,7,8};
int sum = sumNumbers(a, t -> t * 2);
//...
int sumNumbers(int[] a, IntUnaryOperator unary) {
    int sum = 0;
    for(int i : a) {
        sum += unary.applyAsInt(i);
    }
    return sum;
}
```

### `BiPredicate` {#bipredicate}

Interface này biểu diễn một predicate nhận hai argument.

Nó được định nghĩa như sau:

```java
@FunctionalInterface
public interface BiPredicate<T, U> {
    boolean test(T t, U u);
    // Các default method cũng được định nghĩa
}
```

Functional descriptor (method signature) là:

```java
(T, U) -> boolean
```

Đây là ví dụ dùng anonymous class:

```java
BiPredicate<Integer, Integer> divisible =
    new BiPredicate<Integer, Integer>() {
        @Override
        public boolean test(Integer t, Integer u) {
            return t % u == 0;
        }
    };
boolean result = divisible.test(10, 5);
```

Và với biểu thức lambda:

```java
BiPredicate<Integer, Integer> divisible =
    (t, u) -> t % u == 0;
boolean result = divisible.test(10, 5);
```

Interface này định nghĩa các default method giống như interface `Predicate`, nhưng với hai argument:

```java
default BiPredicate<T, U> and(
    BiPredicate<? super T, ? super U> other) {
    return (t, u) -> test(t, u) && other.test(t, u);
}

default BiPredicate<T, U> or(
    BiPredicate<? super T, ? super U> other) {
    return (t, u) -> test(t, u) || other.test(t, u);
}

default BiPredicate<T, U> negate() {
    return (t, u) -> !test(t, u);
}
```

Interface này không có các phiên bản primitive.


### `BiConsumer` {#biconsumer}

Interface này biểu diễn một consumer nhận hai argument (và không trả về kết quả).

Đây là cách nó được định nghĩa:

```java
@FunctionalInterface
public interface BiConsumer<T, U> {
    void accept(T t, U u);
    // default method andThen được định nghĩa
}
```

Functional descriptor (method signature) là:

```java
(T, U) -> void
```

Đây là ví dụ dùng anonymous class:

```java
BiConsumer<String, String> consumeStr =
    new BiConsumer<String, String>() {
        @Override
        public void accept(String t, String u) {
            System.out.println(t + " " + u);
        }
    };
consumeStr.accept("Hi", "there");
```

Và với biểu thức lambda:

```java
BiConsumer<String, String> consumeStr =
    (t, u) -> System.out.println(t + " " + u);
consumeStr.accept("Hi", "there");
```

Interface này cũng có default method sau:

```java
default BiConsumer<T, U> andThen(
    BiConsumer<? super T, ? super U> after)
```

Method này trả về một `BiConsumer` được kết hợp, thực hiện tuần tự operation của consumer rồi đến operation của parameter. Nó sẽ throw `NullPointerException` nếu parameter `after` là `null`.

Như trong trường hợp của `Consumer`, những method này hữu ích để kết hợp các `BiConsumer` và làm code dễ đọc hơn, ví dụ:

```java
BiConsumer<String, String> first = (t, u) -> System.out.println(t.toUpperCase() + u.toUpperCase());
BiConsumer<String, String> second = (t, u) -> System.out.println(t.toLowerCase() + u.toLowerCase());
first.andThen(second).accept("Again", " and again");
```

Kết quả là:

```java
AGAIN AND AGAIN
again and again
```

Cũng có các phiên bản chuyên biệt hóa primitive cho `int`, `long`, và `double`. Chúng không kế thừa từ `BiConsumer`, và thay vì nhận hai `int` chẳng hạn, chúng nhận một object và một primitive value làm argument thứ hai. Vì vậy quy ước đặt tên thay đổi thành **ObjXXXConsumer**, trong đó **XXX** là primitive type. Ví dụ, đây là định nghĩa của `ObjIntConsumer`:

```java
@FunctionalInterface
public interface ObjIntConsumer<T> {
    void accept(T t, int value);
}
```

Vậy nên thay vì dùng:

```java
int[] a = {1,2,3,4,5,6,7,8};
printList(a, (t, i) -> System.out.println(t + i));
//...
void printList(int[] a, BiConsumer<String, Integer> c) {
    for(int i : a) {
        c.accept("Number:", i);
    }
}
```

Bạn có thể dùng:

```java
int[] a = {1,2,3,4,5,6,7,8};
printList(a, (t, i) -> System.out.println(t + i));
//...
void printList(int[] a, ObjIntConsumer<String> c) {
    for(int i : a) {
        c.accept("Number:", i);
    }
}
```

### `BiFunction` {#bifunction}

Interface này biểu diễn một function nhận hai argument thuộc các kiểu khác nhau và tạo ra kết quả thuộc một kiểu khác.

Đây là cách nó được định nghĩa:

```java
@FunctionalInterface
public interface BiFunction<T, U, R> {
    R apply(T t, U u);
    // Các default method và static method khác
    // ...
}
```

Functional descriptor (method signature) là:

```java
(T, U) -> R
```

Giả sử có một method:

```java
void round(double d1, double d2, BiFunction<Double, Double, Long> f) {
    long result = f.apply(d1, d2);
    System.out.println(result);
}
```

Đây là ví dụ dùng anonymous class:

```java
round(5.4, 3.8, new BiFunction<Double, Double, Long>() {
    @Override
    public Long apply(Double d1, Double d2) {
        return Math.round(d1 + d2);
    }
});
```

Và với biểu thức lambda:

```java
round(5.4, 3.8, (d1, d2) -> Math.round(d1 + d2));
```

Interface này, không giống `Function`, chỉ có một default method:

```java
default <V> BiFunction<T, U, V> andThen(Function<? super R, ? extends V> after)
```

Method này trả về một function được kết hợp, đầu tiên áp dụng function gọi `andThen` lên input của nó, rồi áp dụng function được đại diện bởi argument lên kết quả.

Interface này cũng có ít phiên bản primitive hơn `Function`. Nó chỉ có các phiên bản nhận generic type làm argument và trả về các primitive type `int`, `long` và `double`, với quy ước đặt tên **ToXXXBiFunction**, trong đó XXX là primitive type.

Ví dụ, đây là định nghĩa của `ToIntBiFunction`:

```java
@FunctionalInterface
public interface ToIntBiFunction<T, U> {
    int applyAsInt(T t, U u);
}
```

Interface này thay thế `BiFunction`.


### `BinaryOperator` {#binaryoperator}

Interface này là một specialization của interface `BiFunction` (thực tế, interface này kế thừa nó) cho trường hợp các argument và kết quả có cùng kiểu.

Đây là cách interface được định nghĩa:

```java
@FunctionalInterface
public interface BinaryOperator<T> extends BiFunction<T, T, T> {
    // Hai static method được định nghĩa
}
```

Functional descriptor (method signature) là:

```java
(T, T) -> T
```

Đây là ví dụ dùng anonymous class:

```java
BinaryOperator<String> binOp = new BinaryOperator<String>() {
    @Override
    public String apply(String t, String u) {
        return t.concat(u);
    }
};
System.out.println(binOp.apply("Hello", " there"));
```

Và với biểu thức lambda:

```java
BinaryOperator<String> binOp = (t, u) -> t.concat(u);
System.out.println(binOp.apply("Hello", " there"));
```

Interface này kế thừa default method của interface `BiFunction`:

```java
default <V> BiFunction<T, T, V> andThen(Function<? super T, ? extends V> after)
```

Và định nghĩa hai `static` method mới:

```java
static <T> BinaryOperator<T> minBy(Comparator<? super T> comparator)
static <T> BinaryOperator<T> maxBy(Comparator<? super T> comparator)
```

Chúng trả về một `BinaryOperator`, trả về phần tử nhỏ hơn hoặc lớn hơn trong hai phần tử theo `Comparator` được chỉ định.

Đây là một ví dụ đơn giản:

```java
BinaryOperator<Integer> biOp = BinaryOperator.maxBy(Comparator.naturalOrder());
System.out.println(biOp.apply(28, 8));
```

Như bạn thấy, những method này chỉ là một wrapper để thực thi một `Comparator`.

`Comparator.naturalOrder()` trả về một `Comparator` so sánh các `Comparable` object theo thứ tự tự nhiên. Để thực thi nó, chúng ta chỉ cần gọi method `apply()` với hai argument mà `BinaryOperator` cần. Không có gì ngạc nhiên, kết quả là:

```java
28
```

Cũng có các phiên bản primitive cho `int`, `long`, và `double`, trong đó hai argument và kiểu return có cùng một primitive type. Chúng không kế thừa `BinaryOperator` hay `BiFunction`.

Ví dụ, đây là định nghĩa của `IntBinaryOperator`:

```java
@FunctionalInterface
public interface IntBinaryOperator {
    int applyAsInt(int left, int right);
}
```

Bạn có thể dùng nó thay cho `BinaryOperator`.


### Functional interface chuyên biệt cho primitive {#primitive-specific-functional-interfaces}
Ngoài ra còn có một tập hợp các functional interface được thiết kế đặc biệt để làm việc với primitive type. Những interface này có thể mang lại hiệu năng tốt hơn so với các phiên bản generic tương ứng khi làm việc với primitive, vì chúng tránh được chi phí của boxing và unboxing.

Có một số nhóm functional interface chuyên biệt cho primitive:

1. `ToDoubleFunction<T>`, `ToIntFunction<T>`, `ToLongFunction<T>`: Những interface này biểu diễn các function nhận một object thuộc kiểu `T` và trả về primitive `double`, `int`, hoặc `long` tương ứng. Ví dụ, đây là cách `ToIntFunction<T>` được định nghĩa:
```java
@FunctionalInterface
public interface ToIntFunction<T> {
    int applyAsInt(T value);
}
```

Và đây là ví dụ về cách dùng nó:
```java
ToIntFunction<String> stringToInt = Integer::parseInt;
int i = stringToInt.applyAsInt("123");  // 123
```

2. `ToDoubleBiFunction<T, U>`, `ToIntBiFunction<T, U>`, `ToLongBiFunction<T, U>`: Những interface này biểu diễn các function nhận hai object thuộc kiểu `T` và `U` và trả về primitive `double`, `int`, hoặc `long` tương ứng. Ví dụ, đây là cách `ToIntBiFunction<T, U>` được định nghĩa:
```java
@FunctionalInterface
public interface ToIntBiFunction<T, U> {
    int applyAsInt(T t, U u);
}
```

Và đây là ví dụ về cách dùng nó:
```java
ToIntBiFunction<String, String> comparator = String::compareTo;
int result = comparator.applyAsInt("abc", "def");  // một giá trị âm
```

3. `DoubleToIntFunction`, `DoubleToLongFunction`, `IntToDoubleFunction`, `IntToLongFunction`, `LongToDoubleFunction`, `LongToIntFunction`: Những interface này biểu diễn các function nhận một primitive type và trả về một primitive type khác. Ví dụ, đây là cách `DoubleToIntFunction` được định nghĩa:
```java
@FunctionalInterface
public interface DoubleToIntFunction {
    int applyAsInt(double value);
}
```

Và đây là ví dụ về cách dùng nó:
```java
DoubleToIntFunction roundDown = d -> (int) d;
int i = roundDown.applyAsInt(9.9);  // 9
```

4. `ObjDoubleConsumer<T>`, `ObjIntConsumer<T>`, `ObjLongConsumer<T>`: Những interface này biểu diễn các function nhận một object thuộc kiểu `T` và một primitive `double`, `int`, hoặc `long`, và trả về `void`. Ví dụ, đây là cách `ObjIntConsumer<T>` được định nghĩa:
```java
@FunctionalInterface
public interface ObjIntConsumer<T> {

    /**
     * Thực hiện operation này trên các argument đã cho.
     *
     * @param t argument đầu vào thứ nhất
     * @param value argument đầu vào thứ hai
     */
    void accept(T t, int value);
}
```

Và đây là ví dụ về cách dùng nó:
```java
ObjIntConsumer<List<Integer>> listAddInt = List::add;
List<Integer> list = new ArrayList<>();
listAddInt.accept(list, 1);  // [1]
```

Những interface này khác với `DoubleFunction<R>`, `IntFunction<R>`, `LongFunction<R>`, v.v., ở chỗ các interface sau nhận một primitive và trả về một object. Ví dụ:

```java
IntFunction<String> intToString = Integer::toString;
String s = intToString.apply(123);  // "123"
```

Việc chọn interface nào để dùng phụ thuộc vào nhu cầu cụ thể của bạn. Nếu bạn chủ yếu làm việc với primitive và muốn tránh chi phí autoboxing và unboxing, các interface chuyên biệt cho primitive là lựa chọn tốt. Tuy nhiên, nếu bạn cần làm việc với object, hoặc nếu chi phí boxing không phải là vấn đề, các generic interface như `Function<T, R>` và `BiFunction<T, U, R>` thường tiện lợi hơn.

   
## Method References {#method-references}

Như bạn biết, trong Java chúng ta có thể dùng reference tới object, hoặc bằng cách tạo object mới:

```java
List list = new ArrayList();
store(new ArrayList());
```

Hoặc bằng cách dùng object đã tồn tại:

```java
List list2 = list;
isFull(list2);
```

Nhưng còn reference tới một *method* thì sao?

Nếu chúng ta chỉ dùng một method của object trong một method khác, chúng ta vẫn phải truyền cả object làm argument. Sẽ thực tế hơn nếu chỉ truyền method làm argument phải không? Ví dụ như thế này:

```java
isFull(list.size);
```

Nhờ biểu thức lambda, chúng ta có thể làm điều tương tự. Chúng ta có thể dùng method như thể chúng là object hay primitive value.

Và đó là bởi vì method reference là cú pháp viết tắt cho một biểu thức lambda chỉ thực thi **một** method.

Đây là cú pháp của một method reference:

```java
Object :: methodName
```

Bạn có thể dùng biểu thức lambda thay vì dùng anonymous class, nhưng đôi khi, biểu thức lambda thực ra chỉ là một lời gọi tới một method nào đó. Ví dụ:

```java
Consumer<String> c = s -> System.out.println(s);
```

Để làm code rõ ràng hơn, bạn có thể chuyển biểu thức lambda đó thành một method reference:

```java
Consumer<String> c = System.out::println;
```

Trong một method reference, bạn đặt object (hoặc class) chứa method trước toán tử `::` và tên của method sau nó mà không có argument.

Nhưng có thể bạn đang nghĩ:

- Cách này rõ ràng hơn ở chỗ nào?
- Điều gì xảy ra với các argument?
- Làm sao đây có thể là một biểu thức hợp lệ?
- Tôi không hiểu cách tạo ra một method reference hợp lệ

Trước hết, một method reference không thể dùng cho bất kỳ method nào. Chúng chỉ có thể được dùng để thay thế một biểu thức lambda đơn method.

Vậy nên để dùng một method reference, trước tiên bạn cần một biểu thức lambda với một method. Và để dùng một biểu thức lambda, trước tiên bạn cần một functional interface, một interface chỉ có một abstract method.

Nói cách khác:

Thay vì dùng

**MỘT ANONYMOUS CLASS**

bạn có thể dùng

**MỘT BIỂU THỨC LAMBDA**

Và nếu nó chỉ gọi một method, bạn có thể dùng

**MỘT METHOD REFERENCE**

Có bốn loại method reference:

- Method reference tới một *static method*
- Method reference tới một *instance method của một object thuộc một kiểu cụ thể*
- Method reference tới một *instance method của một object đã tồn tại*
- Method reference tới một *constructor*

Hãy bắt đầu bằng việc giải thích trường hợp tự nhiên nhất, một *static method*.

### Static method {#static-methods}

Trong trường hợp này, chúng ta có một biểu thức lambda như sau:

```java
(args) -> Class.staticMethod(args)
```

Nó có thể được chuyển thành method reference sau:

```java
Class::staticMethod
```

Lưu ý rằng giữa một static method và một static method reference, thay vì toán tử `.`, chúng ta dùng toán tử `::`, và chúng ta không truyền argument cho method reference.

Nói chung, chúng ta không phải truyền argument cho method reference. Tuy nhiên, argument được xử lý tùy theo loại method reference.

Trong trường hợp này, mọi argument (nếu có) mà method nhận đều được truyền tự động ở hậu trường.

Ở bất cứ đâu có thể truyền một biểu thức lambda chỉ gọi một static method, chúng ta đều có thể dùng method reference. Ví dụ, giả sử có class này:

```java
class Numbers {
    public static boolean isMoreThanFifty(int n1, int n2) {
        return (n1 + n2) > 50;
    }
    public static List<Integer> findNumbers(
        List<Integer> l, BiPredicate<Integer, Integer> p) {
        List<Integer> newList = new ArrayList<>();
        for (Integer i : l) {
            if (p.test(i, i + 10)) {
                newList.add(i);
            }
        }
        return newList;
    }
}
```

Chúng ta có thể gọi method `findNumbers()`:

```java
List<Integer> list = Arrays.asList(12, 5, 45, 18, 33, 24, 40);

// Dùng anonymous class
findNumbers(list, new BiPredicate<Integer, Integer>() {
    public boolean test(Integer i1, Integer i2) {
        return Numbers.isMoreThanFifty(i1, i2);
    }
});

// Dùng biểu thức lambda
findNumbers(list, (i1, i2) -> Numbers.isMoreThanFifty(i1, i2));

// Dùng method reference
findNumbers(list, Numbers::isMoreThanFifty);
```

### Instance method của một object thuộc một kiểu cụ thể {#instance-method-of-an-object-of-a-particular-type}

Trong trường hợp này, chúng ta có một biểu thức lambda như sau:

```java
(obj, args) -> obj.instanceMethod(args)
```

Trong đó một instance của object được truyền vào, và một trong các method của nó được thực thi với vài parameter tùy chọn.

Nó có thể được chuyển thành method reference sau:

```java
ObjectType::instanceMethod
```

Lần này, việc chuyển đổi không đơn giản như vậy. Đầu tiên, trong method reference, chúng ta không dùng chính instance đó. Chúng ta dùng type của nó.

Thứ hai, argument còn lại của biểu thức lambda, nếu có, không được dùng trong method reference, mà được truyền ở hậu trường giống như trường hợp static method.

Ví dụ, giả sử có class này:

```java
class Shipment {
    public double calculateWeight() {
        double weight = 0;
        // Tính weight
        return weight;
    }
}
```

Và method này:

```java
public List<Double> calculateOnShipments(
    List<Shipment> l, Function<Shipment, Double> f) {
    List<Double> results = new ArrayList<>();
    for (Shipment s : l) {
        results.add(f.apply(s));
    }
    return results;
}
```

Chúng ta có thể gọi method đó bằng cách dùng:

```java
List<Shipment> l = new ArrayList<Shipment>();

// Dùng anonymous class
calculateOnShipments(l, new Function<Shipment, Double>() {
    public Double apply(Shipment s) { // Object
        return s.calculateWeight(); // Method
    }
});

// Dùng biểu thức lambda
calculateOnShipments(l, s -> s.calculateWeight());

// Dùng method reference
calculateOnShipments(l, Shipment::calculateWeight);
```

Trong ví dụ này, chúng ta không truyền argument nào cho method. Điểm mấu chốt ở đây là một instance của object chính là parameter của biểu thức lambda, và chúng ta tạo reference tới instance method bằng type của instance đó.

Đây là một ví dụ khác, nơi chúng ta truyền hai argument cho method reference.

Java có interface `Function` nhận một parameter, `BiFunction` nhận hai parameter, nhưng không có `TriFunction` nhận ba parameter, nên hãy tự tạo một cái:

```java
interface TriFunction<T, U, V, R> {
    R apply(T t, U u, V v);
}
```

Bây giờ giả sử có một class với một method nhận hai parameter và trả về kết quả, như thế này:

```java
class Sum {
    Integer doSum(String s1, String s2) {
        return Integer.parseInt(s1) + Integer.parseInt(s2);
    }
}
```

Chúng ta có thể bọc method `doSum()` trong một implementation `TriFunction` bằng anonymous class:

```java
TriFunction<Sum, String, String, Integer> anon =
    new TriFunction<Sum, String, String, Integer>() {
        @Override
        public Integer apply(Sum s, String arg1, String arg2) {
            return s.doSum(arg1, arg2);
        }
    };
System.out.println(anon.apply(new Sum(), "1", "4"));
```

Hoặc dùng biểu thức lambda:

```java
TriFunction<Sum, String, String, Integer> lambda =
    (Sum s, String arg1, String arg2) -> s.doSum(arg1, arg2);
System.out.println(lambda.apply(new Sum(), "1", "4"));
```

Hoặc chỉ dùng method reference:

```java
TriFunction<Sum, String, String, Integer> mRef = Sum::doSum;
System.out.println(mRef.apply(new Sum(), "1", "4"));
```

Ở đây:

- Type parameter đầu tiên của `TriFunction` là object type chứa method cần thực thi.
- Type parameter thứ hai của `TriFunction` là kiểu của parameter thứ nhất.
- Type parameter thứ ba của `TriFunction` là kiểu của parameter thứ hai.
- Type parameter cuối cùng của `TriFunction` là kiểu return của method cần thực thi. Hãy để ý cách nó được lược bỏ (được suy luận) trong biểu thức lambda và method reference.

Có thể sẽ hơi lạ khi chỉ nhìn thấy interface, class và cách chúng được dùng với method reference, nhưng điều này trở nên rõ ràng hơn khi bạn xem phiên bản anonymous class hoặc thậm chí cả phiên bản lambda.

Từ:

```java
(Sum s, String arg1, String arg2) -> s.doSum(arg1, arg2)
```

Đến

```java
Sum::doSum
```

### Instance method của một object đã tồn tại {#instance-method-of-an-existing-object}

Trong trường hợp này, chúng ta có một biểu thức lambda như sau:

```java
(args) -> obj.instanceMethod(args)
```

Đoạn này có thể được chuyển thành method reference sau:

```java
obj::instanceMethod
```

Lần này, một instance được định nghĩa ở nơi khác được sử dụng, và các argument (nếu có) được truyền ngầm phía sau giống như trường hợp static method.

Ví dụ, giả sử có các class sau:

```java
class Car {
    private int id;
    private String color;
    // Thêm các property
    // Và các getter và setter
}
class Mechanic {
    public void fix(Car c) {
        System.out.println("Fixing car " + c.getId());
    }
}
```

Và

 method này:

```java
public static void execute(Car car, Consumer<Car> c) {
    c.accept(car);
}
```

Chúng ta có thể gọi method trên bằng cách dùng:

```java
final Mechanic mechanic = new Mechanic();
Car car = new Car();

// Dùng anonymous class
execute(car, new Consumer<Car>() {
    public void accept(Car c) {
        mechanic.fix(c);
    }
});

// Dùng biểu thức lambda
execute(car, c -> mechanic.fix(c));

// Dùng method reference
execute(car, mechanic::fix);
```

Điểm mấu chốt trong trường hợp này là dùng bất kỳ object nào mà anonymous class/biểu thức lambda có thể thấy và truyền một vài argument cho một instance method của object đó.

Đây là một ví dụ nhanh khác dùng một `Consumer` khác:

```java
Consumer<String> c = System.out::println;
c.accept("Hello");
```

## Constructor {#constructor}

Trong trường hợp này, chúng ta có một biểu thức lambda như sau:

```java
(args) -> new ClassName(args)
```

Đoạn này có thể được chuyển thành method reference sau:

```java
ClassName::new
```

Việc duy nhất mà biểu thức lambda này làm là tạo một object mới, nên chúng ta chỉ cần tham chiếu đến một constructor của class bằng keyword `new`. Như trong các trường hợp khác, các argument (nếu có) không được truyền trong method reference.

Hầu hết trường hợp, chúng ta có thể dùng cú pháp này với hai (hoặc ba) interface từ package `java.util.function`.

Nếu constructor không nhận argument nào, một `Supplier` sẽ làm được việc đó:

```java
// Dùng anonymous class
Supplier<List<String>> s = new Supplier<List<String>>() {
    public List<String> get() {
        return new ArrayList<String>();
    }
};
List<String> l = s.get();

// Dùng biểu thức lambda
Supplier<List<String>> s = () -> new ArrayList<String>();
List<String> l = s.get();

// Dùng method reference
Supplier<List<String>> s = ArrayList::new;
List<String> l = s.get();
```

Nếu constructor nhận một argument, chúng ta có thể dùng interface `Function`. Ví dụ:

```java
// Dùng anonymous class
Function<String, Integer> f =
    new Function<String, Integer>() {
        public Integer apply(String s) {
            return new Integer(s);
        }
    };
Integer i = f.apply("100");

// Dùng biểu thức lambda
Function<String, Integer> f = s -> new Integer(s);
Integer i = f.apply("100");

// Dùng method reference
Function<String, Integer> f = Integer::new;
Integer i = f.apply("100");
```

Nếu constructor nhận hai argument, chúng ta dùng interface `BiFunction`:

```java
// Dùng anonymous class
BiFunction<String, String, Locale> f = new BiFunction<String, String, Locale>() {
    public Locale apply(String lang, String country) {
        return new Locale(lang, country);
    }
};
Locale loc = f.apply("en", "UK");

// Dùng biểu thức lambda
BiFunction<String, String, Locale> f = (lang, country) -> new Locale(lang, country);
Locale loc = f.apply("en", "UK");

// Dùng method reference
BiFunction<String, String, Locale> f = Locale::new;
Locale loc = f.apply("en", "UK");
```

Nếu bạn có một constructor với ba argument trở lên, bạn sẽ phải tự tạo functional interface của riêng mình.

Bạn có thể thấy rằng tham chiếu đến một constructor rất giống với tham chiếu đến một static method. Điểm khác biệt là *method name* của constructor là `new`.

Nhiều ví dụ trong chương này rất đơn giản và có lẽ chưa đủ thuyết phục để dùng biểu thức lambda hay method reference.

Như đã đề cập ở đầu chương, hãy dùng method reference nếu chúng làm code của bạn rõ ràng hơn.

Bạn có thể tránh hạn chế một method bằng cách nhóm toàn bộ code của mình vào một static method chẳng hạn, rồi tạo tham chiếu đến method đó thay vì dùng một class hay biểu thức lambda với nhiều dòng.

Nhưng sức mạnh thực sự của biểu thức lambda và method reference đến khi chúng được kết hợp với một tính năng khác của Java: streams.

Đó sẽ là chủ đề của chương tiếp theo.


## Những điểm chính {#key-points}
- Functional interface là interface chỉ chứa duy nhất một abstract method. Nó có thể chứa default method hoặc static method.

- Annotation `@FunctionalInterface` được dùng để chỉ ra rằng một interface được dự định là functional interface. Nó cho phép compiler kiểm tra nhưng không bắt buộc nếu interface thỏa tiêu chí functional interface.

- Nếu một interface khai báo một abstract method override một public method trong `java.lang.Object`, method đó không được tính vào số lượng abstract method của interface.

- Biểu thức lambda cho phép bạn coi functionality như method argument hay code như data.

- Cú pháp của một biểu thức lambda là: `(parameters) -> expression` hoặc `(parameters) -> { statements; }`.

- Bạn có thể dùng `var` trong danh sách parameter của biểu thức lambda để cho phép type inference.

- Target type của biểu thức lambda có thể được suy luận trong các ngữ cảnh như khai báo biến, phép gán, câu lệnh return, array initializer, argument của method/constructor, biểu thức ba ngôi và biểu thức cast.

- Biểu thức lambda tương tự anonymous class ở một số điểm, như cách dùng local variable, nhưng khác ở cách xử lý `this`, default method, danh sách parameter và instance variable.

- Local variable được dùng trong biểu thức lambda hoặc anonymous class phải là final hoặc effectively final (không bị sửa đổi sau khi khởi tạo) để đảm bảo thread safety và tính nhất quán.

- Java cung cấp các functional interface có sẵn trong package `java.util.function` cho những use case phổ biến. Những interface chính là `Predicate<T>`, `Consumer<T>`, `Function<T, R>`, `Supplier<T>`, và `UnaryOperator<T>`.

- Những interface này cũng có các phiên bản chuyên biệt cho primitive (như `IntPredicate`, `LongConsumer`, v.v.) để tránh chi phí autoboxing khi làm việc với primitive.

- Một số interface này cũng có phiên bản binary nhận hai parameter, như `BiPredicate<L, R>`, `BiConsumer<T, U>`, `BiFunction<T, U, R>`, và `BinaryOperator<T>`.

- `Predicate<T>` biểu diễn một function trả về giá trị boolean, nhận input là một object thuộc kiểu `T `. Nó có các default method `and`, `or`, và `negate` để kết hợp các predicate.

- `Consumer<T>` biểu diễn một operation nhận một input argument duy nhất và không trả về kết quả. Nó có default method `andThen` để nối chuỗi các consumer. 

- `Function<T, R>` biểu diễn một function nhận một argument và trả về một kết quả. Nó có các default method `compose` và `andThen` để kết hợp các function.

- `Supplier<T>` biểu diễn một supplier của kết quả, nó không nhận argument nào và trả về một kết quả.

- `UnaryOperator<T>` biểu diễn một operation trên một operand duy nhất, tạo ra kết quả cùng kiểu với operand của nó. Đây là phiên bản chuyên biệt của `Function` trong đó kiểu argument và kiểu kết quả giống nhau.

- Method reference cung cấp một cách tham chiếu đến một method mà không gọi nó, dùng toán tử `::`. Chúng có thể được dùng ở nơi cần biểu thức lambda.

- Có bốn loại method reference: đến một static method, đến một instance method của một object thuộc một kiểu cụ thể, đến một instance method của một object đã tồn tại, và đến một constructor.
