## Các class Date/Time cốt lõi {#core-datetime-classes}

Java 8 đã giới thiệu một Date/Time API mới trong package `java.time`. Các class thuộc API này là immutable và thread-safe.

Trong phần này, chúng ta sẽ xem xét các class sau:

- **LocalDate:** Biểu diễn một date với thông tin year, month và day of the month. Ví dụ: `2025-08-25`.

- **LocalTime:** Biểu diễn một time với thông tin hour, minute, second và nanosecond. Ví dụ: `13:21:05.123456789`.

- **LocalDateTime:** Kết hợp của những class trên. Ví dụ: `2025-08-25T13:21:05.123456789`.

- **Instant:** Biểu diễn một điểm thời gian duy nhất với seconds và nanoseconds. Ví dụ: `1970-01-01T00:00:00Z (seconds since epoch: 923456789, nanoseconds: 186,054,812)`.

- **Period:** Biểu diễn một khoảng thời gian theo years, months và days. Ví dụ: `5 years, 2 months, and 9 days`.

- **Duration:** Biểu diễn một khoảng thời gian theo seconds và nanoseconds. Ví dụ: `12.87656 seconds`.

Ngoại trừ `Instant`, các class này không lưu trữ hay biểu diễn time zone.

Ngoài ra, `LocalDate`, `LocalTime`, `LocalDateTime` và `Instant` triển khai interface `java.time.temporal.Temporal`, nên chúng đều có các method tương tự nhau. `Period` và `Duration` triển khai interface `java.time.temporal.TemporalAmount`, điều này cũng khiến chúng rất giống nhau.

Đây là một sơ đồ giúp bạn hình dung các class của Date/Time API:
```

│  │ (Date only) │    │ (Time only) │    │(Date + Time)│  │
│  └──────┬──────┘    └──────┬──────┘    └──────┬──────┘  │
│         │                  │                  │         │
│         └──────────────────┼──────────────────┘         │
│                            │                            │
│                     ┌──────┴──────┐                     │
│                     │   Instant   │                     │
│                     │ (Time-stamp)│                     │
│                     └──────┬──────┘                     │
```

### Class `LocalDate` {#the-localdate-class}

Chìa khóa để học cách sử dụng class này là hiểu rằng nó lưu giữ year, month, day và các thông tin dẫn xuất của một date. Mọi method của nó đều sử dụng thông tin này hoặc có một phiên bản để làm việc với từng thành phần đó.

Sau đây là những method quan trọng nhất của class này.

Để tạo một instance, chúng ta có thể dùng static method `of`:

```java
// Với year (-999999999 đến 999999999), month (1 đến 12), day of the month (1 - 31)
LocalDate newYear2001 = LocalDate.of(2001, 1, 1);
// Phiên bản này dùng enum java.time.Month
LocalDate newYear2002 = LocalDate.of(2002, Month.JANUARY, 1);
```

Lưu ý rằng, không giống `java.util.Date`, month bắt đầu từ một. Nếu bạn cố tạo một date với giá trị không hợp lệ (như ngày 29 tháng Hai trong năm không nhuận), một exception sẽ được throw. Để lấy date của hôm nay, hãy dùng `now()`:

```java
LocalDate today = LocalDate.now();
```

Khi đã có một instance của `LocalDate`, chúng ta có thể lấy year, month và day bằng những method như sau:

```java
int year = today.getYear();
int month = today.getMonthValue();
Month monthAsEnum = today.getMonth(); // Dưới dạng enum: JANUARY, FEBRUARY, v.v.
int dayYear = today.getDayOfYear();
int dayMonth = today.getDayOfMonth();
DayOfWeek dayWeekEnum = today.getDayOfWeek(); // Dưới dạng enum: MONDAY, TUESDAY, v.v.
```

Chúng ta cũng có thể dùng method `get`:

```java
int get(java.time.temporal.TemporalField field); // value dưới dạng int
long getLong(java.time.temporal.TemporalField field); // value dưới dạng long
```

Method này nhận một implementation của interface `java.time.temporal.TemporalField` để truy cập một field cụ thể của date. `java.time.temporal.ChronoField` là một enumeration triển khai interface này, nên ví dụ chúng ta có thể viết:

```java
int year2 = today.get(ChronoField.YEAR);
int month2 = today.get(ChronoField.MONTH_OF_YEAR);
int dayYear2 = today.get(ChronoField.DAY_OF_YEAR);
int dayMonth2 = today.get(ChronoField.DAY_OF_MONTH);
int dayWeek = today.get(ChronoField.DAY_OF_WEEK);
long dayEpoch = today.getLong(ChronoField.EPOCH_DAY);
```

Các giá trị được hỗ trợ cho `ChronoField` là:

- `DAY_OF_WEEK`
- `ALIGNED_DAY_OF_WEEK_IN_MONTH`
- `ALIGNED_DAY_OF_WEEK_IN_YEAR`
- `DAY_OF_MONTH`
- `DAY_OF_YEAR`
- `EPOCH_DAY`
- `ALIGNED_WEEK_OF_MONTH`
- `ALIGNED_WEEK_OF_YEAR`
- `MONTH_OF_YEAR`
- `PROLEPTIC_MONTH`
- `YEAR_OF_ERA`
- `YEAR`
- `ERA`

Dùng một giá trị không được hỗ trợ sẽ throw exception. Điều tương tự cũng đúng khi lấy một giá trị không vừa với `int` bằng `get(TemporalField)`.

Để so sánh một `LocalDate` với instance khác, chúng ta có ba method và một method nữa cho năm nhuận:

```java
boolean after = newYear2001.isAfter(newYear2002); // false
boolean before = newYear2001.isBefore(newYear2002); // true
boolean equal = newYear2001.equals(newYear2002); // false
boolean leapYear = newYear2001.isLeapYear(); // false
```

Khi một instance của class này được tạo, nó không thể bị sửa đổi, nhưng chúng ta có thể tạo một instance khác từ instance đang có.

Một cách là dùng method `with()` và các biến thể của nó:

```java
LocalDate newYear2003 = newYear2001.with(ChronoField.YEAR, 2003);
LocalDate newYear2004 = newYear2001.withYear(2004);
LocalDate december2001 = newYear2001.withMonth(12);
LocalDate february2001 = newYear2001.withDayOfYear(32);
// Vì các method này trả về một instance mới, chúng ta có thể chain chúng lại!
LocalDate xmas2001 = newYear2001.withMonth(12).withDayOfMonth(25);
```

Cách khác là cộng hoặc trừ years, months, days, hoặc thậm chí weeks:

```java
// Cộng thêm
LocalDate newYear2005 = newYear2001.plusYears(4);
LocalDate march2001 = newYear2001.plusMonths(2);
LocalDate january15_2001 = newYear2001.plusDays(14);
LocalDate lastWeekJanuary2001 = newYear2001.plusWeeks(3);
LocalDate newYear2006 = newYear2001.plus(5, ChronoUnit.YEARS);

// Trừ đi
LocalDate newYear2000 = newYear2001.minusYears(1);
LocalDate nov2000 = newYear2001.minusMonths(2);
LocalDate dec30_2000 = newYear2001.minusDays(2);
LocalDate lastWeekDec2000 = newYear2001.minusWeeks(1);
LocalDate newYear1999 = newYear2001.minus(2, ChronoUnit.YEARS);
```

Lưu ý rằng các method plus và minus nhận một enumeration `java.time.temporal.ChronoUnit`, khác với `java.time.temporal.ChronoField`. Các giá trị được hỗ trợ là:

- `DAYS`
- `WEEKS`
- `MONTHS`
- `YEARS`
- `DECADES`
- `CENTURIES`
- `MILLENNIA`
- `ERAS`

Cuối cùng, method `toString()` trả về date theo format `uuuu-MM-dd`:

```java
System.out.println(newYear2001.toString()); // In ra 2001-01-01
```

### Class `LocalTime` {#the-localtime-class}

Chìa khóa để học cách dùng class này là ghi nhớ rằng nó lưu giữ hour, minutes, seconds và nanoseconds. Mọi method của nó đều dùng thông tin này hoặc có một phiên bản để làm việc với từng thành phần.

Sau đây là những method quan trọng nhất của class này. Như bạn thấy, chúng là những method giống (hoặc rất giống) với `LocalDate`, được điều chỉnh để làm việc với time (hours, minutes, seconds) thay vì date (days, months, years).

Để tạo một instance, chúng ta có thể dùng static method `of`:

```java
// Với hour (0-23) và minutes (0-59)
LocalTime fiveThirty = LocalTime.of(5, 30);
// Với hour, minutes và seconds (0-59)
LocalTime noon = LocalTime.of(12, 0, 0);
// Với hour, minutes, seconds và nanoseconds (0-999_999_999)
LocalTime almostMidnight = LocalTime.of(23, 59, 59, 999_999_999);
```

Nếu bạn cố tạo một time với giá trị không hợp lệ (như `LocalTime.of(24, 0)`), một exception sẽ được throw. Để lấy time hiện tại, hãy dùng `now()`:

```java
LocalTime now = LocalTime.now();
```

Khi đã có một instance của `LocalTime`, chúng ta có thể lấy hour, minutes và các thông tin khác bằng những method như sau:

```java
int hour = now.getHour();
int minute = now.getMinute();
int second = now.getSecond();
int nanosecond = now.getNano();
```

Chúng ta cũng có thể dùng method `get()`:

```java
int value = now.get(java.time.temporal.TemporalField field); // value dưới dạng int
long valueLong = now.getLong(java.time.temporal.TemporalField field); // value dưới dạng long
```

Tương tự như với `LocalDate`, ví dụ chúng ta có thể viết:

```java
int hourAMPM = now.get(ChronoField.HOUR_OF_AMPM); // 0 - 11
int hourDay = now.get(ChronoField.HOUR_OF_DAY); // 0 - 23
int minuteDay = now.get(ChronoField.MINUTE_OF_DAY); // 0 - 1,439
int minuteHour = now.get(ChronoField.MINUTE_OF_HOUR); // 0 - 59
int secondDay = now.get(ChronoField.SECOND_OF_DAY); // 0 - 86,399
int secondMinute = now.get(ChronoField.SECOND_OF_MINUTE); // 0 - 59
long nanoDay = now.getLong(ChronoField.NANO_OF_DAY); // 0-86_399_999_999
int nanoSecond = now.get(ChronoField.NANO_OF_SECOND); // 0-999_999_999
```

Các giá trị được hỗ trợ cho `ChronoField` là:

- `NANO_OF_SECOND`
- `NANO_OF_DAY`
- `MICRO_OF_SECOND`
- `MICRO_OF_DAY`
- `MILLI_OF_SECOND`
- `MILLI_OF_DAY`
- `SECOND_OF_MINUTE`
- `SECOND_OF_DAY`
- `MINUTE_OF_HOUR`
- `MINUTE_OF_DAY`
- `HOUR_OF_AMPM`
- `CLOCK_HOUR_OF_AMPM`
- `HOUR_OF_DAY`
- `CLOCK_HOUR_OF_DAY`
- `AMPM_OF_DAY`

Dùng một giá trị khác sẽ throw exception. Điều tương tự cũng đúng khi lấy một giá trị không vừa với `int` bằng `get(TemporalField)`.

Để kiểm tra một time object với object khác, chúng ta có ba method:

```java
boolean after = fiveThirty.isAfter(noon); // false
boolean before = fiveThirty.isBefore(noon); // true
boolean equal = noon.equals(almostMidnight); // false
```

Giống `LocalDate`, khi một instance của `LocalTime` được tạo, chúng ta không thể sửa đổi nó, nhưng có thể tạo một instance khác từ instance đang có.

Một cách là thông qua method `with` và các phiên bản của nó:

```java
LocalTime ten = noon.with(ChronoField.HOUR_OF_DAY, 10);
LocalTime eight = noon.withHour(8);
LocalTime twelveThirty = noon.withMinute(30);
LocalTime thirtyTwoSeconds = noon.withSecond(32);
// Vì các method này trả về một instance mới, chúng ta có thể chain chúng lại!
LocalTime secondsNano = noon.withSecond(20).withNano(999_999);
```

Tất nhiên, cách khác là cộng hoặc trừ hours, minutes, seconds hoặc nanoseconds:

```java
// Cộng thêm
LocalTime sixThirty = fiveThirty.plusHours(1);
LocalTime fiveForty = fiveThirty.plusMinutes(10);
LocalTime plusSeconds = fiveThirty.plusSeconds(14);
LocalTime plusNanos = fiveThirty.plusNanos(99_999_999);
LocalTime sevenThirty = fiveThirty.plus(2, ChronoUnit.HOURS);

// Trừ đi
LocalTime fourThirty = fiveThirty.minusHours(1);
LocalTime fiveTen = fiveThirty.minusMinutes(20);
LocalTime minusSeconds = fiveThirty.minusSeconds(2);
LocalTime minusNanos = fiveThirty.minusNanos(1);
LocalTime fiveTwenty = fiveThirty.minus(10, ChronoUnit.MINUTES);
```

Lưu ý rằng các phiên bản `plus` và `minus` nhận một enumeration `java.time.temporal.ChronoUnit`, khác với `java.time.temporal.ChronoField`. Các giá trị được hỗ trợ là:

- `NANOS`
- `MICROS`
- `MILLIS`
- `SECONDS`
- `MINUTES`
- `HOURS`
- `HALF_DAYS`

Cuối cùng, method `toString()` trả về time theo format `HH:mm:ss.SSSSSSSSS`, bỏ qua những phần có giá trị bằng zero (ví dụ, chỉ trả về `HH:mm` nếu seconds/nanoseconds bằng zero):

```java
System.out.println(fiveThirty.toString()); // In ra 05:30
```

### Class `LocalDateTime` {#the-localdatetime-class}

Chìa khóa để học cách dùng class này là nhớ rằng nó kết hợp các class `LocalDate` và `LocalTime`.

Nó biểu diễn cả date lẫn time, với thông tin như year, month, day, hours, minutes, seconds và nanoseconds. Các field khác, như day of the year, day of the week và week of year, cũng có thể được truy cập.

Để tạo một instance, chúng ta có thể dùng static method `of()` hoặc tạo từ một instance `LocalDate` hay `LocalTime`:

```java
// Đặt seconds và nanoseconds về zero
LocalDateTime dt1 = LocalDateTime.of(2024, 9, 19, 14, 5);
// Đặt nanoseconds về zero
LocalDateTime dt2 = LocalDateTime.of(2024, 9, 19, 14, 5, 20);
// Đặt tất cả các field
LocalDateTime dt3 = LocalDateTime.of(2024, 9, 19, 14, 5, 20, 9);
// Giả sử date này
LocalDate date = LocalDate.now();
// Và time này
LocalTime time = LocalTime.now();
// Kết hợp date ở trên với time đã cho như sau
LocalDateTime dt4 = date.atTime(14, 30, 59, 999999);
// Hoặc như thế này
LocalDateTime dt5 = date.atTime(time);
// Kết hợp time này với date đã cho. Lưu ý rằng LocalTime
// chỉ có method này để kết hợp với một LocalDate
LocalDateTime dt6 = time.atDate(date);
```

Nếu bạn cố tạo một instance với giá trị hoặc date không hợp lệ, một exception sẽ được throw. Để lấy date/time hiện tại, hãy dùng `now()`:

```java
LocalDateTime now = LocalDateTime.now();
```

```java
int year = now.getYear();
```

Chúng ta cũng có thể dùng method `get()`:

```java
int get(java.time.temporal.TemporalField field)

```

Ví dụ:

```java
int month = now.get(ChronoField.MONTH_OF_YEAR);

```

Các giá trị được hỗ trợ cho `ChronoField` là:

- `AMPM_OF_DAY`
- `DAY_OF_WEEK`
- `ALIGNED_DAY_OF_WEEK_IN_MONTH`

Để kiểm tra một `LocalDateTime` object với object khác, chúng ta có ba method:

```java
boolean after = now.isAfter(dt1); // true
```

```java
LocalDateTime dt7 = now.with(ChronoField.HOUR_OF_DAY, 10);
```

### Class `Instant` {#the-instant-class}

Mặc dù trên thực tế, một instance `LocalDateTime` biểu diễn một instant trên dòng thời gian, vẫn có một class khác có thể phù hợp hơn.

Class `java.time.Instant` biểu diễn một instant bằng số giây đã trôi qua kể từ epoch, một quy ước được dùng trong các hệ thống UNIX/POSIX và được đặt tại nửa đêm ngày 1 tháng 1 năm 1970 theo giờ UTC.

Từ mốc thời gian đó, time được đo bằng 86.400 giây mỗi ngày. Thông tin này được lưu dưới dạng `long`. Class cũng hỗ trợ độ chính xác nanosecond, được lưu dưới dạng `int`.

Bạn có thể tạo một instance của class này bằng những method sau:

```java
// Đặt seconds
Instant fiveSecondsAfterEpoch = Instant.ofEpochSecond(5);
// Đặt seconds và nanoseconds (có thể âm)
Instant sixSecTwoNanBeforeEpoch = Instant.ofEpochSecond(-6, -2);
// Đặt milliseconds sau (cũng có thể trước) epoch
Instant fiftyMilliSecondsAfterEpoch = Instant.ofEpochMilli(50);
```

Để lấy instance hiện tại của system clock, hãy dùng:

```java
Instant now = Instant.now();
```

Khi đã có một instance của `Instant`, chúng ta có thể lấy thông tin bằng những method sau:

```java
long seconds = now.getEpochSecond(); // Lấy seconds
int nanos1 = now.getNano(); // Lấy nanoseconds
// Lấy value dưới dạng int
int millis = now.get(ChronoField.MILLI_OF_SECOND);
// Lấy value dưới dạng long
long nanos2 = now.getLong(ChronoField.NANO_OF_SECOND);
```

Các giá trị `ChronoField` được hỗ trợ là:

- `NANO_OF_SECOND`
- `MICRO_OF_SECOND`
- `MILLI_OF_SECOND`
- `INSTANT_SECONDS`

Dùng bất kỳ giá trị nào khác sẽ throw exception. Điều tương tự cũng đúng khi lấy một giá trị không vừa với `int` bằng `get(TemporalField)`.

Để kiểm tra một `Instant` object với object khác, chúng ta có ba method:

```java
boolean after = now.isAfter(fiveSecondsAfterEpoch); // true
boolean before = now.isBefore(fiveSecondsAfterEpoch); // false
boolean equal = now.equals(fiveSecondsAfterEpoch); // false
```

Khi một instance của object này được tạo, chúng ta không thể sửa đổi nó, nhưng có thể tạo một instance khác từ instance đang có.

Một cách là dùng method `with`:

```java
Instant i1 = now.with(ChronoField.NANO_OF_SECOND, 10);
```

Cách khác là cộng hoặc trừ seconds, milliseconds hoặc nanoseconds:

```java
// Cộng thêm
Instant i10 = now.plusSeconds(400);
Instant i11 = now.plusMillis(98622200);
Instant i12 = now.plusNanos(300013890);
Instant i13 = now.plus(2, ChronoUnit.MINUTES);

// Trừ đi
Instant i14 = now.minusSeconds(2);
Instant i15 = now.minusMillis(1);
Instant i16 = now.minusNanos(1);
Instant i17 = now.minus(10, ChronoUnit.SECONDS);
```

Các giá trị `ChronoUnit` được hỗ trợ là:

- `NANOS`
- `MICROS`
- `MILLIS`
- `SECONDS`
- `MINUTES`
- `HOURS`
- `HALF_DAYS`
- `DAYS`

Cuối cùng, method `toString()` trả về một biểu diễn của `Instant` theo format `uuuu-MM-dd'T'HH:mm:ss.SSSSSSSSS`, ví dụ:

```java
// In ra 1970-01-01T00:00:00.050Z
System.out.println(fiftyMilliSecondsAfterEpoch.toString());
```

Lưu ý rằng nó chứa thông tin zone time (`Z`). Điều này là vì `Instant` biểu diễn một điểm thời gian tính từ epoch `1970-01-01Z` theo UTC zone time.


### Class `Period` {#the-period-class}

Class `java.time.Period` biểu diễn một khoảng thời gian theo years, months và days.

Bạn có thể tạo một instance của class này bằng những method sau:

```java
// Đặt years, months, days (có thể âm)
Period period5y4m3d = Period.of(5, 4, 3);
// Đặt days (có thể âm), years và months sẽ bằng zero
Period period2d = Period.ofDays(2);
// Setting months (có thể âm), years và days sẽ bằng zero
Period period2m = Period.ofMonths(2);
// Setting weeks (có thể âm). Period kết quả sẽ
// tính bằng days (1 week = 7 days). Years và months sẽ bằng zero
Period period14d = Period.ofWeeks(2);
// Setting years (có thể âm), days và months sẽ bằng zero
Period period2y = Period.ofYears(2);
```

Một `Period` cũng có thể được xem như khoảng chênh lệch giữa hai `LocalDate`. May thay, có một method hỗ trợ khái niệm này:

```java
LocalDate march2003 = LocalDate.of(2003, 3, 1);
LocalDate may2003 = LocalDate.of(2003, 5, 1);
Period dif = Period.between(march2003, may2003); // 2 tháng
```

Ngày bắt đầu được tính vào, còn ngày kết thúc thì không.

Hãy cẩn thận với cách date được tính.

Đầu tiên, các tháng trọn vẹn được đếm, sau đó số ngày còn lại được tính. Số tháng sau đó được tách thành years (1 year bằng 12 months). Một month được tính nếu ngày kết thúc của month lớn hơn hoặc bằng ngày bắt đầu của month.

Kết quả của method này có thể là một period âm nếu điểm kết thúc nằm trước điểm bắt đầu (year, month và day sẽ mang dấu âm).

Dưới đây là một vài ví dụ:

```java
// dif1 sẽ là 1 năm 2 tháng 2 ngày
Period dif1 = Period.between(LocalDate.of(2000, 2, 10), LocalDate.of(2001, 4, 12));
// dif2 sẽ là 25 ngày
Period dif2 = Period.between(LocalDate.of(2013, 5, 9), LocalDate.of(2013, 6, 3));
// dif3 sẽ là -2 năm -3 ngày
Period dif3 = Period.between(LocalDate.of(2014, 11, 3), LocalDate.of(2012, 10, 31));
```

Khi đã có một instance của `Period`, chúng ta có thể lấy thông tin bằng những method sau:

```java
int days = period5y4m3d.getDays();
int months = period5y4m3d.getMonths();
int year = period5y4m3d.getYears();
long days2 = period5y4m3d.get(ChronoUnit.DAYS);
```

Lưu ý rằng method `get` trả về kiểu `long`.

Ngoài ra, các giá trị `ChronoUnit` được hỗ trợ là:

- `DAYS`
- `MONTHS`
- `YEARS`

Dùng bất kỳ giá trị nào khác sẽ throw exception.

Khi một instance của `Period` được tạo, chúng ta không thể sửa đổi nó, nhưng có thể tạo một instance khác dựa trên instance đang có.

Một cách là dùng method `with` và các phiên bản của nó:

```java
Period period8d = period2d.withDays(8);
// Vì các method này trả về một instance mới, chúng ta có thể chain chúng!
Period period2y1m2d = period2d.withYears(2).withMonths(1);
```

Cách khác là cộng hoặc trừ years, months hoặc days:

```java
// Phép cộng
Period period9y4m3d = period5y4m3d.plusYears(4);
Period period5y7m3d = period5y4m3d.plusMonths(3);
Period period5y4m6d = period5y4m3d.plusDays(3);
Period period7y4m3d = period5y4m3d.plus(period2y);

// Phép trừ
Period period5y4m1d = period5y4m3d.minusYears(2);
Period period5y3m3d = period5y4m3d.minusMonths(1);
Period period5y4m2d = period5y4m3d.minusDays(1);
Period period3y4m3d = period5y4m3d.minus(period2y);
```

Các method `plus` và `minus` nhận một implementation của interface `java.time.temporal.TemporalAmount` (một instance `Period` khác hoặc một instance `Duration`).

Cuối cùng, method `toString()` trả về period theo format `P<years>Y<months>M<days>D`, ví dụ:

```java
System.out.println(period5y4m3d.toString()); // In ra P5Y4M3D
```

Một period bằng zero sẽ được biểu diễn là zero days, `P0D`.


### Class `Duration` {#the-duration-class}

Class `java.time.Duration` tương tự class `Period`, chỉ khác là nó biểu diễn một khoảng thời gian theo seconds và nanoseconds.

Bạn có thể tạo một instance của class này bằng những method sau:

```java
Duration oneDay = Duration.ofDays(1); // 1 ngày = 86400 giây
Duration oneHour = Duration.ofHours(1); // 1 giờ = 3600 giây
Duration oneMin = Duration.ofMinutes(1); // 1 phút = 60 giây
Duration tenSeconds = Duration.ofSeconds(10);
// Set seconds và nanoseconds (nếu chúng nằm ngoài range
// 0 đến 999,999,999 thì seconds sẽ bị thay đổi, như bên dưới)
Duration twoSeconds = Duration.ofSeconds(1, 1000000000);
// Seconds và nanoseconds được trích xuất từ millisecs được truyền vào
Duration oneSecondFromMillis = Duration.ofMillis(2);
// Seconds và nanoseconds được trích xuất từ nanos được truyền vào
Duration oneSecondFromNanos = Duration.ofNanos(1000000000);
Duration oneSecond = Duration.of(1, ChronoUnit.SECONDS);
```

Các giá trị hợp lệ của `ChronoUnit` cho method `Duration.of(long amount, TemporalUnit unit)` là:

- `NANOS`
- `MICROS`
- `MILLIS`
- `SECONDS`
- `MINUTES`
- `HOURS`
- `HALF_DAYS`
- `DAYS`

Một `Duration` cũng có thể được tạo như khoảng chênh lệch giữa hai implementation của interface `java.time.temporal.Temporal`, miễn là chúng hỗ trợ seconds (và để chính xác hơn, cả nanoseconds), như `LocalTime`, `LocalDateTime` và `Instant`. Vậy nên chúng ta có thể viết như sau:

```java
Duration diff = Duration.between(Instant.ofEpochSecond(123456789), Instant.ofEpochSecond(99999));
```

Kết quả có thể âm nếu điểm kết thúc nằm trước điểm bắt đầu. Một duration âm được biểu thị bằng dấu âm ở phần seconds. Ví dụ, một duration -100 nanoseconds được lưu là -1 second cộng 999.999.900 nanoseconds.

Nếu các object thuộc kiểu khác nhau, thì duration được tính dựa trên kiểu của object đầu tiên. Điều này chỉ đúng khi đối số thứ nhất là `LocalTime` và đối số thứ hai là `LocalDateTime` (vì nó có thể được chuyển đổi thành `LocalTime`). Nếu không, một exception sẽ được throw.

Khi đã có một instance của `Duration`, chúng ta có thể lấy thông tin bằng những method sau:

```java
// Phần nanoseconds của duration, từ 0 đến 999,999,999
int nanos = oneSecond.getNano();
// Phần seconds của duration, có thể dương hoặc âm
long seconds = oneSecond.getSeconds();
// Nó hỗ trợ SECONDS và NANOS. Các unit khác sẽ throw exception
long oneSec = oneSecond.get(ChronoUnit.SECONDS);
```

Lưu ý rằng các method `getSeconds()` và `get(TemporalUnit)` trả về kiểu `long`. Ngoài ra, method sau chỉ hỗ trợ `SECONDS` và `NANOS` làm đối số.

Khi một instance của `Duration` được tạo, chúng ta không thể sửa đổi nó, nhưng có thể tạo một instance khác từ instance đang có. Một cách là dùng các method `withNanos` và `withSeconds`:

```java
Duration duration1sec8nan = oneSecond.withNanos(8);
Duration duration2sec1nan = oneSecond.withSeconds(2).withNanos(1);
```

Cách khác là cộng hoặc trừ days, hours, minutes, seconds, milliseconds hoặc nanoseconds:

```java
// Phép cộng
Duration plus4Days = oneSecond.plusDays(4);
Duration plus3Hours = oneSecond.plusHours(3);
Duration plus3Minutes = oneSecond.plusMinutes(3);
Duration plus3Seconds = oneSecond.plusSeconds(3);
Duration plus3Millis = oneSecond.plusMillis(3);
Duration plus3Nanos = oneSecond.plusNanos(3);
Duration plusAnotherDuration = oneSecond.plus(twoSeconds);
Duration plusChronoUnits = oneSecond.plus(1, ChronoUnit.DAYS); 

// Phép trừ
Duration minus4Days = oneSecond.minusDays(4);
Duration minus3Hours = oneSecond.minusHours(3);
Duration minus3Minutes = oneSecond.minusMinutes(3);
Duration minus3Seconds = oneSecond.minusSeconds(3);
Duration minus3Millis = oneSecond.minusMillis(3);
Duration minus3Nanos = oneSecond.minusNanos(3);
Duration minusAnotherDuration = oneSecond.minus(twoSeconds);
Duration minusChronoUnits = oneSecond.minus(1, ChronoUnit.DAYS);
```

Các method `plus` và `minus` nhận một `Duration` khác hoặc một giá trị `ChronoUnit` hợp lệ (cùng những giá trị dùng để tạo instance).

Cuối cùng, method `toString()` trả về duration theo format `PTnHnMnS`. Phần giây lẻ (fractional seconds) được đặt sau dấu thập phân trong phần seconds. Nếu một phần có giá trị bằng zero, nó sẽ bị bỏ qua. Ví dụ:

```java
2 days 4 minutes PT48H4M
45 seconds 99 milliseconds PT45.099S
```


## Time Zones và Daylight Saving {#time-zones-and-daylight-savings}
Nếu bạn muốn làm việc với thông tin time zone, Date/Time API có những class sau:

- **ZoneId:** Biểu diễn ID của time zone. Ví dụ: `Asia/Tokyo`.

- **ZoneOffset:** Biểu diễn một time zone offset. Nó là subclass của `ZoneId`. Ví dụ: `-06:00`.

- **ZonedDateTime:** Biểu diễn một date/time với thông tin time zone. Ví dụ: `2025-08-30T20:05:12.463-05:00[America/Mexico_City]`.

- **OffsetDateTime:** Biểu diễn một date/time với offset so với UTC/Greenwich. Ví dụ: `2025-08-30T20:05:12.463-05:00`.

- **OffsetTime:** Biểu diễn một time với offset so với UTC/Greenwich. Ví dụ: `20:05:12.463-05:00`.

Cũng như các class trong phần trước, những class này nằm trong package `java.time` và là immutable.

Đây là một sơ đồ để hình dung các zone-aware class:
```
┌────────────────────────────────────────────────────────┐
│             Java Time Zone-Aware Classes               │
│                                                        │
│  ┌─────────────┐    ┌─────────────┐                    │
│  │  ZoneId     │    │ ZoneOffset  │                    │
│  │ (Time zone) │    │(UTC offset) │                    │
│  └──────┬──────┘    └──────┬──────┘                    │
│         │                  │                           │
│         └──────────────────┼────────────────┐          │
│                            │                │          │
│                     ┌──────┴──────┐  ┌──────┴───────┐  │
│                     │ZonedDateTime│  │OffsetDateTime│  │
│                     │(Date + Time │  │ (Date + Time │  │
│                     │ + Time Zone)│  │ + UTC offset)│  │
│                     └─────────────┘  └──────┬───────┘  │
│                                             │          │
│                                       ┌─────┴─────┐    │
│                                       │OffsetTime │    │
│                                       │ (Time +   │    │
│                                       │UTC offset)│    │
│                                       └───────────┘    │
│                                                        │
└────────────────────────────────────────────────────────┘

Key Points:
- ZoneId represents a time zone (like "America/New_York")
- ZoneOffset represents a fixed offset from UTC (like "+05:00")
- ZonedDateTime combines LocalDateTime with a ZoneId
- OffsetDateTime combines LocalDateTime with a ZoneOffset
- OffsetTime combines LocalTime with a ZoneOffset
```

### Class `ZoneId` và `ZoneOffset` {#the-zoneid-and-zoneoffset-classes}

Thế giới được chia thành các time zone, trong đó mỗi zone giữ cùng một standard time. Theo quy ước, một time zone được biểu diễn bằng số giờ chênh lệch so với Coordinated Universal Time (*UTC*). Vì Greenwich Mean Time (*GMT*) và Zulu time (*Z*) dùng trong quân đội không có offset so với *UTC*, chúng thường được dùng như những từ đồng nghĩa.

Java sử dụng cơ sở dữ liệu time zone của Internet Assigned Numbers Authority (IANA), nơi lưu lại tất cả time zone đã biết trên thế giới và được cập nhật nhiều lần mỗi năm.

Mỗi time zone có một ID, được biểu diễn bởi class `java.time.ZoneId`. Có ba loại ID:

Loại thứ nhất chỉ nêu offset so với UTC/GMT time. Chúng được biểu diễn bởi class `ZoneOffset` và gồm các chữ số bắt đầu bằng `+` hoặc `-`, ví dụ `+02:00`.

Loại thứ hai cũng nêu offset so với UTC/GMT time, nhưng kèm một trong các tiền tố sau: *UTC*, *GMT* và *UT*, ví dụ `UTC+11:00`. Chúng cũng được biểu diễn bởi class `ZoneOffset`.

Loại thứ ba dựa trên vùng (region-based). Những ID này có format *area/city*, ví dụ `Europe/London`.

Bạn có thể lấy tất cả zone ID khả dụng bằng static method:

```java
Set<String> getAvailableZoneIds()
```

Ví dụ, để in chúng ra console:

```java
ZoneId.getAvailableZoneIds().stream().forEach(System.out::println);
```

Để lấy zone ID của hệ thống của bạn, hãy dùng static method:

```java
ZoneId.systemDefault()
```

Bên trong, nó dùng `java.util.TimeZone.getDefault()` để tìm time zone mặc định và chuyển đổi nó thành một `ZoneId`.

Nếu bạn muốn tạo một `ZoneId` object cụ thể, hãy dùng method `of()`:

```java
ZoneId singaporeZoneId = ZoneId.of("Asia/Singapore");
```

Method này parse ID, tạo ra một `ZoneId` hoặc một `ZoneOffset` (class kế thừa từ `ZoneId`). Một `ZoneOffset` được trả về nếu, ví dụ, ID là `Z`, hoặc bắt đầu bằng `+` hay `-`. Ví dụ:

```java
ZoneId zoneId = ZoneId.of("Z"); // Z đại diện cho zone ID của UTC
ZoneId zoneId2 = ZoneId.of("-2"); // -02:00
```

Các quy tắc cho method này là:

- Nếu zone ID bằng `Z`, kết quả là `ZoneOffset.UTC`. Bất kỳ chữ cái nào khác sẽ throw exception.
- Nếu zone ID bắt đầu bằng `+` hoặc `-`, ID được parse như một `ZoneOffset` bằng `ZoneOffset.of(String)`.
- Nếu zone ID bằng `GMT`, `UTC` hoặc `UT` thì kết quả là một `ZoneId` với cùng ID và các quy tắc tương đương `ZoneOffset.UTC`.
- Nếu zone ID bắt đầu bằng `UTC+`, `UTC-`, `GMT+`, `GMT-`, `UT+` hoặc `UT-` thì ID được tách làm hai, với tiền tố hai hoặc ba chữ cái và phần hậu tố bắt đầu bằng dấu. Hậu tố được parse như một `ZoneOffset`. Kết quả sẽ là một `ZoneId` với tiền tố đã cho và offset ID đã được chuẩn hóa.
- Tất cả các ID khác được parse như zone ID dựa trên vùng. Nếu format không hợp lệ (nó phải khớp biểu thức `[A-Za-z][A-Za-z0-9~/._+-]+)`) hoặc không tìm thấy, một exception sẽ được throw.

Hãy nhớ rằng một `ZoneOffset` biểu diễn một offset, thường là so với UTC. Class này có nhiều constructor hơn hẳn `ZoneId`:

```java
// Offset phải nằm trong range -18 đến +18
ZoneOffset offsetHours = ZoneOffset.ofHours(1);
// Range là -18 đến +18 cho hours và 0 đến ± 59 cho minutes
// Nếu hours âm thì minutes phải âm hoặc bằng zero
ZoneOffset offsetHrMin = ZoneOffset.ofHoursMinutes(1, 30);
// Range là -18 đến +18 cho hours và 0 đến ± 59 cho mins và secs
// Nếu hours âm thì mins và secs phải âm hoặc bằng zero
ZoneOffset offsetHrMinSe = ZoneOffset.ofHoursMinutesSeconds(1, 30, 0);
// Offset phải nằm trong range -18:00 đến +18:00
// Tương ứng với -64800 đến +64800
ZoneOffset offsetTotalSeconds = ZoneOffset.ofTotalSeconds(3600);
// Range phải từ +18:00 đến -18:00
ZoneOffset offset = ZoneOffset.of("+01:30:00");
```

Các format được method `of()` chấp nhận là:

- *Z (cho UTC)*
- *+h*
- *+hh*
- *+hh:mm*
- *-hh:mm*
- *+hhmm*
- *-hhmm*
- *+hh:mm:ss*
- *-hh:mm:ss*
- *+hhmmss*
- *-hhmmss*

Nếu bạn truyền một format không hợp lệ hoặc một giá trị ngoài phạm vi cho bất kỳ method nào trong số này, một exception sẽ được throw.

Để lấy giá trị của offset, bạn có thể dùng:

```java
// Lấy offset dưới dạng int
int offsetInt = offset.get(ChronoField.OFFSET_SECONDS);
// Lấy offset dưới dạng long
long offsetLong= offset.getLong(ChronoField.OFFSET_SECONDS);
// Lấy offset theo seconds
int offsetSeconds = offset.getTotalSeconds();
```

`ChronoField.OFFSET_SECONDS` là giá trị duy nhất được chấp nhận của `ChronoField`, nên ba câu lệnh trên trả về cùng một kết quả. Các giá trị khác sẽ throw exception.

Dù sao, khi đã có một `ZoneId` object, bạn có thể dùng nó để tạo một instance `ZonedDateTime`.


### Class `ZonedDateTime` {#the-zoneddatetime-class}

Một object `java.time.ZonedDateTime` biểu diễn một điểm trong thời gian gắn với một time zone.

Một object `ZonedDateTime` gồm ba phần:

- Một date
- Một time
- Một time zone

Điều này có nghĩa là nó lưu tất cả field date và time với độ chính xác đến nanosecond, cùng một time zone kèm zone offset.

Ví dụ:
```
2025-08-31 T08:45:20.000 +02:00[Africa/Cairo]
```

Trong đó các phần như sau:

| Date | Time | Offset | Time zone |
|------|------|--------|-----------|
| `2025-08-31` | `T08:45:20.000` | `+02:00` | `[Africa/Cairo]` |

Khi đã có một object `ZoneId`, bạn có thể kết hợp nó với một `LocalDate`, một `LocalDateTime`, hoặc một `Instant` để chuyển thành `ZonedDateTime`:

```java
ZoneId australiaZone = ZoneId.of("Australia/Victoria");

LocalDate date = LocalDate.of(2020, 7, 3);
ZonedDateTime zonedDate = date.atStartOfDay(australiaZone);

LocalDateTime dateTime = LocalDateTime.of(2020, 7, 3, 9, 0);
ZonedDateTime zonedDateTime = dateTime.atZone(australiaZone);

Instant instant = Instant.now();
ZonedDateTime zonedInstant = instant.atZone(australiaZone);
```

Hoặc dùng method `of`:

```java
ZonedDateTime zonedDateTime2 = 
    ZonedDateTime.of(LocalDate.now(), LocalTime.now(), australiaZone);
ZonedDateTime zonedDateTime3 = 
    ZonedDateTime.of(LocalDateTime.now(), australiaZone);
ZonedDateTime zonedDateTime4 = 
    ZonedDateTime.ofInstant(Instant.now(), australiaZone);
// year, month, day, hours, minutes, seconds, nanoseconds, zoneId
ZonedDateTime zonedDateTime5 = 
    ZonedDateTime.of(2025, 1, 30, 13, 59, 59, 999, australiaZone);
```

Bạn cũng có thể lấy date/time hiện tại từ system clock theo time zone mặc định bằng:

```java
ZonedDateTime now = ZonedDateTime.now();
```

Từ một `ZonedDateTime` bạn có thể lấy `LocalDate`, `LocalTime`, hoặc một `LocalDateTime` (không có phần time zone) bằng:

```java
LocalDate currentDate = now.toLocalDate();
LocalTime currentTime = now.toLocalTime();
LocalDateTime currentDateTime = now.toLocalDateTime();
```

`ZonedDateTime` cũng có hầu hết các method của `LocalDateTime` mà chúng ta đã xem ở phần trước:

```java
// Để lấy giá trị của một field được chỉ định
int day = now.getDayOfMonth();
int dayYear = now.getDayOfYear();
int nanos = now.getNano();
Month monthEnum = now.getMonth();
int year = now.get(ChronoField.YEAR);
long micro = now.getLong(ChronoField.MICRO_OF_DAY);
// Đây là API mới, lấy zone offset như "-03:00"
ZoneOffset offset = now.getOffset();
// Để tạo một instance khác
ZonedDateTime zdt1 = now.with(ChronoField.HOUR_OF_DAY, 10);
ZonedDateTime zdt2 = now.withSecond(49);
// Vì các method này trả về một instance mới, chúng ta có thể chain chúng!
ZonedDateTime zdt3 = now.withYear(2023).withMonth(12);

// Hai method sau đây là đặc trưng riêng của ZonedDateTime
// Trả về một bản copy của date/time với zone khác, giữ nguyên instant
ZonedDateTime zdt4 = now.withZoneSameInstant(australiaZone);
// Trả về một bản copy của date/time này với time zone khác,
// giữ nguyên local date/time nếu nó hợp lệ với time zone mới
ZonedDateTime zdt5 = now.withZoneSameLocal(australiaZone);

// Phép cộng
ZonedDateTime zdt6 = now.plusDays(4);
ZonedDateTime zdt7 = now.plusWeeks(3);
ZonedDateTime zdt8 = now.plus(2, ChronoUnit.HOURS);

// Phép trừ
ZonedDateTime zdt9 = now.minusMinutes(20);
ZonedDateTime zdt10 = now.minusNanos(99999);
ZonedDateTime zdt11 = now.minus(10, ChronoUnit.SECONDS);
```

Method `toString()` trả về date/time theo định dạng của một `LocalDateTime`, theo sau là một `ZoneOffset`, và tùy chọn thêm một `ZoneId` nếu nó khác với offset, đồng thời bỏ qua những phần có giá trị bằng không:

```java
// In ra 2024-09-19T00:30Z
System.out.println(
    ZonedDateTime.of(2024, 9, 19, 0, 30, 0, 0, ZoneId.of("Z")));
// In ra, ví dụ, 2024-06-17T19:48:39.113332-04:00[America/Montreal]
System.out.println(
    ZonedDateTime.now(ZoneId.of("America/Montreal")));
```


### Daylight Saving {#daylight-savings}

Nhiều quốc gia trên thế giới áp dụng cái được gọi là Daylight Saving Time (DST), tức việc vặn đồng hồ tiến thêm một giờ khi daylight saving time bắt đầu, thường là vào mùa xuân nhưng đôi khi vào cuối mùa đông hoặc đầu mùa thu, tùy theo khu vực.

Khi daylight saving time kết thúc, đồng hồ được lùi lại một giờ. Việc này nhằm tận dụng tốt hơn ánh sáng tự nhiên.

`ZonedDateTime` nhận biết đầy đủ về DST.

Ví dụ, hãy lấy một quốc gia tuân thủ đầy đủ DST, như Ý (UTC+1 theo giờ chuẩn, UTC+2 vào daylight saving time).

Năm 2023, DST bắt đầu ở Ý vào ngày 26 tháng 3 và kết thúc vào ngày 29 tháng 10. Điều này có nghĩa là vào:

*Ngày 26 tháng 3 năm 2023 lúc **2:00:00** A.M., đồng hồ được vặn **tiến** 1 giờ thành*  
*ngày 26 tháng 3 năm 2023 lúc **3:00:00** A.M. theo giờ ban ngày địa phương*  
(Vậy nên thời điểm như 2:30:00 A.M. ngày 26 tháng 3 năm 2023 thực ra không tồn tại!)

*Ngày 29 tháng 10 năm 2023 lúc **3:00:00** A.M., đồng hồ được vặn **lùi** 1 giờ thành*  
*ngày 29 tháng 10 năm 2023 lúc **2:00:00** A.M. theo giờ ban ngày địa phương*  
(Vậy nên thời điểm như 2:30:00 A.M. ngày 29 tháng 10 năm 2023 thực ra tồn tại hai lần!)

Nếu chúng ta tạo một instance của `LocalDateTime` với date/time này và in nó ra:

```java
LocalDateTime ldt = LocalDateTime.of(2023, 3, 26, 2, 30);
System.out.println(ldt);
```

Kết quả sẽ là:

```java
2023-03-26T02:30 // Sai
```

Nhưng nếu chúng ta tạo một instance của `ZonedDateTime` cho Ý (lưu ý rằng định dạng dùng tên thành phố, không phải tên quốc gia) và in nó ra:

```java
ZonedDateTime zdt = ZonedDateTime.of(
   2023, 3, 26, 2, 30, 0, 0, ZoneId.of("Europe/Rome"));
System.out.println(zdt);
```

Kết quả sẽ giống hệt như trong thực tế khi dùng DST:

```java
2023-03-26T03:30+02:00[Europe/Rome] // Đúng
```

Nhưng hãy cẩn thận. Chúng ta phải dùng một `ZoneId` theo vùng (regional), `ZoneOffset` sẽ không làm được điều đó vì class này không có thông tin zone rules để tính đến DST:

```java
ZonedDateTime zdt1 = ZonedDateTime.of(
   2023, 3, 26, 2, 30, 0, 0, ZoneOffset.ofHours(2));
System.out.println(zdt1);

ZonedDateTime zdt2 = ZonedDateTime.of(
   2023, 3, 26, 2, 30, 0, 0, ZoneId.of("UTC+2"));
System.out.println(zdt2);
```

Kết quả sẽ là:

```java
2023-03-26T02:30+02:00              // Sai
2023-03-26T02:30+02:00[UTC+02:00]   // Sai
```

Khi chúng ta tạo một instance của `ZonedDateTime` cho Ý, chúng ta phải cộng thêm một giờ để thấy được hiệu ứng:

```java
ZonedDateTime zdt3 = ZonedDateTime.of(
   2023, 10, 29, 2, 30, 0, 0, ZoneId.of("Europe/Rome"));
System.out.println(zdt3);

ZonedDateTime zdt4 = zdt3.plusHours(1);
System.out.println(zdt4);
```

Kết quả sẽ là:

```java
2023-10-29T02:30+02:00[Europe/Rome]
2023-10-29T02:30+01:00[Europe/Rome]
```

Nếu không thì chúng ta sẽ tạo `ZonedDateTime` tại 3:00 theo giờ mới:
```java
ZonedDateTime zdt5 = ZonedDateTime.of(
        2023, 10, 29, 3, 30, 0, 0, ZoneId.of("Europe/Rome"));
System.out.println(zdt5); // In ra 2023-10-29T03:30+01:00[Europe/Rome]
```


Chúng ta cũng cần cẩn thận khi điều chỉnh thời gian vượt qua ranh giới DST bằng các method `plus()` và `minus()` nhận một implementation của `TemporalAmount`, nói cách khác là một `Period` hoặc một `Duration`. Lý do là cả hai xử lý daylight saving time khác nhau.

Xét một giờ trước khi DST bắt đầu ở Ý:

```java
ZonedDateTime zdt6 = ZonedDateTime.of(
   2023, 3, 26, 1, 0, 0, 0, ZoneId.of("Europe/Rome"));
```

Khi chúng ta cộng một `Duration` một ngày:

```java
System.out.println(zdt6.plus(Duration.ofDays(1)));
```

Kết quả là:

```java
2023-03-27T02:00+02:00[Europe/Rome]
```

Khi chúng ta cộng một `Period` một ngày:

```java
System.out.println(zdt6.plus(Period.ofDays(1)));
```

Kết quả là:

```java
2023-03-27T01:00+02:00[Europe/Rome]
```

Lý do là `Period` cộng một date mang tính *khái niệm* (conceptual), còn `Duration` cộng *chính xác* một ngày (24 giờ hay 86.400 giây), và khi nó vượt qua ranh giới DST thì một giờ được cộng thêm, khiến thời gian cuối cùng là *02:00* thay vì *01:00*.


### Class `OffsetDateTime` và `OffsetTime` {#the-offsetdatetime-and-offsettime-classes}

`OffsetDateTime` biểu diễn một object chứa thông tin date/time và một offset so với UTC, ví dụ `2025-01-01T11:30-06:00`.

Bạn có thể nghĩ `Instant`, `OffsetDateTime` và `ZonedDateTime` rất giống nhau, xét cho cùng thì cả ba đều lưu date và time với độ chính xác đến nanosecond. Tuy nhiên, có những khác biệt tinh tế nhưng quan trọng:

- `Instant` biểu diễn một điểm trong thời gian theo time zone UTC.
- `OffsetDateTime` biểu diễn một điểm trong thời gian kèm một offset (bất kỳ offset nào).
- `ZonedDateTime` biểu diễn một điểm trong thời gian theo một time zone (bất kỳ time zone nào), bổ sung đầy đủ các time zone rules như điều chỉnh daylight saving time.

`OffsetTime` biểu diễn một time kèm offset so với UTC, ví dụ `11:30-06:00`. Cách phổ biến để tạo instance của các class này là:

```java
OffsetDateTime odt = OffsetDateTime.of(
    LocalDateTime.now(), ZoneOffset.of("+03:00"));
OffsetTime ot = OffsetTime.of(
    LocalTime.now(), ZoneOffset.of("-08:00"));

System.out.println(odt);
System.out.println(ot);
```

Nếu bạn chạy ví dụ trên, output sẽ tương tự như sau:
```
2024-06-17T19:19:32.645941+03:00
19:19:32.648413-08:00
```

Cả hai class có gần như toàn bộ method giống các class tương ứng là `LocalDateTime`, `ZonedDateTime` và `LocalTime`. Với một offset so với UTC và không có biến thiên về time zone, chúng luôn biểu diễn một instant chính xác trong thời gian, điều này có thể phù hợp hơn với một số loại ứng dụng (tài liệu Java khuyến nghị dùng `OffsetDateTime` khi giao tiếp với database hoặc trong network protocol).


## Parsing và Formatting {#parsing-and-formatting}

`java.time.format.DateTimeFormatter` là class dùng để parsing và formatting date. Nó có thể được dùng theo hai cách:

- Các class date/time (được biểu diễn bằng `T`) gồm `LocalDate`, `LocalTime`, `LocalDateTime`, `ZonedDateTime` và `OffsetDateTime` đều có ba method sau: 

  ```java
  // Format date/time object bằng formatter được chỉ định
  String format(DateTimeFormatter formatter)

  // Lấy một instance của date/time object (kiểu T) từ một string với format mặc định
  static T parse(CharSequence text)

  // Lấy một instance của date/time object (kiểu T) từ một string bằng formatter cụ thể
  static T parse(CharSequence text, DateTimeFormatter formatter)
  ```

- `DateTimeFormatter` có hai method sau: 

  ```java
  // Format một date/time object bằng formatter instance
  String format(TemporalAccessor temporal)

  // Parse text để tạo ra một temporal object
  TemporalAccessor parse(CharSequence text)
  ```

Tất cả method format đều throw runtime exception `java.time.DateTimeException`.

Tất cả method parse đều throw runtime exception `java.time.format.DateTimeParseException`.

`DateTimeFormatter` cung cấp ba cách để format các object date/time:

- Predefined formatter
- Locale-specific formatter
- Formatter với custom pattern

**Predefined Formatter**

| Formatter | Mô tả | Ví dụ |

```java
LocalDate ldt = LocalDate.of(2025, 1, 20);
```

```java
System.out.println(DateTimeFormatter.ISO_DATE.format(ldt));
System.out.println(ldt.format(DateTimeFormatter.ISO_DATE));
```

Output sẽ là:

```java
2025-01-20
2025-01-20
```

Đây là ví dụ dùng một localized style:

```java
DateTimeFormatter formatter = DateTimeFormatter.ofLocalizedDate(FormatStyle.SHORT);
// Với locale hiện tại
System.out.println(formatter.format(ldt));
System.out.println(ldt.format(formatter));
// Với một locale khác
System.out.println(formatter.withLocale(Locale.GERMAN).format(ldt));
```

Một output có thể là:

```java
1/20/25
1/20/25
20.01.25
```

Và đây là ví dụ dùng một custom pattern:

```java
DateTimeFormatter formatter = DateTimeFormatter.ofPattern("QQQQ Y");
// Với locale hiện tại

System.out.println(ldt.format(formatter));
// Với một locale khác
System.out.println(formatter.withLocale(Locale.GERMAN).format(ldt));
```

Một output có thể là:

```java
1st quarter 2025
1st quarter 2025
1. Quartal 2025
```

Nếu formatter dùng thông tin không có sẵn, một `DateTimeException` sẽ được throw. Ví dụ, dùng `DateTimeFormatter.ISO_OFFSET_DATE` với một instance `LocalDate` (nó không có thông tin offset).

Để parse một giá trị date và/hoặc time từ một string, hãy dùng một trong các method `parse`. Ví dụ:

```java
// Format theo ISO-8601
String dateTimeStr1 = "2025-06-29T14:45:30";
// Format tùy chỉnh
String dateTimeStr2 = "2025/06/29 14:45:30";
LocalDateTime ldt = LocalDateTime.parse(dateTimeStr1);
// Dùng DateTimeFormatter
DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy/MM/dd HH:mm:ss");
// DateTimeFormatter trả về một TemporalAccessor instance
TemporalAccessor ta = formatter.parse(dateTimeStr2);
// LocalDateTime trả về một instance cùng kiểu
ldt = LocalDateTime.parse(dateTimeStr2, formatter);
```

Phiên bản `parse()` của các object date/time nhận một string theo định dạng ISO-8601, cụ thể là:

| Class | Format | Ví dụ |
|-------|--------|---------|
| `LocalDate` | `uuuu-MM-dd` | *2024-12-03* |
| `LocalTime` | `HH:mm:ss` | *10:15* |
| `LocalDateTime` | `uuuu-MM-dd'T'HH:mm:ss` | *2024-12-03T10:15:30* |
| `ZonedDateTime` | `uuuu-MM-dd'T'HH:mm:ssXXXXX[VV]` | *2023-12-03T10:15:30+01:00[Europe/Paris]* |
| `OffsetDateTime` | `uuuu-MM-dd'T'HH:mm:ssXXXXX` | *2023-12-03T10:15:30+01:00* |
| `OffsetTime` | `HH:mm:ssXXXXX` | *10:15:30+01:00* |

Nếu formatter dùng thông tin không có sẵn hoặc nếu pattern của format không hợp lệ, một `DateTimeParseException` sẽ được throw.

Trong chương [Localization](ch15.html#the-datetimeformatter-class), chúng ta sẽ xem lại class `DateTimeFormatter`, tập trung vào ứng dụng của nó trong localization.


## Những điểm chính {#key-points}
- `LocalDate`, `LocalTime`, `LocalDateTime`, `Instant`, `Period` và `Duration` là những class cốt lõi của Date/Time API mới trong Java, nằm trong package `java.time`. Chúng immutable, thread-safe, và ngoại trừ `Instant`, chúng không lưu trữ hay biểu diễn time zone.

- `LocalDate`, `LocalTime`, `LocalDateTime` và `Instant` implement interface `java.time.temporal.Temporal`, nên chúng đều có các method tương tự nhau. Trong khi đó `Period` và `Duration` implement interface `java.time.temporal.TemporalAmount`, điều này cũng khiến chúng rất giống nhau.

- `LocalDate` biểu diễn một date với thông tin year, month và day of the month. Bạn có thể tạo một instance bằng:
  ```java
  LocalDate.of(2025, 8, 1);
  ```

- Các giá trị `ChronoField` hợp lệ để dùng với method `get()` là: `DAY_OF_WEEK, ALIGNED_DAY_OF_WEEK_IN_MONTH, ALIGNED_DAY_OF_WEEK_IN_YEAR, DAY_OF_MONTH, DAY_OF_YEAR, EPOCH_DAY, ALIGNED_WEEK_OF_MONTH, ALIGNED_WEEK_OF_YEAR, MONTH_OF_YEAR, PROLEPTIC_MONTH, YEAR_OF_ERA, YEAR,` và `ERA`.

- Các giá trị `ChronoUnits` hợp lệ để dùng với các method `plus()` và `minus()` là: `DAYS, WEEKS, MONTHS, YEARS, DECADES, CENTURIES, MILLENNIA,` và `ERAS`.

- `LocalTime` biểu diễn một time với thông tin hour, minutes, seconds và nanoseconds. Bạn có thể tạo một instance bằng:
  ```java
  LocalTime.of(14, 20, 50, 99999);
  ```

- Các giá trị `ChronoField` hợp lệ để dùng với method `get()` là: `NANO_OF_SECOND, NANO_OF_DAY, MICRO_OF_SECOND, MICRO_OF_DAY, MILLI_OF_SECOND, MILLI_OF_DAY, SECOND_OF_MINUTE, SECOND_OF_DAY, MINUTE_OF_HOUR, MINUTE_OF_DAY, HOUR_OF_AMPM, CLOCK_HOUR_OF_AMPM, HOUR_OF_DAY, CLOCK_HOUR_OF_DAY,` và `AMPM_OF_DAY`.

- Các giá trị `ChronoUnits` hợp lệ để dùng với các method `plus()` và `minus()` là: `NANOS, MICROS, MILLIS, SECONDS, MINUTES, HOURS,` và `HALF_DAYS`.

- `LocalDateTime` là sự kết hợp của `LocalDate` và `LocalTime`. Bạn có thể tạo một instance bằng:
  ```java
  LocalDateTime.of(2025, 8, 1, 14, 20, 50, 99999);
  ```

- Các giá trị `ChronoField` và `ChronoUnits` hợp lệ là sự kết hợp những giá trị được dùng cho `LocalDate` và `LocalTime`.

- `Instant` biểu diễn một điểm thời gian duy nhất tính bằng seconds và nanoseconds. Bạn có thể tạo một instance bằng:
  ```java
  Instant.ofEpochSecond(134556767, 999999999);
  ```

- Các giá trị `ChronoField` hợp lệ để dùng với method `get()` là: `NANO_OF_SECOND, MICRO_OF_SECOND, MILLI_OF_SECOND,` và `INSTANT_SECONDS`.

- Các giá trị `ChronoUnit` hợp lệ để dùng với các method `plus()` và `minus()` là: `NANOS, MICROS, MILLIS, SECONDS, MINUTES, HOURS, HALF_DAYS,` và `DAYS`.

- `Period` biểu diễn một khoảng thời gian theo years, months và days. Bạn có thể tạo một instance bằng:
  ```java
  Period.of(3, 12, 30);
  ```

- Các giá trị `ChronoUnits` hợp lệ để dùng với method `get()` là: `DAYS, MONTHS, YEARS`.

- `Duration` biểu diễn một khoảng thời gian theo seconds và nanoseconds. Bạn có thể tạo một instance bằng:
  ```java
  Duration.ofSeconds(50, 999999);
  ```

- Các giá trị `ChronoUnits` hợp lệ để dùng với method `of()` là: `NANOS, MICROS, MILLIS, SECONDS, MINUTES, HOURS, HALF_DAYS,` và `DAYS`. Với method `get()`, chỉ `NANOS` và `SECONDS` là hợp lệ.

- `ZoneId`, `ZoneOffset`, `ZonedDateTime`, `OffsetDateTime` và `OffsetTime` là các class của Java Date/Time API lưu thông tin về time zone và time offset. Chúng nằm trong package `java.time` và immutable.

- Mỗi time zone có một ID, được biểu diễn bởi class `ZoneId`. Có ba loại ID.

- Loại thứ nhất chỉ nêu offset so với giờ UTC/GMT. Chúng được biểu diễn bởi class `ZoneOffset` và gồm các chữ số bắt đầu bằng `+` hoặc `-`, ví dụ `+02:00`.

- Loại thứ hai cũng nêu offset so với giờ UTC/GMT, nhưng kèm một trong các prefix sau: UTC, GMT và UT, ví dụ `UTC+11:00`. Chúng cũng được biểu diễn bởi class `ZoneOffset`.

- Loại thứ ba dựa trên vùng (region based). Những ID này có định dạng *area/city*, ví dụ *Europe/London*.

- Nếu bạn muốn tạo một object `ZoneId` cụ thể, hãy dùng method `of`:
  ```java
  ZoneId.of("Asia/Singapore");
  ZoneId.of("+3");
  ZoneId.of("Z");
  ```

- Method đầu tiên trong các method trên tạo ra một object kiểu `ZoneId`. Hai method còn lại tạo ra object kiểu `ZoneOffset`.

- Một object `java.time.ZonedDateTime` biểu diễn một điểm trong thời gian gắn với một time zone.

- Một object `ZonedDateTime` gồm ba phần: một date, một time và một time zone. Nó có thể được tạo bằng một trong hai cách:
  ```java
  ZoneId australiaZone = ZoneId.of("Australia/Victoria");
  ZonedDateTime zonedDateTime5 =
      ZonedDateTime.of(2025, 1, 30, 13, 59, 59, 999, australiaZone);
  ```

- Hoặc bằng cách dùng `LocalDate`, `LocalTime`, `LocalDateTime`, hoặc `Instant` cộng với `ZoneId`.

- Nếu chúng ta tạo một instance của `ZonedDateTime` cho một vùng có tuân thủ Daylight Saving Time (DST), instance đó sẽ hỗ trợ nó, tiến đồng hồ thêm một giờ khi DST bắt đầu và lùi lại khi DST kết thúc.

- `Period` và `Duration` khác nhau trong cách xử lý DST.

- `Period` cộng một ngày mang tính khái niệm (conceptual) vào một date, còn `Duration` cộng một ngày chính xác vào một date mà không tính đến DST.

- `OffsetDateTime` biểu diễn một object chứa thông tin date/time và một offset so với UTC, ví dụ `2025-01-01T11:30-06:00`.

- `OffsetTime` biểu diễn một time kèm offset so với UTC, ví dụ `11:30-06:00`.

- `java.time.format.DateTimeFormatter` là một class dùng để parsing và formatting date. Nó có thể được dùng theo hai cách:
    - Các class date/time `LocalDate`, `LocalTime`, `LocalDateTime`, `ZonedDateTime`, `OffsetDateTime` đều có các method:
      ```java
      String format(DateTimeFormatter formatter)
      static T parse(CharSequence text)
      static T parse(CharSequence text, DateTimeFormatter formatter)
      ```
    - `DateTimeFormatter` có hai method sau:
      ```java
      String format(TemporalAccessor temporal)
      TemporalAccessor parse(CharSequence text)
      ```

- Tất cả method `format` đều throw runtime exception `java.time.DateTimeException`, còn tất cả method `parse` đều throw runtime exception `java.time.format.DateTimeParseException`.
