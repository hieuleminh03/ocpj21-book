## Tìm hiểu các kiểu dữ liệu {#understanding-data-types}

Có hai nhóm kiểu dữ liệu chính: primitive và reference:
```
┌───────────────────────────────────────────────────┐
│                  Java Data Types                  │
│                         │                         │
│          ┌──────────────┴──────────────┐          │
│          │                             │          │
│    Primitive Types               Reference Types  │
│          │                             │          │
│  ┌───────┴───────┐             ┌───────┴───────┐  │
│  │ byte          │             │ Classes       │  │
│  │ short         │             │ Interfaces    │  │
│  │ int           │             │ Arrays        │  │
│  │ long          │             │ Enums         │  │
│  │ float         │             └───────────────┘  │
│  │ double        │                                │
│  │ boolean       │                                │
│  │ char          │                                │
│  └───────────────┘                                │
└───────────────────────────────────────────────────┘
```

Hãy xem xét từng nhóm chi tiết hơn.

### Primitive type {#primitive-types}
Java là ngôn ngữ statically typed, nghĩa là mọi biến đều phải được khai báo trước khi sử dụng. Kiểu của biến quyết định những giá trị mà nó có thể chứa và những phép toán có thể thực hiện trên nó.

Trong Java, primitive type là những kiểu dữ liệu cơ bản nhất. Chúng không phải object và không thuộc về class nào. Thay vào đó, chúng được định nghĩa bởi chính ngôn ngữ. Primitive type được dùng để lưu những giá trị đơn giản như số nguyên, số floating point, boolean và ký tự.

Primitive type được lưu trực tiếp trong bộ nhớ và được truy cập bằng giá trị của chúng. Điều này trái ngược với reference type (object), vốn được truy cập thông qua reference. Nhờ lưu trực tiếp như vậy, primitive nhanh hơn và tốn ít bộ nhớ hơn object.

Java có tám kiểu dữ liệu primitive:

| Kiểu      |  Kích thước (bit)  | Giá trị nhỏ nhất            | Giá trị lớn nhất           | Giá trị mặc định |
|-----------|---------------|----------------------------|---------------------------|---------|
| `byte`    | 8             | -128                       | 127                       | 0       |  
| `short`   | 16            | -32,768                    | 32,767                    | 0       |
| `int`     | 32            | -2,147,483,648             | 2,147,483,647             | 0       |  
| `long`    | 64            | -9,223,372,036,854,775,808 | 9,223,372,036,854,775,807 | 0L      |
| `float`   | 32            | 1.4E-45                    | 3.4028235E38              | 0.0f    |
| `double`  | 64            | 4.9E-324                   | 1.7976931348623157E308    | 0.0d    | 
| `boolean` | n/a           | n/a                        | n/a                       | false   |
| `char`    | 16            | '\u0000' (0)               | '\uffff' (65,535)         | '\u0000'|

Hãy phân tích kỹ hơn. 

Các kiểu số nguyên (`byte`, `short`, `int`, `long`) dùng cho giá trị số nguyên. Chúng khác nhau ở phạm vi giá trị có thể chứa. `byte` có `8` bit và chứa được giá trị từ `-128` đến `127`. `short` có `16` bit và chứa được giá trị từ `-32,768` đến `32,767`. `int` có `32` bit và chứa được giá trị từ `-2,147,483,648` đến `2,147,483,647`. Còn `long` có 64 bit, chứa được giá trị từ `-9,223,372,036,854,775,808` đến `9,223,372,036,854,775,807`.

Bạn có thể thắc mắc: chẳng phải mọi số trong Java đều được xử lý giống nhau sao? Tại sao chúng ta lại cần nhiều kiểu khác nhau như `int`, `long`, v.v.? Lý do là hiệu quả và mức sử dụng bộ nhớ. Nếu bạn biết giá trị của mình luôn nằm trong một phạm vi nhất định, bạn có thể dùng kiểu nhỏ hơn để tiết kiệm bộ nhớ. Ví dụ, một `int` chiếm một nửa bộ nhớ so với một `long`. Trong các ứng dụng quy mô lớn với lượng dữ liệu khổng lồ, điều này có thể tạo ra khác biệt lớn.

Các kiểu floating point (`float` và `double`) dùng cho số có dấu thập phân. `float` có 32 bit và `double` có 64 bit. Nhờ đó `double` có độ chính xác cao hơn `float` rất nhiều. Nhiều lập trình viên chọn dùng `double` cho mọi giá trị thập phân để tránh các vấn đề về độ chính xác, nhưng trong một số tình huống, có thể dùng `float` để tiết kiệm bộ nhớ nếu không cần độ chính xác cao.

Trong Java, kích thước của boolean không được Java Language Specification định nghĩa tường minh. Kích thước bộ nhớ thực tế của một biến boolean phụ thuộc vào implementation và thay đổi tùy theo Java Virtual Machine đang dùng. Tuy nhiên, với kỳ thi, bạn chỉ cần biết rằng kiểu `boolean` chỉ có hai giá trị khả dĩ: `true` và `false`, và nó được dùng cho logic điều kiện.

Kiểu `char` dùng cho một ký tự đơn. Nó dùng 16 bit vì sử dụng Unicode encoding, cho phép biểu diễn rất nhiều ký tự từ các ngôn ngữ khác nhau.

Một điều quan trọng cần nhớ là giá trị mặc định chỉ áp dụng cho field. Ngược lại, local variable phải được khởi tạo tường minh trước khi dùng; nếu không, code của bạn sẽ không compile được.

Bạn có thể gán giá trị cho biến bằng literal. Ngoài ký pháp thập phân tiêu chuẩn, Java còn cho phép gán integer literal bằng ký pháp thập lục phân (tiền tố `0x` hoặc `0X`), bát phân (tiền tố `0`) và nhị phân (tiền tố `0b` hoặc `0B`).

Ví dụ:
```java
// Decimal notation
int decimalNum = 42;

// Hexadecimal notation
int hexNum = 0x2A; // Equivalent to decimal 42
        
// Octal notation
int octalNum = 052; // Equivalent to decimal 42
        
// Binary notation
int binaryNum = 0b101010; // Equivalent to decimal 42
```

Khi gán literal cho biến, điều quan trọng cần lưu ý là kiểu của literal phải khớp với kiểu của biến. Nếu không khớp, bạn có thể cần dùng hậu tố (suffix) để chỉ định kiểu của literal.

Với integer literal:
- Literal `long` dùng hậu tố `L` hoặc `l`: `long longNum = 1000L;`
- Literal `int` không cần hậu tố, vì `int` là kiểu mặc định cho số nguyên: `int intNum = 1000;`

Với floating point literal:
- Literal `float` dùng hậu tố `F` hoặc `f`: `float floatNum = 3.14f;`
- Literal `double` dùng hậu tố `D` hoặc `d`, dù hậu tố này là tùy chọn vì double là kiểu mặc định cho literal thập phân: `double doubleNum = 3.14D;`

Dưới đây là một số ví dụ:

```java
long longNum = 1000L; // Suffix L is required
float floatNum = 3.14f; // Suffix f is required
double doubleNum1 = 3.14; // Suffix d is optional
double doubleNum2 = 3.14d; // Suffix d is optional 
```

Nếu bạn không dùng đúng hậu tố, bạn có thể gặp compile-time error. Ví dụ:

```java
byte longNum = 1000; // Compilation error: integer literal is too large
float floatNum = 3.14; // Compilation error: incompatible types
```

Trong những trường hợp này, Java coi literal lần lượt thuộc kiểu `int` hoặc `double`, và không thể gán trực tiếp cho biến `byte` hoặc `float` nếu không có cast tường minh.

Bạn cũng có thể dùng dấu gạch dưới trong numeric literal để dễ đọc hơn, chẳng hạn `1_000_000`. Dưới đây là một số ví dụ minh họa việc dùng dấu gạch dưới trong numeric literal:
```java
// Valid use of underscores
int million = 1_000_000;
long creditCardNumber = 1234_5678_9012_3456L;
float pi = 3.14_15F;
double avogadro = 6.022_140_857e23;
```

Tuy nhiên, có một số hạn chế. Bạn không thể đặt dấu gạch dưới:
- Ở đầu hoặc cuối một số
- Liền kề dấu thập phân trong floating point literal
- Trước hậu tố `F` hoặc `L`
- Ở vị trí mà một chuỗi chữ số được mong đợi

Dưới đây là thêm một số ví dụ về vị trí đặt dấu gạch dưới không hợp lệ:
```java
// Invalid use of underscores
int x1 = _1000; // Compilation error: illegal underscore
int x2 = 1000_; // Compilation error: illegal underscore
float y1 = 3_.14F; // Compilation error: illegal underscore
float y2 = 3._14F; // Compilation error: illegal underscore

float y3 = 3.14__F; // Compilation error: consecutive underscores
long z1 = 1000_L; // Compilation error: underscore before L suffix

int x3 = 0_x42; // Compilation error: underscore in position where digits are expected
int x4 = 0b_101010; // Compilation error: underscore in position where digits are expected
```

Những quy tắc này tồn tại để tránh sự mơ hồ và đảm bảo việc dùng dấu gạch dưới không xung đột với các phần khác của cú pháp ngôn ngữ.

### Reference type {#reference-types}
Ở phần trước, chúng ta đã tìm hiểu khái niệm primitive type trong Java. Tuy nhiên, như đã biết, Java là ngôn ngữ hướng đối tượng và gần như mọi thứ đều được xem là object. Trong khi primitive cung cấp những khối xây dựng cơ bản, reference type cho phép chúng ta làm việc với object và tận dụng đầy đủ các tính năng hướng đối tượng của Java.

Vậy chính xác reference type là gì? Khác với primitive, vốn giữ giá trị trực tiếp, reference type lưu địa chỉ bộ nhớ nơi object thực sự nằm. Nói cách khác, một reference variable *tham chiếu* tới vị trí của object thay vì chứa chính object đó.

```java
String myString = "Hello"; // Reference type
```

Trong ví dụ này, `myString` là một reference variable kiểu `String`. Nó không giữ giá trị string thực sự mà giữ reference tới vị trí bộ nhớ nơi object `"Hello"` được lưu.

Điều này trái ngược với cách primitive type hoạt động:

```java
int myNumber = 42; // Primitive type 
```

Ở đây, `myNumber` giữ trực tiếp giá trị số nguyên `42` thay vì tham chiếu tới một object.

Nhưng nếu chúng ta muốn xử lý primitive như object thì sao? Đây là lúc wrapper class phát huy tác dụng. Java cung cấp một bộ wrapper class tương ứng với từng primitive type, cho phép chúng được dùng trong những tình huống yêu cầu object:

|  Primitive Type  |  Wrapper Class  | Kế thừa từ Number |
|------------------|-----------------|----------------------|
| `boolean`        | `Boolean`       | Không                |
| `byte`           | `Byte`          | Có                   |
| `short`          | `Short`         | Có                   |
| `int`            | `Integer`       | Có                   |
| `long`           | `Long`          | Có                   |
| `float`          | `Float`         | Có                   |
| `double`         | `Double`        | Có                   |
| `char`           | `Character`     | Không                |

Mỗi primitive type có một wrapper class tương ứng, hầu hết đều kế thừa từ class `Number`. Hai class `Boolean` và `Character` là ngoại lệ vì chúng không biểu diễn giá trị số.

Wrapper class cung cấp các method để tạo instance từ nhiều dạng biểu diễn và để chuyển đổi giữa các kiểu dữ liệu khác nhau. Dưới đây là một số ví dụ:

1. Các method parse:
   - `Integer.parseInt(String s)`: Phân tích một tham số string thành số nguyên thập phân có dấu.
   - `Double.parseDouble(String s)`: Phân tích một tham số string thành số floating point độ chính xác kép (double).
   - `Boolean.parseBoolean(String s)`: Phân tích một tham số string thành giá trị boolean.

   Ví dụ:
   ```java
   int num = Integer.parseInt("42");
   double value = Double.parseDouble("3.14");
   boolean flag = Boolean.parseBoolean("true");
   ```

2. Các method chuyển đổi:
   - `Integer.valueOf(String s)`: Trả về một object `Integer` chứa giá trị của dạng biểu diễn string được chỉ định.
   - `Long.valueOf(long l)`: Trả về một object `Long` chứa giá trị primitive long được chỉ định.
   - `Double.valueOf(double d)`: Trả về một object `Double` chứa giá trị primitive double được chỉ định.

   Ví dụ:
   ```java
   Integer myInt = Integer.valueOf("100");
   Long myLong = Long.valueOf(1234567890L);
   Double myDouble = Double.valueOf(2.71828);
   ```

3. Chuyển đổi giữa các kiểu số:
   - `Integer.byteValue()`: Trả về giá trị của một `Integer` dưới dạng byte.
   - `Long.intValue()`: Trả về giá trị của một `Long` dưới dạng int.
   - `Float.doubleValue()`: Trả về giá trị của một `Float` dưới dạng double.

   Ví dụ:
   ```java
   byte myByte = myInt.byteValue();
   long myLong = myInt.longValue();
   ```

4. Các method của Character:
   - `Character.isDigit(char ch)`: Xác định xem ký tự được chỉ định có phải là chữ số không.
   - `Character.isLetter(char ch)`: Xác định xem ký tự được chỉ định có phải là chữ cái không.
   - `Character.toUpperCase(char ch)`: Chuyển tham số ký tự thành chữ hoa.

   Ví dụ:
   ```java
   char myChar = '7';
   boolean isDigit = Character.isDigit(myChar);
   boolean isLetter = Character.isLetter(myChar);
   char upperCase = Character.toUpperCase(myChar);
   ```

Lưu ý rằng các method này là `static`, cho phép bạn dùng chúng mà không cần tạo instance của wrapper class.

Đây chỉ là một vài ví dụ về các method mà wrapper class cung cấp để tạo instance và chuyển đổi giữa các dạng biểu diễn khác nhau. Mỗi wrapper class có một loạt method riêng cho primitive type tương ứng, mang lại sự linh hoạt và tiện lợi khi làm việc với các định dạng dữ liệu và phép chuyển đổi khác nhau.

Vậy wrapper class có biến primitive thành object không? Không hẳn. Wrapper class tách biệt với primitive nhưng cung cấp cách bọc primitive dưới dạng object. Điều này cho phép primitive được dùng trong những ngữ cảnh yêu cầu object, như collection hay khi dùng generics.

Để thu hẹp khoảng cách giữa primitive và wrapper class tương ứng, Java giới thiệu autoboxing và unboxing. Như đã đề cập trước đó, autoboxing là việc tự động chuyển đổi từ primitive type sang wrapper class tương ứng, còn unboxing là quá trình ngược lại:

```java
int num = 42;
Integer objNum = num; // Autoboxing
int num2 = objNum;    // Unboxing
```

Trong ví dụ này, `num` được tự động box thành object `Integer` khi gán cho `objNum`. Tương tự, `objNum` được unbox trở lại thành `int` khi gán cho `num2`. Việc này diễn ra ngầm định, giúp việc chuyển đổi qua lại giữa primitive và wrapper class trở nên thuận tiện.

Autoboxing và unboxing hoạt động với mọi primitive type và wrapper class tương ứng, không chỉ với `int` và `Integer`. Java xử lý các chuyển đổi này tự động dựa trên ngữ cảnh sử dụng.

Cần lưu ý rằng dù autoboxing và unboxing giúp code dễ đọc hơn, chúng có thể ảnh hưởng đến hiệu năng. Mỗi lần chuyển đổi giữa primitive và wrapper class đều liên quan đến việc tạo hoặc hủy một object, làm phát sinh một khoản overhead nhỏ. Trong hầu hết trường hợp, overhead này không đáng kể, nhưng có thể cộng dồn trong những tình huống nhạy cảm về hiệu năng với nhiều thao tác autoboxing/unboxing.

Một lợi thế của wrapper class là khả năng biểu diễn sự vắng mặt của giá trị bằng `null`. Trong khi primitive không thể là `null`, wrapper object thì có thể.

```java
Integer num = null;
int value = num; // NullPointerException
```

Ở đây, gán `null` cho `num` là hợp lệ vì nó là object `Integer`. Tuy nhiên, việc unbox `num` thành `int` sẽ throw `NullPointerException`. Hành vi này cho phép xử lý `null` tường minh hơn và có thể hữu ích trong những tình huống mà một biến có thể chưa được gán giá trị.

Ngoài ra, cũng cần lưu ý rằng wrapper class là immutable, nghĩa là giá trị của chúng không thể thay đổi sau khi được gán. Khi bạn thực hiện phép toán trên một wrapper object, một object mới được tạo ra với giá trị cập nhật thay vì sửa đổi object hiện có.

```java
Integer num = 42;
num++;
```

Trong ví dụ này, phép toán `++` trên `num` tạo ra một object `Integer` mới với giá trị 43 thay vì sửa đổi object ban đầu. Hành vi này đảm bảo thread safety và tránh những side effect bất ngờ khi chia sẻ wrapper object giữa nhiều phần khác nhau của chương trình.

## Toán tử (operator) {#operators}

### Giới thiệu về operator {#introducing-operators}
Operator là một ký hiệu ra lệnh cho compiler thực hiện những phép toán số học hoặc logic cụ thể. 

Java cung cấp một bộ operator phong phú để thực hiện phép toán trên biến và giá trị:
- Toán tử unary: operator tác động lên một operand duy nhất, chẳng hạn `++` để tăng giá trị hoặc `!` để phủ định boolean.
- Toán tử binary: operator tác động lên hai operand, như operator số học (`+`, `-`, `*`, `/`, `%`) và operator so sánh (`>`, `<`, `>=`, `<=`, `==`, `!=`). 
- Toán tử ternary: operator điều kiện nhận ba operand (`condition ? value_if_true : value_if_false`).
- Toán tử gán (assignment): operator dùng để gán giá trị cho biến (`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `^=`, `|=`, `<<=`, `>>=`, `>>>=`).
- Toán tử logic (logical): operator dùng để xác định logic giữa các biến hoặc giá trị (`&&`, `||`).

Nhiều lập trình viên mới học Java nhầm tưởng operator chỉ dùng cho phép toán số học. Nhưng operator còn đóng vai trò quan trọng trong việc điều khiển luồng chương trình, thực hiện phép toán logic, thao tác trên bit và hơn thế nữa. Ví dụ:

```java
int a = 10;
int b = 5;
        
// Arithmetic operator
System.out.println(a + b);  // 15 

// Comparison operator  
System.out.println(a > b);  // true

// Logical operator
System.out.println((a > b) && (a != b)); // true
```

Như bạn thấy, operator trong Java vượt xa các phép số học cơ bản.

### Độ ưu tiên toán tử (operator precedence) {#operator-precedence}

Một khái niệm quan trọng cần nắm về operator là precedence. Cũng giống như trong toán học, một số operator trong Java có độ ưu tiên cao hơn những operator khác, nghĩa là chúng được tính trước trong một biểu thức.

Chẳng hạn, xét đoạn code sau:
```java
int result = 10 + 5 * 2;
System.out.println(result);
```

Bạn có thể nghĩ `result` sẽ là `30` (`10 + 5` bằng `15`, rồi `15 * 2`). Nhưng thực tế nó in ra `20`. Đó là vì operator `*` có độ ưu tiên cao hơn `+`. Do đó `5 * 2` được tính trước, cho `10`, rồi `10` được cộng với `10` ban đầu.

Dưới đây là bảng thể hiện độ ưu tiên của operator trong Java, từ cao xuống thấp:

| Nhóm             | Operator                                        | Tính kết hợp  |
|------------------|-------------------------------------------------|---------------|
| Postfix          | `expr++`  `expr--`                              | Trái sang phải |
| Unary            | `++expr`  `--expr`  `+expr`  `-expr`  `~`  `!`  | Phải sang trái |
| Multiplicative   | `*` `/` `%`                                     | Trái sang phải |
| Additive         | `+` `-`                                         | Trái sang phải |
| Shift            | `<<` `>>` `>>>`                                 | Trái sang phải |
| Relational       | `<` `>` `<=` `>=` `instanceof`                  | Trái sang phải |
| Equality         | `==` `!=`                                       | Trái sang phải |
| Bitwise AND      | `&`                                             | Trái sang phải |
| Bitwise XOR      | `^`                                             | Trái sang phải |
| Bitwise OR       | `\|`                                            | Trái sang phải | 
| Logical AND      | `&&`                                            | Trái sang phải |
| Logical OR       | `\|\|`                                          | Trái sang phải |
| Ternary          | `? :`                                           | Phải sang trái |
| Assignment       | `=` `+=` `-=` `*=` `/=` `%=` `&=` `^=` `\|=` `<<=` `>>=` `>>>=` | Phải sang trái |

Như bảng cho thấy, hầu hết operator được tính từ trái sang phải. Vậy trong biểu thức như `a + b - c`, `a + b` diễn ra trước, rồi đến `- c`.

Nhưng operator gán và operator unary thực tế được tính từ phải sang trái. Xét đoạn code sau:

```java
int a = 10;
int b = 20;
int c = (a = 3) + (b = 5);
System.out.println(a + ", " + b + ", " + c); // 3, 5, 8
```

Ở đây, `a` được gán `3`, `b` được gán `5`, và vì phép gán được tính từ phải sang trái, các phép gán diễn ra trước phép cộng. Kết quả là `c` bằng `8` (`3 + 5`), còn `a` là `3` và `b` là `5`.

Việc tính từ phải sang trái này cho phép gán chuỗi (chained assignment), như `a = b = c = 5`. `5` được gán cho `c`, rồi kết quả đó được gán cho `b`, và cuối cùng gán cho `a`, theo thứ tự từ phải sang trái.

Có rất nhiều thứ để nhớ, và việc học thuộc toàn bộ bảng độ ưu tiên là không cần thiết. Những điểm chính là:
1. Phép postfix như `x++` diễn ra trước phép prefix như `++x`. 
2. Phép nhân chia (`*`, `/`, `%`) diễn ra trước phép cộng trừ (`+`, `-`).
3. Phép bitwise (`&`, `|`, `^`) diễn ra sau phép so sánh (`>`, `==`, v.v.) nhưng trước phép logic (`&&`, `||`).
4. Phép gán được tính cuối cùng, theo thứ tự từ phải sang trái.

Khi còn nghi ngờ, luôn có thể dùng dấu ngoặc đơn để làm rõ thứ tự. Hai biểu thức `(a + b) * c` và `a + (b * c)` rõ ràng là khác nhau.

Nói chung, nên dùng ngoặc đơn mỗi khi độ ưu tiên không rõ ràng hoặc để code dễ đọc hơn. Nhưng không nên lạm dụng đến mức rối mắt. Khi đã nắm vững operator precedence, nhiều cặp ngoặc đơn trở nên không cần thiết, giúp code gọn gàng và dễ đọc hơn.

Hãy xem thêm vài ví dụ để bạn hiểu rõ hơn về operator và độ ưu tiên trong Java:

```java
int x = 10;
int y = 20;
int z = 30;

System.out.println(x + y - z);  // 10 + 20 - 30 = 0
System.out.println(x - y + z);  // 10 - 20 + 30 = 20
System.out.println(x * y / z);  // 10 * 20 / 30 = 6
System.out.println(x / y * z);  // 10 / 20 * 30 = 0
```

Trong hai câu lệnh đầu, các operator có cùng độ ưu tiên (`+` và `-`), nên chúng được tính từ trái sang phải. Trong câu lệnh thứ ba và thứ tư, `*` và `/` có độ ưu tiên cao hơn và được tính trước, từ trái sang phải, rồi kết quả mới được cộng. Ở ví dụ thứ tư, `10 / 20` bằng 0 (vì chúng ta đang dùng số nguyên).

Giờ hãy kết hợp thêm phép gán và toán tử unary:

```java
int a = 5;
int b = 10;
int c = ++a * b--;
System.out.println(a + ", " + b + ", " + c);  // 6, 9, 60
```

Ở đây, `++a` tăng `a` lên 6 trước phép nhân. Sau đó `6 * 10` cho 60, và 60 được gán cho `c`. Cuối cùng, `b--` giảm `b` xuống 9, nhưng sau phép nhân. Kết quả là `a` bằng 6, `b` bằng 9 và `c` bằng 60.

Bản chất từ phải sang trái của phép gán là điều cực kỳ quan trọng cần hiểu:

```java
int x = 2;
int y = 3;
int z = 1;
x += y -= z;
System.out.println(x + ", " + y + ", " + z);  // 4, 2, 1
```

Đầu tiên, `z` (1) được trừ khỏi `y` (3), cho 2, rồi 2 được gán trở lại cho `y`. Sau đó giá trị này (2) được cộng vào `x` (2), cho 4, và 4 được gán trở lại cho `x`. Kết quả là `x` bằng 4, `y` bằng 2, còn `z` vẫn là 1.

Operator logic và bitwise có thể làm mọi thứ phức tạp thêm:

```java
int a = 10;  // 1010 in binary
int b = 6;   // 0110 in binary

System.out.println(a & b);  // 1010 & 0110 = 0010 (2 in decimal)
System.out.println(a | b);  // 1010 | 0110 = 1110 (14 in decimal)
System.out.println(a ^ b);  // 1010 ^ 0110 = 1100 (12 in decimal)

System.out.println(a > 5 && b < 10); // true && true = true
System.out.println(a > 5 || b < 5);  // true || false = true
```

Các operator bitwise `&`, `|` và `^` thực hiện phép AND, OR và XOR trên từng bit của các số. Các operator logic `&&` và `||` thực hiện AND và OR trên các điều kiện boolean, trong đó `&&` có độ ưu tiên cao hơn.

Cuối cùng, đừng quên toán tử ternary, vốn giống như một câu lệnh `if`-`else` thu gọn:

```java
int x = 10;
int y = 20;
int max = (x > y) ? x : y;
System.out.println(max);  // 20
```

Ở đây, `(x > y)` là false, nên giá trị sau dấu hai chấm (`y`, tức 20) được gán cho `max`.

Trong các phần tiếp theo, chúng ta sẽ xem xét từng loại operator chi tiết hơn.


### Toán tử một ngôi {#unary-operators}
Toán tử một ngôi là toán tử chỉ làm việc trên một toán hạng. Bạn đã thấy một vài toán tử một ngôi hoạt động, chẳng hạn toán tử logical complement (`!`) dùng với giá trị boolean. Tuy nhiên, trong phần này, chúng ta sẽ bàn về những toán tử một ngôi chủ yếu dùng với numeric type.

#### Toán tử Complement và Negation {#complement-and-negation-operators}
Toán tử complement một ngôi (`~`), còn được gọi là toán tử bitwise complement, đảo ngược tất cả các bit trong một số, qua đó đổi mỗi 0 thành 1 và mỗi 1 thành 0. Trong Java, số nguyên được biểu diễn bằng 32 bit theo định dạng two's complement.

Với số dương, bitwise complement sẽ lật tất cả các bit, và số thu được là giá trị đảo dấu của số ban đầu trừ đi một. Điều này là vì khi đảo tất cả các bit rồi diễn giải kết quả theo two's complement, ta thu được `-(n + 1)`.

Đây là cách nó hoạt động:

Với một số dương như 5, biểu diễn nhị phân là:
```
0000 0000 0000 0000 0000 0000 0000 0101
```

Khi bạn áp dụng toán tử bitwise complement, nó lật tất cả các bit:
```
1111 1111 1111 1111 1111 1111 1111 1010
```

Theo two's complement, đây là biểu diễn của `-6`. Do đó, `~5` trong Java bằng `-6`.

Với số âm, toán tử bitwise complement cũng lật tất cả các bit. Kết quả là phiên bản dương của số ban đầu trừ đi một, bởi vì khi lật tất cả các bit của một số âm rồi diễn giải theo two's complement, ta thu được số dương tương ứng giảm đi 1.

Ví dụ, lấy -5. Theo two's complement, nó được biểu diễn như sau:
```
1111 1111 1111 1111 1111 1111 1111 1011
```

Áp dụng toán tử bitwise complement:
```
0000 0000 0000 0000 0000 0000 0000 0100
```

Số nhị phân này biểu diễn 4 trong hệ thập phân. Vậy, `~(-5)` bằng 4.

Tóm lại:
- `~n` với một số dương `n` cho kết quả `-(n + 1)`.
- `~(-n)` cho kết quả `n - 1`.

Mặt khác, toán tử negation một ngôi (`-`) dễ hiểu hơn. Toán tử này dùng để đảo dấu một giá trị số, qua đó thay đổi dấu của nó. Ví dụ, nếu `x` là 5 thì `-x` sẽ là -5.

Một hiểu lầm phổ biến là toán tử negation giống với việc lấy 0 trừ đi số đó. Dù kết quả cuối cùng có thể giống nhau, toán tử negation hoạt động khác đi bên dưới. Nó thay đổi trực tiếp bit dấu của con số thay vì thực hiện một phép trừ.

#### Toán tử Increment và Decrement {#increment-and-decrement-operators}
Java cũng cung cấp toán tử increment (`++`) và decrement (`--`), dùng để tăng hoặc giảm giá trị của một variable đi 1. Những toán tử này có thể được dùng ở dạng prefix hoặc postfix.

Đây là bảng tóm tắt các toán tử increment và decrement khác nhau:

| Toán tử | Tên                      | Mô tả                                                  | Ví dụ  |
|----------|---------------------------|--------------------------------------------------------------|----------|
| `++x`      | Toán tử prefix increment | Tăng `x` thêm 1, sau đó trả về giá trị mới của `x`           | `++x`      |
| `x++`      | Toán tử postfix increment| Trả về giá trị hiện tại của `x`, sau đó tăng `x` thêm 1       | `x++`      | 
| `--x`      | Toán tử prefix decrement | Giảm `x` đi 1, sau đó trả về giá trị mới của `x`           | `--x`      |
| `x--`      | Toán tử postfix decrement| Trả về giá trị hiện tại của `x`, sau đó giảm `x` đi 1       | `x--`      |

Một câu hỏi đặt ra là liệu bạn có thể dùng toán tử increment và decrement với giá trị boolean hay không. Câu trả lời là không. Những toán tử này chỉ áp dụng cho numeric type như `int`, `long`, `float`, `double`, v.v.

Một điểm gây nhầm lẫn khác là liệu `x++` tăng `x` trước hay sau biểu thức mà nó xuất hiện. Toán tử postfix increment (`x++`) trả về giá trị gốc của `x`, rồi sau đó mới tăng `x`. Vì vậy, nếu bạn có biểu thức như `y = x++;`, y sẽ được gán giá trị gốc của `x`, sau đó `x` mới được tăng.

Ngược lại, nếu bạn dùng `--x`, nó giảm giá trị của `x` trước khi biểu thức được đánh giá. Vậy `y = --x;` sẽ giảm `x` trước, rồi gán giá trị mới của `x` cho `y`.

Bạn cũng có thể thắc mắc liệu `++x` và `x++` có khác nhau không nếu chúng là những thao tác duy nhất trong một statement. Trong trường hợp này, không có sự khác biệt. Cả hai đều tăng `x` thêm 1. Sự khác biệt chỉ thể hiện khi thao tác increment là một phần của biểu thức lớn hơn.

#### Tóm tắt các toán tử một ngôi {#summary-of-unary-operators}
Đây là bảng đầy đủ về các toán tử một ngôi trong Java:

| Toán tử | Tên                      | Mô tả                                                  | Ví dụ                |
|----------|---------------------------|--------------------------------------------------------------|------------------------|
| `+`        | Unary plus                | Biểu thị giá trị dương (ít khi dùng)                     | `+x`                     |
| `-`        | Unary minus               | Đảo dấu một giá trị                                              | `-x`                     |
| `++`       | Increment                 | Tăng một giá trị thêm 1                                      | `++x (prefix) x++ (postfix)`|
| `--`       | Decrement                 | Giảm một giá trị đi 1                                      | `--x (prefix) x-- (postfix)`|
| `~`        | Bitwise complement        | Đảo tất cả các bit                                             | `~x`                     |

Lưu ý rằng toán tử complement (`~`) chỉ hoạt động trên integer type, không hoạt động trên `float` hay `double`.

Một vài điểm tinh tế hơn cần cân nhắc:

- Khi dùng `++x` và `x++`, thứ tự thực hiện các phép toán và side effect sẽ phát huy vai trò. Xét ví dụ sau:
  ```java 
  int x = 5;
  int y = ++x + x++; // y = 12, x = 7
  ```
  Đây là những gì đang diễn ra:
  1. Toán tử prefix increment (`++x`) được áp dụng trước. Nó tăng `x` lên 6, và giá trị của biểu thức `++x` là 6.
  2. Sau đó, toán tử postfix increment (`x++`) được áp dụng. Nó trả về giá trị hiện tại của `x`, tức 6, rồi tăng `x` lên 7.
  3. Giá trị của `y` là tổng của biểu thức prefix increment (6) và biểu thức postfix increment (6), tức 12.
  4. Sau khi statement được thực thi, `x` là 7 (nhờ postfix increment), và `y` là 12.

- Có thể dùng toán tử increment và decrement bên trong một biểu thức phức tạp mà không ảnh hưởng đến kết quả, nhưng điều đó có thể khiến code của bạn khó đọc và khó hiểu hơn nhiều. Ví dụ:
  ```java
  int x = 5;
  int y = 3 * x++ + 2; // y = 17, x = 6
  ```
  Cách này vẫn hoạt động, nhưng sẽ rõ ràng hơn nếu thực hiện thao tác increment trên một dòng riêng trước biểu thức.

- Không thể dùng toán tử increment và decrement với giá trị boolean vì giá trị boolean chỉ có thể là `true` hoặc `false`. Chúng không có giá trị "next" hay "previous" như các con số.

- Nếu bạn dùng nhiều toán tử increment hoặc decrement trên cùng một variable trong một statement, thứ tự thực hiện là từ trái sang phải:
  ```java
  int x = 5;
  System.out.println(++x + x++ + x--); // Output: 19
  ```
  Đây là những gì đang diễn ra:
  1. `++x` tăng `x` lên 6 và trả về 6
  2. `x++` trả về 6 (giá trị hiện tại của `x`), rồi tăng `x` lên 7
  3. `x--` trả về 7 (giá trị hiện tại của `x`), rồi giảm `x` xuống 6
  4. Tổng là 6 + 6 + 7 = 19

- Toán tử complement (`~`) hữu ích cho các tác vụ thao tác bit mức thấp, thường được dùng trong systems programming, embedded systems, networking protocol, cryptography, và nhiều lĩnh vực khác.

- Java compiler nhận diện toán tử increment và decrement và sinh bytecode phù hợp tùy theo toán tử được dùng ở dạng prefix hay postfix. Đây không phải điều bạn cần bận tâm với vai trò lập trình viên, vì nó được xử lý ở mức bytecode.

- Toán tử increment và decrement có thể được dùng trên variable thuộc type float và double. Các quy tắc prefix/postfix tương tự cũng được áp dụng như với integer type.

- Nếu bạn dùng `++x` so với `x++` bên trong một vòng lặp, sự khác biệt về giá trị cuối cùng của `x` sau vòng lặp phụ thuộc vào thời điểm phép increment diễn ra. Xét ví dụ:
  ```java
  int x = 0;
  for(int i = 0; i < 5; i++) {
      System.out.println(++x);
  }
  // Output: 1 2 3 4 5
  // x is 5 after the loop

  x = 0;
  for(int i = 0; i < 5; i++) {
      System.out.println(x++);
  }
  // Output: 0 1 2 3 4
  // x is 5 after the loop
  ```
  Trong cả hai trường hợp, `x` cuối cùng đều bằng 5, nhưng thời điểm các giá trị được in ra thì khác nhau. Với `++x`, x được tăng trước khi giá trị của nó được in, còn với `x++`, giá trị gốc của `x` được in trước khi bị tăng.


### Toán tử hai ngôi {#binary-operators}
Toán tử hai ngôi là toán tử làm việc trên hai toán hạng. Java cung cấp một tập toán tử số học hai ngôi để thực hiện các phép toán cơ bản trên toán hạng số. Những toán tử này bao gồm addition (`+`), subtraction (`-`), multiplication (`*`), division (`/`), và modulus (`%`).

#### Toán tử số học {#arithmetic-operators}
Các toán tử addition (`+`), subtraction (`-`), và multiplication (`*`) hoạt động đúng như bạn mong đợi:
```java
int a = 10;
int b = 20;
int sum = a + b; // 30
int difference = b - a; // 10
int product = a * b; // 200
```

Toán tử division (`/`) thực hiện phép chia giữa hai toán hạng số. Điều quan trọng cần lưu ý là khi dùng với toán hạng integer, toán tử division thực hiện phép chia nguyên (integer division), nghĩa là nó trả về thương và bỏ đi phần dư.
```java
int a = 10;
int b = 3;
int quotient = a / b; // 3
```

Nếu bạn muốn thực hiện phép chia floating-point và nhận kết quả có phần thập phân, thì ít nhất một trong hai toán hạng phải thuộc floating-point type (`float` hoặc `double`).
```java
int a = 10;
double b = 3.0;
double quotient = a / b; // 3.3333333333333335
```

Toán tử modulus (`%`) trả về phần dư sau khi thực hiện phép chia nguyên.
```java
int a = 10;
int b = 3;
int remainder = a % b; // 1
```

#### Numeric Promotion {#numeric-promotion}
Khi thực hiện phép toán số học trên các toán hạng khác type, Java tự động promote các toán hạng theo một bộ quy tắc gọi là numeric promotion.

Numeric promotion là việc tự động chuyển đổi một numeric type nhỏ hơn sang numeric type lớn hơn để tránh mất độ chính xác trong các phép toán số học. Điều này cho phép bạn thực hiện phép toán số học trên các type hỗn hợp mà không cần cast toán hạng một cách tường minh.

Java tuân theo các quy tắc numeric promotion sau:

1. Nếu một trong hai toán hạng thuộc type `double`, toán hạng còn lại được promote thành `double`.
2. Ngược lại, nếu một trong hai toán hạng thuộc type `float`, toán hạng còn lại được promote thành `float`.
3. Ngược lại, nếu một trong hai toán hạng thuộc type `long`, toán hạng còn lại được promote thành `long`.
4. Ngược lại, cả hai toán hạng đều được promote thành `int`.

Dưới đây là một số ví dụ:
```java
int a = 10;
double b = 20.0;
double result1 = a + b; // a is promoted to double

float c = 10.0f;
long d = 20L;
float result2 = c + d; // d is promoted to float

short e = 10;
short f = 20;
int result3 = e + f; // e and f are promoted to int
```

#### Thêm dấu ngoặc đơn để thay đổi thứ tự phép toán {#adding-parentheses-to-change-the-order-of-operation}
Bạn có thể dùng dấu ngoặc đơn để thay đổi thứ tự thực hiện phép toán mặc định trong một biểu thức số học. Các biểu thức bên trong ngoặc đơn được đánh giá trước.
```java
int a = 10;
int b = 20;
int c = 30;
int result = a + b * c; // 610 (multiplication happens first)
int result2 = (a + b) * c; // 900 (addition happens first)
```

Tuy nhiên, khi dùng dấu ngoặc đơn, điều quan trọng là đảm bảo chúng được cân đối đúng. Mỗi dấu mở ngoặc phải có một dấu đóng ngoặc tương ứng. Ngoặc không khớp sẽ dẫn đến compilation error.
```java
int result = (a + b) * c; // correct
int result2 = (a + b * c; // compilation error (mismatched parentheses)
```

#### Tóm tắt các toán tử hai ngôi {#summary-of-binary-operators}
Đây là bảng tóm tắt các toán tử hai ngôi trong Java:

| Toán tử   | Tên           | Mô tả                                      | Ví dụ      |
|------------|----------------|--------------------------------------------------|--------------|
| `+`        | Addition       | Cộng hai toán hạng                                | `a + b`      |
| `-`        | Subtraction    | Lấy toán hạng thứ hai trừ toán hạng thứ nhất      | `a - b`      | 
| `*`        | Multiplication | Nhân hai toán hạng                          | `a * b`      |
| `/`        | Division       | Chia toán hạng thứ nhất cho toán hạng thứ hai          | `a / b`      |
| `%`        | Modulus        | Trả về phần dư của phép chia                | `a % b`      |

Một số điểm tinh tế cần cân nhắc là:

- Khi làm việc với số floating-point (`float` và `double`), điều quan trọng cần nhớ là chúng có độ chính xác hạn chế. Điều này có thể dẫn đến những sai số nhỏ trong tính toán.
   ```java
   double a = 0.1;
   double b = 0.2;
   double sum = a + b; // 0.30000000000000004 (not exactly 0.3)
   ```
   Điều này là do cách biểu diễn số floating-point trong hệ nhị phân. Để tính toán thập phân chính xác, bạn nên dùng class `BigDecimal`.

- Khi kết quả của một phép toán số học vượt quá giá trị lớn nhất hoặc nhỏ nhất mà target type có thể biểu diễn, overflow hoặc underflow có thể xảy ra. Trong Java, overflow và underflow với số nguyên không throw exception; giá trị chỉ đơn giản là quay vòng (wrap around).
   ```java
   int a = Integer.MAX_VALUE;
   int b = 1;
   int sum = a + b; // -2147483648 (minimum int value)
   ```
   Với floating-point type, overflow cho ra Infinity còn underflow cho ra 0.

- Cố gắng chia một số nguyên cho 0 sẽ throw `ArithmeticException`.
   ```java
   int a = 10;
   int b = 0;
   int result = a / b; // throws ArithmeticException
   ```
   Tuy nhiên, chia một số floating-point cho 0 không throw exception. Kết quả là `Infinity` hoặc `NaN` (Not-a-Number).
   ```java
   double a = 10.0;
   double b = 0.0;
   double result = a / b; // Infinity or NaN (Not-a-Number)
   ```


### Toán tử bitwise và shift {#bitwise-and-shift-operators}
Ngoài các toán tử số học, Java cung cấp một tập toán tử bitwise và shift cho phép bạn thao tác trên từng bit riêng lẻ của giá trị integer. Những toán tử này đặc biệt hữu ích khi làm việc với flag, mask và các thao tác hệ thống mức thấp.

#### Toán tử bitwise {#bitwise-operators}
Java có bốn toán tử bitwise: AND (`&`), OR (`|`), XOR (`^`), và complement (`~`).

Toán tử bitwise AND (`&`) trả về 1 ở mỗi vị trí bit mà các bit tương ứng của cả hai toán hạng đều là 1.
```java
int a = 0b1010; // 10
int b = 0b1100; // 12
int result = a & b; // 0b1000 = 8
```

Toán tử bitwise OR (`|`) trả về 1 ở mỗi vị trí bit mà các bit tương ứng của một trong hai hoặc cả hai toán hạng là 1.
```java
int a = 0b1010; // 10
int b = 0b1100; // 12
int result = a | b; // 0b1110 = 14
```

Toán tử bitwise XOR (exclusive OR) (`^`) trả về 1 ở mỗi vị trí bit mà các bit tương ứng của một trong hai toán hạng (nhưng không phải cả hai) là 1.
```java
int a = 0b1010; // 10
int b = 0b1100; // 12
int result = a ^ b; // 0b0110 = 6
```

Toán tử bitwise complement (`~`) là toán tử một ngôi đảo ngược tất cả các bit của toán hạng.
```java
int a = 0b1010; // 10
int result = ~a; // 0b11111111111111111111111111110101 = -11
```

#### Toán tử shift {#shift-operators}
Java cung cấp ba toán tử shift: left shift (`<<`), signed right shift (`>>`), và unsigned right shift (`>>>`).

Toán tử left shift (`<<`) dịch các bit của toán hạng thứ nhất sang trái một số vị trí được chỉ định bởi toán hạng thứ hai. Các bit mới ở bên phải nhất được điền bằng 0.
```java
int a = 0b1010; // 10
int result = a << 1; // 0b10100 = 20
```
Mỗi phép left shift thực chất nhân đôi con số.

Toán tử signed right shift (`>>`) dịch các bit của toán hạng thứ nhất sang phải một số vị trí được chỉ định bởi toán hạng thứ hai. Các bit mới ở bên trái nhất được điền bằng bit dấu (0 với số dương, 1 với số âm), giữ nguyên dấu của con số.
```java
int a = 0b1010; // 10
int result = a >> 1; // 0b0101 = 5
```
Mỗi phép signed right shift thực chất chia đôi con số, làm tròn xuống.

Toán tử unsigned right shift (`>>>`) tương tự signed right shift, nhưng các bit mới ở bên trái nhất luôn được điền bằng 0, bất kể dấu.
```java
int a = 0b11111111111111111111111111110110; // -10
int result = a >>> 1; // 0b01111111111111111111111111111011 = 2147483643
```

#### Tóm tắt các toán tử bitwise và shift {#summary-of-bitwise-and-shift-operators}
Đây là tóm tắt các toán tử bitwise và shift trong Java:

| Toán tử   | Tên                | Mô tả                                                 | Ví dụ    |
|------------|---------------------|-------------------------------------------------------------|------------|
| `&`        | Bitwise AND         | Trả về 1 nếu cả hai bit đều là 1                                | `a & b`    |
| `\|`        | Bitwise OR          | Trả về 1 nếu ít nhất một bit là 1                         | `a \| b`   |
| `^`        | Bitwise XOR         | Trả về 1 nếu đúng một bit là 1                           | `a ^ b`    |
| `~`        | Bitwise Complement  | Đảo tất cả các bit                                            | `~a`       |
| `<<`       | Left Shift          | Dịch bit sang trái, điền bằng 0                           | `a << b`   |
| `>>`       | Signed Right Shift  | Dịch bit sang phải, điền bằng bit dấu                    | `a >> b`   |
| `>>>`      | Unsigned Right Shift| Dịch bit sang phải, điền bằng 0                          | `a >>> b`  |

Một vài điểm tinh tế hơn cần cân nhắc:

- Toán hạng bên trái của toán tử shift quyết định type của kết quả. Toán hạng bên phải (khoảng cách dịch) luôn được promote thành int.
   ```java
   byte a = 10;
   byte b = a << 1; // Compilation error: the result is int
   int c = a << 1; // OK
   ```

- Không có *toán tử unsigned left shift* riêng trong Java. Toán tử left shift (`<<`) vốn đã dịch các bit sang trái và điền số 0 vào các bit bên phải nhất, khiến nó thực chất là unsigned. Khái niệm signed hay unsigned không áp dụng cho left shift theo cách tương tự như với right shift, bởi vì dịch trái không liên quan đến bit dấu.

- Toán tử bitwise và shift có độ ưu tiên thấp hơn toán tử số học nhưng cao hơn toán tử so sánh và logic. Hãy dùng dấu ngoặc đơn để thể hiện rõ độ ưu tiên và làm code dễ đọc hơn.



### Toán tử gán {#assignment-operators}
Toán tử gán được dùng để gán giá trị cho variable. Ngoài toán tử gán đơn giản (=), Java cung cấp các toán tử gán kết hợp (compound assignment) kết hợp một phép toán số học hoặc bitwise với phép gán.

Toán tử gán kết hợp (compound assignment) kết hợp một phép toán số học hoặc bitwise với thao tác gán. Chúng cung cấp cách viết ngắn gọn để thay đổi giá trị của một variable dựa trên giá trị hiện tại của nó.

Cú pháp chung cho toán tử gán kết hợp là:
```
variable op= expression;
```

Trong đó `op` là một trong các toán tử số học hoặc bitwise (`+`, `-`, `*`, `/`, `%`, `&`, `|`, `^`, `<<`, `>>`, `>>>`).

Điều này tương đương với:
```
variable = variable op expression;
```

Các toán tử gán kết hợp là:
- `+=` (gán phép cộng)
- `-=` (gán phép trừ)
- `*=` (gán phép nhân)
- `/=` (gán phép chia)
- `%=` (gán modulus)
- `&=` (gán bitwise AND)
- `|=` (gán bitwise OR)
- `^=` (gán bitwise XOR)
- `<<=` (gán left shift)
- `>>=` (gán signed right shift)
- `>>>=` (gán unsigned right shift)

Dưới đây là ví dụ của từng toán tử gán kết hợp:
```java
int a = 10;

a += 5;  // equivalent to a = a + 5; a is now 15
a -= 3;  // equivalent to a = a - 3; a is now 12
a *= 2;  // equivalent to a = a * 2; a is now 24
a /= 4;  // equivalent to a = a / 4; a is now 6
a %= 5;  // equivalent to a = a % 5; a is now 1

int b = 0b1010; // binary representation of 10

b &= 0b1100;  // equivalent to b = b & 0b1100; b is now 0b1000 (8 in decimal)
b |= 0b0101;  // equivalent to b = b | 0b0101; b is now 0b1101 (13 in decimal)
b ^= 0b1001;  // equivalent to b = b ^ 0b1001; b is now 0b0100 (4 in decimal)
b <<= 2;      // equivalent to b = b << 2; b is now 0b10000 (16 in decimal)
b >>= 1;      // equivalent to b = b >> 1; b is now 0b01000 (8 in decimal)
b >>>= 2;     // equivalent to b = b >>> 2; b is now 0b00010 (2 in decimal)
```

Toán tử gán kết hợp không chỉ ngắn gọn hơn mà còn có thể hiệu quả hơn so với dạng khai triển tương đương. Điều này là vì variable chỉ được đánh giá một lần ở dạng kết hợp, trong khi nó được đánh giá hai lần ở dạng khai triển.

Ví dụ, xét đoạn code sau:
```java
int[] array = {1, 2, 3, 4, 5};
int index = 2;

array[index++] += 10; // More efficient
array[index++] = array[index++] + 10; // Less efficient
```

Ở dòng đầu tiên, `index` chỉ được tăng một lần sau khi giá trị của nó được dùng để truy cập phần tử array. Ở dòng thứ hai, `index` bị tăng hai lần, dẫn đến hành vi không như mong đợi và code kém hiệu quả hơn.

#### Thay đổi primitive type bằng suffix {#changing-the-primitive-type-with-suffixes}
Khi gán một giá trị cho variable thuộc một primitive type khác, bạn có thể dùng suffix `f`, `l`, và `d` để chỉ định type của giá trị literal.

- `f` dùng cho float literal
- `l` hoặc `L` dùng cho long literal
- `d` hoặc `D` dùng cho double literal

```java
float a = 3.14f;
long b = 100L;
double c = 3.14d; // d is optional here, as double is the default for decimal literals
```

#### Casting giá trị {#casting-values}
Khi gán một giá trị thuộc type này cho variable thuộc type khác, bạn có thể cần dùng casting để chuyển đổi tường minh giá trị sang target type.
```java
int a = 10;
byte b = (byte) a;
```
Trong ví dụ này, giá trị `int` được cast thành byte trước khi gán.

Khi gán một giá trị quá lớn hoặc quá nhỏ so với target type, overflow hoặc underflow có thể xảy ra.
```java
byte a = 127;
a++; // a is now -128 (underflow)

byte b = -128;
b--; // b is now 127 (overflow)
```
Trong những ví dụ này, việc tăng giá trị lớn nhất của byte gây underflow, còn việc giảm giá trị nhỏ nhất gây overflow.

Để tránh hành vi không như mong đợi do overflow hoặc underflow, điều quan trọng là xem lại các phép gán của bạn và đảm bảo rằng giá trị phù hợp với target type.
```java
int a = 1000;
byte b = (byte) a; // b is now -24 (overflow)
```
Ở đây, cast giá trị int 1000 thành byte dẫn đến overflow, vì 1000 nằm ngoài phạm vi của byte (-128 đến 127).

#### Tóm tắt các toán tử gán {#summary-of-assignment-operators}
Đây là bảng tóm tắt các toán tử gán trong Java:

| Toán tử | Tên                      | Ví dụ |
|----------|---------------------------|---------|
| `=`        | Gán đơn giản         | `a = 10`  |
| `+=`       | Gán phép cộng       | `a += 5`  |
| `-=`       | Gán phép trừ    | `a -= 5`  |
| `*=`       | Gán phép nhân | `a *= 5`  |
| `/=`       | Gán phép chia       | `a /= 5`  |
| `%=`       | Gán modulus      | `a %= 5`  |
| `&=`       | Gán bitwise AND    | `a &= 5`  |
| `\|=`       | Gán bitwise OR    | `a \|= 5`  |
| `^=`       | Gán bitwise XOR    | `a ^= 5`  |
| `<<=`      | Gán left shift     | `a <<= 2` |
| `>>=`      | Gán signed right shift | `a >>= 2` |
| `>>>=`     | Gán unsigned right shift | `a >>>= 2` |

Có một vài điểm tinh tế cần cân nhắc:
- Khi cast một giá trị floating-point sang integer type, phần thập phân bị cắt bỏ (truncate), không phải làm tròn.
   ```java
   double a = 3.9999;
   int b = (int) a; // b is now 3
   ```

- Toán tử gán kết hợp có độ ưu tiên thấp hơn toán tử số học nhưng cao hơn toán tử gán đơn giản.
   ```java
   int a = 10;
   a *= 5 + 2; // a is now 70 ((10 * 5) + 2)
   a = 10;
   a = a * 5 + 2; // a is now 52 ((10 * 5) + 2)
   ```

- Toán tử gán đơn giản (`=`) có thể được nối chuỗi để gán cùng một giá trị cho nhiều variable.
   ```java
   int a, b, c;
   a = b = c = 10; // a, b, and c are all 10
   ```

- Khi gán một variable cho chính nó bằng toán tử gán kết hợp, phép toán được thực hiện với giá trị gốc của variable.
   ```java
   int a = 5;
   a += a++; // a is now 10 (5 + 5, then a is incremented)
   ```
- Khi dùng toán tử gán kết hợp với biểu thức, hãy chú ý đến độ ưu tiên toán tử để tránh kết quả không như mong đợi.
    ```java
    int a = 10;
    a *= 2 + 5; // a is now 70, not 25! (a = a * (2 + 5))
    ```


### Toán tử Equality {#equality-operators}
Toán tử equality trong Java dùng để so sánh hai giá trị xem chúng bằng nhau hay không bằng nhau. Chúng trả về kết quả `boolean` (`true` hoặc `false`) dựa trên phép so sánh.

Java cung cấp hai toán tử equality:
- `==` (bằng)
- `!=` (không bằng)

Dưới đây là ví dụ về cách dùng những toán tử này:
```java
int a = 10;
int b = 20;

boolean result1 = (a == b); // false
boolean result2 = (a != b); // true
```

#### Hiểu về Equality {#understanding-equality}
Khi dùng toán tử equality, điều quan trọng là hiểu cách Java so sánh các giá trị để xác định bằng nhau.

Với primitive type, toán tử `==` so sánh giá trị thực tế:
```java
int a = 10;
int b = 10;
boolean result = (a == b); // true
```

Tuy nhiên, với object, toán tử `==` so sánh reference của object, chứ không so sánh nội dung của object:
```java
String s1 = new String("Hello");
String s2 = new String("Hello");
boolean result = (s1 == s2); // false
```

Trong trường hợp này, `s1` và `s2` là hai object khác nhau trong memory, dù chúng chứa cùng một giá trị string.

Để so sánh nội dung của các object, bạn nên dùng method `equals()`:
```java
String s1 = new String("Hello");
String s2 = new String("Hello");
boolean result = s1.equals(s2); // true
```

Tuy nhiên, khi so sánh object bằng method `equals()`, điều quan trọng là đảm bảo class của object đã override method `equals(Object)` để cung cấp phép so sánh có ý nghĩa.

Implementation mặc định của `equals(Object)` trong class `Object` chỉ so sánh reference của object, giống như toán tử `==`. Để so sánh nội dung của object, bạn cần override `equals(Object)` trong class của mình:
```java
class Person {
    private String name;
    private int age;

    // Constructor, getters, setters...

    @Override
    public boolean equals(Object obj) {
        // Implementation...
    }
}
```

Để override method `equals` trong Java, bạn cần tuân theo một số quy tắc nhất định để đảm bảo method hoạt động đúng và tuân thủ contract do class `Object` định nghĩa:

1. **Symmetry**: Nếu `a.equals(b)` là `true` thì `b.equals(a)` cũng phải là `true`.

2. **Reflexivity**: Một object phải bằng chính nó; nghĩa là `a.equals(a)` phải là `true`.

3. **Transitivity**: Nếu `a.equals(b)` là `true` và `b.equals(c)` là `true` thì `a.equals(c)` phải là `true`.

4. **Consistency**: Nếu `a.equals(b)` trả về `true` một lần thì nó phải tiếp tục trả về `true` chừng nào cả hai object vẫn chưa bị sửa đổi. Tương tự, nếu nó trả về `false` thì phải luôn trả về `false` một cách nhất quán.

5. **Non-nullity**: `a.equals(null)` phải luôn trả về `false`.

Đây là ví dụ override method `equals` trong class `Person`:

```java
public class Person {
    private String name;
    private int age;

    // Constructor, getters, and setters

    @Override // 1.
    public boolean equals(Object obj) {
        // 2. Check if obj is the same as this object
        if (this == obj) {
            return true;
        }
        // 3. Check if obj is null or not an instance of Person
        if (obj == null || getClass() != obj.getClass()) {
            return false;
        }
        // 4. Cast obj to Person and compare significant fields
        Person person = (Person) obj;
                                       
        // 5. Compare significant fields
        return age == person.age && (name != null ? name.equals(person.name) : person.name == null);
    }

    @Override
    public int hashCode() {
        // Ensure consistency with the equals method
        int result = name != null ? name.hashCode() : 0;
        result = 31 * result + age;
        return result;
    }
}
```

Ví dụ trên cho thấy cách override method `equals` một cách chính xác:

1. **Dùng annotation `@Override`**: Điều này đảm bảo bạn đang override đúng method và giúp code dễ đọc hơn.

2. **Kiểm tra `null`**: Kiểm tra đầu tiên nên là xem object đang được so sánh có phải là `null` hay không.

3. **Kiểm tra type**: Dùng toán tử `instanceof` để đảm bảo các object được so sánh cùng type.

4. **Cast object**: Cast object sang type đúng sau khi kiểm tra.

5. **So sánh các field quan trọng**: So sánh những field quyết định tính bằng nhau, dùng toán tử `==` cho primitive field và method `equals` cho object field.

Ngoài ra, hãy luôn override `hashCode` khi override `equals` để duy trì contract chung rằng những object bằng nhau phải có hash code bằng nhau.

#### Tóm tắt các toán tử Equality và Inequality {#summary-of-equality-and-inequality-operators}
Đây là bảng tóm tắt các toán tử equality và inequality trong Java:

| Toán tử | Tên         | Ví dụ    |
|----------|--------------|------------|
| `==`       | Bằng     | `a == b`     |
| `!=`       | Không bằng | `a != b`     |

Có một số điểm tinh tế cần cân nhắc:
- Khi so sánh giá trị floating-point (float và double) bằng `==` hoặc `!=`, hãy lưu ý rằng kết quả có thể không như mong đợi do bản chất thiếu chính xác của cách biểu diễn floating-point.
   ```java
   double a = 0.1 + 0.2;
   double b = 0.3;
   boolean result = (a == b); // false
   ```

- Toán tử `==` và `!=` có độ ưu tiên cao hơn toán tử logic (`&&`, `||`) nhưng thấp hơn toán tử quan hệ (`<`, `>`, `<=`, `>=`).

- Toán tử `!=` là phủ định của toán tử `==`, nên `a != b` tương đương với `!(a == b)`.



### Toán tử quan hệ {#relational-operators}
Toán tử quan hệ trong Java dùng để so sánh hai giá trị và xác định mối quan hệ giữa chúng. Chúng trả về kết quả boolean (`true` hoặc `false`) dựa trên phép so sánh.

Java cung cấp bốn toán tử quan hệ:
- `<` (nhỏ hơn)
- `>` (lớn hơn)
- `<=` (nhỏ hơn hoặc bằng)
- `>=` (lớn hơn hoặc bằng)

Những toán tử này có thể được dùng với numeric primitive type và `char`.

Dưới đây là ví dụ dùng toán tử quan hệ với giá trị integer:
```java
int a = 10;
int b = 20;

boolean result1 = (a < b);  // true
boolean result2 = (a > b);  // false
boolean result3 = (a <= b); // true
boolean result4 = (a >= b); // false
```

Và đây là ví dụ khác với giá trị char, so sánh giá trị Unicode của các ký tự:
```java
char c1 = 'a';
char c2 = 'b';
boolean result = (c1 < c2); // true
```

#### Tóm tắt các toán tử quan hệ {#summary-of-relational-operators}
Đây là bảng tóm tắt các toán tử quan hệ trong Java:

| Toán tử | Tên                     | Ví dụ |
|----------|--------------------------|---------|
| `<`        | Nhỏ hơn                | `a < b`   |
| `>`        | Lớn hơn             | `a > b`   |
| `<=`       | Nhỏ hơn hoặc bằng    | `a <= b`  |
| `>=`       | Lớn hơn hoặc bằng | `a >= b`  |

Ngoài ra, có hai điểm tinh tế cần cân nhắc:
- Khi so sánh giá trị floating-point (`float` và `double`) bằng toán tử quan hệ, hãy lưu ý rằng kết quả có thể không như mong đợi do bản chất thiếu chính xác của cách biểu diễn floating-point.
   ```java
   double a = 0.1 + 0.2;
   double b = 0.3;
   boolean result = (a <= b); // false
   ```

- Toán tử quan hệ có độ ưu tiên cao hơn toán tử equality (`==`, `!=`) và toán tử logic (`&&`, `||`), nhưng thấp hơn toán tử số học (`+`, `-`, `*`, `/`, `%`).



### Toán tử logic {#logical-operators}
Toán tử logic trong Java dùng để thực hiện các phép toán logic trên biểu thức boolean. Chúng trả về kết quả boolean (`true` hoặc `false`) dựa trên các toán hạng và toán tử cụ thể được dùng.

Java cung cấp sáu toán tử logic:
- `&` (logical AND)
- `|` (logical OR)
- `^` (logical XOR)
- `&&` (short-circuit logical AND)
- `||` (short-circuit logical OR)
- `!` (logical NOT)

Những toán tử này có thể được dùng với giá trị `boolean` hoặc biểu thức cho ra giá trị `boolean`.

Dưới đây là ví dụ dùng toán tử logic:
```java
boolean a = true;
boolean b = false;

boolean result1 = a & b;  // false
boolean result2 = a | b;  // true
boolean result3 = a ^ b;  // true
boolean result4 = a && b; // false
boolean result5 = a || b; // true
boolean result6 = !a;     // false
```

Và đây là bảng chân trị (truth table) của các toán tử logical AND (`&`), logical OR (`|`), và logical XOR (`^`):

Logical AND (`&`):

| a       | b       | a & b   |
|---------|---------|---------|
| `false` | `false` | `false` |
| `false` | `true`  | `false` |
| `true`  | `false` | `false` |
| `true`  | `true`  | `true`  |

Logical OR (`|`):

| a       | b       | a \| b  |
|---------|---------|---------|
| `false` | `false` | `false` |
| `false` | `true`  | `true`  |
| `true`  | `false` | `true`  |
| `true`  | `true`  | `true`  |

Logical XOR (`^`):

| a       | b       | a ^ b   |
|---------|---------|---------|
| `false` | `false` | `false` |
| `false` | `true`  | `true`  |
| `true`  | `false` | `true`  |
| `true`  | `true`  | `false` |


Tóm lại:
- `&` (AND) là `true` chỉ khi cả hai toán hạng đều là `true`.
- `|` (OR) là `true` nếu ít nhất một toán hạng là `true`.
- `^` (XOR) là `true` nếu đúng một toán hạng là `true`.

#### Short-circuit {#short-circuit}
Toán tử `&&` và `||` là short-circuit operator. Chúng chỉ đánh giá toán hạng thứ hai khi cần thiết, dựa trên kết quả của toán hạng thứ nhất.

Với `&&`, nếu toán hạng thứ nhất là `false`, toàn bộ biểu thức sẽ là `false`, bất kể toán hạng thứ hai. Do đó, toán hạng thứ hai không được đánh giá.

Với `||`, nếu toán hạng thứ nhất là `true`, toàn bộ biểu thức sẽ là `true`, bất kể toán hạng thứ hai. Do đó, toán hạng thứ hai không được đánh giá.

Short-circuit có thể hữu ích để tránh `NullPointerException` khi kiểm tra `null` trước khi truy cập method hay field của một object:
```java
String str = null;
if (str != null && str.length() > 0) {
    // This code will not throw a NullPointerException
}
```
Tuy nhiên, hãy cẩn thận khi dùng short-circuit operator với những biểu thức có side effect (ví dụ, lời gọi method làm thay đổi dữ liệu hoặc có hậu quả khác):
```java
int a = 10;
if (a > 5 || ++a > 10) {
    // a will be 11 if a > 5, but will remain 10 if a <= 5
}
```

#### Tóm tắt các logical operator {#summary-of-logical-operators}
Dưới đây là bảng tóm tắt các logical operator trong Java:

| Operator | Tên                        | Ví dụ |
|----------|----------------------------|---------|
| `&`        | Logical AND                | `a & b`   |
| `|`        | Logical OR                 | `a \| b`  |
| `^`        | Logical XOR (exclusive OR) | `a ^ b`   |
| `&&`       | Short-circuit logical AND  | `a && b`  |
| `\|\|`       | Short-circuit logical OR | `a \|\| b`|
| `!`        | Logical NOT                | `!a`      |


Dưới đây là một số điểm tinh tế cần cân nhắc:
- Các operator `&`, `|`, và `^` cũng có thể được dùng như bitwise operator khi áp dụng cho các kiểu integer (`byte`, `short`, `int`, `long`). Trong ngữ cảnh này, chúng thực hiện các phép toán bitwise AND, OR và XOR trên từng bit riêng lẻ của các operand.

- Operator `!` có độ ưu tiên cao hơn các operator `&`, `|`, `^`, `&&` và `||`.

- Các operator `&`, `|`, và `^` có độ ưu tiên thấp hơn các operator `&&` và `||`.

- Các operator `&`, `|`, và `^` luôn đánh giá cả hai operand, kể cả khi kết quả đã có thể xác định chỉ từ operand đầu tiên. Điều này có thể kém hiệu quả hơn so với dùng các short-circuit operator `&&` và `||` khi operand thứ hai tốn kém để đánh giá hoặc có side effect.

- Operator `^` trả về `true` khi và chỉ khi đúng một trong hai operand là `true`. Điều này khác với hành vi của operator `!=`, vốn trả về true nếu hai operand không bằng nhau.

- Các logical operator có thể được kết hợp để tạo thành những biểu thức boolean phức tạp. Điều quan trọng là dùng dấu ngoặc đơn để chỉ rõ thứ tự đánh giá mong muốn khi dùng nhiều operator.
   ```java
   boolean result = (a && b) || (c && d);
   ```


## `String` và `StringBuilder` {#string-and-stringbuilder}

Một string đơn giản là một chuỗi các ký tự. Tuy nhiên, bên dưới lớp vỏ, string có một số thuộc tính và tối ưu hóa đặc biệt mà bạn cần hiểu rõ.

```java
String greeting = "Hello World!";
```

Class `String` trong Java là immutable, nghĩa là một khi string object được tạo ra, giá trị của nó không thể thay đổi. Điều này thoạt nghe có vẻ phản trực giác, vì suy cho cùng chúng ta thường xuyên sửa đổi string trong chương trình. Nhưng thực chất điều đang diễn ra là mỗi lần như vậy một string object mới được tạo ra, còn object gốc vẫn giữ nguyên.

Tính immutable này mang lại một số lợi thế. String có thể được chia sẻ an toàn giữa nhiều phần khác nhau của chương trình mà không phải lo một phần nào đó vô tình sửa đổi string ảnh hưởng tới những phần còn lại. JVM cũng có thể tối ưu bộ nhớ bằng cách tái sử dụng những string phổ biến.

Tuy nhiên, tính immutable cũng có nghĩa là các thao tác sửa đổi string (như concatenation) kém hiệu quả hơn, vì mỗi lần đều phải tạo ra một string mới.

### Tạo String {#creating-strings}

Có một vài cách để tạo string trong Java:

```java
String literalString = "I am a literal string";
String objectString = new String("I am a String object");
```

Cả hai cách đều cho ra kết quả cuối cùng như nhau, một string với giá trị đã chỉ định. Tuy nhiên, có một khác biệt nhỏ trong cách JVM xử lý chúng.

Khi bạn tạo một string literal, JVM trước tiên kiểm tra **string pool**, một vùng nhớ đặc biệt dành riêng cho string. Nếu một string tương đương đã tồn tại trong pool, JVM chỉ đơn giản trả về reference tới string đang có đó thay vì cấp phát bộ nhớ mới.

```java
String s1 = "Hello";
String s2 = "Hello";
System.out.println(s1 == s2);  // Prints 'true'
```

Ở đây, `s1` và `s2` thực ra cùng trỏ tới một string object trong bộ nhớ, bởi vì `"Hello"` đã có sẵn trong string pool.

Ngược lại, dùng keyword `new` luôn tạo ra một object mới, kể cả khi một string tương đương đã tồn tại trong pool.

```java
String s3 = new String("Hello");
System.out.println(s1 == s3);  // Prints 'false'
```

Ở đây, dù `s1` và `s3` có cùng nội dung, chúng lại trỏ tới hai object khác nhau trong bộ nhớ.

Nếu bạn có một string object và muốn đảm bảo nó dùng string đã được tối ưu bộ nhớ từ pool, bạn có thể dùng method `intern()`.

```java
String s4 = s3.intern();
System.out.println(s1 == s4);  // Prints 'true'
```

Sau khi intern `s3`, `s4` giờ trỏ tới cùng string trong pool như `s1`.

Tuy nhiên, điều quan trọng là phải dùng `intern()` một cách thận trọng. Lạm dụng có thể thực sự dẫn đến vấn đề về hiệu năng, vì string pool là một tài nguyên hữu hạn. Cách dùng tốt nhất là cho những string mà bạn dự đoán sẽ được tái sử dụng thường xuyên trong suốt chương trình.

### Nối String {#string-concatenation}

Nối string là một thao tác phổ biến, và Java cung cấp hai cách chính để làm điều đó.

```java
String s1 = "Hello";
String s2 = "World";
String s3 = s1 + " " + s2;  // Using the + operator
String s4 = s1.concat(" ").concat(s2);  // Using the concat() method
```

Cả hai cách đều cho cùng kết quả. Tuy nhiên, có một vài khác biệt cần cân nhắc.

Operator `+` thường dễ đọc hơn và được Java compiler tối ưu thành thao tác `StringBuilder` (chúng ta sẽ bàn ngay sau đây). Khi bạn dùng `+`, compiler thực chất biến đổi nó thành đại loại như sau:

```java
String s3 = new StringBuilder(s1).append(" ").append(s2).toString();
```

Vì vậy, dù trông như bạn đang tạo một string mới với mỗi dấu `+`, compiler đủ thông minh để dùng `StringBuilder` bên dưới nhằm tối ưu hóa.

Mặt khác, method `concat` là một method trực tiếp của class `String`. Nó nối string được chỉ định vào cuối string hiện tại và trả về một string mới. Đây là signature của method:

```java
String concat(String str)
```

Và đây là một ví dụ khác:

```java
String s4 = s1.concat(" ");  // s4 is "Hello "
s4 = s4.concat(s2);  // s4 is now "Hello World"
```

Một lợi thế của việc dùng `concat` là nó thể hiện rõ ràng hơn điều đang diễn ra: bạn đang gọi một method để nối string thay vì dùng operator. Điều này có thể làm code dễ đọc hơn, đặc biệt với những developer mới làm quen với Java và có thể chưa biết cách operator `+` được tối ưu.

Tuy nhiên, `concat` chỉ có thể nối một string mỗi lần, nên để nối nhiều string bạn sẽ cần gọi `concat` nhiều lần, điều này có thể khá rườm rà. Operator `+` cho phép nối nhiều string trong một biểu thức duy nhất, thường tiện lợi hơn.

Suy cho cùng, việc chọn `+` hay `concat` thường phụ thuộc vào sở thích cá nhân và coding style. Nhiều developer thích `+` vì sự ngắn gọn và dễ đọc, trong khi những người khác lại thích sự tường minh của `concat`.

Tuy nhiên, cần thận trọng khi dùng một trong hai cách này trong vòng lặp, vì nó có thể dẫn đến vấn đề hiệu năng do tạo ra nhiều string object trung gian. Trong những trường hợp như vậy, nên dùng trực tiếp `StringBuilder`.

```java
String result = "";
for (int i = 0; i < 100; i++) {
    result = result.concat(Integer.toString(i));  // Inefficient!
}
```

Đoạn code này sẽ tạo một string mới trong mỗi vòng lặp. Với số lượng vòng lặp lớn, điều này có thể rất kém hiệu quả cả về thời gian lẫn bộ nhớ. Trong những trường hợp như vậy nên dùng `StringBuilder` (chúng ta sẽ bàn sau).


### Các method quan trọng của String {#important-string-methods}

Class `String` cung cấp một bộ method phong phú để xem xét và thao tác nội dung string. Dưới đây là một số method được dùng phổ biến nhất:

- `int length()`: Trả về số ký tự trong string.

- `char charAt(int index)`: Trả về ký tự tại index được chỉ định.

- `int indexOf(String str)`: Trả về index trong string của lần xuất hiện đầu tiên của substring được chỉ định.

- `String substring(int beginIndex, int endIndex)`: Trả về một string mới là substring của string này.

- `String toLowerCase()`: Chuyển tất cả ký tự trong string này thành chữ thường.

- `String toUpperCase()`: Chuyển tất cả ký tự trong string này thành chữ hoa.

- `boolean equals(Object anObject)`: So sánh string này với object được chỉ định.

- `boolean equalsIgnoreCase(String anotherString)`: So sánh string này với một string khác, bỏ qua yếu tố chữ hoa/chữ thường.

- `boolean startsWith(String prefix)`: Kiểm tra xem string này có bắt đầu bằng prefix được chỉ định hay không.

- `boolean endsWith(String suffix)`: Kiểm tra xem string này có kết thúc bằng suffix được chỉ định hay không.

- `boolean contains(CharSequence s)`: Trả về `true` khi và chỉ khi string này chứa chuỗi `char` được chỉ định.

- `String replace(char oldChar, char newChar)`: Trả về một string mới là kết quả của việc thay thế tất cả lần xuất hiện của `oldChar` trong string này bằng `newChar`.

- `String strip()`: Trả về một string có giá trị là string này với toàn bộ white space ở đầu và cuối được loại bỏ.

- `String trim()`: Trả về một string có giá trị là string này với toàn bộ space ở đầu và cuối được loại bỏ, trong đó space được định nghĩa là bất kỳ ký tự nào có codepoint nhỏ hơn hoặc bằng `'U+0020'` (ký tự space).

- `String indent(int n)`: Điều chỉnh thụt lề của từng dòng trong string này dựa trên giá trị của `n`.

- `String stripIndent()`: Trả về một string có giá trị là string này với incidental whitespace được loại bỏ khỏi đầu và cuối của mỗi dòng.

- `boolean isEmpty()`: Trả về `true` khi và chỉ khi `length()` bằng 0.

- `boolean isBlank()`: Trả về `true` nếu string rỗng hoặc chỉ chứa các codepoint white space, ngược lại trả về `false`.

Mỗi method trong số này đều mang một công dụng riêng, và cùng nhau chúng tạo thành một bộ công cụ mạnh mẽ để làm việc với string. Tuy nhiên, hãy nhớ rằng do tính immutable của string, những method có kiểu trả về là `String` sẽ trả về một string mới thay vì sửa đổi string gốc. Ví dụ:

```java
String s1 = "  Hello World   ";
String s2 = s1.strip();
System.out.println(s1);  // Still prints "  Hello World   "
System.out.println(s2);  // Prints "Hello World"
```

Điều này cũng cho phép một kỹ thuật gọi là method chaining, trong đó nhiều method được gọi trong cùng một biểu thức.

```java
String result = "  Hello World  ".trim().toUpperCase().replace('O', '0');
System.out.println(result);  // Prints "HELL0 W0RLD"
```

Ở đây, string gốc được trim hết whitespace, sau đó chuyển thành chữ hoa, và cuối cùng tất cả ký tự `'O'` được thay bằng `'0'`. Mỗi method trả về một string mới, và string đó trở thành đối tượng để method tiếp theo trong chuỗi thao tác lên.

Method chaining có thể giúp code ngắn gọn và dễ đọc hơn, nhưng đừng lạm dụng quá mức. Những chuỗi quá dài có thể khó hiểu và khó debug.

Ngoài ra, một số method trong đây làm việc với index. Index chạy từ 0 đến `length()` - 1. Giá trị char đầu tiên của chuỗi nằm ở index 0, ký tự tiếp theo ở index 1, cứ như vậy, hoàn toàn giống với cách array hoạt động.

### Overriding `toString()` {#overriding-tostring}

Một method đặc biệt cần lưu ý là `toString()`. Method này được định nghĩa trong class `Object`, mà mọi class trong Java đều kế thừa. Nó trả về một string biểu diễn object.

Theo mặc định, string này không mang nhiều thông tin (nó chỉ gồm tên class của object và hash code). Tuy nhiên, chúng ta có thể override `toString()` trong class của riêng mình để cung cấp một biểu diễn hữu ích hơn.

```java
public class Person {
    private String name;
    private int age;

    // Constructor and other methods...

    @Override
    public String toString() {
        return "Person[name=" + name + ",age=" + age + "]";
    }
}
```

Giờ đây, khi in một object `Person`, chúng ta sẽ nhận được một string được định dạng đẹp đẽ:

```java
Person alice = new Person("Alice", 25);
System.out.println(alice);  // Prints "Person[name=Alice,age=25]"
```

Điều này đặc biệt hữu ích cho mục đích logging và debugging.

### Định dạng String {#formatting-strings}

Ngoài việc thao tác string, Java còn cung cấp những công cụ mạnh mẽ để định dạng string. Class `String` bao gồm các method `format()` và `formatted()`, cho phép bạn tạo một string đã định dạng từ một format string và các argument.

```java
String name = "Alice";
int age = 25;
String city = "Florida";
String formatted = String.format("My name is %s, I'm %d years old, and I live in %s.", name, age, city);
System.out.println(formatted);
// Prints "My name is Alice, I'm 25 years old, and I live in Florida."
```

Format string chứa các placeholder (`%s` cho string, `%d` cho integer, v.v.) và chúng được thay bằng các argument tương ứng.

Dưới đây là một số placeholder định dạng phổ biến nhất:

| Format Specifier   | Mô tả |
|--------------------|-------------|
| `%s`               | String      |
| `%c`               | Character   |
| `%d`               | Decimal integer |
| `%f`               | Floating-point number |
| `%t`               | Date/time   |
| `%n`               | Newline     |

Đây chỉ là một vài ví dụ, [danh sách đầy đủ các tùy chọn định dạng](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Formatter.html#syntax) khá đồ sộ, cho phép kiểm soát chính xác định dạng output.

### Sử dụng class `StringBuilder` {#using-the-stringbuilder-class}

Dù class `String` rất mạnh mẽ, tính immutable của nó có thể gây ra vấn đề hiệu năng khi bạn cần sửa đổi string nhiều lần. Đây chính là lúc `StringBuilder` phát huy tác dụng.

`StringBuilder` là một chuỗi ký tự có thể thay đổi (mutable). Nó cung cấp các method tương tự `String` để thêm vào cuối, chèn và xóa ký tự. Tuy nhiên, những method này sửa đổi chính `StringBuilder` thay vì tạo ra một object mới.

Tính mutable này giúp code hiệu quả hơn khi bạn cần sửa đổi string nhiều lần. Với `String`, mỗi lần sửa đổi lại tạo một string object mới, có thể tốn kém cả thời gian lẫn bộ nhớ nếu làm thường xuyên, chẳng hạn trong vòng lặp. `StringBuilder` tránh điều này bằng cách sửa đổi trực tiếp chuỗi ký tự bên trong của nó.

Hơn nữa, các method của `StringBuilder` có thể được nối chuỗi với nhau, tương tự như method của `String`. Tuy nhiên, vì `StringBuilder` là mutable, mỗi method trong chuỗi thao tác lên cùng một instance `StringBuilder` và trả về reference tới chính nó, cho phép nối tiếp chuỗi thao tác:

```java
StringBuilder sb = new StringBuilder("Hello");
sb.append(" World").insert(0, "Hey, ").delete(4, 10);
System.out.println(sb);  // Prints "Hey, World"
```

Trong ví dụ này, chúng ta bắt đầu với một `StringBuilder` chứa `"Hello"`. Sau đó thêm `" World"` vào cuối, chèn `"Hey, "` vào đầu, và xóa các ký tự từ index 4 đến 9 (bao gồm cả hai đầu). Mỗi thao tác này đều sửa đổi cùng một instance `StringBuilder`.

Bạn có thể tạo `StringBuilder` theo một vài cách:

```java
StringBuilder sb1 = new StringBuilder();  // Creates an empty StringBuilder
StringBuilder sb2 = new StringBuilder(10);  // Creates a StringBuilder with initial capacity of 10
StringBuilder sb3 = new StringBuilder("Hello");  // Creates a StringBuilder initialized with the string "Hello"
```

Khi bạn tạo một `StringBuilder` mà không chỉ định string ban đầu, nó khởi tạo với capacity mặc định là 16 ký tự. Nếu biết rằng mình sẽ xây dựng một string lớn hơn, bạn có thể chỉ định capacity ban đầu cao hơn để tránh việc tự động mở rộng về sau, vốn có thể tốn kém.

### Các method quan trọng của `StringBuilder` {#important-stringbuilder-methods}

`StringBuilder` cung cấp nhiều method giống `String` để xem xét và sửa đổi chuỗi ký tự, tuy nhiên có hai điều đáng lưu ý:
- Những method này sửa đổi chính instance `StringBuilder` thay vì tạo ra một instance mới.
- `StringBuilder` không kế thừa từ `String`, tuy nhiên cả hai class đều kế thừa từ interface [CharSequence](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/CharSequence.html).

**Các method chung với `String`:**
- `int length()`: Trả về số ký tự trong `StringBuilder`.
- `char charAt(int index)`: Trả về ký tự tại vị trí được chỉ định.
- `int indexOf(String str)`: Trả về index trong string này của lần xuất hiện đầu tiên của substring được chỉ định.
- `String substring(int start)` and `substring(int start, int end)`: Trả về một string mới là substring của chuỗi này.

**Thêm giá trị vào cuối:**
- `StringBuilder append(...)`: Thêm biểu diễn string của argument vào chuỗi. Có các overload cho mọi primitive type, array `char`, `CharSequence` và `Object`.

**Chèn dữ liệu:**
- `StringBuilder insert(int offset, ...)`: Chèn biểu diễn string của argument thứ hai vào chuỗi tại vị trí được chỉ định bởi argument đầu tiên. Có các overload cho mọi primitive type, array `char`, `CharSequence` và `Object`.

**Xóa nội dung:**
- `StringBuilder delete(int start, int end)`: Xóa các ký tự trong một substring của chuỗi này.
- `StringBuilder deleteCharAt(int index)`: Xóa char tại vị trí được chỉ định.

**Thay thế một phần:**
- `StringBuilder replace(int start, int end, String str)`: Thay thế các ký tự trong một substring của chuỗi này bằng các ký tự trong string được chỉ định.
- `setCharAt(int index, char ch)`: Đặt ký tự tại index được chỉ định thành `ch`.

**Đảo ngược:**
- `void StringBuilder reverse()`: Khiến chuỗi ký tự này bị thay bằng chuỗi đảo ngược của chính nó.

**Chuyển đổi thành `String`:**
- `String toString()`: Trả về một string biểu diễn dữ liệu trong chuỗi này.

Đây là một ví dụ minh họa một vài method trong số đó:

```java
StringBuilder sb = new StringBuilder("Hello");
sb.append(" there");  // Now contains "Hello there"
sb.insert(5, ",");  // Now contains "Hello, there"
sb.replace(7, 12, "world");  // Now contains "Hello, world"
sb.delete(5, 7);  // Now contains "Helloworld"
sb.reverse();  // Now contains "dlrowolleH"

String finalString = sb.toString();
System.out.println(finalString);  // Prints "dlrowolleH"
```

Trong ví dụ này, chúng ta bắt đầu với `StringBuilder` chứa `"Hello"`, sau đó thêm `" there"` vào cuối, chèn dấu phẩy sau `"Hello"`, thay `"there"` bằng `"world"`, xóa dấu phẩy và dấu cách, đảo ngược toàn bộ string, và cuối cùng chuyển nó thành `String`.

Điều quan trọng cần lưu ý là dù `StringBuilder` là mutable, nó không được synchronized. Nếu nhiều thread cùng truy cập một instance `StringBuilder` một cách đồng thời và có ít nhất một thread đang sửa đổi nó, bạn nên đảm bảo đồng bộ hóa đúng cách trong code để tránh hỏng dữ liệu. Nếu cần một phiên bản thread-safe, bạn có thể dùng `StringBuffer`, tương tự `StringBuilder` nhưng được synchronized (đổi lại là một chút chi phí hiệu năng).

Cuối cùng, đây là sơ đồ tóm tắt sự khác biệt giữa `String` và `StringBuilder`:
```
┌───────────────────────────────────────────────────┐
│           String vs StringBuilder                 │
│                                                   │
│  ┌─────────────────────┐ ┌─────────────────────┐  │
│  │       String        │ │    StringBuilder    │  │
│  ├─────────────────────┤ ├─────────────────────┤  │
│  │ - Immutable         │ │ - Mutable           │  │
│  │ - Thread-safe       │ │ - Not thread-safe   │  │
│  │ - Slower for        │ │ - Faster for        │  │
│  │   concatenation     │ │   concatenation     │  │
│  │ - Less memory       │ │ - More memory       │  │
│  │   efficient for     │ │   efficient for     │  │
│  │   many modifications│ │   many modifications│  │
│  └─────────────────────┘ └─────────────────────┘  │
│                                                   │
│  Use for:               Use for:                  │
│  - Constant strings     - Building strings        │
│  - Simple concatenation - Many modifications      │
│  - Thread safety needed - Performance critical    │
│                           string operations       │
└───────────────────────────────────────────────────┘
```


## Text Block {#text-blocks}
Text block cung cấp một cú pháp ngắn gọn và trực quan hơn để biểu diễn string, giữ nguyên newline và thụt lề mà không cần dùng escape sequence hay concatenation một cách tường minh:
```java
String traditional = "{\n" +
                     "  \"name\": \"John Doe\",\n" +
                     "  \"age\": 30\n" +
                     "}";

String textBlock = """
                   {
                     "name": "John Doe",  
                     "age": 30
                   }
                   """;
```

Như bạn thấy, phiên bản dùng text block sạch sẽ và dễ đọc hơn nhiều. Nó loại bỏ hết sự rối rắm của các ký tự newline (`\n`) và dấu ngoặc kép escape (`\"`) vốn làm string literal truyền thống trở nên lộn xộn. Với text block, thấy sao được vậy, string xuất hiện trong code đúng như khi được output.

Để định nghĩa một text block, bạn dùng ba dấu ngoặc kép (`"""`) làm delimiter mở và đóng. Nội dung của text block nằm giữa hai delimiter này và có thể trải dài trên nhiều dòng:
```java
String textBlock = """
                   This is a Text Block.
                   It can contain multiple lines,
                     indentation,
                   and "special" characters.
                   """;
```

Lưu ý rằng delimiter đóng (`"""`) phải nằm trên một dòng riêng và theo sau là dấu chấm phẩy. Mọi whitespace sau delimiter đóng trên dòng đó sẽ bị bỏ qua.

Một hiểu lầm phổ biến là bạn có thể dùng một dấu ngoặc kép đơn để đóng một text block được mở bằng ba dấu ngoặc kép. Tuy nhiên, điều này không đúng. Delimiter mở và đóng của text block luôn phải là ba dấu ngoặc kép (`"""`).

Compiler coi mọi nội dung giữa hai delimiter là một phần của string literal, bao gồm newline, thụt lề và mọi whitespace khác. Tuy nhiên, có một vài quy tắc về thụt lề và escaping mà chúng ta sẽ bàn ngay sau đây.

### Các tính năng của Text Block {#features-of-text-blocks}
Một trong những tính năng chính của text block là khả năng biểu diễn string nhiều dòng một cách tự nhiên, không cần viện đến ký tự newline tường minh hay concatenation string.
```java
String multiLine = """
                   First line
                   Second line
                   Third line
                   """;
```

Text block này sẽ giữ nguyên newline và thụt lề đúng như khi viết, tạo ra một string gồm ba dòng văn bản. Bạn không cần thêm ký tự `\n` thủ công hay phải lo căn chỉnh các string được nối với nhau.

Text block cũng tự động xử lý thụt lề dựa trên vị trí của delimiter đóng. Compiler sẽ xác định một whitespace prefix chung từ các dòng giữa hai delimiter và tự động loại bỏ prefix đó khỏi từng dòng.
```java
String indented = """
                    Line 1
                      Line 2
                    Line 3
                    """;

// Equivalent to:
// "Line 1\n  Line 2\nLine 3\n"
```

Trong ví dụ này, delimiter đóng được căn thẳng với dòng ít thụt lề nhất (`Line 1`). Do đó, whitespace prefix chung là bốn dấu cách, và nó bị loại bỏ khỏi mỗi dòng. String thu được sẽ có `Line 2` thụt vào hai dấu cách so với các dòng còn lại.

Điều quan trọng cần lưu ý là text block không tự động trim toàn bộ whitespace ở đầu và cuối. Compiler chỉ loại bỏ whitespace prefix chung dựa trên vị trí của delimiter đóng. Mọi whitespace đầu hoặc cuối thêm vào đều được giữ nguyên trong string cuối cùng.

Xét ví dụ sau:
```java
String traditional = "  \n  ";  // This evaluates to two spaces, a newline, and two more spaces.
String textBlock = """
                     \n  
                   """;        // Evaluates to two spaces, a newline, two spaces, 
                               // and an additional final newline added by the text block syntax.

```

Ở đây, string `traditional` sẽ bao gồm các dấu cách trước và sau newline vì chúng là một phần tường minh của string. Trong `textBlock`, tất cả dấu cách và newline được giữ nguyên như khi xuất hiện, và một newline được thêm vào ở cuối do cách text block xử lý delimiter đóng.

Một khía cạnh quan trọng khác của text block là escaping các ký tự đặc biệt. Các quy tắc escaping trong text block phần lớn giống với string literal truyền thống, với một vài lưu ý:
- Một dấu ngoặc kép đơn hoặc một cặp dấu ngoặc kép trong text block không cần escape.
- Ba dấu ngoặc kép trong text block cần được escape để tránh chúng kết thúc block sớm.
- Để đưa ký tự backslash (`\`) vào text block, bạn cần escape nó bằng một backslash khác (`\\`).

Đây là một ví dụ:
```java
String escaped = """
                 This is a "quoted" text with \\ and \u0040.
                 """;
```

Một hiểu lầm phổ biến là backslash bị bỏ qua trong text block vì đây là literal nhiều dòng. Tuy nhiên, điều này không đúng. Backslash vẫn giữ ý nghĩa đặc biệt trong text block và cần được escape nếu bạn muốn đưa một backslash theo nghĩa literal vào string.

Và như bạn thấy trong ví dụ trên, text block cũng hỗ trợ dùng Unicode escape (`\uXXXX`) để biểu diễn ký tự theo Unicode code point của chúng.

Cuối cùng, text block có thể được kết hợp với string literal truyền thống và thậm chí cả những text block khác bằng operator `+`, giống như string thông thường:
```java
String name = "John";
String greeting = """
                  Hello, """ + name + """
                  . How are you?
                  """;
```

Ở đây, chúng ta nối một text block với một string literal truyền thống (`name`) để tạo lời chào cá nhân hóa. Operator `+` nằm cùng dòng với delimiter mở và đóng của các text block. Đặt nó trên một dòng riêng có thể dẫn đến whitespace ngoài ý muốn trong string kết quả.



## Math API {#the-math-api}
`Math` API cung cấp một bộ phong phú các static method để thực hiện các phép toán. Nó bao gồm các method tìm giá trị nhỏ nhất và lớn nhất của hai giá trị, làm tròn số, xác định ceiling và floor của một giá trị, và sinh số ngẫu nhiên. Hãy cùng xem xét từng nhóm.

### Tìm giá trị nhỏ nhất và lớn nhất {#finding-the-minimum-and-maximum}

Class `Math` cung cấp các method `min` và `max` để tìm giá trị nhỏ nhất và lớn nhất của hai giá trị. Những method này được overload để nhận các argument `int`, `long`, `float` và `double`:

```java
static double max(double a, double b)
static float max(float a, float b)
static int max(int a, int b)
static long max(long a, long b)

static double min(double a, double b)
static float min(float a, float b)
static int min(int a, int b)
static long min(long a, long b)
```

Dưới đây là một số ví dụ:

```java
int min = Math.min(5, 10);  // min is 5
int max = Math.max(5, 10);  // max is 10

double min2 = Math.min(5.7, 10.2);  // min2 is 5.7
double max2 = Math.max(5.7, 10.2);  // max2 is 10.2
```

Những method này hữu ích khi bạn cần ràng buộc một giá trị trong một khoảng nhất định.

### Làm tròn số {#rounding-numbers}

Class `Math` cung cấp một số method để làm tròn số:

- `int round(float)` và `long round(double)`: Những method này trả về `int` hoặc `long` gần nhất với argument. Các giá trị nằm giữa (như 0.5) được làm tròn lên, theo quy ước round half up.
- `double rint(double)`: Trả về giá trị `double` gần nhất với argument và bằng một số nguyên toán học. Nếu hai giá trị `double` là số nguyên toán học có khoảng cách bằng nhau, giá trị chẵn sẽ được chọn.
- `double floor(double)`: Trả về giá trị `double` lớn nhất (gần dương vô cực nhất) nhỏ hơn hoặc bằng argument và bằng một số nguyên toán học.
- `double ceil(double)`: Trả về giá trị `double` nhỏ nhất (gần âm vô cực nhất) lớn hơn hoặc bằng argument và bằng một số nguyên toán học.

Dưới đây là một số ví dụ:

```java
long roundedLong = Math.round(5.7);  // roundedLong is 6
int roundedInt = Math.round(5.4f);  // roundedInt is 5

double rintValue = Math.rint(5.5);  // rintValue is 6.0 (ties round to even)
double rintValue2 = Math.rint(6.5);  // rintValue2 is 6.0

double floorValue = Math.floor(5.7);  // floorValue is 5.0
double ceilingValue = Math.ceil(5.2);  // ceilingValue is 6.0
```

Như bạn thấy, floor là số nguyên lớn nhất nhỏ hơn hoặc bằng giá trị đã cho, còn ceiling là số nguyên nhỏ nhất lớn hơn hoặc bằng giá trị đó.

### Sinh số ngẫu nhiên {#generating-random-numbers}

Class `Math` bao gồm một method `random()` trả về giá trị `double` mang dấu dương, lớn hơn hoặc bằng 0.0 và nhỏ hơn 1.0:
```java
static double random()
```

Method này hữu ích để sinh số ngẫu nhiên.

```java
double randomValue = Math.random();  // randomValue is a random double between 0.0 and 1.0
```

Bạn có thể dùng `Math.random()` kết hợp với các method khác của `Math` để sinh số ngẫu nhiên trong một khoảng cụ thể. Ví dụ, để sinh một số nguyên ngẫu nhiên trong khoảng từ 1 đến 10 (bao gồm cả hai đầu), bạn có thể làm như sau:

```java
int randomInt = (int)(Math.random() * 10) + 1;
```

Cách nó hoạt động như sau:
1. `Math.random()` sinh một double ngẫu nhiên trong khoảng từ 0.0 đến 1.0, tạm gọi là `r`.
2. `r * 10` khi đó là một double ngẫu nhiên trong khoảng từ 0.0 đến 10.0.
3. `(int)(r * 10)` cast double này thành int, thực chất là làm tròn xuống. Như vậy ta có một số nguyên ngẫu nhiên trong khoảng từ 0 đến 9.
4. Cuối cùng, ta cộng thêm 1 để dịch khoảng giá trị thành từ 1 đến 10.

Bạn có thể điều chỉnh công thức này để sinh số ngẫu nhiên trong bất kỳ khoảng số nguyên nào. Ví dụ, để sinh một số ngẫu nhiên trong khoảng từ `min` đến `max` (bao gồm cả hai đầu), bạn có thể dùng:

```java
int randomNum = (int)(Math.random() * (max - min + 1)) + min;
```


## Các điểm chính {#key-points}
- Java có 8 primitive data type: `byte`, `short`, `int`, `long`, `float`, `double`, `boolean` và `char`.

- Primitive type là những kiểu dữ liệu cơ bản nhất và không phải là object. Chúng lưu trữ các giá trị đơn giản trực tiếp trong bộ nhớ.

- Integer literal có thể được gán bằng ký pháp thập phân, thập lục phân (tiền tố `0x` hoặc `0X`), bát phân (tiền tố `0`) hoặc nhị phân (tiền tố `0b` hoặc `0B`).

- Dấu gạch dưới có thể được dùng trong numeric literal để dễ đọc hơn nhưng có những hạn chế về vị trí đặt chúng.

- Reference type lưu địa chỉ bộ nhớ nơi một object nằm, chứ không lưu chính object đó.

- Wrapper class (`Boolean`, `Byte`, `Short`, `Integer`, `Long`, `Float`, `Double`, `Character`) cho phép dùng primitive như object.

- Autoboxing tự động chuyển một primitive thành wrapper class tương ứng, còn unboxing chuyển một wrapper object thành primitive type của nó.

- Wrapper class cung cấp các method để parsing, chuyển đổi giữa các kiểu, v.v.

- Wrapper object có thể là `null`, còn primitive thì không. Unboxing một wrapper object `null` sẽ throw `NullPointerException`.

- Java cung cấp một bộ phong phú các operator cho các phép toán số học, logic và bitwise.

- Operator precedence quyết định thứ tự tính toán trong biểu thức. Dấu ngoặc đơn có thể thay đổi precedence mặc định.

- Unary operator (`++`, `--`, `+`, `-`, `~`, `!`) tác động lên một operand duy nhất. Increment và decrement operator (`++` và `--`) có thể được dùng ở dạng prefix hoặc postfix.

- Binary operator (`+`, `-`, `*`, `/`, `%`) tác động lên hai operand. Numeric promotion tự động chuyển các operand sang kiểu lớn hơn để tránh mất độ chính xác.

- Bitwise operator (`&`, `|`, `^`, `~`) và shift operator (`<<`, `>>`, `>>>`) thao tác trên từng bit của các giá trị integer.

- Assignment operator (`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `^=`, `|=`, `<<=`, `>>=`, `>>>=`) gán giá trị cho biến. Compound assignment operator kết hợp một phép toán với phép gán.

- Equality operator (`==` và `!=`) so sánh các giá trị để kiểm tra bằng nhau. Với object, `==` so sánh reference, còn equals() so sánh nội dung.

- Relational operator (`<`, `>`, `<=`, `>=`) so sánh các giá trị và xác định mối quan hệ giữa chúng.

- Logical operator (`&`, `|`, `^`, `&&`, `||`, `!`) thực hiện các phép toán logic trên biểu thức boolean. Short-circuit operator (`&&` và `||`) có thể bỏ qua việc tính toán operand thứ hai dựa trên giá trị của operand thứ nhất.

- String trong Java là immutable, nghĩa là giá trị của chúng không thể thay đổi sau khi được tạo. Mọi thao tác có vẻ như sửa đổi string thực ra đều tạo ra một string mới.

- String literal được lưu trong string pool, một vùng bộ nhớ đặc biệt. Nếu một string tương đương đã tồn tại trong pool, một reference đến string đó sẽ được trả về thay vì tạo object mới.

- String có thể được nối bằng operator `+` hoặc method `concat()`. Operator `+` được compiler tối ưu thành thao tác trên `StringBuilder`.

- Class `String` cung cấp nhiều method để kiểm tra và thao tác nội dung string, như `length()`, `charAt()`, `substring()`, `toLowerCase()`, `equals()`, `startsWith()`, `endsWith()`, `replace()`, `trim()`, v.v.

- Method `toString()`, được kế thừa từ class `Object`, trả về biểu diễn string của một object. Nó có thể được override trong các class tùy chỉnh để cung cấp biểu diễn chứa nhiều thông tin hơn.

- Class `String` cung cấp các method `format()` và `formatted()` để tạo string được định dạng bằng placeholder.

- `StringBuilder` là một chuỗi ký tự có thể thay đổi (mutable). Nó cung cấp các method tương tự `String` để append, insert và delete ký tự, nhưng những method này sửa đổi chính `StringBuilder` thay vì tạo object mới.

- `StringBuilder` hiệu quả hơn `String` khi cần thực hiện nhiều thay đổi, vì nó tránh việc tạo object mới cho mỗi lần sửa đổi.

- Các method quan trọng của `StringBuilder` gồm `append()`, `insert()`, `delete()`, `replace()`, `reverse()` và `toString()`.

- Text block cung cấp cú pháp ngắn gọn và trực quan hơn để biểu diễn string nhiều dòng. Chúng được định nghĩa bằng ba dấu ngoặc kép (`"""`) làm delimiter.

- Text block tự động xử lý newline, thụt lề và whitespace prefix chung, giúp chúng dễ đọc và dễ viết hơn string literal truyền thống.

- Class `Math` cung cấp nhiều static method để thực hiện các phép toán, bao gồm `min()`, `max()`, `round()`, `floor()`, `ceil()` và `random()`.

- Method `random()` có thể được dùng kết hợp với các method khác của `Math` để sinh số ngẫu nhiên trong một khoảng cụ thể.
