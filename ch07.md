## Tìm hiểu Exception {#understanding-exceptions}
Chạy được một chương trình không đồng nghĩa với việc chạy chương trình đó một cách đúng đắn. Bất kỳ chương trình nào không tầm thường đều có thể gặp lỗi. Lỗi từ input của người dùng, các phép toán, việc truy cập tài nguyên, v.v. 

Đó là lúc exception xuất hiện. Exception biểu thị một tình huống bất thường hay ngoại lệ nào đó làm gián đoạn luồng chạy bình thường của chương trình.

Khi một tình huống ngoại lệ xảy ra, ta nói rằng một exception đã được *thrown*. Khi điều này xảy ra, luồng chạy bình thường của chương trình bị gián đoạn và việc thực thi được chuyển đến một block code đặc biệt gọi là exception handler, nếu tồn tại một handler cho exception đó.

Mục đích của exception là xử lý những lỗi này một cách êm đẹp và ngăn chương trình bị crash hay hành xử bất ngờ. Nhờ dùng exception, bạn có thể tách code xử lý lỗi ra khỏi logic bình thường của chương trình, giúp code sạch sẽ và dễ quản lý hơn.

Exception không nhất thiết dừng toàn bộ chương trình khi chúng xảy ra. Khi một exception được throw, nó được lan truyền lên call stack cho đến khi bị bắt và xử lý bởi một exception handler. Nếu không tìm thấy handler phù hợp, chương trình sẽ kết thúc. Nhưng nếu bạn có sẵn một block `try-catch` để xử lý exception, chương trình của bạn có thể giải quyết vấn đề và tiếp tục chạy.

### Tìm hiểu các loại Exception {#understanding-exception-types}
Hầu hết các exception class phổ biến trong Java đều là subtype của class `java.lang.Exception`. Nhưng đó chưa phải là toàn bộ câu chuyện. Để thực sự hiểu về exception, chúng ta cần nhìn vào hệ thống phân cấp exception (exception hierarchy):
```
                         ┌───────────┐
                         │ Throwable │
                         └─────┬─────┘
                               │
                   ┌───────────┴───────────┐
                   │                       │
           ┌───────────────┐       ┌───────────────┐
           │   Exception   │       │     Error     │
           └───────┬───────┘       └───────────────┘
                   │
       ┌───────────┴───────────┐
       │                       │
┌──────────────────┐   ┌───────────────────┐
│ RuntimeException │   │ Checked Exceptions│
└──────────────────┘   └───────────────────┘
```

Đứng đầu hệ thống phân cấp là class `java.lang.Throwable`. Bên dưới `Throwable` có hai nhánh: `Exception` và `Error`. Dù nghe có vẻ giống nhau, chúng thực chất đại diện cho những thứ khá khác biệt trong Java.

Exception là những tình huống mà một ứng dụng hợp lý có thể muốn bắt và xử lý. Chúng thường đại diện cho các tình huống tuy không phổ biến nhưng cũng không hoàn toàn bất ngờ. Ví dụ, cố mở một file không tồn tại sẽ throw một `FileNotFoundException`.

Ngược lại, Error không được thiết kế để chương trình của bạn bắt hay xử lý. Chúng biểu thị những vấn đề nghiêm trọng mà một ứng dụng hợp lý không nên cố bắt. Hầu hết những error như vậy đều là các tình huống bất thường. Ví dụ, nếu ứng dụng của bạn hết bộ nhớ, một `OutOfMemoryError` sẽ được throw.

Bên dưới class `Exception` còn có hai phạm trù nữa: checked exception và unchecked exception (còn được gọi là runtime exception vì chúng kế thừa từ `java.lang.RuntimeException`).

Checked exception là những tình huống ngoại lệ mà một ứng dụng được viết tốt nên lường trước và xử lý. Đây thường là những exception nằm ngoài tầm kiểm soát của chương trình, chẳng hạn file không được tìm thấy, kết nối mạng thất bại, hoặc input của người dùng không hợp lệ. Checked exception là subclass của `Exception` nhưng không phải của `RuntimeException`.

Unchecked exception là những tình huống ngoại lệ mà ứng dụng thường không thể lường trước hay khôi phục. Chúng thường biểu thị bug trong lập trình, chẳng hạn lỗi logic hoặc dùng API không đúng cách. Unchecked exception là subclass của `RuntimeException`.

Dù có vẻ như unchecked exception là đủ, checked exception vẫn phục vụ một mục đích quan trọng. Chúng buộc lập trình viên phải xử lý exception, đảm bảo rằng code xử lý lỗi đúng đắn được viết ra. Điều này dẫn đến code chắc chắn và đáng tin cậy hơn.

Mặt khác, unchecked exception không cần được khai báo trong mệnh đề `throws` của method nếu chúng có thể được throw khi method thực thi. Chúng thường đại diện cho các khiếm khuyết trong chương trình (bug), và vì thế, không thể kỳ vọng một cách hợp lý rằng code client của API sẽ khôi phục hay xử lý chúng theo bất kỳ cách nào. Những exception như vậy hầu như luôn biểu thị khiếm khuyết trong lập trình, và unchecked exception là cách ngôn ngữ lập trình Java cho phép developer chỉ ra một khiếm khuyết tiềm ẩn mà compiler không thể dễ dàng phát hiện.

### Throw một Exception {#throwing-an-exception}
Đến giờ, chúng ta đã nói về exception là gì và các loại exception khác nhau. Nhưng thực tế exception được throw như thế nào?

Một exception có thể được throw theo hai cách: tự động bởi Java runtime system, hoặc một cách tường minh bởi code của bạn.

Nhiều exception được throw tự động bởi Java runtime system. Ví dụ, nếu bạn cố truy cập một phần tử array với index nằm ngoài phạm vi, một `ArrayIndexOutOfBoundsException` sẽ được throw. Nếu bạn cố chia một số cho zero, một `ArithmeticException` sẽ được throw.

Nhưng bạn cũng có thể throw exception một cách tường minh trong code của mình bằng câu lệnh `throw`. Dạng tổng quát của câu lệnh `throw` là:

```java
throw new ExceptionType(messageString);
```

Ở đây, `ExceptionType` là loại exception bạn muốn throw, và `messageString` là một string tùy chọn cung cấp thêm thông tin về exception.

Ví dụ, giả sử bạn có một method nhận tham số integer age. Nếu giá trị age được truyền vào là số âm, bạn có thể muốn throw một exception:

```java
public void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Age cannot be negative");
    }
    // rest of the method
}
```

Trong trường hợp này, chúng ta đang throw một `IllegalArgumentException`, một loại unchecked exception.

Có nhiều trường hợp việc bạn throw exception trong code của chính mình là phù hợp, thậm chí cần thiết.

Bằng cách throw exception, bạn có thể báo hiệu rằng một lỗi đã xảy ra và cung cấp thông tin về việc sai ở đâu. Điều này đặc biệt quan trọng khi bạn viết method hoặc class sẽ được các developer khác sử dụng. Bằng cách throw exception, bạn có thể thông báo cho người dùng code của mình rằng họ đã dùng method hoặc class của bạn không đúng cách, hoặc rằng có gì đó đã sai và họ cần xử lý.

Hơn nữa, bằng cách throw exception, bạn có thể tách code xử lý lỗi ra khỏi luồng chạy bình thường của chương trình. Điều này giúp code của bạn dễ đọc và dễ bảo trì hơn.

### Custom Exception {#custom-exceptions}
Dù Java cung cấp một bộ exception built-in phong phú, có những tình huống mà việc tạo custom exception của riêng bạn có thể mang lại lợi ích.

Custom exception cho phép bạn thêm nhiều ngữ cảnh và ý nghĩa hơn cho các exception được throw bởi ứng dụng của bạn. Chúng có thể giúp đóng gói (encapsulate) tốt hơn các tình huống lỗi đặc thù trong domain ứng dụng của bạn.

Ví dụ, nếu bạn đang viết một library để parse file XML, bạn có thể định nghĩa một custom exception `XMLFileParseException` và throw nó mỗi khi có lỗi khi parse file XML. Điều này thông báo cho người dùng library của bạn chính xác điều gì đã sai, thay vì chỉ throw một `Exception` chung chung.

Để tạo một custom checked exception, bạn chỉ cần kế thừa class `Exception` (hoặc một trong các subclass của nó):

```java
public class XMLFileParseException extends Exception {
    public XMLFileParseException(String message) {
        super(message);
    }
}
```

Để tạo một custom unchecked exception, bạn kế thừa class `RuntimeException` (hoặc một trong các subclass của nó):

```java
public class InvalidInputException extends RuntimeException {
    public InvalidInputException(String message) {
        super(message);
    }
}
```

Sau đó bạn có thể throw custom exception của mình giống như bất kỳ exception nào khác:

```java
throw new XMLFileParseException("Error parsing XML file: " + fileName);
throw new InvalidInputException("Input cannot be negative");
```

Khi quyết định custom exception của bạn nên là checked hay unchecked, hãy cân nhắc các hướng dẫn sau:

- Dùng checked exception cho những tình huống ngoại lệ mà caller nên khôi phục. Đây thường là những tình huống nằm ngoài tầm kiểm soát của chương trình, chẳng hạn file không được tìm thấy hoặc kết nối mạng thất bại.

- Dùng unchecked exception (kế thừa `RuntimeException`) cho những tình huống ngoại lệ mà caller thường không thể khôi phục. Đây thường là dấu hiệu của lỗi lập trình, chẳng hạn cố truy cập một phần tử array với index ngoài phạm vi.

Một điều khác cần cân nhắc khi tạo custom exception là serialization. Nếu class exception của bạn sẽ được throw qua các JVM khác nhau (ví dụ, trong một hệ thống phân tán), nó nên implement interface `java.io.Serializable`.

```java
public class RemoteServiceException extends Exception implements Serializable {
    // ...
}
```

Điều này đảm bảo rằng exception object có thể được serialize và deserialize thành công khi nó được truyền qua mạng.

Cuối cùng, khi tạo custom exception, cung cấp các constructor nhận một message string và một cause exception là một thực hành tốt. Cause là exception đã kích hoạt exception của bạn. Điều này cho phép bạn wrap các exception cấp thấp hơn trong custom exception cấp cao hơn của mình, qua đó cung cấp thêm ngữ cảnh về lỗi.

```java
public class DataAccessException extends Exception {
    public DataAccessException(String message) {
        super(message);
    }
    
    public DataAccessException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

Sau đó bạn có thể dùng nó như sau:

```java
try {
    // some database operation that throws a SQLException
} catch (SQLException ex) {
    throw new DataAccessException("Error accessing database", ex);
}
```

Bằng cách này, caller của code bạn biết rằng một `DataAccessException` đã xảy ra, nhưng vẫn có thể truy cập cause bên dưới (là `SQLException`) nếu cần để xử lý lỗi hoặc ghi log chi tiết hơn.


### Exception và method {#exceptions-and-methods}
Khi một method throw một exception, nó phải khai báo điều này trong method signature. Việc này được thực hiện bằng keyword `throws`, theo sau là danh sách các exception mà method có thể throw.

```java
public void readFile(String fileName) throws FileNotFoundException {
    // code that might throw a FileNotFoundException
}
```

Trong ví dụ này, method `readFile` khai báo rằng nó có thể throw một `FileNotFoundException`.

Tuy nhiên, không phải mọi exception đều cần được khai báo trong method signature. Chỉ checked exception mới cần được khai báo. Unchecked exception (những exception kế thừa `RuntimeException`) thì không cần khai báo.

Điều này đưa chúng ta đến một phân biệt quan trọng: sự khác nhau giữa `throw` và `throws`.

- `throw` được dùng để thực sự throw một exception bên trong một method.
- `throws` được dùng trong method signature để khai báo rằng method có thể throw một exception.

Một phép so sánh hữu ích để ghi nhớ sự khác biệt này là một trận bóng chày (baseball):

- Pitcher (cầu thủ ném bóng) throw quả bóng.
- Nhưng trước trận đấu, manager nói với umpire (trọng tài) loại bóng mà pitcher của mình throw (fastball, curveball, v.v.).

Tương tự trong Java:

- Một method throw một exception.
- Nhưng trong method signature, method khai báo các loại exception mà nó throw.

#### Override method với Exception {#overriding-methods-with-exceptions}
Khi bạn override một method trong subclass, bạn được phép khai báo rằng method throw ít checked exception hơn so với method mà bạn đang override.

```java
class Parent {
    public void doSomething() throws IOException, SQLException {
        // ...
    }
}

class Child extends Parent {
    @Override
    public void doSomething() throws IOException {
        // ...
    }
}
```

Trong ví dụ này, method `doSomething` trong class `Parent` khai báo rằng nó có thể throw `IOException` hoặc `SQLException`. Nhưng khi chúng ta override `doSomething` trong class `Child`, chúng ta khai báo rằng nó chỉ throw `IOException`.

Điều này được phép vì nó làm cho method dễ dùng hơn. Caller của method `doSomething` trong class `Child` chỉ cần xử lý `IOException`, không cần xử lý `SQLException`.

Tuy nhiên, điều ngược lại không được phép. Nếu method của parent class không khai báo exception nào thì method override trong child class cũng không thể khai báo bất kỳ checked exception nào.

```java
class Parent {
    public void doSomething() {
        // ...
    }
}

class Child extends Parent {
    @Override
    public void doSomething() throws IOException {  // Compile-time error
        // ...
    }
}
```

Đoạn code này sẽ không compile được vì method override (trong `Child`) khai báo một checked exception (`IOException`) mà method gốc (trong `Parent`) không khai báo.

Quy tắc là method override có thể khai báo throw ít exception hơn hoặc exception hẹp hơn (subclass của các exception được khai báo) so với method gốc, nhưng không được nhiều hơn hoặc rộng hơn.

Quy tắc này tồn tại để đảm bảo rằng một child class luôn có thể được dùng thay cho parent class mà không gây ra bất kỳ checked exception bất ngờ nào. Đây là một nguyên lý nền tảng của polymorphism và inheritance trong Java.

Tuy nhiên, lưu ý rằng điều này chỉ áp dụng cho checked exception. Unchecked exception có thể được thêm tự do khi override method.

### Tìm hiểu stack trace {#understanding-stack-traces}
Khi một exception xảy ra trong chương trình Java, nó in ra một stack trace. Stack trace cung cấp thông tin về exception và trạng thái của chương trình tại thời điểm exception xảy ra.

Stack trace có thể cực kỳ hữu ích khi debug chương trình. Nó cho bạn biết điều gì đã sai và sai ở đâu trong code.

Hãy xem một stack trace ví dụ:

```
Exception in thread "main" java.lang.NullPointerException
    at com.example.myproject.Book.getTitle(Book.java:16)
    at com.example.myproject.Author.getBookTitles(Author.java:25)
    at com.example.myproject.App.main(Bootstrap.java:14)
```

Stack trace này cho chúng ta biết rằng một `NullPointerException` đã xảy ra trong method `getTitle` của class `Book`, được gọi từ dòng 25 của method `getBookTitles` trong class `Author`, và method này lại được gọi từ dòng 14 của method `main` trong class `App`.

Mỗi dòng trong stack trace đại diện cho một lần gọi method, với lần gọi gần nhất ở trên cùng. Dòng đầu tiên hiển thị exception được throw, tiếp theo là các lần gọi method trên stack tại thời điểm đó.

Với mỗi lần gọi method, stack trace hiển thị:
- Tên đầy đủ (fully qualified) của class chứa method
- Tên của method
- Tên của file source code chứa method
- Số dòng trong file source code nơi lần gọi method diễn ra

Để đọc một stack trace, bạn có thể bắt đầu từ trên cùng rồi đi xuống. Dòng trên cùng cho bạn biết loại exception nào đã được throw. Những dòng sau đó đại diện cho các lần gọi method trên stack, với lần gọi gần nhất ở trên cùng.

Mỗi dòng cung cấp một manh mối về trạng thái của chương trình khi exception được throw. Bạn có thể dùng những manh mối này để xác định chính xác vị trí trong code nơi vấn đề xảy ra.


### Nhận biết các exception class {#recognizing-exception-classes}
Khi bạn gặp một exception trong chương trình Java của mình, một trong những bước đầu tiên để giải quyết vấn đề là xác định xem đó là loại exception nào. Trước đó, bạn đã học về hệ thống phân cấp các exception class, mỗi class được thiết kế để đại diện cho một loại vấn đề cụ thể. Nhận biết những class này và hiểu khi nào chúng được throw có thể giúp bạn chẩn đoán vấn đề nhanh hơn.

**Tip 1: Đọc tên exception class**
Tên exception class thường cho biết điều gì đã sai. Ví dụ, `NullPointerException` gợi ý rằng bạn đang cố dùng một reference `null`, `ArrayIndexOutOfBoundsException` cho biết bạn đang cố truy cập một array với index không hợp lệ, và `IOException` báo hiệu rằng có gì đó đã sai trong một thao tác input/output.

Việc làm quen với tên và ý nghĩa của những exception class phổ biến nhất có thể giúp bạn nhanh chóng nhận ra vấn đề trong code của mình.

**Tip 2: Hiểu hệ thống phân cấp exception**
Hiểu hệ thống phân cấp exception của Java cũng có thể hỗ trợ việc nhận biết exception. Mọi exception trong Java đều kế thừa từ class `Throwable`, class này có hai subclass chính: `Exception` và `Error`.

Những exception kế thừa trực tiếp từ class `Exception` là checked exception. Chúng thường đại diện cho các vấn đề nên được xử lý trong code của bạn. Ví dụ phổ biến gồm `IOException` và `SQLException`

Những exception kế thừa từ class `RuntimeException` (là một subclass của `Exception`) là unchecked exception. Chúng thường biểu thị lỗi lập trình, chẳng hạn cố truy cập một phần tử array với index ngoài phạm vi (`ArrayIndexOutOfBoundsException`) hoặc cố dùng một reference `null` (`NullPointerException`).

Ngược lại, Error đại diện cho những vấn đề nghiêm trọng mà một ứng dụng hợp lý không nên cố bắt. Đây thường là các tình huống không thể khôi phục, chẳng hạn hết bộ nhớ (`OutOfMemoryError`) hoặc tràn stack (`StackOverflowError`).

**Tip 3: Đọc message của exception**
Khi một exception được throw, nó thường kèm theo một message mô tả chi tiết hơn về điều gì đã sai. Message này có thể cực kỳ hữu ích trong việc chẩn đoán vấn đề.

Ví dụ, xét message exception sau:
```
java.lang.ArrayIndexOutOfBoundsException: Index 10 out of bounds for length 5
```

Message này cho biết rằng code đang cố truy cập phần tử ở index 10 trong một array chỉ có 5 phần tử.

**Tip 4: Nhìn vào stack trace**
Stack trace đi kèm với một exception cũng có thể cung cấp những manh mối giá trị về điều gì đã sai. Stack trace cho thấy chuỗi các lần gọi method dẫn đến exception.

Mỗi dòng trong stack trace đại diện cho một lần gọi method, với lần gọi gần nhất ở trên cùng. Dòng đó cho bạn biết tên của method, class chứa nó, và số dòng trong source code nơi lần gọi diễn ra.

Bằng cách lần theo stack trace, bạn thường có thể xác định chính xác vị trí trong code nơi vấn đề xảy ra.

**Tip 5: Tham khảo tài liệu Java API**
Nếu bạn gặp một exception mà mình không quen, tài liệu Java API có thể là một nguồn tài nguyên tuyệt vời. Tài liệu cho mỗi exception class cung cấp thông tin về khi nào exception đó được throw và thường bao gồm các ví dụ về cách xử lý nó.

Chẳng hạn, [tài liệu cho `ArrayIndexOutOfBoundsException`](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/ArrayIndexOutOfBoundsException.html) nói rằng:
```
Thrown to indicate that an array has been accessed with an illegal index. The index is either negative or greater than or equal to the size of the array.
```

Điều này cung cấp lời giải thích rõ ràng về khi nào bạn có thể gặp exception này.

Cuối cùng, đây là danh sách các unchecked và checked exception phổ biến, cùng các error class:

**Các unchecked exception phổ biến**
Unchecked exception là những exception không được kiểm tra tại compile-time. Chúng thường đại diện cho lỗi lập trình, chẳng hạn sai sót logic hoặc dùng API không đúng cách.

1. **ArithmeticException**
   - Được throw khi một tình huống số học ngoại lệ xảy ra.
2. **ArrayIndexOutOfBoundsException**
   - Được throw để chỉ ra rằng một array đã bị truy cập với index không hợp lệ.
3. **ClassCastException**
   - Được throw để chỉ ra rằng code đã cố cast một object sang một subclass mà nó không phải là instance của subclass đó.
4. **IllegalArgumentException**
   - Được throw để chỉ ra rằng một method đã được truyền một argument không hợp lệ hoặc không phù hợp.
5. **IllegalStateException**
   - Báo hiệu rằng một method đã được gọi vào một thời điểm không hợp lệ hoặc không phù hợp.
6. **NullPointerException**
   - Được throw khi một ứng dụng cố dùng `null` trong trường hợp cần một object.
7. **NumberFormatException**
   - Được throw để chỉ ra rằng ứng dụng đã cố chuyển một string sang một trong các numeric type, nhưng string đó không có định dạng phù hợp.

**Các checked exception phổ biến**
Checked exception là những exception được kiểm tra tại compile-time. Chúng thường đại diện cho các tình huống mà một ứng dụng hợp lý có thể muốn bắt.

1. **ClassNotFoundException**
   - Được throw khi một ứng dụng cố load một class thông qua tên string của nó nhưng không tìm thấy định nghĩa cho class với tên đã chỉ định.
2. **IOException**
   - Báo hiệu rằng một exception I/O nào đó đã xảy ra.
3. **FileNotFoundException**
   - Báo hiệu rằng nỗ lực mở file được chỉ định bởi một pathname cụ thể đã thất bại.
4. **InterruptedException**
   - Được throw khi một thread đang chờ, đang sleep, hoặc đang bận làm việc khác, và thread đó bị interrupt.
5. **SQLException**
   - Một exception cung cấp thông tin về lỗi truy cập database hoặc các lỗi khác.
6. **TimeoutException**
   - Được throw khi một thao tác blocking bị timeout.

**Các error class phổ biến**
Error thường được throw bởi Java Virtual Machine và biểu thị những vấn đề nghiêm trọng mà ứng dụng không nên cố bắt.

1. **OutOfMemoryError**
   - Được throw khi JVM không thể cấp phát một object vì hết bộ nhớ.
2. **StackOverflowError**
   - Được throw khi xảy ra tràn stack vì ứng dụng đệ quy quá sâu.
3. **VirtualMachineError**
   - Được throw để chỉ ra rằng Java Virtual Machine bị hỏng hoặc đã cạn kiệt tài nguyên cần thiết để tiếp tục hoạt động.
4. **UnknownError**
   - Được throw khi một exception nghiêm trọng nhưng không xác định đã xảy ra.



## Xử lý Exception {#handling-exceptions}
Khi một exception xảy ra trong chương trình Java của bạn, bạn cần xử lý nó để ngăn chương trình đột ngột kết thúc. Việc này được thực hiện bằng các block `try-catch`.

### Block `try-catch` {#the-try-catch-block}
Cú pháp cơ bản của một block try-catch như sau:

```java
try {
    // code that might throw an exception
} catch (ExceptionType e) {
    // code to handle the exception
}
```

Bạn đặt code có thể throw exception vào block `try`. Nếu một exception xảy ra bên trong block `try`, nó sẽ được bắt bởi block `catch`. Block `catch` chỉ định loại exception mà nó có thể xử lý (`ExceptionType` trong cú pháp trên) và cung cấp code để xử lý exception đó.

Đây là một ví dụ cụ thể:

```java
try {
    File file = new File("example.txt");
    Scanner scanner = new Scanner(file);
    while (scanner.hasNext()) {
        System.out.println(scanner.nextLine());
    }
    scanner.close();
} catch (FileNotFoundException e) {
    System.out.println("File not found: " + e.getMessage());
}
```

Trong ví dụ này, chúng ta đang cố đọc từ một file tên `example.txt`. Nếu file không tồn tại, một `FileNotFoundException` sẽ được throw. Block `catch` bắt exception này và in ra thông báo rằng file không được tìm thấy.

Bạn có thể dùng nhiều block `catch` để xử lý các loại exception khác nhau. Nếu một exception xảy ra trong block `try`, Java sẽ tìm block `catch` đầu tiên có thể xử lý exception đó, bắt đầu từ trên xuống.

```java
try {
    // code that might throw exceptions
} catch (IOException e) {
    // handle IOException
} catch (SQLException e) {
    // handle SQLException
}
```

Trong ví dụ này, nếu một `IOException` xảy ra trong block `try`, nó sẽ được xử lý bởi block `catch` đầu tiên. Nếu một `SQLException` xảy ra, nó sẽ được xử lý bởi block `catch` thứ hai.

Bạn cũng có thể bắt nhiều exception trong một block `catch` duy nhất. Đây được gọi là block `multi-catch`.

```java
try {
    // code that might throw exceptions
} catch (IOException | SQLException e) {
    // handle either IOException or SQLException
}
```

Trong ví dụ này, block `catch` sẽ xử lý `IOException` hoặc `SQLException`.

Điều này có thể làm code ngắn gọn hơn, nhưng chỉ nên dùng khi bạn muốn xử lý các exception theo cùng một cách. Nếu bạn cần xử lý các exception theo cách khác nhau, hãy dùng các block `catch` riêng biệt.

Ngoài ra, block multi-catch phải bắt hai hoặc nhiều exception không liên quan. Các exception không liên quan không có quan hệ cha-con trong hệ thống phân cấp exception, như `IOException` và `SQLException` trong ví dụ trước.

Tuy nhiên, điều quan trọng là sắp xếp các block `catch` từ cụ thể nhất đến tổng quát nhất. Nghĩa là đặt các block catch bắt subclass của exception trước những block bắt exception cha của chúng. Nếu bạn đặt block catch `IOException` trước block catch `FileNotFoundException`, block catch `FileNotFoundException` sẽ không bao giờ được chạm tới vì `FileNotFoundException` là subclass của `IOException`. Kết quả là block catch `IOException` sẽ bắt mọi exception thuộc loại `IOException`, kể cả `FileNotFoundException`, và code xử lý cụ thể hơn dành cho `FileNotFoundException` sẽ bị bỏ qua.

Ví dụ:

```java
try {
    // code that might throw exceptions
} catch (FileNotFoundException e) {
    // handle FileNotFoundException
} catch (IOException e) {
    // handle IOException
}
```

Trong ví dụ này, nếu một `FileNotFoundException` xảy ra, nó sẽ được bắt bởi block `catch` đầu tiên. Nếu một `IOException` khác xảy ra, nó sẽ được bắt bởi block `catch` thứ hai. Điều này đảm bảo rằng những exception cụ thể được xử lý phù hợp trước những exception tổng quát hơn.

### Block `finally` {#the-finally-block}
Block `finally` được dùng để thực thi code luôn phải chạy, bất kể exception có được throw hay không:

```java
try {
    // code that might throw an exception
} catch (ExceptionType e) {
    // handle the exception
} finally {
    // code that always runs
}
```

Block `finally` thường được dùng cho các tác vụ dọn dẹp (cleanup), chẳng hạn đóng file hoặc kết nối database.

Nếu một câu lệnh `return` được thực thi bên trong block `try`, block `finally` vẫn sẽ được thực thi trước khi method return:

```java
public static int returnTest() {
    try {
        return 1;
    } catch (Exception e) {
        return 2;
    } finally {
        System.out.println("Finally block");
    }
}
```

Trong ví dụ này, dù chúng ta return từ bên trong block `try`, block `finally` vẫn sẽ được thực thi và in ra `"Finally block"` trước khi method return.

Điều tương tự cũng đúng nếu câu lệnh `return` nằm trong block `catch`: block `finally` vẫn sẽ được thực thi trước khi method return.

Tuy nhiên, `finally` sẽ không chạy nếu bạn gọi `System.exit()` trong block `try` hoặc `catch`. `System.exit()` khiến Java Virtual Machine thoát, và block `finally` sẽ không được thực thi trước khi chương trình kết thúc:

```java
try {
    System.out.println("Try block");
    System.exit(0);
} catch (Exception e) {
    System.out.println("Catch block");
} finally {
    System.out.println("Finally block");
}
```

Trong ví dụ này, chúng ta gọi `System.exit(0)` trong block `try`, nên chương trình sẽ chỉ in ra `"Try block"` trước khi kết thúc.

Bạn có thể dùng block `try` với block `finally` mà không cần bất kỳ block `catch` nào.

```java
try {
    // code that might throw an exception
} finally {
    // code that always runs
}
```

Điều này hữu ích khi bạn muốn đảm bảo rằng một số code luôn chạy, kể cả khi một exception được throw, nhưng bạn không thực sự muốn xử lý exception đó trong method này.

Cuối cùng, bản thân block `finally` cũng có thể throw exception. Nếu điều này xảy ra, và cũng có một exception trong block `try`, thì exception từ block `finally` sẽ là exception thực sự được throw.

```java
try {
    throw new Exception("Exception in try");
} finally {
    throw new Exception("Exception in finally");
}
```

Trong ví dụ này, exception được throw trong block `finally` sẽ là exception thực sự được throw bởi method. Exception từ block `try` sẽ bị suppressed.


## Tự động hóa quản lý resource với block `try-with-resources` {#automating-resource-management-with-the-try-with-resources-block}
Được giới thiệu từ Java 7, câu lệnh `try-with-resources` là một câu lệnh `try` khai báo một hoặc nhiều resource. Resource là một object phải được đóng sau khi chương trình dùng xong nó. Câu lệnh `try-with-resources` đảm bảo rằng mỗi resource đều được đóng ở cuối câu lệnh.

Cú pháp cơ bản của câu lệnh `try-with-resources` là:

```java
try (Resource declaration) {
    // use the resource
} catch (ExceptionType e1) {
    // catch block
}
```

Để một resource được dùng trong câu lệnh `try-with-resources`, nó phải implement interface `java.lang.AutoCloseable`. Interface này có một method duy nhất là `close()`, được gọi tự động ở cuối block `try`:
```java
public interface AutoCloseable {
    void close() throws Exception;
}
```

Ngoài ra, resource cũng có thể implement interface `java.io.Closeable`:
```java
public interface Closeable  extends AutoCloseable  {
    void close() throws IOException;
}
```

Cả hai đều khai báo method `close()`, và khác biệt thực tế duy nhất giữa hai interface này là method `close` của interface `Closeable` chỉ throw các exception kiểu `IOException`, trong khi method `close` của interface `AutoCloseable` throw các exception kiểu `Exception` (nói cách khác, nó có thể throw bất kỳ loại exception nào):

Tuy nhiên, nhiều resource chuẩn của Java, chẳng hạn như `Scanner`, `FileReader` và `DatabaseConnection`, đã implement sẵn `AutoCloseable`.

Resource có thể được khai báo bên trong dấu ngoặc đơn của câu lệnh `try`, phân tách bằng dấu chấm phẩy nếu có nhiều resource.

```java
try (Scanner scanner = new Scanner(new File("example.txt"));
     PrintWriter writer = new PrintWriter(new File("output.txt"))) {
    // use the resources
}
```

Resource được khai báo theo cách này để chúng có thể được đóng mà không cần làm điều đó một cách tường minh trong block `finally`. Ngoài ra, các resource được khai báo trong câu lệnh `try-with-resources` chỉ nằm trong scope bên trong block `try`. Chúng có tính chất effectively `final`, nghĩa là bạn không thể gán giá trị mới cho chúng sau khi chúng đã được khởi tạo.

Vì vậy, nếu resource được khai báo bên ngoài câu lệnh `try-with-resources`, chúng phải là final:
```java
final Scanner scanner = new Scanner(new File("example.txt"));
final PrintWriter writer = new PrintWriter(new File("output.txt"));

try (scanner; writer) {
    // use the resources
}

```

Hoặc effectively final:
```java
Scanner scanner = new Scanner(new File("example.txt"));
PrintWriter writer = new PrintWriter(new File("output.txt"));

// No reassignment after initialization makes them effectively final
try (scanner; writer) {
    // use the resources
}

```

Nếu khai báo nhiều resource, chúng phải được phân tách bằng dấu chấm phẩy và được đóng theo thứ tự ngược lại với thứ tự khai báo. Điều này quan trọng nếu các resource phụ thuộc lẫn nhau.

```java
try (Scanner scanner = new Scanner(new File("example.txt"));
     DatabaseConnection connection = DriverManager.getConnection(DB_URL)) {
    // use the resources
}
```

Trong ví dụ này, connection sẽ được đóng trước scanner.

Như đã đề cập ở trên, các resource được khai báo trong câu lệnh `try-with-resources` có tính chất effectively `final`. Dù bạn không phải khai báo chúng một cách tường minh là `final`, bạn không thể gán giá trị mới cho chúng sau khi chúng đã được khởi tạo:

```java
try (Scanner scanner = new Scanner(new File("example.txt"))) {
    scanner = new Scanner(new File("other.txt"));  // This will not compile
}
```

Tuy nhiên, một điều cần lưu ý với `try-with-resources` là khả năng xảy ra suppressed exception.

Suppressed exception chỉ xảy ra khi cả block `try` và method `close()` đều throw exception. 

Nếu một exception được throw từ block `try` và một exception khác được throw từ lời gọi `close()` tự động, exception từ lời gọi `close()` sẽ bị suppressed. Nó được thêm vào như một suppressed exception của exception được throw từ block `try`.

```java
try (Scanner scanner = new Scanner(new File("example.txt"))) {
    throw new IllegalStateException("Thrown from try");
}
```

Nếu lời gọi `scanner.close()` cũng throw một exception, exception đó sẽ được thêm vào như một suppressed exception của `IllegalStateException`.

Bạn có thể truy xuất những suppressed exception này bằng cách gọi method `Throwable[] java.lang.Throwable.getSuppressed()` trên exception được throw bởi block `try`:
```java
try (Scanner scanner = new Scanner(new File("example.txt"))) {
    throw new IllegalStateException("Thrown from try");
} catch (Exception e) {
    System.err.println(e.getMessage());
    Stream.of(e.getSuppressed())
        .forEach(t -> System.err.println(t.getMessage()));
}
```

Đây là output (giả sử method `close()` throw một exception):
```
Thrown from try
Close Exception
```

## Những điểm chính {#key-points}
- Exception là một tình trạng bất thường làm gián đoạn luồng thực thi bình thường của chương trình. Khi một exception xảy ra, người ta nói rằng nó đã bị *throw*.

- Mục đích của exception là xử lý error một cách êm đẹp và ngăn chương trình crash hoặc hoạt động bất thường.

- Tất cả exception class trong Java đều là subtype của class `java.lang.Exception`. Hai nhánh chính bên dưới `Exception` là checked exception và unchecked exception (còn được gọi là runtime exception).

- Checked exception là những tình huống đặc biệt mà một application được viết tốt nên lường trước và xử lý, trong khi unchecked exception thường không thể khôi phục được.

- Exception có thể được throw tự động bởi Java runtime hoặc một cách tường minh trong code bằng câu lệnh `throw`.

- Custom exception có thể được tạo bằng cách extends class `Exception` (đối với checked exception) hoặc class `RuntimeException` (đối với unchecked exception).

- Khi một method throw exception, nó phải khai báo điều này trong method signature bằng keyword `throws`. Chỉ checked exception mới cần được khai báo.

- Stack trace cung cấp thông tin về một exception và trạng thái của chương trình tại thời điểm exception xảy ra. Nó có thể được dùng để xác định chính xác vị trí trong code nơi vấn đề xảy ra.

- Exception class có thể được nhận biết qua tên của chúng, vị trí của chúng trong exception hierarchy, exception message và bằng cách tra cứu tài liệu Java API.

- Exception được xử lý bằng block `try-catch`. Block `finally` được dùng để thực thi code cần chạy bất kể exception có được throw hay không.

- Block `multi-catch` cho phép chúng ta catch hai hoặc nhiều exception không liên quan bằng một block `catch` duy nhất.

- Block `finally` luôn được thực thi, kể cả khi exception được catch hoặc khi block `try` hay `catch` chứa câu lệnh `return`. Tuy nhiên, block `finally` sẽ không được thực thi nếu JVM thoát trong lúc block `try` hoặc `catch` đang chạy, chẳng hạn bằng cách gọi `System.exit()`.

- Câu lệnh `try-with-resources`, được giới thiệu từ Java 7, đảm bảo resource được đóng đúng cách sau khi dùng. Resource dùng trong câu lệnh `try-with-resources` phải implement interface `AutoCloseable` hoặc `Closeable`.
