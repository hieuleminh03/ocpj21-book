## Giới thiệu về lập trình hướng đối tượng {#introduction-to-object-oriented-programming}

Như tên gọi của nó, lập trình hướng đối tượng (OOP) là một mô hình lập trình xoay quanh khái niệm object. Thay vì cấu trúc chương trình quanh các procedure và function (như lập trình thủ tục), OOP tổ chức code thành các object, đại diện cho những thực thể trong thế giới thực chứa dữ liệu (attribute) và hành vi (method). Cách tiếp cận này mang lại một số lợi ích:

- Cải thiện tổ chức và tính module hóa
- Tái sử dụng code thông qua inheritance
- Mô hình hóa thế giới thực

Java là một ngôn ngữ OOP, nên các khối xây dựng cơ bản của nó là object và class.

### Object và Class {#objects-and-classes}

Object là những instance riêng biệt trong code chứa dữ liệu và hành vi. Class, ngược lại, là bản thiết kế (blueprint) hay template định nghĩa dữ liệu và hành vi chung cho tất cả object của class đó.

Để hiểu rõ hơn những khái niệm này, hãy nghĩ đến những chiếc bánh cookie được làm ra từ khuôn cắt bánh. Khuôn cắt bánh định hình dạng và kích thước của bánh, giống như class định nghĩa những attribute và method mà các instance object sẽ có. Mỗi chiếc bánh có thể độc đáo, với vị trí các hạt chocolate chip khác nhau, giống như object chứa những giá trị dữ liệu riêng biệt.

Ví dụ, chúng ta có thể định nghĩa một class `Cookie` quy định các attribute của cookie, như flavor, shape, topping, v.v. Bạn cũng có thể định nghĩa các method, là những function thao tác trên dữ liệu. Method cho phép object thực hiện hành động. Các object `Cookie` của chúng ta có thể có một method `eat()`:

```java
public class Cookie {
    // Attributes
    String flavor; 
    int size;
                     
    // Behavior (Method)
    public void eat() {
        System.out.println("That was yummy!");
    }
}
```

- `public class Cookie` định nghĩa một class `Cookie` mới.
- `public` khiến class này có thể truy cập được từ các class khác.
- `String flavor;` khai báo một attribute String mới tên `flavor`.
- `int size;` khai báo một attribute `size` kiểu integer.
- `public void eat()` định nghĩa một method `eat` public không trả về giá trị (`void`).
- Phần thân class và method được bao trong cặp ngoặc `{ }`.
- `System.out.println();` in văn bản ra standard output (thường là console hoặc cửa sổ terminal).

Và chúng ta có thể instantiate các object cookie từ class `Cookie`:

```java 
Cookie chocoChip = new Cookie();
chocoChip.flavor = "Chocolate Chip";
chocoChip.size = 2;

Cookie oatmealRaisin = new Cookie(); 
oatmealRaisin.flavor = "Oatmeal Raisin";
oatmealRaisin.size = 1;
```

- `Cookie chocoChip = new Cookie();` instantiate một object `Cookie` mới tên `chocoChip`.
- Chúng ta dùng tên class `Cookie` và default constructor `new Cookie()`.
- `chocoChip.flavor = "Chocolate Chip";` đặt attribute flavor của `chocoChip`.
- `chocoChip.size = 2;` đặt attribute size thành `2`.
- Chúng ta lặp lại quy trình với `oatmealRaisin`, tạo thêm một object cookie độc đáo khác.

Các object `chocoChip` và `oatmealRaisin` đều là cookie với cùng các method được định nghĩa bởi class `Cookie`. Tuy nhiên, chúng chứa những giá trị dữ liệu khác nhau cho các attribute như flavor và size.

Một ngộ nhận phổ biến là object và class giống hệt nhau. Tuy nhiên, dù object và class có liên quan, chúng phục vụ những mục đích riêng biệt:

- Class định nghĩa cấu trúc của object.
- Object đại diện cho những instance riêng biệt.

Class đóng vai trò khuôn đúc, còn object là những chiếc bánh được tạo ra.

### Các nguyên lý OOP bậc cao {#higher-level-oop-principles}

Khi đã hiểu về object và class, việc nắm bắt các nguyên lý bậc cao của OOP như inheritance, encapsulation và polymorphism sẽ trở nên dễ dàng hơn:

- **Inheritance** cho phép tái sử dụng code và tạo ra các hệ thống phân cấp class. Nó giống như có một công thức cookie cơ bản làm template cho nhiều loại cookie. Công thức cơ bản này (parent class) bao gồm các nguyên liệu và method chung (attribute và hành vi) mà mọi cookie đều có. Các công thức chuyên biệt (subclass) cho những loại cookie khác nhau, như chocolate chip hay oatmeal raisin, kế thừa những thành phần chung nhưng cũng thêm vào nguyên liệu hoặc bước làm riêng.

- **Encapsulation** là việc gói gọn các attribute dữ liệu và hành vi vào định nghĩa class. Nó giống như đóng gói bột bánh và hướng dẫn công thức của bạn vào một gói gọn gàng. Mỗi loại cookie, như chocolate chip hay oatmeal raisin, có hộp riêng chứa mọi thứ cần thiết để làm ra nó: nguyên liệu (dữ liệu) và các bước (method). Gói này đảm bảo mọi bí quyết để nướng ra chiếc cookie hoàn hảo được giữ chặt với nhau, chỉ có thể truy cập qua một khe mở cụ thể trên hộp.

- **Polymorphism** cho phép tùy biến hành vi kế thừa từ parent trong các subclass, chẳng hạn override method `eat()` của parent bên trong `ChocolateChip` để in ra `"Mmm chocolate chip!"`.

Khép lại vòng tròn này, chúng ta có thể mô hình hóa các hệ thống phân cấp cookie trong thế giới thực thông qua:

- **Inheritance** – Tận dụng các đặc tính của parent cookie và mở rộng chúng.
- **Encapsulation** - Gói gọn nguyên liệu và công thức làm cookie.
- **Polymorphism** - Tùy biến các hành vi như `eat()` theo từng subclass.

Cùng nhau, những khái niệm OOP cốt lõi này cho phép thiết kế class cookie linh hoạt và module hóa. Chúng ta sẽ xem xét những khái niệm này chi tiết hơn trong chương tiếp theo. Trước tiên, hãy nói về vòng đời của một object.


## Vòng đời object trong Java {#object-life-cycle-in-java}

Hiểu các giai đoạn khác nhau trong vòng đời của một object là điều thiết yếu trong lập trình hướng đối tượng của Java. Điều này bao gồm việc tạo object, cách các reference variable truy cập chúng, và cách những object không còn được dùng được quản lý bởi garbage collector của Java.

Dưới đây là một sơ đồ minh họa vòng đời điển hình của một object Java, từ lúc tạo đến lúc được garbage collection:
```
┌────────────────────┐
│   Object Creation  │
│    (new keyword)   │
└────────┬───────────┘
         │
         ▼
┌────────────────────┐
│   Initialization   │
│   (Constructor)    │
└────────┬───────────┘
         │
         ▼
┌───────────────────┐
│     Object Use    │
│ (Active Lifetime) │
└────────┬──────────┘
         │
         ▼
┌────────────────────┐
│     Unreachable    │
│(No more references)│
└────────┬───────────┘
         │
         ▼
┌────────────────────┐
│   Garbage Collect  │
│     (finalize)     │
└────────────────────┘
```

Nhưng để minh họa các giai đoạn sống của một object Java, hãy dùng phép so sánh với một cuốn sách thư viện. Khi một cuốn sách mới đến thư viện, nó giống như việc construct một object mới bằng keyword `new`. Ví dụ:

```java
Book javaBook = new Book("The Java Book");
```

Hãy phân tích từng bước điều xảy ra trong dòng lệnh duy nhất đó:

1. **Khai báo reference variable:**
    ```java
    Book javaBook;
    ```
    Dòng này khai báo một variable tên `javaBook` kiểu `Book`. Lúc này, chưa có object `Book` nào tồn tại; chúng ta chỉ vừa tạo một reference variable có thể trỏ đến một object `Book`.

2. **Instantiate object:**
    ```java
    = new Book("The Java Book");
    ```
    Keyword `new` instantiate hay construct một object `Book` mới. Thao tác này cấp phát bộ nhớ trên heap cho object, truyền đối số string vào constructor của `Book` để khởi tạo trạng thái của nó, và trả về một reference đến object vừa được tạo.

3. **Gán reference:**
    Toán tử `=` gán reference của object `Book` mới cho variable `javaBook`. 

Vậy nên, `javaBook` giờ chứa một reference trỏ đến instance `Book` mới trong bộ nhớ:

```
javaBook --> [New Book object]
```

Ở đây, `javaBook` là reference variable trỏ đến instance `Book` vừa được tạo trên Java heap.

### Gán lại reference {#reference-reassignment}

Giống như sách thư viện được những người khác nhau mượn, object reference trong Java có thể được gán lại. Ví dụ:

```java
Book refBook = javaBook; // Assign second reference
javaBook = null; // Remove original reference
```

Hãy xem lại từng bước:

1. **Tạo reference thứ hai:**
    ```java
    Book refBook = javaBook;
    ```
    Dòng này tạo một reference variable mới `refBook` và gán cho nó giá trị của `javaBook`. Cả `javaBook` và `refBook` giờ đều trỏ đến cùng một object `Book`.

    ```
    javaBook --> [Book object]
    refBook --> [Book object]
    ```

2. **Vô hiệu hóa reference gốc:**
    ```java
    javaBook = null;
    ```
    Dòng này đặt `javaBook` thành `null`, nghĩa là nó không còn tham chiếu đến object nào nữa.

    ```
    javaBook --> null
    refBook --> [Book object]
    ```

Giờ chỉ còn `refBook` trỏ đến object `Book`. Object này không đủ điều kiện cho garbage collection vì `refBook` vẫn tham chiếu đến nó.

### Garbage Collection {#garbage-collection}

Những cuốn sách không còn được mượn cuối cùng sẽ bị loại khỏi danh mục của thư viện. Tương tự, trong Java, những object không còn reference nào sẽ được dọn dẹp bởi garbage collector:

```java
refBook = null; // Unreferenced object eligible for garbage collection
```

Khi mọi reference đến một object đều biến mất, nó trở nên đủ điều kiện cho garbage collection. 

Quá trình garbage collection có thể được tóm tắt như sau:

1. **Xác định object không còn được dùng:**
    Garbage collector (GC) định kỳ quét heap để tìm những object không còn được bất kỳ phần nào của ứng dụng tham chiếu.

2. **Thu hồi bộ nhớ:**
    Những object không còn reference, không thể truy cập được nữa, được coi là *garbage*. GC giải phóng bộ nhớ mà những object này chiếm giữ, trả lại cho pool bộ nhớ khả dụng trên heap.

3. **Quản lý tự động:**
    Garbage collection diễn ra tự động ở background, không cần chương trình kích hoạt tường minh, đảm bảo việc quản lý bộ nhớ được xử lý hiệu quả.

Ở những ngôn ngữ như C, bộ nhớ phải được quản lý thủ công bằng cách cấp phát và giải phóng bộ nhớ. Java tự động hóa quá trình này với garbage collection, tăng năng suất của lập trình viên và giảm rủi ro memory leak cùng những vấn đề liên quan khác.

Giờ, hãy cùng thảo luận một số khái niệm chúng ta sẽ dùng để khai báo class và những thành phần khác.



## Keyword {#keywords}
Trong Java, keyword là một reserved word có ý nghĩa được định trước trong ngôn ngữ. Keyword định nghĩa cấu trúc và cú pháp của chương trình Java. Chúng không thể được dùng làm identifier (tên cho variable, method, class, v.v.) vì chúng được dành riêng cho những mục đích cụ thể.

Java bao gồm một tập keyword nền tảng của ngôn ngữ. Một số keyword thường dùng bao gồm:

- `class`: Dùng để khai báo một class.
- `public`, `private`, `protected`: Access modifier quyết định khả năng hiển thị và truy cập của class, method và variable.
- `static`: Chỉ ra rằng một thành viên thuộc về chính class thay vì các instance của class.
- `void`: Chỉ định rằng một method không trả về giá trị.
- `if`, `else`, `switch`, `case`: Dùng cho các câu lệnh điều kiện.
- `for`, `while`, `do`: Dùng cho vòng lặp và lặp.
- `return`: Dùng để trả về một giá trị từ method.
- `new`: Dùng để tạo instance mới của một class.
- `try`, `catch`, `finally`: Dùng cho xử lý exception.
- `import`: Dùng để import class hoặc package.

Hãy luôn ghi nhớ rằng mỗi keyword có một mục đích cụ thể và được dùng để định nghĩa cấu trúc và hành vi của chương trình Java.

Ngoài ra, điều quan trọng cần lưu ý là keyword trong Java phân biệt chữ hoa chữ thường. Ví dụ, `class` là keyword, nhưng `Class` thì không. Hơn nữa, bạn không thể dùng keyword làm identifier, chẳng hạn tên variable hay method, vì chúng được ngôn ngữ dành riêng.

Đây là một ví dụ minh họa cách dùng một số keyword:

```java
public class MyClass {
    private static int myVariable;
    
    public static void myMethod() {
        if (myVariable > 0) {
            System.out.println("Positive");
        } else {
            System.out.println("Negative");
        }
    }
}
```

Trong ví dụ này, `public`, `class`, `private`, `static`, `int`, `void`, `if` và `else` đều là keyword được dùng để định nghĩa cấu trúc và hành vi của class `MyClass`.

Chúng ta sẽ xem xét những keyword này và các keyword khác trong những phần và chương tiếp theo.

## Comment {#comments}
Comment là những chú thích trong code được compiler bỏ qua. Chúng có thể được dùng để:
- Mô tả hoặc giải thích code làm gì.
- Ghi tài liệu mục đích của những khối code cụ thể.
- Giải thích logic đằng sau các thuật toán phức tạp.
- Đánh dấu các phần của code.

Java hỗ trợ ba loại comment:

1. Comment một dòng
2. Comment nhiều dòng
3. Comment tài liệu (javadoc)

Comment một dòng bắt đầu bằng hai dấu gạch chéo (`//`). Mọi thứ theo sau `//` trên cùng dòng đều bị compiler Java bỏ qua:

```java
// This is a single-line comment
int variable = 1; // This is another single-line comment
```

Comment nhiều dòng, còn gọi là block comment, bắt đầu bằng `/*` và kết thúc bằng `*/`. Mọi thứ nằm giữa `/*` và `*/` được coi là comment, bất kể nó kéo dài bao nhiêu dòng:

```java
/* This is a multi-line comment
   and it can span multiple lines. */
int variable = 1;
```

Comment tài liệu, hay javadoc comment, được thiết kế để ghi tài liệu cho code Java. Chúng bắt đầu bằng `/**` và kết thúc bằng `*/`. Những comment này có thể được trích xuất thành tài liệu HTML bằng công cụ Javadoc. Comment tài liệu chủ yếu được dùng trước định nghĩa của class, interface, method và field:

```java
/**
 * This is a documentation comment.
 * It can be used to describe classes, interfaces, methods, and fields.
 */
public class MyClass {
    /**
     * This method adds up two int values.
     *
     * @param a First value
     * @param b Second value
     * @return The sum of a and b
     */
    public int add(int a, int b) {
        return a + b;
    }
}
```
## Tổ chức class vào package {#organizing-classes-into-packages}
Package tổ chức các class, interface và sub-package liên quan thành một đơn vị duy nhất.

Ví dụ, hãy tưởng tượng bạn sở hữu một cửa hàng tạp hóa bán nhiều loại sản phẩm. Để mọi thứ gọn gàng và dễ tìm, bạn quyết định nhóm những sản phẩm tương tự nhau vào các khu vực hoặc lối đi khác nhau trong cửa hàng.

Trong phép so sánh này:
- Cửa hàng tạp hóa đại diện cho project Java của bạn.
- Các khu vực hoặc lối đi trong cửa hàng đại diện cho package trong Java.
- Các sản phẩm trên kệ đại diện cho class và interface trong Java.

Cũng giống như cách bạn nhóm những sản phẩm liên quan vào cùng khu vực trong cửa hàng, bạn nhóm những class và interface liên quan vào cùng package trong Java. 

Ví dụ, trong cửa hàng tạp hóa của bạn, bạn có thể có:
- Khu vực *Fruits* (Trái cây) nơi bạn đặt tất cả các loại trái cây khác nhau như táo, chuối và cam.
- Khu vực *Dairy* (Sữa) cho sữa, phô mai, sữa chua và các sản phẩm từ sữa khác.
- Khu vực *Beverages* (Đồ uống) cho các loại đồ uống như nước, nước ép và soda.

Tương tự, trong project Java của bạn, bạn có thể có:
- Package `com.example.products` cho các class liên quan đến quản lý sản phẩm, như `Product`, `Inventory` và `Category`.
- Package `com.example.orders` cho các class liên quan đến xử lý đơn hàng, như `Order`, `ShoppingCart` và `Payment`.
- Package `com.example.auth` cho các class liên quan đến xác thực người dùng, như `User`, `Login` và `Permission`.

Bằng cách tổ chức class vào package, bạn tạo ra một cấu trúc logic giúp dễ dàng định vị và quản lý các phần tử code liên quan, giống như cách sắp xếp sản phẩm thành các khu vực giúp khách hàng dễ tìm thấy thứ họ cần trong cửa hàng tạp hóa.

### Tạo package {#creating-a-package}

Để tạo một package, dùng keyword `package` theo sau là tên package ở đầu source file Java của bạn. Ví dụ:
```java
package com.example.mypackage;
```

Tên package nên viết thường và tuân theo quy ước tên miền đảo ngược (reverse domain name convention) để đảm bảo tính duy nhất.

Tên package không được chứa bất kỳ từ dành riêng nào của Java (như `int`, `if`, `for`, v.v.)

Package declaration phải là câu lệnh đầu tiên trong source file, trước mọi import statement hoặc class declaration. Đoạn code sau sẽ không compile:
```java
import java.util.ArrayList; // Import statement before the package declaration

package mypackage; // Package declaration not at the beginning

public class MyClass {
    public static void main(String[] args) {
        System.out.println("This will not compile.");
    }
}
```

### Sử dụng câu lệnh import {#using-import-statements}

Câu lệnh `import` được dùng để đưa các class hoặc interface từ package khác vào namespace hiện tại. Thay vì dùng fully qualified name mỗi lần bạn tham chiếu đến một class từ package khác, bạn có thể dùng câu lệnh `import` để tham chiếu class bằng tên của nó. Ví dụ:
```java
import java.util.ArrayList;
// ...
ArrayList list = new ArrayList();
```

Nếu bạn chọn không dùng câu lệnh `import` cho một class từ package khác, bạn sẽ phải dùng fully qualified name của class đó mỗi lần tham chiếu đến nó trong code. Hãy nhớ rằng, fully qualified name bao gồm cả tên package và tên class.

Ví dụ, nếu bạn không import class `ArrayList` từ package `java.util`, bạn sẽ phải dùng `java.util.ArrayList` mỗi lần muốn tạo hoặc dùng một object `ArrayList` trong code:
```java
// No import statement for java.util.ArrayList
// ...
java.util.ArrayList list = new java.util.ArrayList();
```

### Các trường hợp đặc biệt và best practice {#special-cases-and-best-practices}

Có một vài ngoại lệ hoặc trường hợp đặc biệt đối với quy tắc về việc dùng fully qualified name và import statement:

1. **Class trong package `java.lang`**: Class và interface trong package `java.lang` không cần được import tường minh, vì chúng tự động khả dụng. Ví dụ, bạn không cần import những class như `String`, `Math`, `System`, hay các wrapper class như `Integer`, `Double`, v.v.

2. **Cùng package**: Class và interface nằm cùng package với class bạn đang viết không cần import statement. Java tự động tìm trong package hiện tại các class và interface khác nếu nó không tìm thấy class hoặc interface được tham chiếu trong các package đã import.

3. **Xung đột fully qualified name**: Khi hai class có cùng tên nhưng nằm ở các package khác nhau, và bạn cần dùng cả hai trong cùng một file, bạn không thể import trực tiếp cả hai vì xung đột tên. Trong những trường hợp như vậy, ít nhất một class (và có thể cả hai) phải được tham chiếu bằng fully qualified name để tránh nhập nhằng.

Đây là một ví dụ minh họa điểm cuối cùng này:

```java
import java.sql.Date;

public class Example {
    public static void main(String[] args) {
        Date sqlDate = new Date(System.currentTimeMillis());
        java.util.Date utilDate = new java.util.Date();
    }
}
```

Trong ví dụ này, `Date` từ `java.sql` được import, nên nó có thể được tham chiếu bằng tên đơn giản. Tuy nhiên, vì chúng ta cũng muốn dùng `Date` từ `java.util`, chúng ta phải tham chiếu nó bằng fully qualified name để phân biệt với `java.sql.Date`.

Bạn cũng có thể dùng wildcard (`*``) để import tất cả class từ một package. Ví dụ:
```java
import java.util.*;
```

Tuy nhiên, thường được khuyến nghị import các class cụ thể thay vì dùng wildcard vì chúng có thể làm code kém dễ đọc, dẫn đến xung đột tên nếu nhiều package có class cùng tên, và tạo thêm dư thừa, chẳng hạn đưa một class vào hai lần.

### Import dư thừa {#redundant-imports}

Mặc dù compiler cho phép import dư thừa, chúng có thể làm rối code và giảm khả năng đọc.

Ví dụ, giả sử chúng ta có hai class, `MyClass` và `HelperClass`, trong cùng package `mypackage`:

```java
// File: HelperClass.java
package mypackage;

public class HelperClass {
    public static void doSomething() {
        System.out.println("Doing something...");
    }
}
```

Class sau minh họa import dư thừa:

```java
package mypackage;

import mypackage.HelperClass; // Redundant import because HelperClass is in the same package
import java.util.List; // Redundant import because it's not used in the class

public class MyClass {
    public static void main(String[] args) {
        HelperClass.doSomething();
    }
}
```

Trong ví dụ này:
- Câu lệnh import `import mypackage.HelperClass;` là dư thừa vì `HelperClass` đã nằm cùng package với `MyClass`. Hãy nhớ rằng, các class trong cùng package tự động khả dụng với nhau mà không cần import statement.
- Câu lệnh import `import java.util.List;` cũng dư thừa vì interface `List` không được dùng ở đâu trong `MyClass`.

Việc xóa những import dư thừa này sẽ làm code sạch hơn mà không ảnh hưởng đến chức năng của nó.

### Kiểm soát truy cập {#access-control}

Package cung cấp một mức kiểm soát truy cập, tương tự như cách một số khu vực trong cửa hàng có thể chỉ dành cho nhân viên được phép. Bạn có thể dùng access modifier (`public`, `protected`, default, `private`) để kiểm soát khả năng hiển thị và truy cập của class và các thành viên bên trong cũng như giữa các package.

Ví dụ, giả sử bạn có một package tên `com.example.internals` chứa các class và method chỉ dành cho mục đích nội bộ trong package đó:
```java
package com.example.internals;
class InternalClass {
    void internalMethod() {
        // Internal implementation
    }
}
```

Giờ, hãy xem xét một package khác `com.example.api`:
```java
package com.example.api;
import com.example.internals.InternalClass;
public class APIClass {
    public void someMethod() {
        InternalClass obj = new InternalClass(); // Not accessible
        obj.internalMethod(); // Not accessible
    }
}
```
Trong ví dụ này, `InternalClass` và các method của nó có quyền truy cập default (package-private). Chúng có thể truy cập được trong package `com.example.internals` nhưng không từ các package khác. `APIClass` trong package `com.example.api` không thể truy cập `InternalClass` hay các method của nó một cách trực tiếp.

Hãy cùng xem xét chi tiết hơn về các access modifier khả dụng.


## Access modifier {#access-modifiers}
Access modifier là những keyword được dùng trong khai báo class, method hoặc variable để kiểm soát khả năng hiển thị của thành viên đó từ những phần khác của chương trình. Có bốn loại access modifier chính trong Java:

1. **`public`**: Access modifier `public` chỉ định rằng thành viên có thể được truy cập từ bất kỳ class nào khác trong ứng dụng Java, bất kể package mà nó thuộc về. Dùng modifier `public` nghĩa là không có hạn chế nào khi truy cập thành viên đó.

2. **`protected`**: Access modifier `protected` cho phép thành viên được truy cập trong package của chính nó và cả bởi các subclass của class đó ở những package khác. Điều này ít hạn chế hơn package-private nhưng hạn chế hơn `public`.

3. **`default`** (còn gọi là **package-private**): Nếu không có access modifier nào được chỉ định, thành viên mặc định có quyền truy cập package-private. Nghĩa là thành viên chỉ có thể được truy cập trong package của chính nó và không hiển thị với các class bên ngoài package. Điều quan trọng cần lưu ý là không có keyword `default` tường minh trong Java; bạn chỉ cần bỏ qua access modifier.

4. **`private`**: Access modifier `private` chỉ định rằng thành viên chỉ có thể được truy cập trong class mà nó được khai báo. Đây là mức truy cập hạn chế nhất và được dùng để đảm bảo thành viên không thể được truy cập từ bên ngoài class của chính nó, kể cả bởi các subclass.

Mỗi access modifier này phục vụ một mục đích cụ thể trong bối cảnh thiết kế hướng đối tượng và encapsulation. Chúng cho phép bạn cấu trúc code theo cách bảo vệ dữ liệu nhạy cảm và chi tiết triển khai trong khi vẫn phơi bày chức năng cần thiết cho những phần khác của ứng dụng.

Đây là một sơ đồ để hiểu phạm vi của mỗi access modifier dễ dàng hơn:
```
┌─────────────────────────────────────────────────────────────┐
│                         public                              │
│  ┌─────────────────────────────────────────────────┐        │
│  │               protected                         │        │
│  │  ┌─────────────────────────────────────┐        │        │
│  │  │    default (package-private)        │        │        │
│  │  │  ┌─────────────────────────┐        │        │        │
│  │  │  │      private            │        │        │        │
│  │  │  └─────────────────────────┘        │        │        │
│  │  └─────────────────────────────────────┘        │        │
│  └─────────────────────────────────────────────────┘        │
└─────────────────────────────────────────────────────────────┘

Access Levels (from most restrictive to least restrictive):
private   : Same class only
default   : Same package
protected : Same package + subclasses in other packages
public    : Accessible from anywhere
```

Trong các phần tiếp theo, chúng ta sẽ giải thích access modifier trong bối cảnh class, field và method. Nhưng trước tiên, hãy xem lại cách khai báo một class đúng cách.

## Khai báo class {#declaring-classes}

Class trong Java đóng vai trò bản thiết kế cho object, đóng gói cả dữ liệu lẫn hành vi.

Cú pháp để khai báo một class theo định dạng sau:

```java
[accessModifier] class ClassName [extends Superclass] [implements Interface1, Interface2, ...] {
    // class body
}
```

Ví dụ, một class declaration có thể trông như thế này:
```java
public class MyClass extends MySuperClass implements MyInterface {
    private int myField;

    public MyClass() {
        // Constructor body
    }

    public void myMethod() {
        // Method body
    }
}
```
Đầu tiên, bạn có thể tùy chọn chỉ định một access modifier để quyết định khả năng hiển thị và truy cập của class với những phần khác của ứng dụng Java:

- **`public`**: Class có thể được truy cập từ bất kỳ class nào khác ở các package khác nhau.
- **Default (Package-Private)**: Nếu không có access modifier nào được chỉ định, class chỉ có thể được truy cập bởi các class khác trong cùng package. Điều này hữu ích để nhóm các class liên quan lại với nhau mà không phơi bày chúng cho toàn bộ ứng dụng.

Sau access modifier tùy chọn, bạn phải dùng keyword `class`, theo sau là tên của class.

Tên class hay class identifier nên tuân theo các quy tắc sau:

1. **Ký tự Unicode**: Java cho phép dùng ký tự Unicode trong identifier, nghĩa là bạn cũng có thể dùng các chữ cái từ bảng chữ cái không phải Latinh. Tuy nhiên, điều này không được dùng phổ biến và có thể dẫn đến code khó đọc, khó bảo trì.

2. **Ký tự chữ cái, chữ số, dấu gạch dưới (_) và dấu đô la ($)**: Đây là những ký tự phổ biến nhất được dùng trong identifier. Mọi kết hợp của những ký tự này đều được phép, nhưng tên class **không được** bắt đầu bằng chữ số.

3. **Không dùng ký tự đặc biệt**: Ngoài dấu gạch dưới và dấu đô la, các ký tự đặc biệt như `@`, `%`, `!`, `?`, `#`, `&`, `*`, `^`, `~`, `_`, `-`, `+`, `=`, `{`, `}`, `[`, `]`, `|`, `,`, `;`, `<`, `>`, `/`, `\`, hoặc `'` đều không được phép trong class identifier.

4. **Tên class không được chứa dấu cách**. Điều này sẽ làm code không hợp lệ và dẫn đến compile error.

5. **Không được là từ dành riêng của Java**: Identifier không thể dùng bất kỳ từ dành riêng nào của Java (như `int`, `if`, `for`, v.v.). Từ dành riêng có ý nghĩa cụ thể trong Java và không thể được dùng cho tên class, tên variable hay bất kỳ identifier nào khác.

6. **Phân biệt chữ hoa chữ thường**: Java phân biệt chữ hoa chữ thường, nghĩa là các identifier như `MyClass`, `myclass` và `MYCLASS` được coi là khác nhau.

7. **Độ dài**: Không có giới hạn độ dài cho tên class trong Java.

Những quy tắc này đảm bảo tên class đúng cú pháp và tránh xung đột với các tính năng ngôn ngữ có sẵn của Java. Ngoài ra, thực hành tốt là tuân theo các quy ước đặt tên của Java bên trên những quy tắc này, như bắt đầu tên class bằng chữ cái viết hoa và dùng camel case cho tên nhiều từ (như dùng `MyClass` thay vì `myclass` hay `MY_CLASS`). Nhưng một lần nữa, đây chỉ là quy ước, không phải quy tắc.

Sau tên class, bạn có thể tùy chọn extends một superclass bằng keyword `extends`, theo sau là tên của superclass. Java hỗ trợ đơn kế thừa (single inheritance), nghĩa là một class chỉ có thể extends một superclass.

Tuy nhiên, bạn có thể implements một hoặc nhiều interface bằng keyword `implements`, theo sau là danh sách tên interface phân tách bằng dấu phẩy:
```java
public class MyClass implements MyInterface1, MyInterface2, MyInterface3 {
    // ...
}
```

Cuối cùng, bạn định nghĩa thân class trong cặp ngoặc nhọn `{}`. Thân class chứa các thành viên của class, bao gồm field, method, constructor và nested class.

Theo cách này, trong ví dụ tiếp theo:
```java
public class MyClass extends MySuperClass implements MyInterface {
    /* Class body begins */
    // Fields
    private int myField;

    // Constructor
    public MyClass() {
        // Constructor body
    }

    // Methods
    public void myMethod() {
        // Method body
    }
    /* Class body ends */
}
```

- `public` là access modifier, chỉ ra rằng class có thể được truy cập từ mọi nơi.
- `class` là keyword dùng để khai báo một class.
- `MyClass` là tên của class.
- `extends MySuperClass` chỉ định rằng `MyClass` kế thừa từ superclass `MySuperClass`.
- `implements MyInterface` chỉ ra rằng `MyClass` implements interface `MyInterface`.
- Thân class chứa một field `private` `myField`, một constructor `public` `MyClass()`, và một method `public` `myMethod()`.

Giờ, trước khi xem lại cách khai báo field và method chi tiết hơn, hãy nói về thành viên static và instance.

## Thành viên static và instance {#static-and-instance-members}
Class có thể có hai loại thành viên: thành viên static và thành viên instance. Hãy dùng phép so sánh với một model TV để hiểu rõ hơn về những loại thành viên này.

Hãy tưởng tượng những chiếc TV khác nhau cùng một model ở những ngôi nhà khác nhau. Mỗi chiếc TV đại diện cho một instance (object) của class `Television`. Bản thân model TV đại diện cho class.

Instance member, như instance variable và instance method, thuộc về từng chiếc TV (object) riêng lẻ:
- Mỗi chiếc TV có tập instance variable riêng, như kênh hiện tại, âm lượng, và việc nó đang bật hay tắt.
- Instance method, như `changeChannel()` hay `adjustVolume()`, là những hành động mà mỗi chiếc TV có thể thực hiện độc lập.
- Instance member được truy cập thông qua instance (object) của class.

Static member, như static variable và static method, thuộc về chính model TV (class):
- Model TV có những static variable được chia sẻ giữa tất cả các chiếc TV, như logo của nhà sản xuất hoặc số model.
- Static method, như `getManufacturerInfo()` hay `getModelNumber()`, là những hành động thuộc về model TV và có thể được truy cập mà không cần tạo instance của class `Television`.
- Static member được truy cập bằng chính tên class, không cần tạo instance.

Đây là class `Television`:

```java
public class Television {
    // Instance fields
    private int currentChannel;
    private int volume;
    private boolean isOn;
    
    // Static field
    private static String manufacturerLogo = "MyBrand";
    
    // Instance method
    public void changeChannel(int channel) {
        this.currentChannel = channel;
        System.out.println("Channel changed to: " + channel);
    }
    
    // Static method
    public static void getManufacturerInfo() {
        System.out.println("All TVs by: " + manufacturerLogo);
    }
}
```

Trong ví dụ này:
- Các field `currentChannel`, `volume` và `isOn` là instance variable. Mỗi chiếc TV (object) có tập variable riêng của nó.
- Field `manufacturerLogo` là một variable `static`. Nó thuộc về chính class và được chia sẻ giữa tất cả các chiếc TV.
- Method `changeChannel()` là instance method. Mỗi chiếc TV có thể gọi method này một cách độc lập.
- Method `getManufacturerInfo()` là static method. Nó thuộc về class và có thể được gọi mà không cần tạo instance của class `Television`.

Để truy cập instance member, bạn cần tạo một instance của class:
```java
Television tv1 = new Television();
tv1.changeChannel(5); // Changes channel of tv1
```

Nhưng để truy cập static member, bạn có thể dùng trực tiếp tên class:
```java
Television.getManufacturerInfo();
```

Static member hữu ích để biểu diễn dữ liệu và hành vi ở cấp class được chia sẻ giữa tất cả instance của class. Chúng có thể được truy cập mà không cần tạo instance của class, giúp tiết kiệm bộ nhớ. Tuy nhiên, static member không thể truy cập trực tiếp instance member, vì chúng không gắn với bất kỳ instance cụ thể nào.

Điều quan trọng cần lưu ý là Java cho phép truy cập static member (field và method) thông qua instance của một class. Ví dụ, static method `getManufacturerInfo()` cũng có thể được dùng theo cách này:
```java
tv1.getManufacturerInfo();
```

Tuy nhiên, đây không phải là thực hành được khuyến nghị, vì nó không thể hiện rõ ràng rằng thành viên đó là static và thuộc về class chứ không phải instance.

Instance member, ngược lại, gắn với từng instance riêng lẻ của class. Chúng giữ dữ liệu riêng cho từng object và có thể truy cập cả static lẫn instance member.

Giờ, bạn có thể đang thắc mắc: Tại sao static member có thể được truy cập mà không cần tạo instance của class? Điều này có đi ngược lại ý tưởng của lập trình hướng đối tượng không??

Vâng, điều này không hẳn đi ngược lại các nguyên lý của lập trình hướng đối tượng (OOP), mà bổ sung cho chúng bằng cách cung cấp một cơ chế để định nghĩa hành vi và trạng thái ở cấp class.

Static method có thể được dùng để triển khai các utility hoặc helper function không phụ thuộc vào trạng thái của một instance object. Điều này phổ biến trong các utility class, như class `Math`, nơi mọi method đều là static vì chúng không cần truy cập dữ liệu ở cấp instance.

Ngoài ra, static member cho phép truy cập toàn cục. Đành rằng có một số tranh cãi về điều này do khả năng tăng coupling và code khó test hơn, tuy nhiên nó có thể phù hợp cho các hằng số toàn cục cần được truy cập từ nhiều điểm khác nhau trong một ứng dụng.

Sơ đồ này minh họa một số điểm chính về static và instance member trong Java:
```
┌─────────────────────────────────────────────────────────────┐
│                         Class                               │
│  ┌─────────────────────────┐ ┌─────────────────────────┐    │
│  │    Static Members       │ │    Instance Members     │    │
│  │ ┌─────────────────────┐ │ │ ┌─────────────────────┐ │    │
│  │ │   Static Fields     │ │ │ │  Instance Fields    │ │    │
│  │ └─────────────────────┘ │ │ └─────────────────────┘ │    │
│  │ ┌─────────────────────┐ │ │ ┌─────────────────────┐ │    │
│  │ │   Static Methods    │ │ │ │  Instance Methods   │ │    │
│  │ └─────────────────────┘ │ │ └─────────────────────┘ │    │
│  └─────────────────────────┘ └─────────────────────────┘    │
│                                                             │
│  ┌─────────────────────────┐ ┌─────────────────────────┐    │
│  │      Object 1           │ │      Object 2           │    │
│  │ ┌─────────────────────┐ │ │ ┌─────────────────────┐ │    │
│  │ │  Instance Fields    │ │ │ │  Instance Fields    │ │    │
│  │ └─────────────────────┘ │ │ └─────────────────────┘ │    │
│  └─────────────────────────┘ └─────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘

- The class contains both static and instance members.
- Static members (fields and methods) are associated with the class itself.
- Instance members (fields and methods) are associated with objects of the class.
- Multiple objects of the class each have their own instance members.
- All objects share the same static members.
```

## Khai báo field {#declaring-fields}
Field là một biến được khai báo ở cấp class. Field, còn được gọi là attribute hay instance variable, được dùng để lưu giữ state của một object.

Để khai báo một field, bạn dùng cú pháp sau:
```
[accessModifier] [specifiers] type fieldName [= initialValue];
```

Dưới đây là một vài ví dụ:
```java
public class MyClass {
    public static final int MAX_VALUE = 100;
    private String name;
    protected double salary;
    boolean active = true;
    
    // ...
}
```

Access modifier là tùy chọn và có thể là `public`, `private`, `protected` hoặc default (package-private) access nếu không chỉ định gì. Lưu ý rằng khác với class, field có thể dùng cả bốn loại access modifier. Tùy vào access modifier được dùng, field có thể được truy cập từ bên trong class, subclass, class trong cùng package hoặc bất kỳ class nào khác. Chúng ta sẽ nói thêm về điều này ở phần sau.

Phần specifier cũng là tùy chọn và có thể bao gồm các keyword như `static`, `final`, `transient` và `volatile`. Bạn có thể chỉ định không hoặc nhiều specifier (như trong khai báo field đầu tiên), nhưng keyword `final` chỉ có thể được áp dụng một lần:

- Một field được khai báo là `static` thuộc về chính class đó, chứ không thuộc về một instance cụ thể. Sẽ chỉ có một bản sao của field `static` được chia sẻ cho tất cả instance của class. Một cách dùng phổ biến của field `static` là định nghĩa hằng số.
- Một field được khai báo là `final` không thể được gán lại để tham chiếu tới một object hoặc giá trị khác. Nếu đó là primitive type, giá trị không thể bị thay đổi. Nếu đó là reference type, reference không thể bị thay đổi để trỏ tới object khác, nhưng internal state của object vẫn có thể bị thay đổi nếu nó mutable. Field `final` có thể dùng cho hằng số hoặc để biến field thành read-only sau khi khởi tạo. Tuy nhiên, dù bản thân field trở thành read-only, những object được tham chiếu bởi field `final` vẫn có thể bị thay đổi internal state nếu chúng mutable.
- Hai keyword `transient` và `volatile` nâng cao hơn và liên quan tới serialization và multi-threading. Chúng ta sẽ đề cập chúng ở các chương sau.

Kiểu của field đứng sau các specifier. Nó có thể là primitive type như `int`, `boolean`, v.v. hoặc reference type như `String`, `LocalDate`, `ArrayList`, v.v.  

Tên field tuân theo các quy tắc đặt tên identifier chuẩn của Java. Dưới đây là những quy tắc chính bạn cần nhớ cho identifier của field:

1. **Ký tự Unicode**: Java cho phép ký tự Unicode trong identifier, nghĩa là bạn có thể dùng ký tự từ các bộ ký tự không phải chữ Latinh. Tuy nhiên, điều này không phổ biến với tên field vì nó có thể khiến code khó đọc và khó bảo trì hơn.

2. **Ký tự được phép**: Identifier của field chỉ có thể chứa ký tự chữ và số (`A-Z`, `a-z`, `0-9`), dấu gạch dưới (`_`) và dấu đô la (`$`). Identifier phải bắt đầu bằng một chữ cái (`A-Z` hoặc `a-z`), dấu gạch dưới (`_`) hoặc dấu đô la (`$`). Nó không thể bắt đầu bằng một chữ số.

3. **Không dùng reserved word**: Identifier không thể là reserved word của Java. Reserved word bao gồm các keyword như `int`, `if`, `class`, v.v. Chúng là một phần của cú pháp ngôn ngữ Java và có ý nghĩa cụ thể với compiler.

4. **Phân biệt chữ hoa chữ thường**: Java phân biệt chữ hoa chữ thường, nghĩa là các identifier như `myField`, `MyField` và `MYFIELD` được coi là khác nhau.

5. **Độ dài không giới hạn**: Về mặt kỹ thuật, không có giới hạn nào cho độ dài của identifier, nhưng điều quan trọng là giữ nó ở mức hợp lý để đảm bảo khả năng đọc và bảo trì.

Điều quan trọng là phân biệt giữa rule và convention. Rule phải được tuân theo để code Java compile được, còn convention, chẳng hạn bắt đầu tên field bằng chữ thường hoặc dùng `camelCase` cho nhiều từ, là best practice nhằm giúp code dễ đọc và dễ bảo trì hơn nhưng không bị compiler bắt buộc.

Cuối cùng, việc cung cấp giá trị khởi tạo là tùy chọn. Nếu không cung cấp, field sẽ được khởi tạo với default value (`0`, `false` hoặc `null` tùy theo kiểu). Tuy nhiên, với field `static final`, giá trị khởi tạo phải là compile-time constant.

Sau khi một field được khai báo, bạn có thể truy cập nó để đọc giá trị hoặc sửa đổi nó bằng cách gán giá trị mới. Cách bạn truy cập một field phụ thuộc vào việc nó là instance field hay static field và nó dùng access modifier nào.

### Truy cập và sửa đổi field {#accessing-and-modifying-fields}
Để truy cập một instance field, trước tiên bạn cần một instance của class. Sau đó bạn có thể đọc giá trị của field bằng toán tử dot (`.`) như sau:
```java
instanceVariable.fieldName
```

Ví dụ:
```java
String name = person.firstName;
int age = employee.age;  
```

Để sửa đổi một instance field, bạn dùng toán tử gán (`=`) như sau:
```java
person.firstName = "John";
employee.age = 45;
```

Truy cập field `static` có chút khác biệt. Vì chúng thuộc về chính class, bạn không cần instance. Bạn có thể truy cập một static field bằng tên class và toán tử dot:

```java
ClassName.fieldName
```

Ví dụ:
```java
double pi = Math.PI;
int max = Integer.MAX_VALUE;
```

Bên trong chính class khai báo field, bạn có thể truy cập nó trực tiếp bằng tên, không cần tiền tố, bất kể access modifier được dùng. Ngoại lệ duy nhất là khi truy cập field `static`, nên dùng tên class ngay cả khi ở trong cùng class để dễ đọc hơn.

Các access modifier `public`, `private`, `protected` và default (package) kiểm soát visibility của field và quyết định xem nó có thể được truy cập trực tiếp từ bên ngoài class hay không.

Hãy xem một vài ví dụ để minh họa các mức access khác nhau.

```java
public class Person {
    public String name;
    private int age;
    protected String email;
    double height;
}
```

Field `name` là `public`, nên nó có thể được truy cập từ bất kỳ class nào khác:
```java
Person p = new Person();
p.name = "Alice";
```

Field `age` là `private`. Nó chỉ có thể được truy cập bên trong class `Person`. Cố gắng truy cập nó trực tiếp từ bên ngoài class sẽ dẫn tới compile error:
```java
// This will not compile
p.age = 30; 
```

Field `email` là `protected`. Nó có thể được truy cập trong cùng class, trong bất kỳ subclass nào và các class khác trong cùng package:

```java
// This is okay
String email = p.email;

// This is also valid in a subclass, even in a different package
class Employee extends Person {
    public void setEmail(String e) {
         email = e;
    }
}
```

Field `height` có default (package) access vì không chỉ định modifier. Nó có thể được truy cập bởi các class khác trong cùng package:
```java
// This is okay if Person and Student are in same package 
class Student {
    public void printHeight(Person p) {
        System.out.println(p.height);
    }
}
```

Việc khai báo field là `private` và truy cập chúng thông qua các method getter và setter là chuyện thường gặp. Field `public` và `protected` ít được dùng hơn. Default (package-private) access hữu ích cho các class có liên quan trong cùng package.


## Khai báo method {#declaring-methods}
Method là một khối code thực hiện một nhiệm vụ cụ thể và tùy chọn trả về một giá trị. Method được dùng để định nghĩa behavior của một object. Chúng cung cấp cách đóng gói logic phức tạp, chia nhỏ chương trình thành những phần dễ quản lý và cho phép tái sử dụng code.

Để khai báo một method, dùng cú pháp sau:
```java
[accessModifier] [specifiers] returnType methodName([parameters]) [throws ExceptionType1, ExceptionType2, ...] {
    // method body
}
```

Ví dụ:
```java
public static String addParenthesis(String s) {
    return "(" + s + ")";
}

private int sum(int a, int b) {
    return a + b;
}

protected void setName(String name) throws IllegalArgumentException {
    if (name == null || name.isEmpty()) {
        throw new IllegalArgumentException("Name cannot be null or empty");
    }
    this.name = name;
}
```

Access modifier là tùy chọn và kiểm soát visibility của method. Nó có thể là `public`, `private`, `protected` hoặc default (package) access nếu không chỉ định gì. Các quy tắc tương tự như với field mà chúng ta đã thảo luận trước đó.

Các specifier cũng là tùy chọn và có thể bao gồm các keyword như `static`, `final`, `abstract` và `synchronized`. Những keyword này thay đổi behavior của method:

- Method `static` thuộc về chính class và có thể được gọi mà không cần instance của class.
- Method `final` không thể bị override bởi subclass.
- Method `abstract` không có implementation trong class hiện tại và phải được override bởi các subclass không abstract.
- Method `synchronized` chỉ có thể được thực thi bởi một thread tại một thời điểm.

Return type chỉ định kiểu giá trị mà method trả về. Nó có thể là primitive type, reference type hoặc `void` nếu method không trả về gì. Mọi khai báo method đều phải có return type.

Tên method tuân theo cùng convention đặt tên như class và field, thường dùng `camelCase`. Hãy chọn những cái tên có ý nghĩa mô tả mục đích của method.

Các parameter được chỉ định trong cặp ngoặc đơn sau tên method. Có thể có không hoặc nhiều parameter. Nhiều parameter được phân tách bằng dấu phẩy. Parameter là các biến nhận giá trị được truyền cho method khi nó được gọi. Mỗi parameter gồm hai phần, hoặc tùy chọn ba phần:

```java
[parameterModifier] parameterType parameterName
```

Parameter modifier là tùy chọn và có thể là `final`. Nếu một parameter được khai báo là `final`, nghĩa là giá trị của parameter không thể bị thay đổi bên trong thân method. Đây là một ví dụ:
```java
public void printMessage(final String message) {
    // message = "Hello"; // This would cause a compile error
    System.out.println(message);
}
```

Parameter type là bắt buộc và chỉ định kiểu dữ liệu của parameter. Nó có thể là primitive type (như `int`, `double`, `boolean`) hoặc reference type (như `String`, `ArrayList` hay các class tự định nghĩa).

Tên parameter cũng là bắt buộc và tuân theo cùng convention đặt tên như identifier của class, field và method, thường dùng `camelCase`. Tên parameter được dùng để tham chiếu tới giá trị được truyền vào trong thân method.

Dưới đây là một vài ví dụ về định nghĩa parameter:
```java
// A single parameter of type int
public void printNumber(int number) {
    System.out.println("The number is: " + number);
}

// Multiple parameters of different types
public void printPersonDetails(String name, int age, boolean isStudent) {
    System.out.println("Name: " + name);
    System.out.println("Age: " + age);
    System.out.println("Is a student? " + isStudent);
}

// A parameter with a modifier
public void calculateDiscount(final double price, double discountPercentage) {
    double discountAmount = price * (discountPercentage / 100);
    double finalPrice = price - discountAmount;
    System.out.println("Discounted price: " + finalPrice);
}
```

Quay lại các phần của một khai báo method, mệnh đề `throws` là tùy chọn và chỉ định bất kỳ checked exception nào mà method có thể throw. Nhiều exception được phân tách bằng dấu phẩy.

Thân method được bao trong cặp ngoặc nhọn `{}` và chứa code hiện thực chức năng của method. Nó có thể bao gồm khai báo biến, vòng lặp, câu lệnh điều kiện, lời gọi method và các câu lệnh khác.

Nếu method có return type khác `void`, nó phải bao gồm câu lệnh `return` chỉ định giá trị được trả về. Giá trị trả về phải tương thích với return type đã khai báo:
```java
// A simple method that returns a string
public String getName() {
    return "Mark";
}
```

### Method signature {#method-signatures}
Method signature định danh duy nhất một method trong một class. Nó gồm tên method và danh sách có thứ tự các parameter type. Các access modifier (như `public` hay `private`), return type (như `void` hay `int`) và tên parameter không thuộc method signature:
```java
methodName(parameterType1, parameterType2, ...)
```

Ví dụ, xét các khai báo method sau:
```java
public void printMessage(String message) {
    System.out.println(message);
}

public int calculateSum(int a, int b) {
    return a + b;
}

private void updateUser(String username, int age, boolean isActive) {
    // method body
}
```

Method signature của các method này là:

- `printMessage(String)`
- `calculateSum(int, int)`
- `updateUser(String, int, boolean)`

### Gọi method {#calling-a-method}
Khi gọi một method, bạn truyền các argument khớp về kiểu và thứ tự với các parameter được khai báo trong method signature. Argument là những giá trị thực tế được truyền cho method.

Như vậy, để gọi một method, bạn cần dùng tên method theo sau là cặp ngoặc đơn và cung cấp mọi argument cần thiết. Cú pháp là:
```java
[ObjectReference.]methodName([arguments]);
```

Nếu method là instance method (non-static), bạn cần có một object của class chứa method đó. Sau đó bạn có thể gọi method bằng object reference theo sau là toán tử dot và tên method.

Nếu method là method `static`, bạn có thể gọi nó trực tiếp bằng tên class theo sau là toán tử dot và tên method. Bạn không cần object instance để gọi một static method.

Dưới đây là một vài ví dụ về gọi method:
```java
// Calling an instance method
Person person = new Person();
person.setName("John");
String name = person.getName();

// Calling a static method
int max = Math.max(10, 20);
double random = Math.random();

// Calling a method with arguments
Calculator calculator = new Calculator();
int sum = calculator.add(5, 3);
double result = calculator.multiply(2.5, 4.0);
```

Hãy đảm bảo cung cấp đúng số lượng và kiểu của argument như được định nghĩa trong method signature. Nếu có sự không khớp, compiler sẽ throw error.

### Dùng access modifier với method {#using-access-modifiers-with-methods}
Cũng như với field, access modifier kiểm soát visibility và khả năng truy cập của method. Cùng bốn access modifier có thể được dùng: `public`, `private`, `protected` và default (package-private).

Xét class sau:
```java
package com.my.package;

public class MathUtils {
    public static int add(int a, int b) {
        return a + b;
    }

    private static int subtract(int a, int b) {
        return a - b;
    }

    protected static int multiply(int a, int b) {
        return a * b;
    }

    static int divide(int a, int b) {
        return a / b;
    }
}
```

Method `add` được khai báo là `public`, nên nó có thể được gọi từ bất kỳ class nào khác:

```java
int sum = MathUtils.add(1, 2);
```

Method `subtract` được khai báo là `private`. Nó chỉ có thể được gọi từ bên trong chính class `MathUtils`. Cố gắng gọi nó từ class khác sẽ dẫn tới compile error:

```java
// This will not compile
int difference = MathUtils.subtract(10, 7);
```

Method `multiply` được khai báo là `protected`. Nó có thể được gọi từ bên trong cùng class, bất kỳ subclass nào (kể cả ở package khác) và các class khác trong cùng package:

```java
package com.my.other.package;

// Calling from a subclass in a different package
public class AdvancedMathUtils extends MathUtils {
    public static int square(int a) {
        return multiply(a, a);
    }
}
```

Method `divide` có default (package-private) access vì không chỉ định modifier rõ ràng. Hãy nhớ rằng điều này nghĩa là method chỉ có thể được truy cập bởi các class trong cùng package:

```java
package com.my.package;

// Calling from another class in the same package
public class ArithmeticOperations {
    public static int performDivision(int a, int b) {
        return MathUtils.divide(a, b);
    }
}
```

### Truyền argument giữa các method {#passing-arguments-among-methods}
Trong Java, khi bạn truyền argument cho một method, chúng luôn được truyền theo kiểu pass-by-value. Nghĩa là một bản sao của giá trị được truyền cho method, chứ không phải một reference tới biến gốc. Tuy nhiên, hành vi của pass-by-value khác nhau tùy vào việc bạn đang truyền primitive type (như `int`) hay reference type (như một object chẳng hạn `String`).

Khi bạn truyền một primitive type cho method, method nhận được một bản sao của giá trị. Mọi thay đổi được thực hiện trên parameter bên trong method không ảnh hưởng tới biến gốc bên ngoài method.

Đây là một ví dụ:
```java
public void testPrimitive() {
    int num = 10;
    modifyPrimitive(num);
    System.out.println(num); // Output: 10
}

public void modifyPrimitive(int value) {
    value = 20;
}
```

Trong ví dụ này, method `modifyPrimitive` nhận một bản sao giá trị của `num`. Việc sửa đổi parameter `value` bên trong method không làm thay đổi biến `num` gốc trong method `testPrimitive`.

Khi bạn truyền một reference type cho method, method nhận được một bản sao của reference tới object. Trong khi bản thân reference được truyền theo kiểu pass-by-value, method vẫn có thể sửa đổi state của object mà reference trỏ tới.

Đây là một ví dụ:
```java
public void test() {
    Person person = new Person("John", 25);
    modifyPerson(person);
    System.out.println(person.getName()); // Output: Alice
    System.out.println(person.getAge()); // Output: 25
}

public void modifyPerson(Person p) {
    p.setName("Alice"); // Sets a new name
    p = new Person("Bob", 30); // Reassigns p to a new person
}
```

Trong ví dụ này, method `modifyPerson` nhận một bản sao của reference tới object `Person`. Bên trong method, method `setName()` được gọi trên object được tham chiếu bởi `p`, điều này sửa đổi name của object gốc. Tuy nhiên, khi `p` được gán lại thành một object `Person` mới, nó không ảnh hưởng tới reference `person` gốc trong method `main`.

Hãy khám phá thêm vài ví dụ để làm rõ sự khác nhau giữa việc gán lại reference và sửa đổi chính object. 

Đầu tiên, xét ví dụ về việc gán lại reference:
```java
public void test() {
    StringBuilder sb = new StringBuilder("Hello");
    modifyStringBuilder(sb);
    System.out.println(sb.toString()); // Output: Hello
}

public void modifyStringBuilder(StringBuilder builder) {
    builder = new StringBuilder("World");
}
```

Trong ví dụ này, method `modifyStringBuilder` nhận một bản sao của reference tới object `StringBuilder`. Bên trong method, reference `builder` được gán lại thành một object `StringBuilder` mới, nhưng điều này không ảnh hưởng tới reference `sb` gốc trong method `main`.

Hãy đối chiếu ví dụ trước với ví dụ sau, minh họa việc sửa đổi state của object khác với việc chỉ gán lại reference như thế nào:
```java
public void test() {
    StringBuilder sb = new StringBuilder("Hello");
    appendToStringBuilder(sb);
    System.out.println(sb.toString()); // Output: Hello, World!
}

public void appendToStringBuilder(StringBuilder builder) {
    builder.append(", World!");
}
```

Trong ví dụ này, method `appendToStringBuilder` nhận một bản sao của reference tới object `StringBuilder`. Bên trong method, method `append()` được gọi trên object được tham chiếu bởi `builder`, điều này sửa đổi state của object gốc. Những thay đổi được thực hiện trên object có thể thấy được từ bên ngoài method.

Hiểu hành vi của pass-by-value và sự khác nhau giữa việc gán lại reference và sửa đổi chính object là điều quan trọng để viết code đúng đắn và có thể đoán trước. Khi truyền reference type cho method, hãy luôn cân nhắc xem bạn định sửa đổi object hay chỉ đơn giản là gán lại reference.



### Method overloading {#method-overloading}
Trong Java, có thể định nghĩa hai hay nhiều method trong cùng một class có chung tên, miễn là khai báo parameter của chúng khác nhau. Đây gọi là method overloading. Xét các method của class sau:
```java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {
        return a + b;
    }
}
```

Khi method `add` được gọi, Java compiler quyết định phiên bản nào của overloaded method sẽ được gọi dựa trên kiểu của các argument được truyền vào. 

Điều này tương tự như gọi cà phê ở quán cà phê. Barista có thể pha nhiều biến thể cà phê khác nhau dựa trên yêu cầu của bạn: cà phê đen, cà phê sữa, hay cà phê sữa có đường. Mỗi biến thể đều được gọi bằng cùng một từ (coffee), nhưng nguyên liệu bạn chỉ định quyết định loại cà phê chính xác mà bạn sẽ nhận được. Tương tự như vậy, khi bạn gọi một overloaded method trong Java, các argument bạn truyền quyết định phiên bản nào của method sẽ được thực thi.

Ví dụ, nếu chúng ta gọi method `add` với các argument khác nhau:

```java
Calculator calc = new Calculator();

int result1 = calc.add(5, 10);
System.out.println(result1);  // Output: 15

double result2 = calc.add(5.5, 10.2);
System.out.println(result2);  // Output: 15.7

double result3 = calc.add(5, 10.2);
System.out.println(result3);  // Output: 15.2
```

Điều xảy ra như sau: 

1. Khi `calc.add(5, 10)` được gọi, cả hai argument đều có kiểu `int`. Java compiler khớp lời gọi này với method `add` nhận hai parameter `int`, và kết quả là một giá trị `int` bằng 15.

2. Khi `calc.add(5.5, 10.2)` được gọi, cả hai argument đều có kiểu `double`. Java compiler khớp lời gọi này với method `add` nhận hai parameter `double`, và kết quả là một giá trị `double` bằng 15.7.

3. Khi `calc.add(5, 10.2)` được gọi, một argument là `int` và argument còn lại là `double`. Trong trường hợp này, Java compiler thực hiện chuyển đổi argument `int` thành `double` để khớp với method `add` nhận hai parameter `double`. Kết quả là một giá trị `double` bằng 15.2.

Ví dụ này minh họa cách Java compiler dùng kiểu của các argument để xác định overloaded method nào sẽ được gọi. Nó khớp các argument với method signature cụ thể nhất hiện có.

Java chỉ có thể chọn một overloaded method nếu nó tìm được khớp chính xác cho các argument hoặc nếu nó tìm được một phiên bản cụ thể hơn thông qua widening conversion.

Widening conversion là khi bạn đi từ một kiểu dữ liệu nhỏ hơn sang một kiểu dữ liệu lớn hơn, ví dụ từ `int` sang `long`, hoặc như trong ví dụ trên, từ `int` sang `double`.

Tuy nhiên, Java không thể tự động áp dụng narrowing conversion (đi từ kiểu dữ liệu lớn hơn sang kiểu nhỏ hơn). Nếu nó không tìm được khớp chính xác hoặc khớp thông qua widening, nó sẽ báo compile error.

Điều quan trọng cần lưu ý là method overloading không giống method overriding. Chúng ta sẽ nói thêm về overriding ở chương sau, nhưng khi overriding, bạn cung cấp một implementation khác cho một method được kế thừa. Method bị override phải có cùng tên, return type và parameter với method được kế thừa. Ngược lại, các overloaded method phải có cùng tên nhưng parameter khác nhau.

Vì vậy hãy luôn ghi nhớ điều này: chỉ thay đổi return type là không đủ để method overloading. Danh sách parameter phải khác nhau.

Ngoài ra, một hiểu lầm phổ biến là Java luôn chọn overloaded method có nhiều parameter nhất. Không phải vậy. Java chọn method dựa trên khớp cụ thể nhất với các kiểu argument, không nhất thiết là method có nhiều parameter nhất.

Xét class sau có nhiều overloaded method cùng tên `display`:

```java
public class DisplayOverload {
    
    // Method with a single String argument
    public void display(String str) {
        System.out.println("Displaying a String: " + str);
    }
    
    // Overloaded method with a single int argument
    public void display(int num) {
        System.out.println("Displaying an integer: " + num);
    }
    
    // Overloaded method with two int arguments
    public void display(int num1, int num2) {
        System.out.println("Displaying two integers: " + num1 + " and " + num2);
    }
}

// ...

DisplayOverload obj = new DisplayOverload();
        
obj.display("Hello, World!"); // Calls the method with a String argument
obj.display(5); // Calls the method with a single int argument
obj.display(10, 20); // Calls the method with two int arguments
```

Trong ví dụ này:
- Khi `display("Hello, World!");` được gọi, Java chọn method `display(String str)` vì argument là một `String`, khớp với parameter type của method cụ thể này.
- Khi `display(5);` được gọi, Java chọn method `display(int num)` vì argument là một số nguyên, khiến nó trở thành khớp cụ thể nhất trong các overloaded method.
- Khi `display(10, 20);` được gọi, dù về lý thuyết có những method `display` khác có thể nhận số nguyên, Java vẫn chọn `display(int num1, int num2)` vì nó khớp cụ thể nhất với hai argument số nguyên được cung cấp.

Một điều cuối cần lưu ý là bạn không thể overload các method chỉ khác nhau bởi một varargs parameter. Ví dụ, đoạn code này sẽ không compile:
```java
public void sum(int[] numbers) { }
public void sum(int... numbers) { } // Compile-time error
```

Lý do là cả `int[] numbers` và `int... numbers` về cơ bản là giống nhau từ góc nhìn của Java vì `int...` chỉ là syntactic sugar cho một array các số nguyên (`int[]`). Khi bạn cố overload một method với hai parameter type này, Java coi chúng là những signature giống hệt nhau. Nhưng hãy nói thêm về varargs.



### Varargs {#varargs}
Varargs, viết tắt của variable-length arguments, là một tính năng cho phép method nhận một số lượng argument không xác định của một kiểu cụ thể. Hãy nghĩ về varargs như một bữa buffet thỏa thích. Ở buffet, bạn không bị giới hạn ở một số món cố định; bạn có thể chọn bao nhiêu món khác nhau tùy thích, và thậm chí có thể quay lại lấy thêm. Tương tự, với varargs, một method có thể được gọi với số lượng argument thay đổi; bạn không bị cố định ở một con số cụ thể. Điều này khiến method linh hoạt hơn và dễ dùng hơn khi số lượng input chính xác có thể thay đổi.

Để định nghĩa một method với varargs, bạn dùng dấu ba chấm (`...`) sau kiểu dữ liệu của parameter cuối cùng. Cách nó hoạt động như sau:

```java
public void display(String... words) {
    for (String word : words) {
        System.out.println(word);
    }
}
```

Trong ví dụ này, `display` có thể được gọi với bất kỳ số lượng argument `String` nào, kể cả không có argument nào. Cứ như thể bạn đang nói với method: "Đây là những gì tôi có, lấy hết đi." Sự linh hoạt này khiến varargs cực kỳ hữu ích để tạo những method cần xử lý số lượng object không biết trước, như danh sách tên, số hay thậm chí các object phức tạp.

Giờ thì có những quy tắc cụ thể bạn phải tuân theo để dùng varargs hiệu quả và đúng đắn.

Thứ nhất, một varargs parameter phải là parameter cuối cùng trong danh sách parameter của method. Quy tắc này đảm bảo method có thể nhận số lượng argument thay đổi mà không gây nhập nhằng về việc argument nào thuộc varargs parameter và argument nào không. Ví dụ, xét method sau:

```java
void printStrings(String title, String... strings) {
    System.out.println(title + ":");
    for (String str : strings) {
        System.out.println(str);
    }
}
```

Trong ví dụ này, `String... strings` là một varargs parameter có thể nhận bất kỳ số lượng argument `String` nào. Việc nó là parameter cuối cùng cho phép bạn gọi `printStrings` với bất kỳ số lượng string nào, hoặc thậm chí không có string nào.

Thứ hai, chỉ cho phép một varargs parameter trong danh sách parameter của method. Hạn chế này tránh nhầm lẫn về việc argument nào thuộc varargs parameter nào nếu cho phép nhiều hơn một. Ví dụ, nếu bạn muốn tạo một method cộng các số, bạn có thể làm như sau:

```java
double multiplyAndSum(double multiplier, int... numbers) {
    double sum = 0;
    for (int num : numbers) {
        sum += num;
    }
    return sum * multiplier;
}
```

Method này chỉ bao gồm đúng một varargs parameter (`int... numbers`), đảm bảo rõ ràng về cách nó nên được gọi và cách nó xử lý các argument được truyền vào.

Thứ ba, một method với varargs parameter có thể được overload, nhưng bạn phải đảm bảo tránh nhập nhằng. Điều này đòi hỏi phải chắc chắn mỗi method signature đủ khác biệt để tránh compile-time error. Ví dụ, bạn có thể có:

```java
void display(String s, int... numbers) {
    System.out.println(s);
    for (int num : numbers) {
        System.out.print(num + " ");
    }
    System.out.println();
}

void display(String first, String second) {
    System.out.println(first + ", " + second);
}
```

Ở đây, `display` được overload với một phiên bản nhận một string và một varargs parameter kiểu integer, và một phiên bản khác nhận hai string. Overloading này hợp lệ vì các method signature khác biệt nhau, đảm bảo compiler có thể xác định method nào cần gọi dựa trên các argument được cung cấp.

Bên trong method, việc truy cập các phần tử của một varargs parameter có thể được thực hiện theo nhiều cách, mỗi cách phù hợp với những tình huống khác nhau.

Cách đơn giản nhất để truy cập các phần tử trong một varargs parameter là coi nó như một array và truy cập trực tiếp các phần tử bằng index. Cách này hữu ích khi bạn biết chính xác số lượng argument hoặc cần truy cập những phần tử cụ thể. Ví dụ, xét một method in ra phần tử thứ nhất, thứ hai và cuối cùng của một varargs parameter:

```java
void printSelectedNumbers(int... numbers) {
    if (numbers.length >= 3) {
        System.out.println("First: " + numbers[0]);
        System.out.println("Second: " + numbers[1]);
        System.out.println("Last: " + numbers[numbers.length - 1]);
    } else {
        System.out.println("Insufficient arguments.");
    }
}
```

Method này truy cập trực tiếp các phần tử theo index của chúng, tương tự truy cập array, giúp việc lấy các giá trị cụ thể trở nên đơn giản.

Để lặp qua từng phần tử trong một varargs parameter, enhanced for loop cung cấp cách xử lý từng argument gọn gàng và súc tích. Cách này đặc biệt hữu ích khi bạn cần thực hiện thao tác trên mọi phần tử hoặc khi số lượng argument thay đổi. Đây là ví dụ cộng tất cả các số được truyền cho method:

```java
int sumAll(int... numbers) {
    int sum = 0;
    for (int num : numbers) {
        sum += num;
    }
    return sum;
}
```

Enhanced `for` loop tự động lặp qua từng phần tử trong `numbers`, cho phép tổng hợp hoặc xử lý dễ dàng.

Dù tương tự việc dùng enhanced `for` loop, đôi khi bạn có thể cần lặp thủ công qua một varargs parameter bằng thuộc tính `length` của nó cho những logic phức tạp hơn, chẳng hạn khi bạn cần truy cập index hiện tại. Đây là cách bạn có thể in từng phần tử kèm index của nó:

```java
void printWithIndices(String... strings) {
    for (int i = 0; i < strings.length; i++) {
        System.out.println("Element " + i + ": " + strings[i]);
    }
}
```

Method này tận dụng thuộc tính `length` của varargs parameter để kiểm soát vòng lặp thủ công, mang lại sự linh hoạt cho các thao tác dựa trên index.

Với những thao tác phức tạp hơn, bao gồm filter, map hay tổng hợp các phần tử, Stream API của Java có thể làm việc trực tiếp với varargs. Cách này đặc biệt mạnh mẽ để xử lý các phần tử theo phong cách functional programming. Chúng ta sẽ đề cập stream ở chương sau, nhưng ví dụ, bạn có thể filter và chỉ cộng các số chẵn như sau:

```java
int sumEvenNumbers(int... numbers) {
    return Arrays.stream(numbers) // Convert varargs to a stream
                 .filter(n -> n % 2 == 0) // Filter even numbers
                 .sum(); // Sum them
}
```

Sau khi đã định nghĩa một method nhận vararg parameter, bạn có thể gọi nó bằng cách truyền từng argument riêng lẻ, truyền một array, hoặc gọi mà không truyền argument nào.

Cách đơn giản nhất để gọi một method với varargs là truyền từng argument riêng lẻ cho nó. Cách này giống hệt việc gọi một method với số lượng parameter cố định, nhưng có thêm sự linh hoạt khi chỉ định bất kỳ số lượng argument nào. Đây là ví dụ dùng một method in ra từng argument:

```java
void printArgs(String... args) {
    for (String arg : args) {
        System.out.println(arg);
    }
}

// Calling the method
printArgs("Hello", "World", "Varargs", "are", "flexible");
```

Trong ví dụ này, method `printArgs` được gọi với năm argument string, minh họa sự dễ dàng khi bạn có thể truyền bất kỳ số lượng argument nào.

Một cách khác, bạn có thể gọi một varargs method bằng cách truyền một array thuộc kiểu đã chỉ định. Cách này hữu ích khi các argument đã có sẵn trong một array, hoặc khi bạn muốn xây dựng danh sách argument một cách linh động. Xét một method cộng một số lượng tùy ý các số nguyên:

```java
int sumNumbers(int... numbers) {
    return Arrays.stream(numbers).sum();
}

// Calling the method with an array
int[] numberArray = {1, 2, 3, 4, 5};
int sum = sumNumbers(numberArray);
System.out.println("Sum is: " + sum);
```

Ở đây, `sumNumbers` được gọi với một integer array, cho thấy cách một array khớp với varargs signature, mang lại cách truyền nhiều argument gọn gàng.

Cuối cùng, một varargs method cũng có thể được gọi mà không truyền argument nào. Tính năng này đặc biệt hữu ích khi một thao tác là tùy chọn hoặc khi có một hành vi mặc định hợp lệ trong trường hợp không có input. Đây là một method nối bất kỳ số lượng string nào, kèm minh họa gọi nó mà không có argument:

```java
String concatenateStrings(String... strings) {
    return Stream.of(strings).collect(Collectors.joining(", "));
}

// Calling the method without arguments
String result = concatenateStrings();
System.out.println("Result: " + result);
```

Ví dụ trên minh họa rằng gọi `concatenateStrings` mà không có argument nào là hoàn toàn hợp lệ và varargs cung cấp một method signature linh hoạt đáp ứng nhiều trường hợp sử dụng khác nhau.


### Method `main` {#the-main-method}
Method `main` là một method đặc biệt trong Java, đóng vai trò điểm vào (entry point) của một ứng dụng Java. Khi bạn chạy một chương trình Java, JVM tìm method này và bắt đầu thực thi code bên trong nó. Mọi ứng dụng Java phải có một method `main` trong ít nhất một class của nó.

Đây là cú pháp để khai báo một method `main`:
```java
public static void main(String[] args) {
    // ...
}
```

Hãy phân tích từng phần:

- `public`: Method `main` phải được khai báo là `public` để cho phép JVM gọi nó từ bên ngoài class.
- `static`: Method `main` phải được khai báo là `static` để nó có thể được gọi mà không cần tạo instance của class.
- `void`: Method `main` không trả về giá trị nào, nên return type của nó là `void`.
- `main`: Tên của method phải là "main" (viết thường toàn bộ) để JVM nhận ra nó là entry point.
- `String[] args`: Method `main` nhận một parameter duy nhất, kiểu `String` array, theo quy ước đặt tên là `args`. Parameter này cho phép bạn truyền command-line argument cho chương trình.

Đây là ví dụ về một method `main` đơn giản:
```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

Trong ví dụ này, method `main` chỉ đơn giản in `Hello, World!` ra console.

Các argument của chương trình được truyền dưới dạng một `String` array, trong đó mỗi phần tử đại diện cho một argument riêng biệt:
```java
public class CommandLineArguments {
    public static void main(String[] args) {
        if (args.length > 0) {
            System.out.println("Arguments:");
            for (String arg : args) {
                System.out.println(arg);
            }
        } else {
            System.out.println("No arguments provided.");
        }
    }
}
```

Trong ví dụ này, method `main` kiểm tra xem có argument nào được truyền vào không, bằng cách dùng `args.length`. Nếu có argument, nó lặp qua array `args` và in từng argument. Nếu không có argument nào được cung cấp, nó in một thông báo cho biết điều đó.

Bạn có thể chạy chương trình này từ command line và truyền argument như sau:
```
java CommandLineArguments arg1 arg2 arg3
```

Kết quả sẽ là:
```
Arguments:
arg1
arg2
arg3
```

Nếu bạn chạy chương trình mà không có argument nào:
```
java CommandLineArguments
```

Kết quả sẽ là:
```
No arguments provided.
```

Có thể có nhiều method tên `main` trong một class, miễn là chúng có danh sách parameter khác nhau. Tuy nhiên, chỉ method được định nghĩa là `public static void main(String[] args)` mới được nhận diện là entry point của ứng dụng:
```java
public class MainOverloading {
    public static void main(String[] args) {
        System.out.println("Main method with String[] args");
        main(42);
    }

    public static void main(int num) {
        System.out.println("Main method with int parameter: " + num);
    }
}
```

Trong ví dụ này, class có hai method `main`: một với signature chuẩn và một với parameter `int`, tuy nhiên, method `main(String[] args)` là entry point và nó gọi method `main(int num)`.

Kết quả là:
```
Main method with String[] args
Main method with int parameter: 42
```

## Constructor và Initializer {#constructors-and-initializers}

### Constructor {#constructors}
Trong Java, constructor là một method đặc biệt dùng để khởi tạo object. Nó được gọi khi một instance của class được tạo.

Hãy hình dung constructor như một công thức làm một chiếc bánh cụ thể. Giống như công thức chứa hướng dẫn và nguyên liệu để làm bánh, constructor chứa code để thiết lập trạng thái ban đầu của một object.

Cú pháp định nghĩa constructor rất đơn giản. Nó có cùng tên với class và không có return type, kể cả void.

Đây là một ví dụ:
```java
class Cake {
    String flavor;
    double price;
    Cake() {
        flavor = "Vanilla";
        price = 9.99;
    }
}
```

Để tạo một object, chúng ta dùng keyword `new` theo sau là lời gọi constructor:
```java
Cake myCake = new Cake();
```

Dòng trên sẽ tạo một object `Cake` mới với flavor mặc định là `Vanilla` và giá `9.99`.

Nhưng nếu bạn muốn giữ flavor mặc định nhưng giá khác thì sao? Hoặc tùy chỉnh cả hai trong một số trường hợp?

Vâng, giống như bạn có thể nướng nhiều loại bánh khác nhau bằng cách chỉnh sửa công thức, bạn có thể tạo các object với trạng thái ban đầu khác nhau bằng cách cung cấp nhiều constructor.

Ví dụ, hãy thêm một constructor nữa vào class `Cake` của chúng ta:
```java
Cake(String flavor, double price) {
    this.flavor = flavor; 
    this.price = price;
}
```

Với constructor này, chúng ta có thể tạo một chiếc bánh với bất kỳ flavor và price nào mình muốn:
```java
Cake specialCake = new Cake("Chocolate", 12.99);
```

Việc có nhiều constructor mang lại sự linh hoạt trong quá trình tạo object. Chúng ta có thể cung cấp nhiều cách khác nhau để khởi tạo một object dựa trên dữ liệu có sẵn tại thời điểm tạo.

Constructor không có parameter được gọi là default constructor. Nếu bạn không định nghĩa constructor nào trong class, compiler sẽ tự động cung cấp một default constructor với thân rỗng.

Tuy nhiên, nếu bạn định nghĩa bất kỳ constructor nào (như constructor có parameter của chúng ta), compiler sẽ không cung cấp default constructor nữa. Trong trường hợp này, nếu bạn vẫn muốn có tùy chọn tạo object mà không cần chỉ định parameter, bạn cần định nghĩa default constructor một cách tường minh.

Vậy trong class `Cake` của chúng ta, có thể có cả hai constructor:
```java
class Cake {
    String flavor;
    double price;

    Cake() {
        flavor = "Vanilla";
        price = 9.99;
    }

    Cake(String flavor, double price) {
        this.flavor = flavor;
        this.price = price;
    }
}
```

Giờ chúng ta có thể tạo một chiếc bánh vanilla mặc định với `new Cake()` hoặc một chiếc bánh tùy chỉnh với `new Cake("Chocolate", 10.99)`.

### Instance Initializer {#instance-initializers}
Instance initializer là các block code được thực thi khi một object được tạo, giống như constructor. Tuy nhiên, trong khi constructor là method có tên cụ thể và có thể có parameter, instance initializer chỉ là những block code nằm trong class.

Hãy dùng một phép so sánh để hiểu về instance initializer.

Hãy tưởng tượng bạn chuyển vào một ngôi nhà mới. Mỗi người chúng ta đều có những "nghi thức" riêng để biến ngôi nhà thành tổ ấm. Người thì treo ảnh gia đình, người thì sơn tường bằng màu yêu thích. Những nghi thức này đặc trưng cho từng người, cũng như instance initializer đặc trưng cho từng object.

Đây là cú pháp của một instance initializer:
```java
class House {
    String color;
    // instance initializer
    {
        color = "White";
        System.out.println("Performing move-in ritual");
    }
}
```

Mỗi khi một object `House` mới được tạo, code bên trong block instance initializer sẽ chạy. Nó sẽ đặt color thành `White` và in ra `"Performing move-in ritual"`.

Vậy instance initializer so với constructor như thế nào, và khi nào bạn nên dùng chúng?

Hãy tưởng tượng bạn có một class với nhiều constructor. Mỗi constructor cần thực hiện một số tác vụ khởi tạo chung. Thay vì lặp lại code trong từng constructor, bạn có thể đặt nó trong một instance initializer. Code trong initializer sẽ chạy bất kể constructor nào được dùng.

```java
class House {
    String color;
    int numberOfRooms;

    // instance initializer    
    {
        color = "White";
        System.out.println("Performing move-in ritual");
    }

    House(int numberOfRooms) {
        this.numberOfRooms = numberOfRooms;
    }

    House(String color, int numberOfRooms) {
        this.color = color;
        this.numberOfRooms = numberOfRooms;
    }
}
```

Trong trường hợp này, bất kể constructor nào được dùng để tạo object `House`, instance initializer vẫn chạy, đặt color mặc định thành `White` và in thông báo move-in.

Tuy nhiên, cần lưu ý rằng trong hầu hết trường hợp, bạn có thể đạt kết quả tương tự bằng cách chuyển code khởi tạo chung vào một method riêng và gọi method đó từ mỗi constructor.

Thực tế, một số người cho rằng instance initializer là dư thừa vì bất cứ điều gì bạn làm được với instance initializer thì cũng làm được với constructor. Khác biệt chính là constructor có thể nhận parameter, còn instance initializer thì không.

Dù vậy, có một số tình huống instance initializer có thể hữu ích. Ví dụ, nếu bạn đang dùng anonymous class (sẽ bàn ở phần sau), bạn không thể định nghĩa constructor, nên instance initializer là lựa chọn duy nhất cho code khởi tạo.

### Static Initializer {#static-initializers}
Static initializer là các block code được thực thi khi một class được load vào bộ nhớ, trước khi bất kỳ instance nào của class được tạo. Chúng được dùng để khởi tạo static variable hoặc thực hiện các hành động chung cho mọi instance của class.

Hãy tưởng tượng một cuộc họp thị dân diễn ra một lần khi thị trấn được thành lập. Trong cuộc họp này, những người lãnh đạo thị trấn đặt ra các quy tắc và hướng dẫn áp dụng cho mọi người trong thị trấn. Việc thiết lập một lần này giống như những gì một `static` initializer làm cho một class.

Đây là cú pháp của một `static` initializer:
```java
class TownHall {
    static String townName;
    static int population;

    // static initializer
    static {
        townName = "JavaVille";
        population = 1000;
        System.out.println("Town established: " + townName);
    }
}
```

Keyword `static` trước dấu ngoặc nhọn mở biểu thị rằng đây là một block static initializer. Nó sẽ chạy một lần khi class `TownHall` được load, đặt `townName` thành `JavaVille`, `population` ban đầu thành `1000`, và in ra `Town established: JavaVille`.

Giờ bạn có thể nghĩ rằng static initializer chỉ là một cách khác để khởi tạo static variable, và bạn có thể đạt kết quả tương tự bằng cách khởi tạo trực tiếp biến tại chỗ khai báo, như thế này:
```java
static String townName = "JavaVille";
static int population = 1000;
```

Và bạn đúng một phần. Với những khởi tạo đơn giản, gán trực tiếp thường rõ ràng và ngắn gọn hơn.

Tuy nhiên, static initializer mang lại nhiều linh hoạt hơn. Chúng cho phép bạn viết logic khởi tạo phức tạp hơn, chẳng hạn như:
- Gọi method
- Dùng các cấu trúc điều khiển như loop và câu lệnh điều kiện
- Xử lý exception

Đây là một ví dụ minh họa điều này:
```java
static List<String> residents = new ArrayList<>();

static {
    Path path = Paths.get("residents.txt");
    try (Stream<String> lines = Files.lines(path)) {
        lines.forEach(residents::add);
    } catch (IOException e) {
        System.out.println("Residents file not found.");
    }
}
```

Trong trường hợp này, chúng ta dùng static initializer để đọc danh sách cư dân từ một file và nạp vào list `residents`. Kiểu khởi tạo phức tạp này sẽ không thể thực hiện bằng một phép gán trực tiếp đơn giản.

Một khác biệt quan trọng nữa là một class có thể có nhiều static initializer, và chúng sẽ được thực thi theo thứ tự xuất hiện trong class. Điều này có thể hữu ích để tổ chức logic khởi tạo phức tạp thành những phần dễ đọc.

Cần lưu ý rằng static initializer được thực thi trước khi bất kỳ instance nào của class được tạo, và thậm chí trước khi method `main` được gọi. Chúng là một phần của quá trình class loading.

Ngược lại, instance initializer và constructor chạy mỗi khi một instance mới của class được tạo. Chúng là một phần của quá trình object creation.

### Thứ tự khởi tạo {#initialization-order}
Chúng ta đã xem xét constructor, instance initializer và static initializer. Tuy nhiên, nếu một class chứa cả ba, cái nào chạy trước? Thứ tự khởi tạo là gì?

Khi một class được load, những thứ đầu tiên được khởi tạo là static variable và static initializer, theo thứ tự chúng xuất hiện trong class. Điều này xảy ra một lần cho mỗi lần class loading, trước khi bất kỳ instance nào được tạo.

Sau đó, mỗi khi một instance mới của class được tạo, các instance variable được khởi tạo, và instance initializer cùng constructor được chạy. 

Thứ tự như sau:

1. Instance variable được khởi tạo về giá trị mặc định (`0`, `false` hoặc `null`). Bước này đảm bảo mọi instance variable có trạng thái khởi đầu có thể dự đoán được trước khi bất kỳ code khởi tạo nào tiếp theo được thực thi.
2. Instance initializer chạy theo thứ tự xuất hiện trong class.
3. Constructor được thực thi.

Đây là một ví dụ minh họa thứ tự này:
```java
class InitializationOrder {
    static int staticVar = 1;
    int instanceVar = 1;

    static {
        System.out.println("Static Initializer: staticVar = " + staticVar);
        staticVar = 2;
    }

    {
        System.out.println("Instance Initializer: instanceVar = " + instanceVar);
        instanceVar = 2;
    }

    InitializationOrder() {
        System.out.println("Constructor: instanceVar = " + instanceVar);
        instanceVar = 3;
    }

    public static void main(String[] args) {
        System.out.println("Creating new instance");
        InitializationOrder obj = new InitializationOrder();
        System.out.println("Created instance: instanceVar = " + obj.instanceVar);
    }
}
```

Nếu bạn chạy code này, output sẽ là:
```
Static Initializer: staticVar = 1
Creating new instance
Instance Initializer: instanceVar = 1
Constructor: instanceVar = 2
Created instance: instanceVar = 3
```

Hãy phân tích từng bước:
1. Khi class `InitializationOrder` được load, static variable `staticVar` được khởi tạo thành `1`, sau đó static initializer chạy, in giá trị hiện tại của `staticVar` (`1`) rồi đặt nó thành `2`.
2. Trong method `main`, chúng ta in `Creating new instance` để đánh dấu thời điểm bắt đầu tạo instance.
3. Một object `InitializationOrder` mới được tạo. Đầu tiên, instance variable `instanceVar` được khởi tạo với giá trị mặc định là `1`.
4. Instance initializer chạy, in giá trị hiện tại của `instanceVar` (`1`) rồi đặt nó thành `2`.
5. Constructor được thực thi, in giá trị hiện tại của `instanceVar` (`2`) rồi đặt nó thành `3`.
6. Cuối cùng, quay lại method `main`, chúng ta in giá trị cuối cùng của `instanceVar` (`3`).

Điều quan trọng là ghi nhớ thứ tự này, đặc biệt nếu các initializer và constructor của bạn phụ thuộc lẫn nhau. Những giả định sai về thứ tự khởi tạo có thể dẫn đến những bug tinh vi.

Ngoài ra, lưu ý rằng nếu một class có nhiều static initializer, chúng sẽ chạy theo thứ tự xuất hiện trong class. Điều tương tự cũng đúng với instance initializer.

Hãy mở rộng ví dụ trước của chúng ta để minh họa điều này:

```java
class MultipleInitializers {
    static int staticVar1;
    static int staticVar2;
    int instanceVar1;
    int instanceVar2;

    static {
        System.out.println(
          "Static Initializer 1: staticVar1 = " + staticVar1
        );
        staticVar1 = 1;
    }

    static {
        System.out.println(
          "Static Initializer 2: staticVar2 = " + staticVar2
        );
        staticVar2 = 2;
    }

    {
        System.out.println(
          "Instance Initializer 1: instanceVar1 = " + instanceVar1
        );
        instanceVar1 = 1;
    }

    {
        System.out.println(
          "Instance Initializer 2: instanceVar2 = " + instanceVar2
        );
        instanceVar2 = 2;
    }

    MultipleInitializers() {
        System.out.println("Constructor");
    }

    public static void main(String[] args) {
        System.out.println("Creating new instance");
        MultipleInitializers obj = new MultipleInitializers();
        System.out.println(
          "Created instance: instanceVar1 = " 
              + obj.instanceVar1 
              + ", instanceVar2 = " 
              + obj.instanceVar2
        );
    }
}
```

Khi chạy code này, output sẽ là:
```
Static Initializer 1: staticVar1 = 0
Static Initializer 2: staticVar2 = 0
Creating new instance
Instance Initializer 1: instanceVar1 = 0
Instance Initializer 2: instanceVar2 = 0
Constructor
Created instance: instanceVar1 = 1, instanceVar2 = 2
```

Đây là những gì đang diễn ra:
1. Khi class `MultipleInitializers` được load, các static variable `staticVar1` và `staticVar2` được khởi tạo về giá trị mặc định `0`.

2. Static initializer đầu tiên chạy, in giá trị hiện tại của `staticVar1` (`0`) rồi đặt nó thành `1`.

3. Static initializer thứ hai chạy, in giá trị hiện tại của `staticVar2` (`0`) rồi đặt nó thành `2`.

4. Trong method `main`, chúng ta in `Creating new instance` để đánh dấu thời điểm bắt đầu tạo instance.

5. Một object `MultipleInitializers` mới được tạo. Đầu tiên, các instance variable `instanceVar1` và `instanceVar2` được khởi tạo về giá trị mặc định `0`.

6. Instance initializer đầu tiên chạy, in giá trị hiện tại của `instanceVar1` (`0`) rồi đặt nó thành `1`.

7. Instance initializer thứ hai chạy, in giá trị hiện tại của `instanceVar2` (0) rồi đặt nó thành `2`.

8. Constructor được thực thi, chỉ đơn giản in ra `Constructor`.

9. Cuối cùng, quay lại method `main`, chúng ta in giá trị cuối cùng của `instanceVar1` (`1`) và `instanceVar2` (`2`).

Hãy nhớ rằng, mọi static initializer sẽ chạy trước mọi instance initializer, và mọi initializer sẽ chạy trước constructor. Nhưng trong từng nhóm (static hay instance), các initializer sẽ chạy theo thứ tự chúng được định nghĩa trong class.


## Kế thừa từ `java.lang.Object` {#extending-from-javalangobject}
Trong Java, mọi class đều ngầm là một subclass của class `java.lang.Object`, vốn là gốc của hệ thống phân cấp class. Kể cả khi bạn không extends bất kỳ class nào một cách tường minh, class của bạn vẫn tự động kế thừa từ `Object`.

Class `Object` cung cấp một tập method nền tảng chung cho mọi object. Khi bạn tạo một class mới, bạn tự động kế thừa những method này. Một số method thường dùng được kế thừa từ `Object` gồm:

1. `toString()`: Trả về biểu diễn chuỗi (string representation) của object. Theo mặc định, nó trả về một string gồm tên class của object, ký hiệu `@`, và hash code của object ở định dạng thập lục phân (hexadecimal). Bạn có thể override method này để cung cấp biểu diễn chuỗi tùy chỉnh cho object của mình.

2. `equals(Object obj)`: So sánh object với một object khác để kiểm tra bằng nhau. Theo mặc định, nó so sánh reference của các object bằng toán tử `==`. Bạn có thể override method này để định nghĩa logic so sánh bằng tùy chỉnh dựa trên trạng thái của object.

3. `hashCode()`: Trả về giá trị hash code cho object. Hash code được dùng trong các cấu trúc dữ liệu dựa trên hash như `HashSet` và `HashMap`. Theo mặc định, nó trả về một giá trị integer duy nhất cho mỗi object. Nếu bạn override method `equals()`, bạn cũng nên override method `hashCode()` để đảm bảo những object bằng nhau có cùng hash code.

4. `getClass()`: Trả về runtime class của object. Đây là method `final`, nghĩa là nó không thể bị override.

5. `clone()`: Tạo và trả về một bản sao của object. Theo mặc định, nó thực hiện shallow copy object. Để dùng method này, class của bạn phải implements interface `Cloneable`.

Đây là một ví dụ minh họa một số method được kế thừa từ `Object`:

```java
class MyClass {
    private int value;
    
    public MyClass(int value) {
        this.value = value;
    }
    
    @Override
    public String toString() {
        return "MyClass[value=" + value + "]";
    }
    
    @Override
    public boolean equals(Object obj) {
        if (this == obj)
            return true;
        if (obj == null || getClass() != obj.getClass())
            return false;
        MyClass other = (MyClass) obj;
        return value == other.value;
    }
    
    @Override
    public int hashCode() {
        return Objects.hash(value);
    }
}
```

Trong ví dụ này, `MyClass` override các method `toString()`, `equals()` và `hashCode()` được kế thừa từ `Object`. Method `toString()` cung cấp biểu diễn chuỗi tùy chỉnh cho object, method `equals()` định nghĩa tiêu chí bằng nhau dựa trên field value, và method `hashCode()` sinh hash code dựa trên field value.

Bằng cách tận dụng những method này, bạn có thể cung cấp biểu diễn chuỗi có ý nghĩa, định nghĩa các phép so sánh bằng, và đảm bảo hành vi đúng trong các cấu trúc dữ liệu dựa trên hash.

## Nested Class {#nested-classes}
Trong Java, có thể định nghĩa một class bên trong một class khác. Những class như vậy được gọi là nested class. Giống như một chiếc hộp có thể chứa nhiều chiếc hộp nhỏ hơn bên trong nó, một class (outer class hay enclosing class) có thể có các class khác (nested class) được định nghĩa bên trong nó.

Có bốn loại nested class trong Java:

1. Static nested class

2. Inner class (còn gọi là non-static nested class)

3. Local class

4. Anonymous class

Mỗi loại nested class có những đặc điểm và trường hợp sử dụng riêng:

- Static nested class giống như một chiếc hộp nhỏ không phụ thuộc vào chiếc hộp lớn để tồn tại. Nó có thể truy cập trực tiếp các static member của enclosing class. Tuy nhiên, để truy cập các non-static member, nó cần một instance của enclosing class, giống như bất kỳ class bên ngoài nào khác.

- Inner class thì giống như một chiếc hộp nhỏ gắn chặt với chiếc hộp lớn. Nó có thể truy cập trực tiếp cả static lẫn non-static member của enclosing class. Tuy nhiên, một instance của inner class không thể tồn tại nếu không có một instance của enclosing class.

- Local class giống như một chiếc hộp tạm thời được tạo bên trong một method hoặc một block của enclosing class. Scope của local class chỉ giới hạn trong block mà nó được định nghĩa. Mặc dù local class không dùng các access modifier truyền thống như `public` hay `private`, khả năng truy cập của chúng vốn dĩ chỉ giới hạn trong block chứa nó.

- Anonymous class giống như một chiếc hộp dùng một lần, không tên, được tạo cho một mục đích cụ thể. Nó được định nghĩa và khởi tạo trong một câu lệnh duy nhất, thường là argument của một lời gọi method hoặc một initializer. Khả năng truy cập của anonymous class được quyết định bởi ngữ cảnh sử dụng, chẳng hạn trong một method hay như một field initializer, và nó không dùng các access modifier truyền thống.

Khi phải chọn giữa static nested class và inner class, hãy cân nhắc mối quan hệ giữa nested class và enclosing class. Nếu nested class không cần truy cập các non-static member của enclosing class, hãy dùng static nested class. Điều này giúp class độc lập và dễ tái sử dụng hơn. Nếu nested class cần truy cập các non-static member của enclosing class hoặc cần gắn với một instance của enclosing class, hãy dùng inner class.

Cần lưu ý rằng dù nested class giúp tổ chức code tốt hơn, chúng có ảnh hưởng đến cách code hoạt động. Mỗi loại nested class có hành vi và trường hợp sử dụng riêng. Ví dụ, inner class có một reference ngầm đến một instance của enclosing class, điều này có thể ảnh hưởng đến việc dùng bộ nhớ và serialization.

Một hiểu lầm phổ biến là static nested class và inner class về cơ bản giống nhau vì cả hai đều được định nghĩa bên trong một class khác. Tuy nhiên, điều này không đúng. Static nested class về mặt ngữ nghĩa tương tự bất kỳ top-level class nào khác và không có reference ngầm đến một instance của enclosing class. Ngược lại, inner class gắn bó mật thiết với một instance của enclosing class và không thể tồn tại độc lập.

Về access modifier, nested class có thể được khai báo là `public`, package-private (mặc định), `protected` hoặc `private`, khác với top-level class vốn không thể khai báo `protected` hay `private`.

Khả năng truy cập của static và non-static nested class phụ thuộc vào access modifier của nó và khả năng truy cập của enclosing class. Ví dụ, nếu enclosing class là `public` và nested class là `private`, nested class chỉ có thể được truy cập bên trong enclosing class. Nếu nested class là public, nó có thể được truy cập từ bất kỳ đâu, miễn là enclosing class cũng truy cập được.

Dưới đây là chi tiết hơn một chút về từng loại:

- **Public Nested Class:** Một nested class `public` có thể được truy cập từ bất kỳ class nào khác, nhưng khả năng truy cập của nested class vẫn phụ thuộc vào khả năng truy cập của outer class. Nếu outer class không truy cập được trong một ngữ cảnh nào đó thì nested public class của nó cũng không truy cập được ở đó.

- **Protected Nested Class:** Một nested class `protected` có thể được truy cập trong package của nó và bởi các subclass của outer class, bất kể subclass nằm ở package nào. Điều này cho phép kiểm soát visibility chặt chẽ hơn so với nested public class, đặc biệt hữu ích khi bạn chỉ muốn lộ một số chức năng nhất định cho một số subclass nhất định.

- **Private Nested Class:** Một nested class `private` chỉ có thể được truy cập bên trong outer class của nó. Điều này hữu ích để ẩn hoàn toàn class khỏi thế giới bên ngoài, chỉ cho outer class truy cập được. Nó thường được dùng cho các helper class không ai quan tâm bên ngoài outer class.

- **Package-Private (Default) Nested Class:** Một nested class không có access modifier là package-private, nghĩa là chỉ có thể được truy cập trong package của nó. Đây là mức truy cập mặc định khi không chỉ định access modifier. Đây là mức trung gian về khả năng truy cập, chặt hơn `public` nhưng thoáng hơn `private`.

Local class được định nghĩa trong một block, thường là trong thân của một method. Visibility của local class bị giới hạn trong block mà nó được định nghĩa. Vì vậy, dù bạn không thể áp dụng các access modifier truyền thống (`public`, `protected`, `private`) cho chính class này vì nó không hiển thị bên ngoài block, bạn vẫn có thể kiểm soát việc truy cập các instance của class này từ bên trong block. 

Và vì anonymous class được dùng trong một biểu thức, chúng không cho phép access modifier cho chính class đó. Ngữ cảnh nơi chúng được khai báo quyết định khả năng truy cập của chúng. Tuy nhiên, các method và field bên trong anonymous class có thể có access modifier, tuân theo các quy tắc scope thông thường.


Đây là bảng tóm tắt các access modifier được phép cho từng loại nested class:

| Loại nested class | `public` | `protected` | `default` | `private` |
|-------------------|----------|-------------|-----------|-----------|
| Static Nested Class | Yes | Yes | Yes | Yes |
| Inner Class       | Yes | Yes | Yes | Yes |
| Local Class       | No | No | Yes* | No |
| Anonymous Class   | No | No | Yes* | No |

- `Yes` nghĩa là access modifier đó được phép.
- `No` nghĩa là access modifier đó không áp dụng được.
- `Yes*` nghĩa là với local class và anonymous class, khái niệm access modifier truyền thống không áp dụng cho các class này vì visibility của chúng vốn chỉ giới hạn trong block nơi chúng được khai báo. Do đó, chúng không có access modifier theo nghĩa truyền thống.

Giờ hãy đi vào chi tiết từng loại.

### Static Nested Class {#static-nested-classes}
Static nested class là một class được định nghĩa bên trong một class khác và được đánh dấu bằng keyword `static`:

```java
class OuterClass {
    static class StaticNestedClass {
        // members of the static nested class
    }
}
```

Static nested class có thể được khai báo với bất kỳ access modifier nào trong bốn mức: `public`, `protected`, package-private (mặc định) hoặc `private`. Khả năng truy cập của static nested class phụ thuộc vào access modifier được dùng và khả năng truy cập của enclosing class. Đây là một ví dụ:

```java
public class OuterClass {
    private static class PrivateNestedClass {
        // ...
    }

    protected static class ProtectedNestedClass {
        // ...
    }

    static class PackagePrivateNestedClass {
        // ...
    }

    public static class PublicNestedClass {
        // ...
    }
}
```

Trong ví dụ này, `PrivateNestedClass` chỉ truy cập được bên trong `OuterClass`, `ProtectedNestedClass` truy cập được bên trong `OuterClass` và các subclass của nó, `PackagePrivateNestedClass` truy cập được trong cùng package với `OuterClass`, và `PublicNestedClass` truy cập được từ bất kỳ đâu.

Static nested class có thể extends một class khác và implements interface, giống như bất kỳ top-level class nào khác:
```java
class BaseClass {
    // ...
}

interface MyInterface {
    // ...
}

class OuterClass {
    static class NestedClass extends BaseClass implements MyInterface {
        // ...
    }
}
```

Ở đây, `NestedClass` extends `BaseClass` và implements `MyInterface`, cho thấy một static nested class có thể extends một class khác và implements interface.

Chúng có thể truy cập trực tiếp các static member của enclosing class, bằng cách dùng tên của enclosing class theo sau là ký hiệu dấu chấm. Tuy nhiên, để truy cập các non-static member của enclosing class, static nested class cần một instance của enclosing class. Đó là vì static nested class vốn không có quyền truy cập các instance variable của enclosing class.

Đây là một ví dụ về nested static class:
```java
class OuterClass {
    private static int staticField = 10;
    private int instanceField = 20;

    static class NestedClass {
        void accessOuterMembers() {
            System.out.println(staticField); // Accessible directly
            System.out.println(instanceField); // Compilation error: cannot access non-static field
            System.out.println(new OuterClass().instanceField); // Accessible via an instance of OuterClass
        }
    }
}
```

Trong ví dụ này, `NestedClass` có thể truy cập trực tiếp `staticField` của `OuterClass`, nhưng không thể truy cập trực tiếp `instanceField`. Để truy cập `instanceField`, nó cần một instance của `OuterClass`.

Để tạo instance của static nested class, bạn không cần instance của enclosing class. Bạn có thể khởi tạo nó bằng tên của enclosing class, theo sau là ký hiệu dấu chấm và tên của static nested class.

```java
OuterClass.StaticNestedClass nestedObject = new OuterClass.StaticNestedClass();
```

Khi tham chiếu các static member của static nested class từ bên ngoài enclosing class, hãy dùng tên của enclosing class, theo sau là một dấu chấm, tên của static nested class, thêm một dấu chấm nữa, rồi đến tên của member. Cú pháp này làm nổi bật cấu trúc lồng nhau đồng thời cung cấp đường dẫn rõ ràng để truy cập static member:

```java
OuterClass.StaticNestedClass.staticField;
OuterClass.StaticNestedClass.staticMethod();
OuterClass.StaticNestedClass.StaticNestedNestedClass nestedNestedObject 
                  = new OuterClass.StaticNestedClass.StaticNestedNestedClass();
```

Từ bên trong enclosing class, bạn có thể truy cập trực tiếp các member của static nested class mà không cần tên của enclosing class.

```java
class OuterClass {
    static class StaticNestedClass {
        static void staticMethod() {
            // ...
        }
    }

    void outerMethod() {
        StaticNestedClass.staticMethod();
    }
}
```

Như bạn thấy, static nested class giống top-level class thông thường ở nhiều điểm:

1. Chúng có thể có mọi loại access modifier (`public`, `private`, `protected` và package).

2. Chúng có thể extends class khác và implements interface.

3. Chúng có thể có static và non-static member.

4. Chúng có thể được khởi tạo độc lập (không cần instance của enclosing class).

Tuy nhiên, có một vài khác biệt chính:

1. Static nested class được định nghĩa bên trong một class khác, còn top-level class được định nghĩa độc lập.

2. Static nested class truy cập trực tiếp được các static member của enclosing class, còn top-level class phải dùng tên enclosing class để truy cập các static member của nó.

3. Static nested class có thể là `private`, cho phép encapsulation tốt hơn, còn top-level class chỉ có thể là `public` hoặc package-private.

Tóm lại, static nested class về cơ bản giống như một top-level class thông thường được lồng vào một class khác nhằm mục đích tổ chức code. Chúng không có reference ngầm đến một instance của enclosing class và có thể được khởi tạo độc lập. Điều này khiến chúng hữu ích để nhóm các class liên quan lại với nhau và cung cấp một mức encapsulation.

### Non-static Nested Class {#non-static-nested-classes}
Non-static nested class, còn gọi là inner class, là các class được định nghĩa bên trong một class khác mà không có keyword `static`:

```java
class OuterClass {
    class InnerClass {
        // members of the inner class
    }
}
```

Inner class có thể được khai báo với bất kỳ access modifier nào trong bốn mức: `public`, `protected`, `private` hoặc mức truy cập mặc định. Khả năng truy cập của inner class phụ thuộc vào access modifier được dùng và khả năng truy cập của enclosing class. Nếu outer class là `public` và inner class là `private`, inner class chỉ có thể được truy cập bên trong outer class. Đây là một ví dụ:

```java
public class OuterClass {
    private class PrivateInnerClass {
        // ...
    }

    protected class ProtectedInnerClass {
        // ...
    }

    class PackagePrivateInnerClass {
        // ...
    }

    public class PublicInnerClass {
        // ...
    }
}
```

Trong ví dụ này, `PrivateInnerClass` chỉ truy cập được bên trong `OuterClass`, `ProtectedInnerClass` truy cập được bên trong `OuterClass` và các subclass của nó, `PackagePrivateInnerClass` truy cập được trong cùng package với `OuterClass`, và `PublicInnerClass` truy cập được từ bất kỳ đâu, miễn là `OuterClass` cũng truy cập được.

Inner class có thể extends một class khác và implements interface, giống như bất kỳ class nào khác. Điều này cho phép inner class kế thừa hành vi và tuân theo các contract do class và interface khác định nghĩa:
```java
class BaseClass {
    // ...
}

interface MyInterface {
    // ...
}

class OuterClass {
    class InnerClass extends BaseClass implements MyInterface {
        // ...
    }
}
```

Ở đây, `InnerClass` extends `BaseClass` và implements `MyInterface`, cho thấy một inner class có thể kế thừa từ một class khác và tuân theo một interface.

Inner class có quyền truy cập tất cả member (field, method và nested class) của enclosing class, kể cả các `private` member. Đó là vì inner class gắn với một instance của outer class và có mối quan hệ đặc biệt với nó. Inner class có thể truy cập và thay đổi trực tiếp trạng thái của instance outer class:

```java
class OuterClass {
    private int privateField = 10;
    protected int protectedField = 20;
    int packagePrivateField = 30;
    public int publicField = 40;

    class InnerClass {
        void accessOuterMembers() {
            System.out.println(privateField);
            System.out.println(protectedField);
            System.out.println(packagePrivateField);
            System.out.println(publicField);
        }
    }
}
```

Trong ví dụ này, `InnerClass` truy cập trực tiếp mọi member của `OuterClass`, kể cả private field `privateField`. Inner class có thể tự do truy cập và thay đổi trạng thái của instance outer class.

Để tạo instance của inner class, thông thường bạn cần một instance của outer class. Cách phổ biến nhất để khởi tạo inner class là từ bên trong một non-static method của outer class:

```java
class OuterClass {
    class InnerClass {
        // ...
    }

    void outerMethod() {
        InnerClass innerObject = new InnerClass();
    }
}
```

Từ bên ngoài outer class, bạn có thể khởi tạo inner class bằng cú pháp sau:

```java
OuterClass outerObject = new OuterClass();
OuterClass.InnerClass innerObject = outerObject.new InnerClass();
```

Để tham chiếu các member (field, method, nested class) của inner class từ bên ngoài outer class, trước tiên bạn cần một instance của outer class, sau đó dùng ký hiệu dấu chấm để truy cập inner class, rồi thêm một dấu chấm và tên member:

```java
OuterClass outerObject = new OuterClass();
OuterClass.InnerClass innerObject = outerObject.new InnerClass();
innerObject.innerField;
innerObject.innerMethod();
```

Từ bên trong outer class, bạn có thể truy cập trực tiếp các member của inner class thông qua một instance của inner class:

```java
class OuterClass {
    class InnerClass {
        void innerMethod() {
            // ...
        }
    }

    void outerMethod() {
        InnerClass innerObject = new InnerClass();
        innerObject.innerMethod();
    }
}
```

Inner class khác top-level class thông thường ở một số điểm:

1. Inner class được định nghĩa bên trong một class khác, còn top-level class được định nghĩa bên ngoài các class khác.

2. Inner class có quyền truy cập mọi member của enclosing class, kể cả `private` member, còn top-level class chỉ có thể truy cập các member `public`, `protected` và `default` của class khác.

3. Inner class gắn với một instance của outer class và không thể tồn tại độc lập, còn top-level class có thể được khởi tạo độc lập.

4. Inner class có thể là `private`, cho phép encapsulation tốt hơn, còn top-level class chỉ có thể là `public` hoặc package-private.

Inner class hữu ích khi một class gắn chặt với một class khác và cần truy cập nội bộ của nó. Chúng cung cấp cách tổ chức các class liên quan và duy trì sự gắn kết chặt chẽ giữa chúng. Inner class thường được dùng để triển khai event listener, iterator hoặc các chức năng khác đặc thù cho enclosing class.

### Local Class {#local-classes}
Local class được định nghĩa trong một block code, thường là trong một method hoặc một constructor. Chúng có scope hạn chế và chỉ truy cập được trong block nơi chúng được định nghĩa:

```java
void someMethod() {
    class LocalClass {
        // members of the local class
    }
}
```

Local class không thể có bất kỳ access modifier nào. Chúng không thể được truy cập từ bên ngoài block hoặc method nơi chúng được định nghĩa. Đó là vì local class không phải là member của enclosing class, mà được định nghĩa bên trong một method hoặc block.

Tuy nhiên, chúng có thể extends một class khác và implements interface, giống như bất kỳ class nào khác.

Ví dụ:
```java
void someMethod() {
    class LocalClass extends BaseClass implements MyInterface {
        // ...
    }
}
```

Ngoài ra, local class có quyền truy cập mọi member (field, method và nested class) của enclosing class, kể cả các `private` member. Hơn nữa, local class có thể truy cập các local variable và parameter `final` hoặc effectively final của method chứa nó:
```java
class OuterClass {
    private int privateField = 10;

    void someMethod(final int parameter) {
        final int localVariable = 20;

        class LocalClass {
            void accessOuterMembers() {
                System.out.println(privateField);
                System.out.println(parameter);
                System.out.println(localVariable);
            }
        }

        LocalClass localObject = new LocalClass();
        localObject.accessOuterMembers();
    }
}
```

Trong ví dụ này, `LocalClass` truy cập được private field `privateField` của `OuterClass`, cũng như parameter `final` `parameter` và local variable `localVariable` của `someMethod()`.

Để tạo instance của local class, bạn có thể khởi tạo nó trong method hoặc block nơi nó được định nghĩa, dùng keyword `new`:
```java
void someMethod() {
    class LocalClass {
        // ...
    }

    LocalClass localObject = new LocalClass();
}
```

Để tham chiếu các member (field, method, nested class) của local class, bạn có thể truy cập trực tiếp chúng thông qua một instance của local class trong method hoặc block nơi nó được định nghĩa:
```java
void someMethod() {
    class LocalClass {
        int localField = 10;

        void localMethod() {
            System.out.println("Local method");
        }
    }

    LocalClass localObject = new LocalClass();
    System.out.println(localObject.localField);
    localObject.localMethod();
}
```

Local class khác top-level class thông thường ở một số điểm:

1. Local class được định nghĩa trong một method hoặc block, còn top-level class được định nghĩa độc lập.

2. Local class có scope hạn chế và chỉ truy cập được trong block nơi nó được định nghĩa, còn top-level class có scope rộng hơn.

3. Local class không thể có access modifier, còn top-level class có thể là `public` hoặc package-private.

4. Local class có thể truy cập các local variable và parameter `final` hoặc effectively final của method chứa nó, còn top-level class không thể truy cập trực tiếp local variable hay parameter.

Local class hữu ích khi bạn cần định nghĩa một class chỉ được dùng trong một method hoặc block cụ thể và không cần được truy cập từ các phần khác của code. Chúng cung cấp cách đóng gói hành vi và trạng thái trong một scope hạn chế.

### Anonymous Class {#anonymous-classes}
Anonymous class là cách định nghĩa và khởi tạo một class tại cùng một thời điểm, mà không cần đặt tên cho nó. Chúng được dùng để tạo các implementation dùng một lần cho interface hoặc abstract class.

Để khai báo một anonymous class, bạn dùng keyword `new` theo sau là tên của một interface hoặc một abstract class, rồi cung cấp class body trong cặp dấu ngoặc nhọn.

```java
interface MyInterface {
    void myMethod();
}

MyInterface myObject = new MyInterface() {
    @Override
    public void myMethod() {
        // Implementation of myMethod()
    }
};
```

Vì anonymous class không được đặt tên tường minh và được định nghĩa ngay tại nơi sử dụng, chúng không thể có access modifier tường minh. Khả năng truy cập của chúng được quyết định bởi ngữ cảnh sử dụng. Cụ thể, scope nơi anonymous class được định nghĩa quyết định khả năng truy cập của nó. Ví dụ, nếu một anonymous class được định nghĩa bên trong một method, nó chỉ truy cập được bên trong method đó. Nếu nó được định nghĩa bên trong một class, nó tuân theo các quy tắc truy cập của class đó.

Một anonymous class có thể extends một class hoặc implements một interface, tuy nhiên nó không thể làm cả hai cùng lúc:
```java
class BaseClass {
    void baseMethod() {
        System.out.println("Base method");
    }
}

interface MyInterface {
    void myMethod();
}

BaseClass anonymousObject1 = new BaseClass() {
    @Override
    void baseMethod() {
        System.out.println("New implementation of base method");
    }
};

MyInterface anonymousObject2 = new MyInterface() {
    @Override
    public void myMethod() {
        System.out.println("Implementation of myMethod()");
    }
};
```

Một anonymous class có quyền truy cập tất cả member (field, method và nested class) của enclosing class, kể cả các `private` member. Ngoài ra, anonymous class có thể truy cập các local variable và parameter `final` hoặc effectively `final` của enclosing method:
```java
class OuterClass {
    private int privateField = 10;

    void someMethod(final int parameter) {
        final int localVariable = 20;

        MyInterface anonymousObject = new MyInterface() {
            @Override
            public void myMethod() {
                System.out.println(privateField);
                System.out.println(parameter);
                System.out.println(localVariable);
            }
        };

        anonymousObject.myMethod();
    }
}
```

Anonymous class không có tên, nên bạn không thể tham chiếu trực tiếp các member của nó từ bên ngoài class body. Tuy nhiên, bạn có thể tham chiếu các member của interface hoặc abstract class mà anonymous class implements hoặc extends:
```java
interface MyInterface {
    void myMethod();
    int myField = 10;
}

MyInterface anonymousObject = new MyInterface() {
    @Override
    public void myMethod() {
        System.out.println("Implementation of myMethod()");
    }
};

anonymousObject.myMethod();
System.out.println(MyInterface.myField);
```

Anonymous class khác top-level class thông thường ở một số điểm:

1. Anonymous class được định nghĩa và khởi tạo cùng lúc, không có tên tường minh, còn top-level class được định nghĩa riêng và khởi tạo bằng keyword `new`.

2. Anonymous class được định nghĩa ngay tại nơi sử dụng, thường là argument của một method hoặc một initializer, còn top-level class được định nghĩa độc lập.

3. Anonymous class không thể có access modifier hay constructor tường minh, còn top-level class có thể có tất cả những thứ này.

4. Anonymous class được dùng để tạo các implementation hoặc instance dùng một lần, còn top-level class được dùng để tạo các class có tên và có thể tái sử dụng.

Tóm lại, anonymous class hữu ích khi bạn cần tạo một implementation dùng một lần cho interface hoặc abstract class mà không cần một class có tên. Chúng cung cấp cách ngắn gọn để định nghĩa và khởi tạo một class trong một biểu thức duy nhất.

Cuối cùng, để khép lại phần này, đây là bảng tóm tắt nhiều thuộc tính của từng loại nested class:

| Thuộc tính                                    | Static Nested Class | Inner Class         | Local Class         | Anonymous Class     |
|-----------------------------------------------|---------------------|---------------------|---------------------|---------------------|
| Liên kết với outer class                      | Liên kết lỏng lẻo (có thể tồn tại mà không cần instance của outer class) | Gắn chặt (không thể tồn tại nếu không có instance của outer class) | Gắn chặt (gắn với một instance của enclosing block) | Gắn chặt (được khởi tạo bên trong một biểu thức và gắn với một instance của enclosing block) |
| Có thể khai báo static member                 | Có (bao gồm static method và field) | Không (trừ final static field) | Không (không thể khai báo static member, chỉ final variable) | Không (không thể khai báo static member, chỉ final variable) |
| Truy cập member của outer class               | Chỉ static member | Cả static lẫn instance member | Cả static lẫn instance member | Cả static lẫn instance member |
| Cần reference đến instance của outer class    | Không | Có | Có (các variable `final` hoặc effectively final ngầm định từ enclosing scope) | Có (các variable `final` hoặc effectively final ngầm định từ enclosing scope) |
| Trường hợp sử dụng điển hình                  | Nhóm các class chỉ được dùng ở một nơi, tăng cường encapsulation | Xử lý event, truy cập private member của outer class, mang lại code dễ đọc và dễ bảo trì hơn | Đóng gói code phức tạp bên trong một method mà không để nó hiển thị ra bên ngoài | Đơn giản hóa việc khởi tạo các object vốn chỉ dùng một lần, hoặc khi định nghĩa class là không cần thiết |



## Class và Source File {#classes-and-source-files}
Cần lưu ý rằng bạn có thể có một hoặc nhiều định nghĩa class trong một Java source file. Tuy nhiên, bạn nên tuân theo các quy tắc sau:

#### Quy tắc public class {#public-class-rule}
Nếu một Java class được khai báo là `public`, tên file phải khớp chính xác với tên của public class, kể cả phân biệt chữ hoa chữ thường, cộng thêm phần mở rộng `.java`. Ví dụ, nếu bạn có một `public` class tên là `MyClass`, thì source file phải được đặt tên là `MyClass.java`:
```java
// File name: MyClass.java
public class MyClass {
    // class body
}
```

#### Chỉ một public class mỗi file {#single-public-class-per-file}
Một Java source file có thể chứa nhiều class, nhưng chỉ có thể có một `public` class. Nếu có nhiều class trong một file và một trong số đó được khai báo `public`, tên file phải khớp với tên của `public` class. Ví dụ, nếu `PublicClass` là `public` class, file phải được đặt tên là `PublicClass.java`, và nó cũng có thể chứa `AnotherClass` không phải `public`:
```java
// File name: PublicClass.java
public class PublicClass {
    // class body
}

class AnotherClass {
    // class body
}
```

#### Không có public class {#no-public-class}
Nếu file không có `public` class nào, bạn có thể dùng bất kỳ tên nào. Ví dụ, file sau đây, `ManyClasses.java`, chứa nhiều class, không class nào là `public`:
```java
// File name: ManyClasses.java
class FirstClass {
    // class body
}

class SecondClass {
    // class body
}
```

#### Các non-public class {#non-public-classes}
Nếu có nhiều non-public class trong một file, thì tên file không cần khớp với tên của bất kỳ class nào. Ví dụ, bạn có thể có một file tên `UtilityClasses.java` chứa nhiều non-public class không khớp với tên này:
```java
// File name: UtilityClasses.java
class HelperClass {
    // class body
}

class AnotherHelperClass {
    // class body
}
```

#### Phân biệt chữ hoa chữ thường {#case-sensitivity}
Java phân biệt chữ hoa chữ thường. Nếu class của bạn được đặt tên là `CaseSensitiveClass`, tên file phải khớp chính xác (`CaseSensitiveClass.java`):
```java
// File name: CaseSensitiveClass.java
public class CaseSensitiveClass {
    // class body
}
```

Vậy hạn chế chính trong Java là một source file không được chứa nhiều hơn một `public` class. Điều này giúp tổ chức code và dễ quản lý hơn. Mỗi public class phải nằm trong source file riêng của nó, và tên file phải khớp với tên class (bao gồm phân biệt chữ hoa chữ thường) cùng phần mở rộng `.java`.

Tuy nhiên, một Java source file có thể chứa bất kỳ số lượng non-public class nào. Những class này mặc định là package-private, và file cũng có thể chứa các nested class `protected` hoặc `private` bên trong các class `public` hoặc package-private. Sự linh hoạt này cho phép nhóm các class có liên quan về mặt logic trong cùng một file nếu chúng không dành cho mục đích `public`, hỗ trợ encapsulation và thiết kế modular.

## Những điểm chính {#key-points}
- Lập trình hướng đối tượng (OOP) tổ chức code thành các object, đại diện cho những thực thể trong thế giới thực chứa dữ liệu (attribute) và hành vi (method).

- Class là bản thiết kế hay template định nghĩa dữ liệu và hành vi chung cho mọi object thuộc kiểu đó, còn object là những instance riêng biệt của một class chứa các giá trị dữ liệu riêng.

- Các giai đoạn chính trong vòng đời của một object trong Java là tạo bằng keyword `new`, truy cập qua reference variable, và dọn dẹp bởi garbage collector của Java khi không còn được tham chiếu nữa.

- Keyword là những từ dành riêng trong Java, định nghĩa cấu trúc và cú pháp của chương trình Java. Chúng không thể được dùng làm identifier.

- Comment là những annotation trong code được compiler bỏ qua, dùng để mô tả hoặc giải thích code. Java hỗ trợ comment một dòng (`//`), nhiều dòng (`/* */`) và documentation (`/** */`).

- Package tổ chức các class, interface và sub-package có liên quan thành một đơn vị duy nhất, cung cấp một mức kiểm soát truy cập. Keyword `package` được dùng để tạo một package.

- Access modifier (`public`, `protected`, `default`, `private`) kiểm soát visibility và khả năng truy cập của class, method và variable từ những phần khác của ứng dụng Java.

- Một class được khai báo bằng keyword `class` theo sau là tên class. Nó có thể tùy chọn extends một superclass bằng `extends` và implements các interface bằng `implements`.

- Field là những variable được khai báo ở cấp class để lưu trạng thái của object. Chúng có thể có access modifier, specifier (`static`, `final`), một kiểu dữ liệu và một giá trị khởi tạo tùy chọn.

- Method là những block code thực hiện các nhiệm vụ cụ thể và tùy chọn trả về giá trị. Chúng được khai báo với access modifier tùy chọn, specifier, return type, tên, parameter và method body.

- Method overloading là việc định nghĩa nhiều method cùng tên nhưng khác parameter list trong cùng một class.

- Java compiler quyết định method overloaded nào sẽ được gọi dựa trên số lượng, kiểu và thứ tự của các argument được truyền khi gọi method.

- Java chỉ có thể chọn một method overloaded nếu nó tìm được kết quả khớp chính xác cho các argument hoặc tìm được một phiên bản cụ thể hơn thông qua widening conversion (`int` sang `long`, `int` sang `double`, v.v.).

- Varargs (argument có độ dài thay đổi) cho phép method nhận số lượng argument không xác định của một kiểu cụ thể. Để định nghĩa một method với varargs, dùng dấu ba chấm (...) sau kiểu dữ liệu của parameter cuối cùng trong method signature.

- Parameter varargs phải là parameter cuối cùng trong parameter list của method, và mỗi method chỉ cho phép một parameter varargs.

- Các method có varargs có thể được overload, nhưng bạn phải tránh sự mơ hồ bằng cách đảm bảo các method signature khác nhau.

- Constructor là method đặc biệt dùng để khởi tạo object, được gọi khi một instance của class được tạo bằng keyword `new`. Chúng có cùng tên với class và không có return type.

- Instance initializer là những block code được thực thi khi một object được tạo, tương tự constructor nhưng không có parameter. Chúng được đặt trong `{}` bên trong class body.

- Static initializer là những block code được thực thi khi một class được nạp vào bộ nhớ, trước khi bất kỳ instance nào được tạo. Chúng được định nghĩa bằng keyword `static` theo sau là `{}`.

- Mọi class đều ngầm extends class `java.lang.Object`, kế thừa những method nền tảng như `toString()`, `equals()` và `hashCode()`.

- Nested class là những class được định nghĩa bên trong một class khác. Chúng có thể là static nested class, inner class (non-static nested class), local class hoặc anonymous class.

- Static nested class gắn với chính outer class và có thể truy cập trực tiếp các static member của nó. Chúng có thể được khởi tạo độc lập, không cần instance của outer class.

- Inner class (non-static nested class) gắn với một instance của outer class và có quyền truy cập cả static lẫn non-static member của outer class. Chúng cần một instance của outer class để được khởi tạo.

- Local class được định nghĩa bên trong một block, thường là một method, và có quyền truy cập các variable `final` hoặc effectively final từ enclosing scope. Chúng không thể có access modifier và chỉ hiển thị bên trong block định nghĩa.

- Anonymous class được định nghĩa bên trong một biểu thức và được dùng để tạo các implementation dùng một lần cho interface hoặc abstract class. Chúng không có tên và được khởi tạo ngay tại điểm khai báo.

- Nếu một class được khai báo `public`, tên của Java source file phải khớp chính xác với tên của `public` class, kể cả phân biệt chữ hoa chữ thường, cùng phần mở rộng `.java`.

- Một Java source file có thể chứa nhiều định nghĩa class, nhưng chỉ một trong số đó được khai báo `public`. Nếu không có `public` class, tên file có thể khác với tên các class.

**23. Xét đoạn code Java dưới đây minh họa việc dùng anonymous class:**

```java
public class HelloWorld {
    interface HelloWorldInterface {
        void greet();
    }

    public void sayHello() {
        HelloWorldInterface myGreeting = new HelloWorldInterface() {
            @Override
            public void greet() {
                System.out.println("Hello, world!");
            }
        };
        myGreeting.greet();
    }

    public static void main(String[] args) {
        new HelloWorld().sayHello();
    }
}
```

Câu nào sau đây đúng về anonymous class trong Java?

**A)** Anonymous class có thể implements interface và extends class mà không cần khai báo một class có tên.  
**B)** Một anonymous class phải override tất cả method trong superclass hoặc interface mà nó tuyên bố là đang implements hay extends.  
**C)** Anonymous class có thể có constructor như các class có tên.  
**D)** Instance của anonymous class không thể được truyền làm argument cho method.
